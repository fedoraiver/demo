# demo

使用 Bevy 0.19.1，构建策略在 `Cargo.toml` 中配置。

## 最初原型

使用简易 3D 资产：胶囊人物、木箱、平地和固定角度跟随镜头。输入由 `bevy_enhanced_input` 0.26.0 管理。

| 操作 | 行为 |
| --- | --- |
| WASD | 沿地面移动，朝向移动方向，斜向移动不会加速。 |
| 空格 | 地面起跳并落回地面；持续按住不会反复跳跃，空中不能再次起跳。 |
| E | 拿起范围内最近的可拾取木箱；持有时再次按下则放到面前地面。 |

持箱时可以继续移动和跳跃。首版只生成一名键盘玩家，玩家身份、控制目标和角色状态分别存储，输入按控制者路由；后续可增加其他玩家，当前不包含联机或分屏。
人物和木箱的视觉模型放在各自业务实体的子实体上，后续美术替换不需要改移动或拾取逻辑。

### 模拟频率与渲染上限

移动、跳跃、重力和交互使用固定 60 Hz 模拟。渲染循环单独限制帧率，默认上限为 120 FPS；性能足够时尽量接近上限，性能不足时不额外等待。主窗口使用 `AutoNoVsync`，避免垂直同步额外限制帧率；平台不支持时 Bevy 仍可能回退到垂直同步，关闭垂直同步也可能出现画面撕裂。

在工作目录的 `settings.json` 中修改 `max_fps` 为正整数，例如 `60`、`120` 或 `144`，重启游戏后生效。当前尚无游戏内设置界面。文件缺失时使用默认设置；读取失败或内容无效时记录警告并使用默认设置，不覆盖原文件。渲染上限不会改变模拟频率，也不会保证每秒一定能渲染到该数量的帧；当前尚未添加移动插值。

帧率限制只等待从上一帧起点算起的剩余时间，操作系统调度可能使实际帧率略低于上限。初始化日志记录模拟频率、实际采用的上限及设置文件路径。

### 用户手动验收

Agent 未启动游戏，实际运行和视觉效果尚未验收。请在仓库根目录自行运行 `cargo run --locked`，然后检查：

1. 场景中能看到人物、前方木箱和地面；按 WASD 后人物移动、转向，镜头持续跟随。
2. 按空格时人物起跳并落地；持续按住或在空中再次按下不会额外起跳。
3. 靠近木箱按 E，木箱移动到人物身前；移动和跳跃时木箱跟随，持续按住 E 不会重复拿放。
4. 松开后再次按 E，木箱落在面前地面；走远后按 E 不会拾取，走近后可以再次拿起。
5. 正常关闭窗口后查看 `logs/` 中本次 `unix-<时间戳>_<会话UUID>.log`，应包含会话开始、版本和配置、实体生成、移动速度变化、起跳着陆、拿起放下和正常退出；再次启动生成新文件，旧文件保留。
6. 默认设置下用外部帧率监测工具观察帧率：性能足够时应接近 120 FPS，性能不足时可低于上限。把 `settings.json` 中的 `max_fps` 改为 `60` 后重新启动，观察上限降低，人物移动和跳跃速度仍保持一致。两次会话日志中的 `simulation_hz` 应均约为 `60`，`max_fps_after` 分别为 `120` 和 `60`。完成后恢复设置为 `120`。

日志消息及代码定义的状态、原因和错误提示使用英文，外部错误信息和文件路径保留原文。日志与存档分开管理。异常上下文也写入会话日志；如果出现问题，可提供对应日志供排查。

日志由 Bevy 默认 `LogPlugin` 初始化，通过 `custom_layer` 同时写入会话文件；控制台格式和过滤规则使用 Bevy 默认配置，可用 `RUST_LOG` 调整级别。

### Corner cases（暂缓）

以下情况仅作记录，暂不纳入最初原型的实现与验收范围。

| 场景 | 暂缓的处理 |
| --- | --- |
| 多个角色在同一固定步请求拿起同一个木箱 | 暂不增加集中裁决、同批次占用预留和多人抢箱规则。 |
| 角色退出或被销毁时仍持有木箱 | 暂不增加销毁前主动放下木箱的业务流程及对应离开原因日志；保留 Bevy 关系自身的生命周期维护。 |
| 持有关系被异常解除后，木箱留在空中 | 暂不增加自由物体落地兜底或异常关系恢复流程。 |

持有状态使用 `HeldBy` / `HoldingItems` 自定义关系，拾取入口通过 `With<Pickable>` 过滤；反向索引由 Bevy 自动维护。

### 无窗口验证

```powershell
cargo fmt --all -- --check
cargo check --locked
cargo test --locked
```

测试只使用最小 App / World 和临时日志文件，不创建窗口或启动完整游戏。

## 日常开发与调试

```powershell
cargo run
cargo build
cargo check
```

项目代码使用一级优化并保留完整调试信息，兼顾编译速度和运行性能。
Bevy 等依赖使用三级优化，避免调试构建的引擎运行过慢。
调试断言和整数溢出检查保持开启。优化可能使单步调试跳行，或使部分变量无法查看。
首次构建依赖耗时较长，后续修改项目代码可以复用依赖缓存。

输出：`target/debug/demo.exe`。

## 正式发布

```powershell
cargo build --release --locked
cargo run --release --locked
```

使用三级优化、Thin LTO 和单个代码生成单元，优先考虑运行性能；构建会比调试模式更慢。
移除调试信息，使用 Cargo 默认的发布模式断言与溢出检查设置。
保留默认 panic 行为，便于正常清理资源和处理线程异常。
`--locked` 确保使用提交的 `Cargo.lock`，依赖需要变化时直接报错。

输出：`target/release/demo.exe`。后续添加外部资源时，发布包也需要包含对应的 `assets` 文件。
