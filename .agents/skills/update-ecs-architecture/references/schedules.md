# Schedule 快照、导入与筛选模型

在导出、导入、Graphviz 生成或调度筛选模型维护前读取；执行阶段及命令归[维护流程](workflow.md)，筛选控件与历史归[查看器](viewer.md)。

## 真实装配与注册快照

按[调度快照](../../../../docs/diagrams/README.md#调度快照)核对覆盖和边界。导出复用真实应用装配，在插件就绪并完成 `finish` 后、`cleanup` 前，记录主应用及可访问子应用中的全部已注册 Schedule。应用与 Schedule 共同标识图，不按标签名称合并不同应用的调度。

## 导出有效性与导入失败

统一执行器除源码指纹、锁定版本和输入哈希外还核对构建配置与工具链上下文；旧导出缺少来源记录时为 `unknown`，`run` 专用导出一次补证。有效上下文匹配时复用，不重复导出。需要独立导出时仍可使用以下命令，再把目录传给维护入口：

```powershell
cargo run --locked --features debugdump -- --dump-schedules tmp/debugdump
```

该专用导出允许 Agent 执行，不进入游戏循环、不执行 Startup，但完整装配可能初始化 GPU、音频设备及资产。执行边界见[验证参考](../../../../docs/testing/README.md#agent-验证边界)；不得省略 `--dump-schedules` 或改为启动、操作游戏。导出失败时完成独立工作并明确缺项，不用测试夹具或旧系统图冒充真实结果。

检查导出清单的应用、Schedule、稳定文件身份、依赖版本、内容哈希及源码指纹。缺失、冲突或过期输入必须使导入失败。正式清单、DOT、SVG 和 HTML 一起保留，源码指纹匹配时可从正式 DOT 离线重建。

## Graphviz 呈现与语义边界

Graphviz 由锁定的 `@viz-js/viz` 生成默认 SVG，并在浏览器离线 Worker 中按需重排筛选后的 Schedule。呈现样式在布局前应用，系统、集合和依赖线复用对象样式，位置与路径仍由 Graphviz 产生；不套用 Mermaid 的身份或严格走线检查，不手工接线、改箭头或补画关系。它表达注册快照，不表示条件成立、系统实际执行、后续动态注册或 Observer 触发关系，也不拼接跨 Schedule 总序。

## Plugin 分组与条件语义

维护[调度筛选](../../../../docs/diagrams/README.md#调度筛选与重新布局)时，核对包含／排除下拉按来源 Plugin 组多选、目录与完整路径的对应、未知来源及无当前系统的已选组；不把定义路径当作实际注册 Plugin 的证据。勾选、取消、批量选择和清空立即生效，搜索仅缩小选项范围，集合名不参与筛选；核对多组并集、空包含与排除优先，以及旧完整名称、旧文本条件的兼容和取消。

## 筛选投影与中间模型

筛选保留命中系统、必要祖先集合与 marker，以及两端仍存在的原边，不加入未命中系统邻居或跨删除节点补边；原生上下文端点按该节规则保留，不补造名称或计入系统数。空筛选直接恢复默认 SVG，不初始化 WASM；零命中与失败明确反馈。保留原始 DOT、来源哈希及节点身份，核对中间模型的边、有效属性和集合层级，以及分组元数据与来源的对应；不把限定的 debugdump 转换器当作通用 DOT 无损解析器。
