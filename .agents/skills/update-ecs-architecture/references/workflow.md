# 维护流程与执行记录

实际维护时先读取本参考，再按阶段读取[调度](schedules.md)、[对象模型](object-model.md)、[绘图](rendering.md)、[查看器](viewer.md)及[视觉验收](visual-validation.md)中涉及的规则。仅局部维护时按相关阶段读取；仅修改 Skill 的检查边界见[入口](../SKILL.md#读取与范围)。

## 维护输入与文件归属

核对 `build-ecs.mjs`、调度导出与导入模块、`ecs-data.json`、对象目录、源码策略、查看器及对应 Rust 源码。修改维护入口，不手改生成 HTML、SVG 路径或源码快照。

包根仅保留说明、配置和 build／check／serve 薄入口；实现、人工目录、测试及许可证分别归入 `src/`、`catalog/`、`tests/`、`licenses/`。生成文件在 `generated/` 内按页面、数据、对象／调度／图例 SVG、DOT 和 Mermaid 分类。路径由共享模块管理，新格式夹具使用相同目录策略，旧格式平铺夹具仅保留兼容验证；移动文件后更新引用、文件属性和清理清单，保持原始 SVG／DOT／Mermaid 字节与身份。

## 角色与默认模型

以下是项目的子代理默认分工，模型标识与 reasoning effort 使用当前委派接口支持的值；主代理按范围选择所需角色，可顺序复用代理，不要求每轮同时启用全部角色。主代理统筹输入、依赖、结果与用户已授权的合并，不把 PR 合并或其他分支变基列为架构维护的默认任务。

| 角色 | 默认模型与 reasoning effort | 职责 |
| --- | --- | --- |
| 架构维护 | `gpt-6.1-sol` / `high` | 核对真实源码与身份，修改清单、生成器及必要产物。 |
| 独立复审 | `gpt-6.1-terra` / `high` | 复核源码证据、关系、身份和验收缺口；不得复审自己参与的修改。 |
| SVG 目测 | `gpt-6.1-terra` / `medium` | 子代理实际查看分配的 SVG 并记录逐图证据。 |
| HTTP／浏览器验收 | `gpt-6.1-sol` / `medium` | 核对冻结后的页面、资源、交互及访问边界。 |
| 检查执行 | `gpt-6.1-terra` / `low` | 执行已确定的命令、收集退出结果与日志，不代替语义复审。 |

仅当现有推理强度仍无法消除具体歧义，或同一原因的修复再次失败时，将相关角色的 reasoning effort 提高到 `xhigh`，并记录升级原因；普通泛型核对不自动升级其他角色。复杂修改可拆分互不覆盖的任务。

## 委派、单写者与恢复

委派时给出工作区、输入提交及未提交变更指纹、文件范围、依赖和交付证据。同一工作区的生成器及共享索引各指定单写者；有既定 Cargo 串行约束时，由单一 owner 排队执行，其他代理只读结果。

确定性的预检、执行、恢复、计时、模型差异和 SVG 证据管理统一调用[正式维护入口](../../../../docs/diagrams/README.md#生成与校验命令)，不再复制临时脚本。阶段记录在所属工作区 `tmp/ecs-architecture/maintenance/`，交付时区分实际执行与排队／交接等待。

语义、用途、未知源码行为仍由维护代理判断；实际 SVG 观察及浏览器、协议和离线验收仍由对应代理执行。恢复时用 `status`／`report` 核对当前内容、真实进程、输出与退出，不凭 session 标识或 mtime 判定通过。已完成代理用会触发执行的接口唤醒，不只发送普通消息。

## 计划与预检

先运行 `npm run maintain --prefix docs/diagrams -- plan` 核对真实导出；来源上下文有效性及专用导出见[调度输入](schedules.md#导出有效性与导入失败)。

完整构建前，通过 `preflight` 共用正式构建的准备和核对逻辑，在 Chromium／SVG 编译前检查真实声明与注册身份、泛型实参、实体投影、悬空引用及生命周期源码。删除或拆分旧对象仍由维护代理检查迁移清单与业务语义。

## 源码行号修复与快速回归

源码行号问题可先用 `fix-source-lines` 只读预览，只有明确且唯一的定义入口才可显式 `--apply`；其余位置人工修复，禁止自动猜测注册、别名或业务关系。按改动补充快速语义回归，失败先修复，再进入编译。

## 结果复用与受影响检查

真实调度清单与 DOT 的复用以[来源上下文核对](schedules.md#导出有效性与导入失败)为准。依赖安装与锁文件匹配时不重复 `npm ci`；渲染输入、配置与工具版本匹配时复用现有合法缓存，仍保留文字、身份及严格几何检查。

仅查看器、筛选模型或样式变化且导出仍有效时不要求重新运行应用，也不触发 Rust 检查。修复后重跑受影响的检查及下游，不重新执行输入未变且已通过的全链路。

## 执行、恢复与报告

从仓库根使用统一入口；`--workspace` 可明确指定 worktree，`--debugdump` 可指定已取得的真实导出。执行器按必要性安装依赖／导出、预检、记录旧模型、生成、校验和完整 Node 回归，失败停止下游，未改的有效阶段按内容复用。最终输入必须具有对应的全量成功结果，快速回归不替代它：

```text
npm run maintain --prefix docs/diagrams -- run
npm run maintain --prefix docs/diagrams -- run --resume <run-id>
npm run maintain --prefix docs/diagrams -- report --format markdown
```

Node.js、渲染器及编译要求以锁定依赖为准；Mermaid Chromium 只用于文档编译。

自动检查稳定后进入[冻结与视觉验收](visual-validation.md)，交付时使用该参考的分类报告要求。

## 产物清单与检查器边界

动态产物清单包含 Schedule DOT／默认 SVG、object Mermaid／SVG、独立图例 SVG，以及两份 HTML、外部索引／逐视图数据、完整校验模型和源码快照；旧总览、插件及基础设施系统图不残留。筛选结果不覆盖正式产物。校验器按 engine 分派：Graphviz 核对清单、来源、尺寸与输入输出对应；Mermaid object 保留原身份、单卡／一跳可见投影、源码与几何检查。自动审计不代替源码核对，也不保证发现全部遗漏的 Rust 行为。
