# 编译器对象模型与源码证据

在维护对象身份、类型、关系、源码或用途前读取；可见图投影归[绘图规则](rendering.md#对象可见投影)，阶段组织归[维护流程](workflow.md)。

## 事实与身份

[编译器事实契约](../../../../tools/rustc-analysis/contract/src/facts.rs)表达声明、类型实例、可调用实例、访问、操作、调用、实体创建模板、注册和缺口。[提取器](../../../../tools/rustc-analysis/compiler/src/ecs.rs)使用展开后的源码、类型检查结果与 MIR，[模型装配](../../../../tools/rustc-analysis/runner/src/model.rs)连接真实运行时快照。Node 只消费其结果，不扫描 Rust 或维护结构事实副本。

声明身份使用精确 Cargo 包来源、目标以及原生定义路径的命名空间和消歧序列，会话内 `DefId`、`StableCrateId` 和 `-Cmetadata` 不作为持久声明身份。workspace 路径包使用相对工作区的位置，物理 worktree 根不进入持久身份；来源无法唯一绑定时保留原生身份与缺口，不按 crate 短名猜包。跨编译单元合并同一声明时，`local` 标记使自身编译单元的 HIR 证据优先于导入元数据回退，不依赖单元到达顺序；多个 owning unit 的 HIR 行为证据冲突时拒绝合并。类型实例保留完整类型和常量泛型实参；别名和重导出指向真实声明，未解析的关联类型保留自身投影与缺口，不借用同名声明。

具体系统入口来自 rustc 代码生成单元的单态实例及依赖导出的泛型实例，以真实 `System` trait 方法身份筛选，优先分析其中的函数和闭包。依赖私有实例需要在依赖自身的编译单元采集；只分析根项目不能覆盖全部注册。

运行时注册以应用、Schedule 和快照内原生键区分，同函数多次注册及不同泛型、闭包和组合系统保持独立。系统条件和集合条件作为独立的 System 实例保留，以条件作用域区分，并记录自己的访问与操作；条件求值不等于主系统执行。实体对象表示创建模板，不表示运行时 `Entity` 的永久身份；创建位置、实例化上下文和子实体路径共同区分模板。同类型组件在不同模板中的装配关系分别表达。

对象 ID 随模型生成。

类型对象的 `typeIdentity` 保留原生声明 ID、crate、定义路径、trait 角色及可取得的包名和版本。基础设施菜单按这些字段唯一选择真实对象，缺失或歧义时明确失败，不合成对象 ID。`local` 表示定义相对采集编译单元的位置，不表示项目归属；`NonSend` 是存储投影，不据此给原生类型补造 trait 角色。

## 关系与操作证据

Component、Resource、Local、NonSend、SystemParam、QueryData、消息和事件根据完整类型与真实 trait 实现区分。包含未实例化泛型或未解析投影的类型保留为带缺口的事实，不晋升为具体对象。Bevy 0.20 的 Resource 同时满足 Component 约束，默认对象分类优先 Resource，每条访问仍保留明确的存储角色；无法关联的运行时访问连同原始记录保存在 `runtime-access-type` 缺口中，不按名称补绑定。参数访问声明与函数体操作分开记录：可变访问不证明字段修改，更不证明插入或移除；`With`／`Without`／`Has` 和存在检查不自动成为字段读取。当前赋值证据先确认具体类型值被修改；没有追踪到 ECS 存储来源时使用 `typed-value` 作用域和 `storage-origin` 缺口，不把普通副本的赋值当成组件或资源写入。

真实方法声明用于区分 ECS 操作与容器同名方法。MIR 调用摘要按实例传播泛型、helper、闭包捕获、引用修改和有限分支，保留实际操作、调用链、条件、主／子世界及 Commands 的延迟时机。普通 helper 不冒充注册系统，销毁实体不证明其必然拥有某个固定组件。`callGraph` 保留可达调用点、条件的正反分支及延迟标记；schema 2 在主模型保存相对文件名、SHA-256 和边数，完整边及证据逐行保存在同目录的 `model.calls.ndjson`。生成与校验流式遍历全部记录，正式分发原样复制并登记清单，不因对象图不直接使用调用图就略过验证。操作附带的 `callChain` 只是一条有明确标记的代表静态路径，不能当成全部路径或实际执行轨迹。Local 对象对应实际注册入口的具体可调用实例与参数槽，组合系统的同名参数不合并；helper 传递 Local 值不证明存在新的局部存储，未确定来源的传递保存在 `local-origin` 缺口中。

Bundle、required components 和 BSN 按实际实现及值流提取，父实体与子实体独立。创建调用只连接与当前可调用实例、源码及宏来源唯一匹配的根模板；子模板沿实际层级关系表达。导入资产、动态场景、类型擦除回调或无法收敛的路径保留明确缺口，不能画成已确认的组件装配或业务边。已确认的创建、销毁等操作若尚未连接到具体运行时实体模板或可见类型，保存在 `operation-target` 分析缺口中，不能静默丢弃或猜测目标。

场景分支保留独立结构候选及源码，不能把不同候选的组件或同序号后代合并成一个确定实体。候选关系与子实体关系分别记录，候选及其条件后代保留 `possible` 上下文。单次场景调用的多个返回状态使用 `one-of`；无法证明互斥或同时存在的创建记录使用 `unresolved`，不补猜分支条件或创建数量。

## 源码范围与生命周期

源码位置来自编译器 `Span` 和宏展开链，保留定义、参数、调用、注册、装配、操作及可确认的生命周期角色。按[源码范围](../../../../docs/diagrams/README.md#源码范围)呈现；类型定义不能代替操作，普通使用位置不能提升为定义。

Component 的创建、后续插入、移除与销毁只连接具备模板证据的对象；自动生命周期同时保留配置与实际实现。无法确认模板或必要入口时写入具体 `sourceGaps`，不以可变参数、名称或通用 helper 填补。

项目与依赖源码文件由当前编译单元及锁定 Cargo 包定位，标准库源码通过与编译器提交匹配的 `sourceOrigins` 定位。保留包身份、目录边界、真实行列、宏来源和完整文件哈希；生成的源码快照必须对应同一输入。依赖没有本地 HIR 时使用编码 MIR 和可取得的声明信息，不退回正则扫描。

## 中文用途与业务解释

[annotations.json](../../../../docs/diagrams/catalog/annotations.json)只保存自然语言说明。按[待补流程](workflow.md#中文用途补写)由大模型阅读确切声明、函数体及必要 helper，补写 `description` 与 `summary`；证据已变化的说明重新核对。同一完整规范路径对应多个声明时，注释键使用 `<完整路径>#<declarationId>`，始终以待补项的 `key` 为准，不按短名合并。

本地声明的用途哈希覆盖 rustc HIR owner 及其独立存放的函数体，以同一持久定义身份散列引用并排除 Span；模型还合入可达 helper 的行为证据。实体用途散列创建结构及 creator/helper 行为，不序列化源码行列或文件 SHA。纯行号移动更新源码位置与文件快照，不使本地用途失效；函数体、初始化值或宏展开后函数体变化会使对应说明失效。源码文件 SHA 校验完整文件，与用途哈希分别承担定位有效性和行为证据职责。

实际引用的 const/static 初始化证据进入用途哈希，无关声明不因此使一般用途失效。外部 static 使用原生求值后的初始化分配、类型及可变性，不以包含编译 metadata 的 crate hash 代替。尚不能绑定具体 impl 的关联常量及没有可用 Rust 初始化体的引用保留未知标记与缺口；仅受影响的用途保守合入全部实际编译单元的可移植 HIR 摘要，以覆盖下游实现，缺少任一单元摘要时失败。摘要包含编译器、target 和实际 cfg，不包含物理位置。说明的证据哈希必须匹配当前身份与用途证据算法；不匹配时按待补项复核说明。

系统说明主要行为、输入输出、条件和清理职责；类型说明承载的数据；Local 按所属函数与参数槽说明局部状态；集合说明类型或枚举项的职责，匿名集合只说明快照确认的成员和条件。空集合不声称存在执行成员，未知结构不通过自然语言猜测补齐。

外部 I/O 或业务分组属于解释层，仍须关联真实源码证据。日志输出区分 tracing producer、File worker、会话文件和 Console worker；没有编译器操作或已确认业务证据时，不补造队列、stderr 或退出关系。
