## 对照源码维护

以源码的实际注册和访问为准，按请求范围核对以下内容：

- 插件装配、系统与 Observer 注册、Schedule/SystemSet、运行条件、显式顺序及延迟命令可见时机。
- Entity 身份、组件与资源字段、系统私有状态、查询读写和过滤条件；区分 `QueryData`、`SystemParam`、普通辅助值和 ECS 组件。
- `ChildOf` 等 Bevy 关系与普通 `Entity` 引用、生成和销毁、消息与事件、动作上下文及 Observer 触发条件。
- 功能总览中的 14 个项目插件、主要协作契约，以及 Bevy、Avian、Enhanced Input、Kira、Egui 各独立入口的“系统与调度”“数据与实体”“事件与协作”三个页签、对应说明和源码入口。空页签保留明确空态，不能删减系统、实体关系、Observer 或必需节点来简化布局。没有显式顺序的系统或 Observer 不得画成全序流水线。

在清单集中维护插件目录、节点归属、显式调度与协作边，复用系统 `module`、实体关系与 Observer 记录。区分类型定义归属、系统注册归属和实体装配来源；数据页已出现的每个 Entity 补齐 `entities[].components` 完整清单，其他页签继续按插件关注范围展示，完整详情保留。补齐组件不递归增加其他实体、系统或关系，组件原归属、源码与外部引用保持。跨视图沿用稳定语义节点 ID，同一视图内每个语义节点只声明并显示一次，全部关系连接这个方框，不按关系行复制端点。旧 ID 仅可通过显式 `node_aliases` 指向同一声明和身份的规范节点并保留旧链接；同函数的不同调度注册、不同实体上的同名组件分别保留，禁止通过别名合并。外部系统、插件和协作契约显示摘要、所属插件和跳转入口，不展开其他插件内部流程；日志后台线程保持外部 I/O 身份。

按[读图规则](../../../docs/diagrams/README.md)在视图层过滤 `main / App` 到插件的纯装配注册边，原始模型与稳定 ID 保留；生成后检查没有因过滤而孤立的外部 `main / App`，同时确认项目插件安装第三方插件及日志退出刷新等其他关系仍有可见入口。

通过共享 `architecture-infrastructure.mjs` 维护 Bevy 与四个第三方入口、侧栏分节和文件前缀；插值归 Avian 分组，第三方 Inspector 归 Egui 分组，实际来源与类型身份保留。区分浏览归属与类型定义归属，Bevy 泛型容器承载第三方类型时保留其 Bevy `defined_in`。系统优先使用显式 `feature`，缺省时沿用项目 `module` 或 Bevy 的归属规则，不把所有非项目模块归为 Bevy。总览复用现有规范插件节点，不保留第三方汇总卡片或混合业务图。保留业务节点 ID、关系及旧节点深链接；旧 `third_party` 的真实节点链接转到当前归属，没有节点、节点失效或指向 `third-party-plugins` 则回总览，保留工作区参数及其他 URL 状态并替换历史。跨入口摘要与跳转使用当前归属，`main / App` 仅是应用上下文，原生窗口回调归窗口策略。

侧栏第三方四个入口位于 Bevy 引擎之前。按[源码定位规则](../../../docs/diagrams/README.md#在-vs-code-中打开源码)核对 Bevy 与第三方 `Component`、`Plugin` 及已审阅的系统集合、引擎系统／Observer、同步节点：通过 `architecture-source-definitions.mjs` 的集中映射和 `dependency-sources.mjs` 定位真实锁定依赖定义，组件按 `defined_in`、插件按提供包审阅，系统集合及同步契约按实际声明或实现核对，不按显示名称猜测。原项目使用或注册位置 `source` 保留，生成注册表另附 `definition_source`；资源、实体和聚合输出继续使用原入口。核对 Kira 项目别名、宏展开入口及 Avian 二维／三维同名定义，声明必须精确唯一；按动态目标清单覆盖全部定义入口，特别核对 PlayTypedChannels 与三处 ApplyDeferred 在项目页和提供方页均定位依赖定义，各自项目注册信息保留。Cargo 路径由本机 `cargo metadata --locked --offline` 取得，不把个人根目录写入维护清单或映射；生成的两份 HTML 保存本机 Cargo 根目录及完整依赖源码快照，跨机器定位需要重新生成，工作区配置只影响项目文件。校验包名、版本、目录、文件、行号及快照，覆盖缺失、篡改、目录外逃和快照残缺，保留原项目源码校验。
日志拓扑按读图规则核对 producer、worker 与文件的方向，不画业务系统绕过 worker 直写文件；物理插件的日志协作只引用 producer，完整内部链仅在会话日志页展示。保留文件节点 `physics-file-log` 的身份与 `External I/O` 类型，将源码入口定位到 `create_session_file`；不扩展既有退出刷新关系，不新增队列或 stderr 终点，生成后逐边核对两条输出分支。

全部正式图形使用 Mermaid 定义真实编译。“系统与调度”用 Dagre 布局，主图区横排、Schedule 子图 `direction TB` 纵排系统；当前真实关系保留在各自 `schedule_group` 内。`view.scheduleLinks` 单独连接当前视图中真实先后的可见阶段，Egui 使用内部驱动，原生回调、渲染子应用和说明框不进入主调度链；阶段标题不显示“0…N 次”，不增加循环分支。不可见 `layoutLinks` 只约束排版，系统显式执行依赖由 `kind=order` 表达，三者不得混淆。数据页整体采用 Dagre `TB`，移除透明 `diagram_main` 包装并以默认 `rankSpacing: 8` 减少嵌套空白；总览与事件页采用 Dagre `LR`。业务 SVG 与 `.mmd` 不包含读图指南样例。分别检查节点横纵坐标、关系语义及实际遮挡。Mermaid 定义通过 YAML frontmatter 中的合法 JSON 对象携带完整主题、布局与配置。Node 编译器和离线浏览器运行时均须在 Mermaid 初始化时显式读取同一共享 `maxTextSize: 200000`，支持完整 Bevy 等超过 `50000` 字符的定义，不能仅依赖解析前尚未应用的 frontmatter。独立 CLI 编译也须从定义配置取得相同初始化上限，完整 frontmatter 保留。具体约定见 [Mermaid 布局与连线](../../../docs/diagrams/README.md#mermaid-布局与连线)。

按 [节点与连线视觉规范](../../../docs/diagrams/README.md#节点与连线视觉规范) 维护集中样式模块 `architecture-style.mjs`：`visualType`、`edgeSemantic` 与 `displayLabel` 分别维护视觉类型、连线语义和可见文字，不改变稳定身份或复用 `kind` 偷换模型含义。节点使用真实 Mermaid 扩展形状，以描边色 `8%` 与白色 `92%` 按通道四舍五入生成填充；形状、描边和 16 类连线仍以集中定义为准。图内文字统一 `14px`，完整名称加粗、短用途常规字重；名称优先在 `_`、`::` 边界换行，不截断或省略字符，也不重复类型标题或所在 Schedule。所有页签的 Component 均不注入所属实体前缀，外部提供插件仍融入用途句，实体身份在嵌套上下文及详情查看。共享 `guideSamples.nodes[type]` 仅编译该类型一个普通 SVG，右侧按当前页实际出现的节点和连线类型筛选；仅作为外部引用出现的类型仍展示普通样例。有外部节点时只补充 `Dashed node outlines indicate external references.`，不编译或绘制外部变体；业务外部虚线继续独立校验。不保留旧指南正文，不增加业务节点或关系，也不混入业务图形布局。

右侧图例使用 `Nodes`、`Edges` 分节标题和 `Legend` 无障碍名称；14 类节点与 16 类连线的英文名称由集中样式的独立 `legendLabel` 提供，不能改写原有 `label`，详情与业务图形无障碍描述仍使用原文案。以 `System`、`Entity`、`Component`、`Resource`、`Local<T>`、`NonSend<T>`、`Messages<T>`、`EntityEvent` 等名称核对真实类别；混合职责使用 `Contract`、`Note`、`External I/O` 等泛称，不假设其对应单一 Bevy API。检查英文词表覆盖所有类型、泛型字符未被 HTML 吞掉、按页筛选与清除选择仍有效，其他中文内容和选中样式不因图例调整改变。

逐类审阅节点 `description`，检查全部 canonical Component 的短句是否说明实际用途。已有简洁用途直接复用；过长、仅描述实现步骤或没有说明承载内容时，在原记录添加或修正 `display_summary`，用完整中文短句说明系统实际做什么、资源或组件承载什么，不重复归属、读写或条件，不机械截取旧说明。完整 `description` 保留在右侧详情，不以短用途覆盖原始字段；总览插件也使用同一规范节点的用途，避免各视图另写文案。

选中样式从集中定义读取：填充以语义描边色 `22%` 与白色 `78%` 混合，透明或无填充图元保持原样；真实轮廓额外加粗 `2` 个屏幕像素，保留语义描边色和外部虚线。通过原生 `SourceAlpha` 扩张与相减绘制蓝色外圈，间隔 `1px`、宽 `2px`、颜色 `#2563EB`、透明度 `85%`，不添加代理矩形；滤镜作用于现有纯几何根分支，排除兄弟文字分支，覆盖透明填充与多图元；滤镜范围随局部真实 bbox 与实际缩放扩大，包含极小 fit 比例，不能裁切外圈。交互模块只为当前选中对象同步缩放，不自动移动画布或添加动画；Schedule 与 Entity 容器仅处理各自直属轮廓，不递归修改内部卡片。原始填充、宽度、滤镜及优先级只保存一次，重复选择与缩放不累加，取消时准确恢复，原无内联值时移除临时覆盖。点击、搜索多选、连线端点和键盘激活共用选中路径；未选中节点显示键盘焦点，已选中节点仅使用真实轮廓选中效果。回归检查真实样式数值、缩放补偿、切页及历史恢复，不只检查 `selected` 类；静态 SVG 和 Mermaid 保持默认状态。

按[画布交互与焦点](../../../docs/diagrams/README.md#画布交互与焦点)维护焦点生命周期：画布使用 `tabindex="-1"`、有名称的 `role="region"`，不进入 Tab 顺序、不显示默认焦点框；有效 `pointerdown` 以 `focus({ preventScroll: true })` 聚焦画布，`pointerup` 不聚焦卡片。节点保留 Tab、Enter 和 Space 操作，焦点规则使用 `:focus-visible:not(.selected)`；Entity 容器焦点只作用于直属真实轮廓，不通过父级外框影响组件，不与持续选中叠加矩形蓝框。显式清除只在 `activeElement` 位于图内或即将移除的清除按钮上时聚焦画布，不抢搜索、分组下拉及其他控件焦点；`paint` 只更新视觉状态，不迁移焦点。回归分别断言焦点对象、`preventScroll`、清除前后的条件和键盘行为，真实浏览器检查滚动、双框及焦点顺序；不改变原生轮廓选中样式或源码反馈。

Schedule 标题使用模型的共享推导函数：`Startup` 只显示名称，状态切换组从当前视图实际运行时 `registrations` 提取 `OnEnter`、`OnExit`、`OnTransition` 等 Schedule 类型名，按出现顺序去重并逐行显示，不显示参数，排除测试注册，不使用 OnEnter 白名单。完整状态参数保留在系统详情的每条注册中。按[分组显示标题](../../../docs/diagrams/README.md#mermaid-布局与连线)核对七个短标题，不附加解释后缀；`RunFixedMainLoop · AfterFixedMainLoop` 保留完整标题。显示精简不覆盖原始 `label` 或 `notes`，保留原组 ID、轨道、顺序与节点，多个参数不拆框、不复制系统，也不因标题列表增加执行边。生成器和校验器复用相同推导，回归覆盖短标题、同类型多目标去重、多注册、测试排除及其他状态 Schedule。

按[节点详情](../../../docs/diagrams/README.md#节点详情)维护右侧内容：顶部不显示类型或 `phase` 标签，系统信息使用 `Schedule`、`Read`、`Write`、`Query` 四栏。`Read`、`Write` 一级标题之下的 `Entity`、`Resource`、`Local<T>`、`NonSend<T>` 分类缩进 `16px`，条目再缩进 `16px`；保留原字体、字号、字重及配色，最小 `240px` 面板中长名称和泛型仍能换行，不叠加默认列表缩进。`Read` 与 `Write` 各自按 canonical Entity 身份去重且只显示实体名，不列组件，同名不同实体与读写两侧保持独立；非实体访问保持原记录顺序。保留原始读写清单、实体完整组件、查询声明与过滤条件，不从展示归并推断执行顺序。每条注册单独成块，完整保留 Schedule 参数和字段，字段逐行、数组逐项分行，不截断或把多处注册拼成一条；源码入口、插件导航和其他详情不因精简顶部或读写列表丢失。

Schedule 与普通分组详情不重复类别标签或通用阅读提示，具体 `notes` 继续显示。Schedule 连线详情不附加通用调度解释，保留关系语义、方向、端点及具体契约；用途、条件、图例、源码操作和必要错误反馈不属于通用说明，不能随之删减。

连线只显示具体契约或约束，类型由颜色、线型、线宽及同色标准箭头表达。区分消息发布／消费与事件发出／Observer 触发，区分集合成员、调度契约参与和装配注册。检查 HTML、独立 SVG 及 `.mmd` 的业务图形与样式一致，右侧样例与对应类型一致。形状几何由 `svg-shape-geometry.mjs` 根据原生 `path`、`polygon`、`rect` 等轮廓和祖先变换计算；不使用透明矩形代理，不把所有形状当作旧矩形处理。

按[实体嵌套布局](../../../docs/diagrams/README.md#mermaid-布局与连线)仅在 data 页从 `model.entities[*].components` 派生 canonical Component 到 Entity 的索引；不按 ID 前缀、名称或中文 `owner` 猜测归属。对数据页已出现的每个 Entity 补齐清单中的全部组件，不扩展其他实体、系统或业务关系，保留组件归属、源码和外部引用。Entity 使用砖红描边 `#A6533B`、填充 `#F8F1EF` 和选中填充 `#EBD9D4`，System 保持蓝色，Component 保持绿色；展开时，Mermaid 原生子图的真实外框就是 Entity 容器卡片，顶部显示完整名称、用途与开合控件，内部放置完整组件清单，不再另画 Entity 小卡片或空标题外框。没有组件的 Entity、缩略 Entity 和单份普通 Entity 图例统一使用砖红色单层矩形，不增加图例变体。Entity 子图从集中样式显式生成 Mermaid `style`，外部容器同时输出虚线；核对编译后直属轮廓的实际填充、描边与线宽，不能只因源码有 `class` 就假定子图继承样式，也不能在 SVG 归一化阶段补画或涂色。缺失的实体上下文复用原 Entity ID、归属、源码及外部虚线；没有规范实体归属的组件独立显示，不新增原始清单字段。

数据页整体采用 Dagre `TB`，组件保持清单顺序，按 `min(4, ceil(N / 6))` 列均分，用原生 `shape: text` 标题布局节点连接各列首个组件，各列继续使用独立不可见链；标题没有轮廓、独立业务身份或 Tab 停靠点，点击转交原 Entity，不连接 Entity 容器与自身组件，不另建列子图或增加语义边。实体容器整体参与布局，`relations` 按真实连通网络划分透明排版子图；Entity 容器已完整包含组件，不增加末行组件到父容器的 `ChildOf` 排版链。指向相同数据目标的独立 Observer 按原节点顺序用不可见链错开源卡片；复用 `dataObserverLayoutPairs`，不重复已有可达关系或引入循环，排版链不属于语义关系，也不表达执行先后。孤立实体容器和普通节点在 `catalog` 的 `LR` 区按整组估计行数平衡分列，普通节点按单行计，`relations` 与 `catalog` 之间不加排版链。生成态 `view.entityGroups` 保留稳定组 ID、Entity ID、完整组件成员、布局标题 `headerMermaidId`、真实外框与标题边界，Entity 节点以 `presentation: 'entity-container'` 区分容器展示；完整态的真实关系连接各自原端点，缩略态仅投影显示端点，Entity 端点直接使用当前原生轮廓，其他页签不增加实体嵌套，不复制语义节点。

Entity 容器保留原身份的点击、Tab、Enter／Space、搜索、连线端点、详情、源码与导航，组件点击只选择最近的组件。“定位分组”根据编译后真实 bbox 和祖先变换定位整个容器，原入口与切页更新保留。选择 Entity 时保留完整组件清晰，选择 Component 时保留所属 Entity 清晰；只有实际选中对象绘制外圈和滤镜，命中数及边关联不因上下文扩展改变。容器轮廓与标题按所属 Entity ID 独立更新，选中滤镜和键盘焦点仅作用直属真实轮廓；不递归修改组件轮廓或继承父级透明度。回归覆盖同名组件、外部 Entity、缺失实体上下文、单列与多列、重复选择、搜索多选、极小缩放、清除、切页与历史返回，分别断言身份、真实边界、滤镜数量和准确恢复。

所有视图的业务边与 Schedule 边共用 `architecture-routing.mjs` 的原生几何检查。Dagre 先编译直线布局，实际路径在 `0.5` 个图内像素容差内共线且无遮挡时保留直线，其余由 Mermaid 原生 `basis` 曲线重新编译；至少一段原生曲线的实际轨迹须偏离其端点弦线超过 `0.25` 个图内像素，共线曲线命令、折线或弯曲不足均不算曲线；这些情况尝试原生 `bumpX`／`bumpY` 方向曲线，继续通过同一箭头与轮廓检查。曲线与全部实际节点轮廓的避让共用 `0.25` 个图内像素的误差界，覆盖多轮廓、凹形、外部虚线以及 Entity、Schedule 的原生标题边界，不只检查 Component 或轴向包围框。成员边可以穿过所属容器正文及边界，但不能穿过标题或无关卡片。总览与事件页先尝试普通 Dagre `LR`，失败后再用透明原生 `layout-card` 容器辅助排版，之后尝试有界间距及边跨度；透明容器不增加业务身份、端点或关系。完整 Entity 的稠密数据页普通布局失败时，复用 `entityHeaderContext`，从既有组件访问方向生成“容器外端点 → Entity 标题”或“Entity 标题 → 容器外端点”的不可见 `layoutLinks`；排除实体自身端点，不新增业务箭头或执行顺序。必要时采用 `cardContainers: related`，仅为实际参与连线的组件及容器外 System／Observer 加透明原生布局容器。所有候选保留节点身份、组件成员顺序、真实边端点与语义，并通过同一轮廓、列序、标题、路径、箭头和标签校验后才采用。数据页继续通过有界的原生间距、边跨度调整重新编译，候选均失败时可调整同一关系网络内业务边的 Mermaid 声明顺序，保留原关系数组、ID、端点、标签、组件顺序和排版链，仍须完整原生校验。对需要避让的 Entity 关系子网，有限回退候选以完整 Entity 容器或缩略 Entity 卡片为原生布局单位，整体调整声明块顺序，并对子网内已有关系共同增加最小跨层跨度；不得拆分声明块、改变实体内部组件顺序、删改业务节点／关系／ID 或增加业务箭头，展开与缩略混合子网仍须通过同一严格几何检查。不能手工替换路径、删边、加虚假业务端点或放宽校验；HTML、独立 SVG、`.mmd` 使用最终同一套原生走线，修改后重查所有受影响图形。

端点接触须同时验证两端：源端路径起点及目标端原生箭头尖端分别贴合各自业务端点的真实轮廓，按实际线宽与 `0.25` 个图内像素的几何误差计算接触容差。展开 Entity 使用其直属原生外框，缩略 Entity、嵌套 Component、多轮廓和外部虚线分别使用自身轮廓，不能以透明布局容器或轴向包围框代替。源端断口和目标端悬空均使严格校验失败；补充回归并重新编译原生布局，不手工接线、移动箭头或放宽容差。默认保留 `flowchart.padding: 16`；只有候选的其它几何、列序、标题、曲线、标签及目标端检查全部通过、仅源端接触失败，才在同一原生候选尝试 `flowchart.padding: 4`。重新编译后执行同一完整校验，不能用更小内边距掩盖其它失败或放宽接触标准。

连线标签的 Mermaid 原生背景轮廓也须参与避让，不能压住节点轮廓、Entity 边框或容器标题。Component、System 端点所属容器的正文可承载该边标签；直接以 Entity 为端点时，标签须在容器正文外。回归须同时检查标签背景和业务路径，失败时重新编译原生布局，不能手工移动文字或只确认箭头已避开卡片。

更新 `ecs-data.json` 和必要的生成器布局、说明，保留离线 HTML 的交互。界面壳层统一为浅色，顶栏仅保留品牌与工作区入口；总览卡片只显示右侧详情与关联高亮，通过侧栏或显式所属插件按钮进入插件，项目插件顶部仅保留名称与标识。总览和基础设施标题区不显示介绍段落，所有视图画布顶部仅保留分组定位，不显示摘要或画布操作提示；搜索结果不重复类别标签和通用说明，空页签只显示明确空态标题。完整 `description`、`display_summary` 和 `view.summary` 保留，右侧详情继续显示完整说明。工具栏不提供图例或导出按钮，独立 SVG 与 `.mmd` 继续生成。右侧面板按 [读图说明](../../../docs/diagrams/README.md) 的桌面宽度边界拖动调整，仅保留当前页面会话状态。

右侧节点与连线详情只提供 VS Code、定位路径和复制定位，不提供离线快照跳转；独立源码页从读图说明进入，继续生成并校验完整快照和自身源码控件。两份 HTML 不重复展示源码打开方式和快照时效说明，[源码使用说明](../../../docs/diagrams/README.md#在-vs-code-中打开源码)继续维护配置、协议及快照边界。工作区配置保留目录输入与局部校验，删除底部目录状态栏及配置说明正文；未配置根目录的提示不再声称存在离线快照入口。复制定位在当前控件给出成功、恢复与失败反馈，并提供 `aria-live`；源码页行定位状态及必要错误保留。源码行号应指向类型声明或实际注册／使用位置；删除失效节点、关系和入口。受影响的长期架构说明按文档维护规则同步更新。用户对维护范围和结果的明确要求优先于本 Skill 的工作流建议，不据此增设审批。

生成器只渲染输入，校验器不分析 Rust 架构语义，也无法发现所有遗漏系统；必须完成上述人工源码核对。

## 生成与自动校验

按[Entity 开合规则](../../../docs/diagrams/README.md#entity-展开与缩略)维护独立开合：默认缩略全部 Entity 并隐藏其全部组件，多实体可以同时展开，单卡开合不改变其他 Entity，不提供“展开全部”或“全部缩略”按钮。右上角原生按钮缩略显示 `+`、展开显示 `−`，尺寸 `24×24` 个 SVG 单位，距上、右边界各 `8` 个 SVG 单位并随画布缩放；原生布局预留空间，不遮挡名称和用途。实体清单无组件的 Entity 没有按钮；无障碍名称包含实体与组件数，`aria-expanded` 及详情开合同步，点击不选择卡片或拖动画布，Tab、Enter、Space 和重排后焦点恢复必须有效。完整清单、关系的 canonical `from`／`to` 和 ID 保留，缩略仅通过 `displayFrom`／`displayTo` 投影到 Entity；原关系详情和源码不可丢失。

保留完整主视图、全部缩略及单实体展开的有限预编译 `entityViews` 作为即时缓存，不穷举组合。其他组合使用离线架构 HTML 内嵌的锁定版本 Mermaid 及依赖按需原生编译，不使用 CDN 或网络服务；定义生成、SVG 归一化及严格几何校验由 Node 与浏览器共享。每个变体保留全部组成员和 `expanded` 标记，并独立测量真实轮廓、标题、定位与走线。规范 Entity 顺序作为缓存键，最多保留 `8` 个额外布局并按最近使用淘汰；编译串行执行，连续点击累计目标，切页与历史返回使旧任务失效。计算期间保留旧图并显示忙碌反馈，通过完整几何检查后整体替换；失败保留旧图及开合状态，提供重试，不手改路径、放宽检查或以 CSS 隐藏已有组件代替真实缩略。

手动开合状态以 Entity ID 数组按视图保存在 history.state，兼容旧 `all`、`collapsed` 和单 Entity ID，工作区配置不覆盖状态。搜索只临时补开命中组件所属 Entity，清空后恢复手动集合；搜索中手动开合时退出搜索，仅对原手动集合应用当前 Entity 的目标状态，其他搜索临时补开项不写入历史。深链接与详情端点补开目标，不关闭其他实体。收起当前选中组件所在 Entity 时选择转到 Entity，其他选择保留；切换清理旧滤镜、保持画布锚点和缩放。回归覆盖多个实体独立开合、缓存与失败、快速操作与过期任务、搜索及历史兼容，分别断言状态、焦点、真实端点、样式和滤镜；实际浏览器还须检查未预编译组合及断网开合，不能用静态产物检查代替。

在仓库根依次执行，每条成功后再继续；失败时修复原因并重试，不将失败产物报告为完成：

```text
npm ci --prefix docs/diagrams
node docs/diagrams/build-ecs.mjs
node docs/diagrams/check-ecs.mjs
node --test docs/diagrams/*.test.mjs
```

Node.js 最低版本为 `22.13.0`，依赖版本与实际要求以 `docs/diagrams/package.json` 和 `package-lock.json` 为准。若 PATH 中没有符合要求的 Node.js，使用当前环境已安装的运行时，不把个人绝对路径写进仓库。Mermaid 编译使用 headless Chromium；可设 `MERMAID_CHROMIUM_PATH`，否则自动查找已安装的 Chrome／Edge，只编译架构图，不启动游戏。

生成会读取当前工作区源码与清单，覆盖两份离线 HTML、`ecs-overview.svg`、非空插件页签的 `ecs-plugin-<module>-<aspect>.svg`、Bevy 页签的 `ecs-infrastructure-<aspect>.svg` 和四个第三方入口的 `ecs-third-party-<library>-<aspect>.svg`；`library` 为 `avian`、`enhanced-input`、`kira`、`egui`，`aspect` 为 `systems`、`data` 或 `events`。每份 SVG 同时生成同名 `.mmd`，内嵌动态 `views` 记录插件、页签、Mermaid 源文件与导出文件，校验器据此检查对应关系和产物完整性，不使用固定产物数量。HTML 内嵌编译结果，无需在线 Mermaid 服务。检查最终 diff，确认只出现预期变更且无旧混合第三方产物；保留编辑器入口、离线快照和全部业务节点入口，导航的 `feature`、`tab`、`node` 参数与 `workspace` 配置应兼容。只有用户另行要求时才暂存或提交；部分暂存的源码不代表这些产物只反映索引版本。

## 最终视觉检查与交付

架构图有变更时，按 [架构图视觉检查](../../../docs/testing/README.md#架构图视觉检查) 实际查看最终 HTML 的总览、所有插件及基础设施页签和空态，并检查动态 `views` 中全部 SVG。先看整体，再放大修改区域，检查浅色壳层、精简标题与说明边界、画布顶部仅分组定位、Schedule 横排、阶段箭头、组内系统纵排、唯一节点、完整名称与短用途，以及原生形状、右侧当前页样例和真实连线的方向、颜色、线型、遮挡与裁切。用 `log_policy` 检查名称与用途两个内容层次，选择后核对完整读写和条件；分组与 Schedule 连线只省略通用说明，具体 `notes` 和契约仍可读。放大检查砖红色 Entity 容器中的完整绿色 Component 清单、容器标题和组件文字，确认原 Entity 小卡片与空布局框已移除；逐条检查所有类型及所有页签的原生直线、曲线与箭头，无卡片穿线或标题遮挡，最终共享图例只有一份砖红色单层矩形 Entity 样例。将详情收窄至 `240px`，检查读写两级缩进和文字换行；实际检查增强填充、真实外圈、缩放补偿、取消恢复、未选中节点键盘焦点及选中后无第二层矩形框。锚点与走线由 Mermaid 生成，不套用手工 SVG 的端口等分或固定末段规则；修复定义或配置并重新编译后检查最终版本。验证总览详情与显式插件跳转、返回与历史、搜索、关联高亮、平移缩放、分组定位、面板拖动与窄屏布局、详情的编辑器定位控件、从读图说明进入独立源码页、复制反馈和工作区配置；确认独立业务 SVG 与 `.mmd` 完整，读图指南没有旧正文或其他页签类型。

只编译或查看静态架构文档，禁止启动或操作游戏。截图和渲染临时文件放在根 `tmp/`。自动编译、模型语义校验、SVG 视觉检查和 HTML 实际浏览器验证分别记录，不能互相替代；不得用编译浏览器绕过本地文档访问限制。工具不可用时明确记录原因及未检查范围，不声称验收通过。

交付说明列出源码核对范围、具体图变化、自动校验结果、实际视觉检查结果和未完成事项。有关联 Issue 或 PR 时将本次执行记录放在那里，长期文档只保留可复用方法。
