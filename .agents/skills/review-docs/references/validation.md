# 验证与交付

- 按 [验证指南](../../../../docs/testing/README.md) 选择检查。普通文档检查内容、职责、相对链接、锚点和差异；运行 review-docs 工具并按报告处理问题，不为措辞调整启动 Rust 全套测试或架构图生成。
- 区分源码支持、现有测试覆盖与本次实际执行，记录覆盖范围和未验证边界。相关输入或基点变化后复核受影响的事实和检查，旧报告不能作为新基点通过的证据。执行文档命令前核对作用和仓库限制；禁止启动或操作游戏。依赖真实窗口、平台或听感的内容保留用户验收边界，不能报告为本次已验证。
- 编辑后检查本轮完整增量，逐项核对删改前后的必要事实、责任与义务强度，确认没有误删、反转或新增承诺；字数下降、检索无命中或链接可解析都不能证明内容正确。外链未访问须单列；工具拒绝时停止对应检查并记录缺项，不绕过，也不把计划或生成截图等同于检查通过。运行 `git diff --check`，临时材料放根 `tmp/`；具体执行记录放对应 Issue／PR，不写入长期规范正文；不自动提交。
- 交付时简述本轮修正、剩余问题及其文件位置和依据、实际完成的检查与未验证事项，区分本轮成果与已有差异。仅检查时报告发现；没有发现也如实说明，不为报告完整而制造问题。
