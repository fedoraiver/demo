# 文档检查与改进

在当前项目工作区检查文档，使其满足已有约束并便于后续开发。默认检查并修正整个项目的维护文档；用户指定文件、目录或仅检查时，以用户的范围和动作要求为准。

## 范围与依据

- 先检查 `git status --short`、暂存和未暂存差异，保留已有修改。全项目范围包含根目录、`docs/`、美术与资源说明，以及 `.agents/` 中维护的手写文档；通过仓库文件清单发现隐藏目录，排除临时目录、构建缓存和第三方内容。
- 读取根 [AGENTS.md](../../../AGENTS.md)、适用的子目录指令、[文档规范](../../../docs/AGENTS.md)和目标文档。按主题、读者和用途确定归属及详细程度，再区分指南、参考、设计、决策记录和事故复盘；不为统一外观强套章节或格式。
- 决策记录和事故复盘分别遵循 [Agent Notes](../../notes/README.md) 与 [复盘约定](../../../docs/postmortem/README.md)。提案与否决理由按其状态审查，归档历史不按当前实现重写；许可正文与第三方来源记录不作一般措辞清理。
- 生成产物先核对其维护入口和来源。涉及架构图本体的修复使用 [update-ecs-architecture](../update-ecs-architecture/SKILL.md)，不手改 HTML、SVG 或源码快照；普通文档检查不触发统一重新生成。

## 审查与修正

先核对事实与内容职责，再调整结构和措辞。问题需要有具体位置、适用规则或事实依据，以及修正方向；区分违反约束的问题、可选的表达改进与待核实事项。

- **事实与状态**：行为、默认值、命令、路径和平台差异追查当前源码、配置、测试或已确认的设计依据。区分实现、确认的设计、建议和未决问题；规则与实现冲突时分别说明，不为迎合代码而削弱规范或改写已确认决策。
- **必要性与归属**：按文档规范判断后续开发是否需要额外说明。可从仓库直接可靠推导的目录结构、配置或实现细节不重复铺陈；保留任务入口和理解文档所需的最少上下文。重复内容保留在其归属文档，其他位置用简短引导和链接连接。
- **现行表述与契约**：普通指南和参考清理已失效设计、完成的迁移说明、无必要的前后对比和推理过程。按语义判断，不按“不再”“不要”等词批量删除；保留当前有效的禁止性约束、条件、例外、时序、失败和恢复要求。只值得删除的说明直接删除，不为它新建决策记录。
- **读者路径**：指南将前置条件放在操作前，让成功结果、常见失败及恢复方法可找到；参考按主题便于查阅。拆分实质混杂的内容时复用已有归属，避免重复抄写源码清单或增加无必要文档。
- **引用与维护**：核对相对链接、锚点、命令和示例。移动或删除内容时同步修复入链；信息有唯一可靠来源时据此修正，不能通过猜测目标或删除有效契约消除问题。

默认直接修正文档中依据明确的问题。仅检查时不修改文件；无法确认的事实、需求歧义和会改变既有承诺的建议单独报告，不编造结论，也不因未能执行就删除合理说明。文档任务不改产品行为，不自行增加项目约束。

## 验证与交付

- 按 [验证指南](../../../docs/testing/README.md) 选择检查。普通文档检查内容、职责、相对链接、锚点和差异；有对应的检查工具时运行相关检查，不为措辞调整启动 Rust 全套测试或架构图生成。
- 区分源码支持、现有测试覆盖与本次实际执行。执行文档命令前核对作用和仓库限制；禁止启动或操作游戏。依赖真实窗口、平台或听感的内容保留用户验收边界，不能报告为本次已验证。
- 编辑后检查完整差异，确认必要契约仍在，并运行 `git diff --check`。临时材料放根 `tmp/`，具体执行记录按仓库要求交付，不写入长期规范正文。
- 交付时简述已修正内容、剩余问题及其文件位置和依据、实际完成的检查与未验证事项。仅检查时报告发现；没有发现也如实说明，不为报告完整而制造问题。
