# 文档检查与改进

在当前项目工作区检查文档，保留后续使用与维护需要的信息，删除无用表达。默认检查并修正整个项目的维护文档；用户指定文件、目录或仅检查时，以用户的范围和动作要求为准。

## 范围与依据

- 确认目标 worktree、分支、HEAD 和用户指定基线；先运行 `git status --short` 并检查暂存和未暂存差异，保存已有增量，以本轮开始的工作区为比较起点，必要时在根 `tmp/` 保存对照。事实只按当前分支核对，不提前纳入其他 PR、worktree 或计划中但未合并的改动。
- 通过仓库文件清单发现隐藏文档；全项目清单包含根目录、`docs/`、美术与资源说明和隐藏目录中的手写文档；排除临时目录、构建缓存和第三方内容。逐项区分内容已审、仅检查链接、已委派、排除和待审；清单总数或搜索结果不代表已完成全文审查。
- 读取根 [AGENTS.md](../../../AGENTS.md)、适用的子目录指令、[文档规范](../../../docs/AGENTS.md)和目标文档。按主题、读者和用途确定归属及详细程度，再区分指南、参考、设计、决策记录和事故复盘；不为统一外观强套章节或格式。
- 决策记录和事故复盘分别遵循 [Agent Notes](../../notes/README.md) 与 [复盘约定](../../../docs/postmortem/README.md)，保留其职责需要的动机、替代方案、证据和因果链。提案与否决理由按其状态审查，归档历史不按当前实现重写；许可正文与第三方来源记录不作一般措辞清理。
- 生成产物先核对其维护入口和来源。架构维护并行时先约定文件归属；普通架构说明可直接核对源码，仅涉及图模型、生成器或产物时交给 [update-ecs-architecture](../update-ecs-architecture/SKILL.md)。不手改生成的 HTML、SVG 或源码快照，普通文档检查不触发统一重新生成。

## 分工与派发

默认由子代理承担下表职责；主代理负责确定范围、文件分区和接口，裁决事实，汇总结果并检查最终完整增量。小范围可合并非独立职责并由主代理承担，仍须由未参与编辑者独立复审；仅检查时不派发写入任务，跨主题全仓审查可按文件组并行核对事实，不为增加代理而扩大范围。同一文件始终只有一个编辑者。

| 职责 | 默认模型与推理强度 | 调整 |
| --- | --- | --- |
| 事实与归属审查 | `gpt-6.1-sol` / `high` | 简单范围可用 `medium` |
| 文案修订 | `gpt-6.1-terra` / `medium` | 纯机械修正可用 `low` |
| 链接、锚点和差异检查 | `gpt-6.1-terra` / `low` | 可由其他适合的角色兼任 |
| 独立终审 | 未参与编辑的 `gpt-6.1-sol` / `high` | 窄范围可用 `medium` |

这是本项目的可调整起点，不是能力保证；参照 [模型选择指南](https://developers.openai.com/api/docs/guides/model-selection)。默认按表选择，简单范围可按表下调；跨多文档契约、冲突证据或复杂义务保留等情况才考虑进一步提高强度，不默认使用 `max`／`ultra`。

派发时写明绝对 worktree 路径、基线、目标文件及可写边界、约束、验收和交付物。“只读”限制受控文档、源码和外部状态；允许写临时报告时须写明其可写路径。核对当前工具支持的模型标识与档位，在调用参数中实际设置 `model` 和 `reasoning_effort`。使用当前 collaboration 工具覆盖模型时设置 `fork_turns='none'`，并提供自包含上下文。指定模型不可用时不静默替换，报告受影响的分工。

事实审查先提供具体位置、依据和修正方向，编辑者按下述逐项保留规则修订。独立终审读取修改前后原文及最终差异，核对责任、条件、时序、义务强度和当前事实；发现问题退回唯一编辑者，修正后复审受影响部分。

## 审查与取舍

先核对事实与内容职责，判断信息是否需要保留，再调整结构和措辞。问题需要有具体位置、适用规则或事实依据，以及修正方向；区分违反约束的问题、可选的表达改进与待核实事项。

- **事实与状态**：行为、默认值、命令、路径和平台差异追查当前源码、配置、测试或已确认的设计依据。区分实现、确认的设计、建议和未决问题；规则与实现冲突时分别说明，不为迎合代码而削弱规范或改写已确认决策。
- **必要性与归属**：不重复铺陈可从源码、配置或清单直接可靠推导的内容。保留任务入口、理解文档所需的上下文，以及省略后容易导致误用或错误简化的约束与原因。完整解释放在唯一归属文档；使用处需要的行为、失败和责任说明可最少量重复，不能只用链接代替。
- **逐项保留事实**：以事实子句为删改单位，保留必要的主体与动作、条件、时序、义务强度（必须、可以、禁止）、例外、责任归属、副作用、失败及后果。归并相似段落时，先确认各自独有的观察项、生效条件与失败恢复操作在最终位置仍有明确表述，再删除重复部分。不能把待迁移义务改成永久许可、把建议或假设写成已实现能力，或把实测结果写成固定保证；实测依据与已知覆盖缺口不能随措辞一起丢失。
- **直接删除冗余**：删除重复结论、无信息的修饰与强调、空泛概括，以及只复述代码分支、配置条目或测试步骤的说明。纯冗余直接删，不改成更短的空话；代码复述中夹有非显然的约束或原因时，只保留这些内容。指南的操作步骤、验证入口和可观察结果不属于代码复述。
- **清理讨论过程**：普通指南和参考描述现行机制，清理已失效设计、完成的迁移说明、前后对比、评审往返和自我辩护。让读者无需本次聊天、评审轮次或未保存草稿也能理解事实与引用；不可解析的决策编号、审计代号等，替换为真实归属链接或删去标记，保留其中仍有效的事实。未确认的打算保留其状态，缺乏依据的断言单独报告，不补造结论、TODO 或承诺。
- **按语义判断**：检索词只用于发现候选，还需通读内容；不按“不再”“旧”“先……再……”等词批量删除。运行中新旧对象的交接顺序、有效的禁止性约束、迁移义务、失败反例与恢复要求应保留。有效的 Issue、决策及外部资料引用不因看似讨论记录而删除；只值得删除的内容不另建笔记安置。
- **读者路径**：指南将前置条件放在操作前，让成功结果、常见失败及恢复方法可找到；参考按主题便于查阅。拆分实质混杂的内容时复用已有归属，不为统一外观或降低字数增加无必要文档。
- **引用与维护**：核对相对链接、锚点、命令和示例。用链接替代说明前，通读目标章节，确认它承接被删的必要事实；章节拆分或移动后同步修复入链并核对引用主题，文件与锚点存在不代表引用正确。信息有唯一可靠来源时据此修正，不能通过猜测目标或删除有效契约消除问题。

默认直接修正文档中依据明确的问题。仅检查时不修改文件；无法确认的事实、需求歧义和会改变既有承诺的建议单独报告，不编造结论，也不因未能执行就删除合理说明。文档任务不改产品行为，不自行增加项目约束。

## 验证与交付

- 按 [验证指南](../../../docs/testing/README.md) 选择检查。普通文档检查内容、职责、相对链接、锚点和差异；有对应的检查工具时运行相关检查，不为措辞调整启动 Rust 全套测试或架构图生成。
- 区分源码支持、现有测试覆盖与本次实际执行，记录覆盖范围和未验证边界。相关输入或基点变化后复核受影响的事实和检查，旧报告不能作为新基点通过的证据。执行文档命令前核对作用和仓库限制；禁止启动或操作游戏。依赖真实窗口、平台或听感的内容保留用户验收边界，不能报告为本次已验证。
- 编辑后检查本轮完整增量，逐项核对删改前后的必要事实、责任与义务强度，确认没有误删、反转或新增承诺；字数下降、检索无命中或链接可解析都不能证明内容正确。外链未访问须单列；工具拒绝时停止对应检查并记录缺项，不绕过，也不把计划或生成截图等同于检查通过。运行 `git diff --check`，临时材料放根 `tmp/`；具体执行记录放对应 Issue／PR，不写入长期规范正文；不自动提交。
- 交付时简述本轮修正、剩余问题及其文件位置和依据、实际完成的检查与未验证事项，区分本轮成果与已有差异。仅检查时报告发现；没有发现也如实说明，不为报告完整而制造问题。
