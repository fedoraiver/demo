# 当前 ECS 架构图

打开 [交互式 HTML](ecs-architecture.html)，先从功能总览查看 14 个项目插件的名称、职责和主要协作契约，再通过侧栏进入插件、Bevy 引擎或第三方的 Avian、Enhanced Input、Kira、Egui 四个独立入口。点击总览卡片只在右侧显示对应详情和关联高亮；通过详情中的“打开所属插件”进入所属入口。项目插件详情顶部只显示名称与标识，下方按“系统与调度”“数据与实体”“事件与协作”切换；无内容的页签显示空态。

页头、侧栏、工具栏、画布与详情采用统一浅色界面。顶栏保留品牌与工作区配置入口，内容区标题显示当前视图名称，项目插件同时显示标识；总览及基础设施标题区不显示介绍段落。画布顶部仅保留“定位分组”，不显示视图摘要或操作提示。图内每个节点只显示完整名称与一句短用途；职责、读写声明、注册条件和技术细节集中在右侧详情。搜索结果不重复类别标签与通用说明，空页签仅显示明确的空态标题。

全部图形由 Mermaid 源码编译为 SVG，HTML 内嵌编译结果与节点数据，可离线使用，无需联网加载 Mermaid。搜索可定位节点，点击节点或连线在右侧展开字段、读写声明、约束和源码入口，并高亮关联；滚轮缩放、左键拖动平移。未选择节点或清除选择时，右侧英文图例只显示当前页实际使用的节点和连线类型；每种节点类型仅有一个普通样例，存在外部节点时只补充一条英文虚线含义说明。画布内的文字不参与选择，避免拖动误选；右侧详情和源码页中的文字仍可选择复制。详情中的组件与资源可继续点击，外部契约可跳转所属插件；返回按钮及浏览器前进／后退保留导航位置。链接通过 `feature`、`tab`、`node` 查询参数记录插件、页签和节点，导航时保留 `workspace` 配置。

视口宽于 `900px` 时，可横向拖动画布与右侧面板之间的分隔条。面板初始宽度为 `286px`，最小 `240px`、最大 `720px`，同时为画布保留至少 `360px`；可用空间不足时相应收紧面板上限。宽度只在本次页面会话内保留，刷新后恢复初始值。较窄视口采用上下布局，不提供横向分隔条。

右侧节点及连线详情中的“源码位置”提供 VS Code 入口、定位路径和复制定位，不提供离线快照跳转。项目源码按当前工作区定位；Bevy 和第三方的组件、插件优先打开本机锁定依赖中的真实类型声明，定位到记录的行，默认列为 `1`。需要查看生成时的完整文件时，可从本文打开独立的 [源码查看页](ecs-source.html)，选择项目文件或依赖文件并定位、高亮指定行。源码页也提供 VS Code 入口，使用当前选择的文件和定位行；切换文件、点击行号后会更新定位。复制定位成功后，当前按钮显示“已复制”并在 `2` 秒后恢复，同时提供无障碍状态反馈；失败时在当前控件附近提示，仍可选择定位文本手动复制。源码文本是生成时的快照，不会自动跟随本地文件变化，修改后的内容和行号可能与快照不同。两份 HTML 放在同一目录即可离线使用，无需启动服务。

`<module>` 是插件的源码目录名；Bevy 和四个第三方入口使用相同三个页签。Bevy 独立文件为 `ecs-infrastructure-<aspect>.svg`，第三方分别为 `ecs-third-party-avian-<aspect>.svg`、`ecs-third-party-enhanced-input-<aspect>.svg`、`ecs-third-party-kira-<aspect>.svg`、`ecs-third-party-egui-<aspect>.svg`，其中 `<aspect>` 为 `systems`、`data` 或 `events`。总览及每个非空页签同时生成同名 `.mmd` 源文件，例如 `ecs-overview.mmd`；空页签保留 HTML 空态，不生成 `.mmd` 或 SVG。文件清单以 HTML 内嵌的动态 `views` 为准，独立 SVG 和 `.mmd` 保存在本目录，页面工具栏不提供图例或导出按钮。Mermaid 文件的 YAML frontmatter 使用合法 JSON 对象写入完整主题、布局及配置，使用相同依赖版本可按原设置重新编译。

基础设施入口由 [共享目录](architecture-infrastructure.mjs) 维护：`infrastructure` 表示 Bevy，`avian`、`enhanced_input`、`kira`、`egui` 分别表示四个第三方浏览分组，侧栏中四个第三方入口位于 Bevy 引擎之前。插值纳入 Avian，第三方世界检查器纳入 Egui；分组不改变实际库来源和类型身份。浏览归属按清单中核对的提供方与具体契约维护，Bevy 泛型容器承载第三方类型时可以浏览归对应第三方分组，`defined_in` 仍保留 Bevy 的类型定义归属。总览复用现有插件节点，不显示第三方汇总卡片；`main / App` 留作 Bevy 入口的应用上下文，不表示其源码由 Bevy 定义，原生窗口回调归项目窗口策略。跨入口引用显示真实来源并跳转所属入口，现有业务节点 ID 与关系保持不变。

旧 `feature=third_party` 链接携带真实节点时，按节点当前归属定位合适页签；没有节点、节点失效或指向旧目录 ID `third-party-plugins` 时回到功能总览。旧 `infrastructure` 节点链接仍可定位，无节点时仍进入 Bevy。兼容导航使用历史替换，保留 `workspace`、其他查询参数与片段，不增加一次历史记录；旧混合第三方 SVG 和 `.mmd` 不再生成。

节点通过形状和配色表达类型，名称置于首行；连线通过颜色、线型和宽度表达语义，文字仅保留具体契约或约束。图例位于右侧读图指南，独立 SVG 和 `.mmd` 只包含业务图形，详见 [节点与连线视觉规范](#节点与连线视觉规范)。

数据访问不代表调度顺序；无显式顺序的系统或 Observer 不得画成全序流水线。

视图不展示 `main / App` 到插件的纯装配注册边，也不保留因过滤这些边而孤立的外部 `main / App`；原始模型与稳定 ID 保留，项目插件安装第三方插件、`main / App` 退出刷新等其他关系继续展示。

外部系统、插件和协作契约显示摘要、所属插件与跳转入口，不展开其他插件内部流程。类型定义归属、系统注册归属和实体装配来源分别记录；数据页中已出现的 Entity 按实体清单补齐完整组件，其他页签仍按插件关注范围展示，详情保留同一实体身份与完整组件。补齐组件不递归引入其他实体、系统或关系，组件的真实归属、外部引用与源码入口保持。跨视图复用稳定语义节点 ID；同一视图中每个语义节点只出现一次，全部关系直接连接这个方框，不再为每条约束复制端点。仅当旧 ID 与当前节点指向同一声明和身份时，使用显式 `node_aliases` 保留旧链接，画布仍只显示规范节点；同一函数的不同调度注册、不同实体上的同名组件拥有各自身份，不得通过别名合并。

“数据与实体”页按规范实体身份将完整 Component 清单放在砖红色 Entity 容器卡片内部，容器顶部显示实体名称与用途，组件使用绿色；实体清单中没有组件的 Entity 保持独立卡片。完整实体清单及可选组件在详情中查看，图中出现不表示组件始终存在。业务根、视觉根和 GLB 子节点分别表达，“系统与调度”“事件与协作”及总览不增加实体嵌套。引擎集合与渲染等只展示相关流程，不代表全部内部系统或精确全序；日志后台线程标作外部 I/O。项目类型的源码入口指向声明。Bevy 和第三方的 `Component` 按定义归属、`Plugin` 按提供方定位依赖声明；已审阅的系统集合、引擎系统／Observer 与同步节点也优先定位真实依赖定义。资源、实体和聚合输出继续使用原有入口。原项目内使用或注册位置保留在 `source`，依赖定义另存为生成注册表的 `definition_source`，不覆盖架构清单。运行机制由 [当前架构](../architecture.md) 维护。

依赖定义由 [集中映射](architecture-source-definitions.mjs) 及 [定位模块](dependency-sources.mjs) 维护，包名、相对源码路径和声明符号需要对照真实源码核对。同一类型的多个实体组件复用同一声明；Kira 的项目别名 `KiraAudioPlugin` 指向真实的 `AudioPlugin`，Avian 的二维／三维同名声明按当前三维功能选择。系统集合卡片按实际契约定位集合声明或实现函数，`ApplyDeferred` 的不同调度注册共用引擎定义，各自的项目注册位置仍保留。生成与校验通过 `cargo metadata --locked --offline` 获取当前机器的锁定包版本和目录，需要本机已有对应依赖源码；声明缺失、多处匹配、目录或行号不符均使检查失败。

日志拓扑将业务碰撞日志连到 `tracing producer`，再分为 `File worker → 统一会话日志文件` 与 `Console worker` 两路，不绘制业务系统绕过 worker 直接写文件的边。物理插件的日志协作仅展示 producer 外部契约，完整内部链在会话日志页查看；文件节点保留 `physics-file-log` 稳定 ID 与 `External I/O` 类型，源码入口指向 `create_session_file`。退出刷新沿用已有关系，队列与 stderr 不另设终点节点。

[ecs-data.json](ecs-data.json) 集中保存插件目录、节点归属、显式调度和协作边等源码核对清单。[build-ecs.mjs](build-ecs.mjs) 生成总览与插件详情，[source-locator.mjs](source-locator.mjs) 按明确指定的声明定位生成器源码入口，[source-viewer.mjs](source-viewer.mjs) 内嵌源码快照，[source-editor.mjs](source-editor.mjs) 提供共享工作区配置与编辑器入口。各视图复用系统 `module`、实体关系和 Observer 记录，不各自维护一份语义关系。分享时保留两份 HTML 的相对位置；生成后的页面无需额外加载模块。

节点的 `description` 保留完整架构说明；过长或技术细节密集时，在同一记录添加可选 `display_summary`，写一句完整的中文用途，系统说明实际做什么，资源和组件说明承载什么。图内优先使用该短句，否则复用简洁的 `description`；不机械截句或增加省略号。组件在所有页签均使用完整名称和实际用途，不由生成器注入所属实体前缀；实体身份由数据页嵌套组及右侧详情表达，外部提供插件的来源说明仍保留。短句无需重复读写或运行条件，右侧详情始终使用完整说明。`view.summary` 保留为视图元数据，不在画布顶部显示。

生成入口调用 [模型模块](architecture-model.mjs) 构造各页签的视图模型，[绘图模块](architecture-renderer.mjs) 生成 Mermaid 定义，[视觉样式模块](architecture-style.mjs) 集中维护节点、连线及图例。编译后由 [查看器模块](architecture-viewer.mjs) 内嵌 SVG 并生成 HTML 交互；[导航模块](architecture-navigation.mjs) 统一解析与更新页面参数。维护时按修改范围核对对应模块，不手工重画编译产物。

## 画布交互与焦点

画布是具有无障碍名称的 `role="region"`，使用 `tabindex="-1"` 接收程序化焦点，不增加 Tab 停靠点，也不显示浏览器默认焦点框。有效 `pointerdown` 使用 `focus({ preventScroll: true })` 将焦点移到画布；`pointerup` 只激活命中节点或连线，不再聚焦卡片，焦点迁移不改变滚动、平移或缩放。节点仍可通过 Tab 到达，并使用 Enter 或 Space 激活。未选中节点通过 `:focus-visible:not(.selected)` 显示键盘焦点，已选中节点使用真实轮廓的持续选中效果，不再叠加第二层矩形焦点框。

显式清除选择时，仅当 `activeElement` 位于图内，或位于即将移除的“清除选择”按钮上，才将焦点移到画布，并阻止焦点操作引起滚动；搜索框、分组下拉及其他控件的焦点保持不变。交互模块的 `paint` 只更新选中、关联及弱化状态，不负责焦点迁移。源码操作的成功、失败与无障碍反馈保持独立。

## 节点详情

选择节点后，右侧从名称和完整说明开始，不在顶部显示类型或 `phase` 标签。系统访问与注册信息分为 `Schedule`、`Read`、`Write`、`Query` 四栏；源码定位、所属插件跳转及实体完整组件详情继续保留。

Schedule 与普通分组的详情显示分组标题及已有的具体 `notes`，不重复类别标签或通用阅读提示。Schedule 连线详情保留关系语义、方向、端点及具体契约，不附加通用调度说明；节点用途、运行条件、约束、图例和错误反馈按各自内容保留。

`Read` 与 `Write` 各自按 canonical Entity 身份归并同一实体的访问，只显示实体名称，不在这两栏列出组件。同名但身份不同的实体仍分别保留；读与写独立去重，不能把写入合并到读取。非实体访问按 `Resource`、`Local<T>`、`NonSend<T>` 分类，保持原记录中的出现顺序；原始访问清单和组件数据继续保留。查询声明及过滤条件在 `Query` 中完整显示。

`Read`、`Write` 是一级标题，下面的 `Entity`、`Resource`、`Local<T>`、`NonSend<T>` 分类相对一级缩进 `16px`，分类条目再缩进 `16px`。字体、字号、字重和配色沿用原样；详情面板收窄至 `240px` 时，分类、长名称及条目仍可换行，不横向溢出。

`Schedule` 中每条注册使用独立块，保留完整 Schedule 参数与注册字段；每个字段单独一行，数组逐项分行，不拼成一长串或截断。图中状态分组标题省略的具体状态值在这里查看；多处注册与测试注册的完整记录继续保留，显示归并不改写原始数据。

## 在 VS Code 中打开源码

从实际检出或 worktree 的 `docs/diagrams/` 目录通过 `file://` 打开 HTML 时，页面根据自己的位置推导工作区根目录；通过“配置工作区”修正“仓库根目录”，点击“保存目录”生效。“恢复默认”清除手动配置并重新使用本地页面推导。由 HTTP 服务提供、HTML 搬到其他位置，或需要指向另一份 worktree 时，先填写目标工作区的绝对根目录。路径可以包含空格、中文、`#` 和 `%`，无需手动编码。配置入口保留目录输入与校验反馈，页面底部不显示当前目录状态栏。

配置按页面所在目录的完整 URL 保存在浏览器本地，主检出和各 worktree 的页面目录相互独立。`workspace` 查询参数优先于保存的配置，保存的配置优先于 `file://` 推导；浏览器禁用存储时，本页仍保留配置，并通过同目录两份 HTML 的链接携带 `workspace` 参数。分享链接前移除该参数中的个人路径。项目工作区目录不写入维护清单；两份生成 HTML 为打开依赖声明保存生成机器的 Cargo 包绝对根目录，并包含完整依赖源码快照。移动到其他机器后仍可阅读快照，依赖的本机编辑器定位需要在目标机器重新生成；修改工作区配置只影响项目文件，不覆盖 Cargo 目录。

VS Code 入口仅在用户点击时调用 `vscode://file/...` 协议；页面加载、选择节点及修改根目录都不会自动打开编辑器。浏览器可能要求确认外部应用，只有安装并注册了该协议的 VS Code 才能处理请求。页面无法确认浏览器是否批准或编辑器是否打开，发出请求不等于打开成功。项目入口未配置有效根目录时按提示补齐；依赖入口使用生成时的 Cargo 根目录。浏览器拒绝请求或本机未安装 VS Code 时，可使用复制定位入口保留文件、行、列信息，或从本文打开独立源码页查看离线快照。两份 HTML 不重复展示打开方式和快照时效说明，相关使用边界由本文维护；源码操作、定位与校验反馈仍保留。仅打开源码不会启动游戏。

## 节点与连线视觉规范

节点使用浅色填充、深色描边和 Mermaid 原生轮廓。填充色由描边色与白色按 `8% : 92%` 混合，每个 RGB 通道计算 `round(stroke × 0.08 + 255 × 0.92)`。类型由形状与配色表达，不在名称上方重复 `System`、`Component`、`Resource` 等类型标题；类型文字保留在图例与无障碍描述中，节点详情顶部不重复类型标签。

## Entity 展开与缩略

数据页默认缩略全部 Entity，隐藏其全部 Component 卡片；实体清单中存在组件的 Entity 提供开合控件，没有组件的 Entity 保持普通卡片。每个 Entity 独立开合，展开或收起一个不会改变其他 Entity；画布不提供“展开全部”或“全部缩略”按钮。点击 Entity 名称或空白仍显示详情，右上角的原生按钮负责开合：缩略为 `+`，展开为 `−`，尺寸为 `24×24` 个 SVG 单位，距上、右边界各 `8` 个 SVG 单位并随画布缩放。原生布局为按钮预留空间，不遮挡名称和用途；按钮沿用砖红色 Entity 样式，组件数量在无障碍名称中提供。按钮与节点选择及画布拖动独立，支持 Tab、Enter、Space 和 `aria-expanded`；重排后恢复对应按钮焦点，详情中的开合入口同步。开合保持缩放和被操作 Entity 的屏幕位置，不添加动画；实体内组件顺序和分列规则在展开时恢复。

缩略时，原来连接隐藏 Component 的边显示连接到所属 Entity；展开后恢复到具体 Component。生成态关系的 `from`、`to` 及稳定 ID 保存真实端点，`displayFrom`、`displayTo` 单独保存当前画面端点；不合并、删除关系或改变颜色、线型和契约。选中连线时高亮画面端点，右侧仍显示原 Component 端点和完整源码入口，点击具体端点先展开再定位。手动缩略当前选中的 Component 时，选择转到其所属 Entity；清除选择不改变开合状态。

搜索始终检索本页完整节点清单，隐藏组件计入命中数；在手动展开集合上临时补开命中组件所属的 Entity，不展开未命中的其他实体，清空搜索后恢复手动集合。组件深链接、详情入口、所属插件跳转统一补开目标 Entity 后定位，不关闭其他 Entity。开合按钮退出搜索，仅对原手动集合应用当前 Entity 的目标状态，搜索临时补开的其他实体不写入历史。开合状态按本次页面会话和视图保存为规范 Entity ID 数组，首次进入默认空集合；刷新、切页及历史返回恢复手动集合，旧 `all`、`collapsed` 或单 Entity ID 状态仍兼容。工作区配置不覆盖导航历史中的开合状态。

完整展开的主视图及原有 SVG／Mermaid 文件保持原入口；生成态 `view.entityViews` 另存全部缩略与逐个实体展开的有限视图，作为即时布局缓存，分别生成对应 SVG／Mermaid 并由动态清单统一校验。任意多实体组合使用离线架构 HTML 内嵌的锁定版本 Mermaid 运行时及依赖在浏览器内按需编译，不穷举全部组合，也不请求 CDN 或网络服务。定义生成、SVG 归一化及严格几何检查由 Node 与浏览器共享；每个变体保留 `parentViewId`、独立 SVG 名称空间和全部组的 canonical 成员，`entityGroups[].expanded` 只控制展示，原始清单不新增字段。所有状态分别测量真实轮廓、分组定位和连线避让，不能只隐藏现有 SVG 的组件而保留原来的巨大外框或旧路径。

运行时按视图 ID 及本页规范 Entity 顺序生成组合缓存键，页面全局最多保留 `8` 个额外布局，最近未使用的先移出。编译串行执行，连续开合累计到最新目标集合；切页或历史返回使旧任务失效，不能覆盖当前页面。计算期间保留当前图并显示简短忙碌反馈，通过同一套严格几何检查后再整体替换。编译或校验失败时保留原图及其开合状态，提供重试入口；重试不改变节点身份、原关系、选择与源码入口。预编译及按需布局分别进行自动检查，实际浏览器验收还须覆盖新组合与断网开合。

## Mermaid 布局与连线

“系统与调度”使用 Mermaid 流程图与 Dagre 布局，主图区从左到右排列；按规范化的 Schedule 分组，每个子图内声明 `direction TB`，使 Schedule 容器横排、系统纵排。当前系统图的真实关系保留在各自 `schedule_group` 内，避免内部节点外连覆盖子图方向。系统框显示完整名称与短用途，真实依赖直接连到唯一的语义节点。

Schedule 之间按当前视图可见阶段的真实先后关系增加箭头，单独记录在 `view.scheduleLinks`，不混入系统执行依赖；跳过本页未展示的阶段不代表两个阶段在引擎中直接相邻。Egui 使用内部 Schedule 驱动连接，原生回调、渲染子应用与说明框不串入主调度链。阶段标题不显示“0…N 次”，不另画循环分支；初始化与条件运行的边界仍保留在说明及详情中。

启动阶段标题仅显示 `Startup`。状态切换分组保留稳定身份，标题从本页系统的实际运行时注册中提取 `OnEnter`、`OnExit`、`OnTransition` 等 Schedule 类型名，按出现顺序去重后逐行显示，不列参数；测试注册不进入标题。多个状态目标或不同状态 Schedule 共用原分组，不重复系统，也不因标题列表增加执行边；点击系统后在[节点详情](#节点详情)查看每条注册的完整状态参数。

其余分组的解释后缀不进入显示标题：`FixedLast`、`FixedPostUpdate`、`EguiPrimaryContextPass`、`RenderApp`、`原生平台回调`、`Observer`、`约束与说明` 各自只显示这里列出的名称；`RunFixedMainLoop · AfterFixedMainLoop` 保留完整标题。显示标题由共享模型推导，原始 `label`、具体 `notes`、稳定组 ID、轨道、系统归属与调度关系不变。

容器之间及组内使用独立记录的不可见 `layoutLinks` 约束排版。它们不进入语义关系，也不表示执行先后；系统实际执行依赖由模型中 `kind=order` 的关系表达。自动校验分别检查 Schedule 横坐标递增、组内系统纵坐标递增及阶段连线方向，不能把“图已经横排／纵排”当作调度语义成立的证据。

总览和“事件与协作”使用从左到右的 Dagre `LR` 布局；“数据与实体”整体使用 Dagre `TB`，移除透明的 `diagram_main` 包装子图，默认 `rankSpacing: 8`，减少嵌套空白并保持跨组真实关系下实体标题与组件列序的确定性。同一节点只声明一次，各条关系复用其 ID，业务图形的布局不包含读图指南样例。Mermaid 子图的方向约束及布局配置见 [官方流程图说明](https://mermaid.js.org/syntax/flowchart.html#direction-in-subgraphs) 与 [布局说明](https://mermaid.js.org/config/layouts.html)。

数据页依据 `model.entities[*].components` 建立 canonical Component 到 Entity 的索引，不按 ID 前缀、显示名称或中文 `owner` 猜测归属。对当前数据页已出现的每个 Entity，按其 `entities[].components` 清单补齐全部组件；补齐不扩展其他实体、系统或业务关系，保留组件定义归属、源码及外部引用提示。展开时，以同一规范 Entity 身份声明一个 Mermaid 原生子图，外框就是可交互的 Entity 容器卡片，顶部显示完整名称、用途与开合控件，内部放置完整组件清单，不再另外声明 Entity 小卡片或空标题布局框。缺失的实体上下文使用原 Entity ID、真实归属、源码及外部虚线，没有实体索引的组件保持独立显示。组件按清单顺序分成 `min(4, ceil(N / 6))` 列，各列数量均分，标题使用 Mermaid 原生 `shape: text` 布局节点，通过不可见链连接每列首个组件，各列再依次连接后续组件；标题没有轮廓，不是独立业务卡片或 Tab 停靠点，点击时转交原 Entity。Entity 容器本身不连接自己的组件，不另建列子图或增加语义边。

实体组作为整体布局，`relations` 内按真实关系的连通网络划分透明排版子图，互不相关的网络独立布局，真实边保留原稳定端点；连接 Entity 的边直接连接其原生容器，连接 Component 的边仍连接对应组件。Entity 容器本身完整包含组件，`ChildOf` 等关系不另加末行组件到父容器的排版链。指向相同数据目标的独立 Observer 按原节点顺序用不可见排版链错开源卡片，避免汇入连线穿过相邻卡片；已有可达关系不重复加链，也不增加循环，排版链不表达执行顺序。无真实关系的实体组及普通节点进入 `catalog` 孤立区，该区采用 `LR`，按实体整组的估计行数平衡分列；普通节点按单行计，不按裸节点数量均分。`relations` 与 `catalog` 独立排版，二者之间不增加排版链。生成态 `view.entityGroups` 保留稳定组 ID、Entity ID、完整组件成员、布局标题 `headerMermaidId`、真实容器边界与标题边界；对应节点以 `presentation: 'entity-container'` 区分容器展示，不新增原始清单字段。“定位分组”使用编译后的真实 bbox 及祖先变换定位整个 Entity 容器，原有入口与切页更新保留。

点击 Entity 标题或容器空白、Tab 后用 Enter／Space 激活，以及搜索和连线端点选择，都使用该 Entity 原 ID 的详情、源码和导航。点击内部 Component 只选择该组件。选中 Entity 时其完整组件保持清晰，选中 Component 时所属 Entity 保持清晰；只有实际选中的对象绘制外圈，搜索命中数和真实关系高亮不因上下文扩展改变。容器轮廓、标题及组件分别管理状态，避免父级弱化或滤镜传到子组件；清除、切页和历史返回准确恢复。

节点尺寸、锚点和走线由锁定版本的 Mermaid 编译器产生。视图中的 `visualType` 表达节点视觉类型，`edgeSemantic` 表达连线视觉语义，`displayLabel` 表达可见文字；稳定身份和模型中的 `kind` 继续维护架构语义。模型语义校验检查节点身份、归属、关系方向与类型、覆盖和产物一致性；渲染检查另行检查编译后的真实轮廓、布局及样式，不能用某一项通过替代另一项。

所有视图的业务边与 Schedule 边统一通过[走线规则](architecture-routing.mjs)检查最终原生 SVG。Dagre 先编译直线布局，实际路径在 `0.5` 个图内像素容差内共线且无遮挡的边保留直线，其余边由 Mermaid 以 `basis` 曲线重新编译；曲线须有至少一段原生曲线的实际轨迹偏离其端点弦线超过 `0.25` 个图内像素；共线的曲线命令、折线或弯曲幅度不足不能冒充曲线，须尝试原生 `bumpX`／`bumpY` 方向曲线，并继续核对真实箭头及轮廓。曲线与全部节点真实轮廓的相交检查共用 `0.25` 个图内像素的几何误差，覆盖多轮廓、凹形节点及 Entity、Schedule 的标题。组件连线可以穿过所属 Entity 的正文与边界，但不能穿过其标题或无关卡片；普通边不能借容器包含关系绕过避让。总览与事件页先尝试普通 Dagre `LR` 布局，失败时使用透明的原生 `layout-card` 容器辅助排版，再尝试有界的间距和边跨度调整；容器只约束布局，不增加业务节点、端点或关系。完整 Entity 的稠密数据页布局失败时，可按既有组件访问方向增加指向 Entity 标题的不可见排版约束，并对参与连线的卡片使用透明原生布局容器；这些约束只服务布局，不表示执行顺序，节点身份、成员顺序与真实关系保持，仍须通过同一严格校验。数据页同时通过有界的原生间距及边跨度调整重新编译；候选均失败时可调整同一关系网络内业务边的 Mermaid 声明顺序，保留原关系数组、ID、端点、标签、组件顺序和排版链，仍须通过完整原生校验。Entity 关系子网还可在有限候选中按完整容器或缩略卡片等原生布局单位调整声明块顺序，并对子网中的已有关系共同增加最小跨度；实体内部组件顺序、业务关系与 ID 不变，通过同一严格校验后才采用。不能手工改写 SVG 路径、增加业务端点、删除关系或放宽校验来交付。

连线两端均须贴合各自端点的真实轮廓：源端检查路径起点，目标端检查原生箭头尖端；容差沿用实际线宽与 `0.25` 个图内像素的几何误差。展开 Entity 使用自身原生外框，不能用透明布局容器或包围框代替；源端断口与目标端悬空均使校验失败。默认原生内边距仍为 `flowchart.padding: 16`；仅在其它几何、列序、标题、曲线、标签及目标端检查全部通过、只剩源端接触失败时，才在同一原生候选尝试 `padding: 4`，并重新通过全部检查。

连线标签以 Mermaid 原生背景轮廓参与同一套避让检查，不得压住节点轮廓、Entity 边框或容器标题。以 Component 或 System 为端点的边，其标签可以放在该端点所属容器的正文内；直接以 Entity 为端点的边，其标签须位于容器正文外。标签避让失败也通过原生布局重新编译修复，不手工移动 SVG 文字。

最终 HTML 和独立 SVG 都须按 [视觉检查](../testing/README.md#架构图视觉检查) 核对：Schedule 横排与组内纵排、文字换行与裁切、节点唯一性、连线起止与箭头方向，以及标签、线条、方框的遮挡。箭头应清晰连接目标节点，线型和标签须与契约含义一致；密集交叉不能掩盖端点或暗示不存在的顺序，所有页签的业务边均须避开无关节点及容器标题。发现问题时修改 Mermaid 定义、分组、标签或配置并重新编译，保留真实节点和关系，重新检查最终曲线及箭头。

## 项目 Skill 维护

架构图维护使用 [update-ecs-architecture](../../.agents/skills/update-ecs-architecture/SKILL.md)。用户调用 `$update-ecs-architecture` 或提出匹配请求时，按 Skill 核对当前工作区的清单、关系、布局、说明和源码入口。普通代码修改和 Git 提交不要求刷新图。

清单与生成器共同维护语义和 Mermaid 定义；生成器不分析 Rust 架构，校验器也不能识别所有新系统，自动通过不能代替源码核对。生成器的源码定位在声明缺失或匹配多处时失败；清单的 `required_nodes` 保留功能插件、日志拓扑及关键跨功能契约，校验其注册和可见卡片，避免路径迁移后静默省略。生成覆盖两份 HTML、总览与各非空页签的 `.mmd` 和 SVG 及内嵌源码快照，并按动态 `views` 校验产物完整性与源码／编译结果对应关系，反映整个当前工作区，不自动暂存或提交。开始前检查已有修改；无法安全合并的产物修改先记录冲突，不能直接覆盖。

图有变更时，按 [架构图视觉检查](../testing/README.md#架构图视觉检查) 查看最终 HTML 的总览、全部插件与基础设施页签，以及动态清单中的全部 SVG；重新生成改变图形后须重查。检查只打开静态文档，临时文件放根 `tmp/`。失败原因、日志位置和未完成范围写入对应 Issue 或 PR，不能将生成或校验成功当作视觉验收完成。

### 生成与校验命令

以下命令由 Skill 在完成语义更新后使用，也可用于排查当前工作区的生成或校验问题。在仓库根执行；Node.js 最低版本为 `22.13.0`，实际依赖版本与要求以 [package.json](package.json) 和 [package-lock.json](package-lock.json) 为准：

```text
npm ci --prefix docs/diagrams
node docs/diagrams/build-ecs.mjs
node docs/diagrams/check-ecs.mjs
node --test docs/diagrams/*.test.mjs
```

Node 编译器与浏览器运行时在初始化 Mermaid 时显式采用共享的 `maxTextSize: 200000`，以支持完整 Entity 清单产生的长定义；完整配置仍保留在 Mermaid frontmatter 中。Mermaid 编译使用 headless Chromium；可通过 `MERMAID_CHROMIUM_PATH` 指定浏览器可执行文件，也可自动发现已安装的 Chrome／Edge。浏览器只为编译架构图提供字体测量与 SVG 生成，不启动游戏。依赖恢复和编译失败须先修复并重试，不以原有 SVG 冒充新的编译结果。

生成器与校验器还依赖 [项目声明定位模块](source-locator.mjs)、[依赖声明定位模块](dependency-sources.mjs)、[源码查看页生成器](source-viewer.mjs)、[编辑器入口共享模块](source-editor.mjs) 及引用的项目与锁定依赖源码。独立校验可能报告未刷新产物的源码入口或快照不符；校验仅允许 CRLF/LF 换行差异，不忽略其他源码内容变化，并核对所有依赖声明入口、Cargo 包根目录和完整文件快照。临时文件遵循 [临时文件管理](../development.md#临时文件管理)。VS Code URI、根目录配置与生成页交互按 [源码定位验证](../testing/README.md#架构图源码定位验证) 检查；编译浏览器或无窗口回归不能代替最终 HTML 的浏览器视觉检查及本机 VS Code 的实际协议打开验证。

图描述代码结构与调度约束，不替代游戏运行或视觉验收。
