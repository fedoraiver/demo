# 当前 ECS 架构图

打开 [交互式 HTML](ecs-architecture.html)，先从功能总览查看 App 的整体系统调度，再通过侧栏进入 14 个项目插件、Bevy 引擎或第三方的 Avian、Enhanced Input、Kira、Egui 四个独立入口。各入口只保留“系统与调度”；Observer 在事件发出系统旁分支展示，由发出位置直接连线并标明事件名，没有固定 Schedule 的回调不加入每帧调度链。点击节点查看详情，通过“打开所属插件”切换入口，通过“打开对象关系图”查看该对象的关系。没有系统的入口显示空态。

页头、侧栏、工具栏、画布与详情采用统一浅色界面。顶栏保留品牌与工作区配置入口，内容区标题显示当前视图名称，项目插件同时显示标识；总览及基础设施标题区不显示介绍段落。画布顶部仅保留“定位分组”，不显示视图摘要或操作提示。图内每个节点只显示完整名称与一句短用途；职责、读写声明、注册条件和技术细节集中在右侧详情。全局搜索覆盖对象目录，同名结果通过所属实体或注册阶段区分；空系统页仅显示明确的空态标题。

全部图形由 Mermaid 源码编译为 SVG，HTML 内嵌编译结果与节点数据，可离线使用，无需联网加载 Mermaid。点击节点或连线在右侧展开字段、读写声明、约束和源码入口，并高亮关联；桌面使用滚轮缩放、左键拖动平移，窄屏触摸方式见[画布交互与焦点](#画布交互与焦点)。未选择节点或清除选择时，右侧显示当前视图的[英文图例](#节点与连线视觉规范)。画布内的文字不参与选择，避免拖动误选；右侧详情和源码页中的文字仍可选择复制。详情中的对象与外部契约可继续浏览；返回按钮及浏览器前进／后退保留导航位置。链接通过 `feature`、`tab`、`node` 记录插件、系统页和节点；对象专属图使用 `object` 保存精确投影或注册 ID，保留来源上下文。导航继续携带 `workspace`、其他查询参数与片段。

视口宽于 `900px` 时，可横向拖动画布与右侧面板之间的分隔条。面板初始宽度为 `286px`，最小 `240px`、最大 `720px`，同时为画布保留至少 `360px`；可用空间不足时相应收紧面板上限。宽度只在本次页面会话内保留，刷新后恢复初始值。视口为 `900px` 及以下时采用上下布局，不提供横向分隔条；详情按内容完整展开，随页面一起滚动，不设独立的纵向滚动区。

右侧节点及连线详情中的“源码位置”提供 VS Code 入口、定位路径和复制定位，不提供离线快照跳转。项目源码按当前工作区定位；Bevy 和第三方的组件、插件优先打开本机锁定依赖中的真实类型声明，定位到记录的行，默认列为 `1`。需要查看生成时的完整文件时，可从本文打开独立的 [源码查看页](ecs-source.html)，选择项目文件或依赖文件并定位、高亮指定行。源码页也提供 VS Code 入口，使用当前选择的文件和定位行；切换文件、点击行号后会更新定位。复制定位成功后，当前按钮显示“已复制”并在 `2` 秒后恢复，同时提供无障碍状态反馈；失败时在当前控件附近提示，仍可选择定位文本手动复制。源码文本是生成时的快照，不会自动跟随本地文件变化，修改后的内容和行号可能与快照不同。两份 HTML 放在同一目录即可离线使用，无需启动服务。

`<module>` 是插件的源码目录名。Bevy 独立文件为 `ecs-infrastructure-systems.svg`，第三方分别为 `ecs-third-party-avian-systems.svg`、`ecs-third-party-enhanced-input-systems.svg`、`ecs-third-party-kira-systems.svg`、`ecs-third-party-egui-systems.svg`。总览、每个非空系统页及每个对象图同时生成同名 `.mmd` 源文件，例如 `ecs-overview.mmd`；空系统页保留 HTML 空态，不生成 `.mmd` 或 SVG。文件清单以 HTML 内嵌的动态 `views` 为准，生成时清理已经退出清单的旧产物。独立 SVG 和 `.mmd` 保存在本目录，页面工具栏不提供图例或导出按钮。Mermaid 文件的 YAML frontmatter 使用合法 JSON 对象写入完整主题、布局及配置，使用相同依赖版本可按原设置重新编译。

基础设施入口由 [共享目录](architecture-infrastructure.mjs) 维护：`infrastructure` 表示 Bevy，`avian`、`enhanced_input`、`kira`、`egui` 分别表示四个第三方浏览分组，侧栏中四个第三方入口位于 Bevy 引擎之前。插值纳入 Avian，第三方世界检查器纳入 Egui；分组不改变实际库来源和类型身份。浏览归属按清单中核对的提供方与具体契约维护，Bevy 泛型容器承载第三方类型时可以浏览归对应第三方分组，`defined_in` 仍保留 Bevy 的类型定义归属。插件导航由侧栏及节点详情中的所属插件入口提供；`main / App` 是项目应用上下文，不表示其源码由 Bevy 定义，原生窗口回调归项目窗口策略。跨入口引用显示真实来源并跳转所属入口，现有业务节点 ID 与关系保持不变。

旧 `feature=third_party` 链接携带真实节点时，按节点当前归属定位；没有节点、节点失效或指向旧目录 ID `third-party-plugins` 时回到功能总览。旧 `infrastructure` 节点链接仍可定位，无节点时仍进入 Bevy。旧 `component=<投影ID>` 精确迁移到该投影的对象图；旧 `tab=data/events` 携带有效对象节点时进入对象图，否则回所属系统页。旧聚合 ID 对应多个实际对象时在搜索中列出候选项，不任意选中其中一个。兼容导航使用历史替换，保留 `workspace`、其他查询参数与片段，不增加一次历史记录。

节点通过形状和配色表达类型，名称置于首行；连线通过颜色、线型和宽度表达语义，文字仅保留具体契约或约束。图例位于右侧读图指南，独立 SVG 和 `.mmd` 只包含业务图形，详见 [节点与连线视觉规范](#节点与连线视觉规范)。

数据访问不代表调度顺序；无显式顺序的系统或 Observer 不得画成全序流水线。

系统视图不展示 `main / App` 到插件的纯装配注册边，也不保留因过滤这些边而孤立的外部 `main / App`。对象图保留这些真实装配关系；项目插件安装第三方插件、`main / App` 退出刷新等关系继续按真实对象和操作表达。

插件局部视图中的外部系统、插件和协作契约显示摘要、所属插件与跳转入口，不展开其他插件内部流程。类型定义归属、系统注册归属和实体装配来源分别记录。每个 Entity 的右侧详情保留 `entities[].components` 完整清单；组件清单补齐不递归引入其他实体、系统或关系。跨视图复用原节点 ID，旧 ID 仅可通过显式 `node_aliases` 指向同一声明和身份。不同实体上的组件投影与同函数的不同注册各有自己的对象图，不按类型或函数合并卡片。

Entity 在画布中始终使用砖红色单层圆角矩形，完整组件及可选性在右侧查看；组件清单可进入该投影的[对象专属图](#对象专属图)。业务根、视觉根和 GLB 子节点分别表达，图内存在某个组件不表示该组件始终存在。引擎集合与渲染等仅展示相关流程，不代表全部内部系统或精确全序；日志后台线程保持 External I/O 身份。节点和连线的源码入口按[源码范围](#源码范围)核对，不把原项目使用位置当作类型定义。运行机制由[当前架构](../architecture.md)维护。

依赖定义由 [集中映射](architecture-source-definitions.mjs) 及 [定位模块](dependency-sources.mjs) 维护，包名、相对源码路径和声明符号需要对照真实源码核对。同一类型的多个实体组件复用同一声明；Kira 的项目别名 `KiraAudioPlugin` 指向真实的 `AudioPlugin`，Avian 的二维／三维同名声明按当前三维功能选择。SystemSet 卡片定位真实集合声明与配置，关联函数在完整说明中保留，不把集合当成单个系统函数；`ApplyDeferred` 的不同调度注册共用引擎定义，各自的项目注册位置仍保留。生成与校验通过 `cargo metadata --locked --offline` 获取当前机器的锁定包版本和目录，需要本机已有对应依赖源码；声明缺失、多处匹配、目录或行号不符均使检查失败。

日志拓扑将业务碰撞日志连到 `tracing producer`，再分为 `File worker → 统一会话日志文件` 与 `Console worker` 两路，不绘制业务系统绕过 worker 直接写文件的边。沿相应对象图逐步浏览生产者、后台线程和输出文件；文件节点保留 `physics-file-log` 稳定 ID 与 `External I/O` 类型，源码入口指向 `create_session_file`。退出刷新沿用已有关系，队列与 stderr 不另设终点节点。

[ecs-data.json](ecs-data.json) 保存源码核对清单，[build-ecs.mjs](build-ecs.mjs) 为生成入口。各视图复用系统 `module`、实体关系和 Observer 记录，不各自维护一份语义关系。

节点的 `description` 保留完整架构说明；过长或技术细节密集时，在同一记录添加可选 `display_summary`，写一句完整的中文用途，系统说明实际做什么，资源和组件说明承载什么。图内优先使用该短句，否则复用简洁的 `description`；不机械截句或增加省略号。组件使用完整名称和实际用途，不由生成器注入所属实体前缀；实体身份由包含关系及右侧详情表达，外部提供插件的来源说明仍保留。短句无需重复读写或运行条件，右侧详情始终使用完整说明。`view.summary` 保留为视图元数据，不在画布顶部显示。

## App 调度总览

“功能总览”保留 `overview` 视图身份和 `feature=overview` 入口，画布展示 App 的整体系统调度。总览汇总全部项目系统，以及已核实的引擎／第三方集合、命令同步和聚合流程，复用局部视图的规范节点、注册身份和显式关系；同一规范节点只声明一次，不同 Schedule 的注册信息继续保留。节点详情提供完整的 Schedule、运行条件、读写与查询及源码入口，所属插件仍可逐一进入。

调度骨架分别表达一次性启动、每帧 Main 与 `RunFixedMainLoop` 驱动的固定步。固定循环每帧执行 `0..N` 个完整 FixedMain，循环结束后的呈现同步在零固定步帧也运行；状态转换保留首次初始化和每帧处理的不同入口，OnEnter／OnExit 等仅在对应状态变化时执行。阶段驱动与系统执行依赖分别表达，未声明依赖的系统没有额外全序；插件安装顺序和功能协作契约不转成系统顺序。

Egui 的相关 Schedule 由 PostUpdate 内部驱动；RenderApp 是独立渲染子应用。Observer 沿真实事件触发线在来源旁排布，所在排版容器不表示它注册于该 Schedule；原生平台回调保留调度外分组，两者均不追加到主 Schedule 链中，也不伪造固定注册。引擎与第三方的集合和聚合流程只覆盖已核实的职责及公开边界，不代表穷举全部内部系统；聚合节点保留自己的类别和说明，不冒充单个系统函数。

## 画布交互与焦点

首次打开、切换插件、进入对象图，以及使用“返回总览”或“返回原视图”按钮时，均自动“适合窗口”，完整显示并居中整张图。带 `node` 参数的链接仍选中目标并显示详情，但不自动放大到该节点。浏览器后退／前进有有效历史视角时恢复此前的缩放、平移和选择，否则同样“适合窗口”；空系统页保持空态，不计算图形尺寸。同图内主动定位节点、定位分组和手动缩放保持各自行为。

画布是具有无障碍名称的 `role="region"`，使用 `tabindex="-1"` 接收程序化焦点，不增加 Tab 停靠点，也不显示浏览器默认焦点框。由查看器处理的有效 `pointerdown` 使用 `focus({ preventScroll: true })` 将焦点移到画布；`pointerup` 只激活命中节点或连线，不再聚焦卡片，焦点迁移不改变滚动、平移或缩放。节点仍可通过 Tab 到达，并使用 Enter 或 Space 激活。未选中节点通过 `:focus-visible:not(.selected)` 显示键盘焦点，已选中节点使用真实轮廓的持续选中效果，不再叠加第二层矩形焦点框。

窄屏画布直接支持单指拖动平移、双指开合缩放，双指中点移动同时平移图形；轻点节点或连线查看详情，无需切换操作模式。拖动及多指手势结束时不触发选择，触点数量变化时不跳动。在画布外的详情、标题及页面空白处上下滑动滚动页面；详情随内容完整展开，不设独立纵向滚动区。桌面鼠标交互保持不变。窄屏仅高度变化时保留图形缩放和位置，避免地址栏伸缩或软键盘出现后重置阅读位置。

显式清除选择时，仅当 `activeElement` 位于图内，或位于即将移除的“清除选择”按钮上，才将焦点移到画布，并阻止焦点操作引起滚动；搜索框、分组下拉及其他控件的焦点保持不变。交互模块的 `paint` 只更新选中、关联及弱化状态，不负责焦点迁移。源码操作的成功、失败与无障碍反馈保持独立。

## 节点详情

选择节点后，右侧从名称和完整 `description` 开始，不显示类型 badge、`phase`、短摘要替代正文或自定义标签。其后按实际数据依次显示功能归属与“打开所属插件”、“打开对象关系图”、注册功能、定义归属、装配来源、所属实体、公开契约、`Schedule`、`Read`、`Write`、`Query`、事件／消息、字段、约束与说明、完整实体组件、源码位置及清除选择；空栏目省略。对象图与系统图共用相同字体、间距、可点击条目、源码控件和面板宽度。同函数其他注册提供独立对象入口，不用其字段与源码覆盖当前注册。

Schedule 与普通分组的详情显示分组标题及已有的具体 `notes`，不重复类别标签或通用阅读提示。Schedule 连线详情保留关系语义、方向、端点及具体契约，不附加通用调度说明；节点用途、运行条件、约束、图例和错误反馈按各自内容保留。

`Read` 与 `Write` 各自按 canonical Entity 身份归并同一实体的访问，只显示实体名称，不在这两栏列出组件。同名但身份不同的实体仍分别保留；读与写独立去重，不能把写入合并到读取。非实体访问按 `Resource`、`Local<T>`、`NonSend<T>` 分类，保持原记录中的出现顺序；原始访问清单和组件数据继续保留。查询声明及过滤条件在 `Query` 中完整显示。

`Read`、`Write` 是一级标题，下面的 `Entity`、`Resource`、`Local<T>`、`NonSend<T>` 分类相对一级缩进 `16px`，分类条目再缩进 `16px`。字体、字号、字重和配色沿用原样；详情面板收窄至 `240px` 时，分类、长名称及条目仍可换行，不横向溢出。

`Schedule` 中每条注册使用独立块，保留完整 Schedule 参数与注册字段；每个字段单独一行，数组逐项分行，不拼成一长串或截断。图中状态分组标题省略的具体状态值在这里查看。实际系统按运行时注册分别建图；测试注册保留其 scope，不增加生产对象或调度阶段。SystemSet 与 Engine flow 的多个阶段属于原对象配置，不复制为多个系统函数。

## 源码范围

源码区仅渲染按语义类型核对的 `sourceEntries`，按角色分组并在单个“源码位置”栏目提供明确入口。旧 `source` 保留原使用或注册语义，`definition_source` 保留依赖声明信息，二者不能被查看器无条件提升为类型定义。角色、定位与证据由[源码策略](architecture-source-policy.mjs)和[证据清单](architecture-source-evidence.mjs)维护；相同角色与定位去重，不同 Schedule 注册仍保留各自来源。下表按规范语义类别规定允许显示的入口；不同类别可具有相同的允许角色，但不能据此合并卡片身份或图例。

| 语义类型 | 节点源码入口范围 |
| --- | --- |
| Component | 仅真实类型定义。 |
| Entity | 创建／装配生成位置、销毁位置。 |
| System | 函数定义及该对象对应的真实 Schedule 注册位置；同函数其他注册通过独立对象入口浏览。 |
| Observer | 回调定义及 Observer 注册位置。 |
| Resource | 类型定义、初始化、插入与移除位置。 |
| Local<T> | 参数声明、自定义类型定义及初始化位置。 |
| NonSend<T> | 类型定义、初始化、插入、移除及清理实现。 |
| Message | 消息类型定义。 |
| Messages<T> | 缓冲类型及消息类型定义、注册、初始化与移除位置。 |
| EntityEvent | 事件类型定义及对应动作类型定义。 |
| Plugin | 插件类型定义、build 实现及安装位置。 |
| PluginGroup | 组类型定义、构建实现及安装位置。 |
| App | 创建、装配及运行入口。 |
| SystemSet | 集合定义及 configure_sets 等配置位置。 |
| SystemParam | 真实定义、配置与参数位置，不能当作 Component。 |
| QueryData | 真实定义、配置与参数位置，不能当作 Component。 |
| Scheduling constraint | 建立调度约束的实际配置；存在独立声明时才列定义。 |
| Shared data contract | 真实声明、约束配置及参数使用位置。 |
| Synchronization | 真实同步定义、实际实现、注册与促成同步的配置。 |
| System group | 真实成员及其注册／配置，不虚构分组类型或独立系统函数。 |
| Observer group | 真实成员回调及注册／配置，不伪造统一 Observer 函数或 Schedule。 |
| Engine flow | 真实流程入口、相关集合定义、实际实现及安装配置，不冒充单个函数。 |
| Registration helper | 真实辅助函数定义及项目调用／装配位置，不当作 Plugin 类型。 |
| External I/O | 定义、创建、安装、实际实现及关闭位置。 |
| Platform API | 创建／安装、实际执行和关闭／卸载实现，保留平台条件。 |
| Platform event | 真实事件／回调定义、OS 注册及项目启用位置，保留平台与触发条件。 |
| Note | 仅支持说明的已核实相关实现，不虚构定义。 |
| Lifecycle note | 相关生命周期配置与实际清理实现，不虚构独立声明。 |
| BSN layout | 真实装配或布局声明。 |
| Operation result | 实际赋值或其他已核实操作位置，不虚构类型定义。 |
| Relationship | Bevy 关系声明、约束配置及参数使用位置；建立／解除与 hook 操作通过连线追踪。 |
| Entity reference | 普通实体引用的字段／参数声明；赋值与清除通过连线追踪，不套用 Bevy 关系 hook。 |

本表规定允许显示的范围，不代表每种角色必有独立实现。间接销毁、导入场景、关系生命周期或引擎自动初始化须标明真实机制和来源。尚无证据的必要入口写入 `sourceGaps` 并明确“待核实”，不拿普通使用处填补，也不伪造不存在的销毁函数或定义。

连线源码定位到该具体操作、条件或约束的实际位置，包含必要参数、配置、赋值、Commands 操作或 helper 实现。Component 节点只列定义，相关修改、添加、移除的证据在 System／Observer 或相应连线查看；数据访问与注册顺序分别维护。

## 在 VS Code 中打开源码

从实际检出或 worktree 的 `docs/diagrams/` 目录通过 `file://` 打开 HTML 时，页面根据自己的位置推导工作区根目录；通过“配置工作区”修正“仓库根目录”，点击“保存目录”生效。“恢复默认”清除手动配置并重新使用本地页面推导。由 HTTP 服务提供、HTML 搬到其他位置，或需要指向另一份 worktree 时，先填写目标工作区的绝对根目录。路径可以包含空格、中文、`#` 和 `%`，无需手动编码。配置入口保留目录输入与校验反馈，页面底部不显示当前目录状态栏。

配置按页面所在目录的完整 URL 保存在浏览器本地，主检出和各 worktree 的页面目录相互独立。`workspace` 查询参数优先于保存的配置，保存的配置优先于 `file://` 推导；浏览器禁用存储时，本页仍保留配置，并通过同目录两份 HTML 的链接携带 `workspace` 参数。分享链接前移除该参数中的个人路径。项目工作区目录不写入维护清单；两份生成 HTML 为打开依赖声明保存生成机器的 Cargo 包绝对根目录，并包含完整依赖源码快照。移动到其他机器后仍可阅读快照，依赖的本机编辑器定位需要在目标机器重新生成；修改工作区配置只影响项目文件，不覆盖 Cargo 目录。

VS Code 入口仅在用户点击时调用 `vscode://file/...` 协议；页面加载、选择节点及修改根目录都不会自动打开编辑器。浏览器可能要求确认外部应用，只有安装并注册了该协议的 VS Code 才能处理请求。页面无法确认浏览器是否批准或编辑器是否打开，发出请求不等于打开成功。项目入口未配置有效根目录时按提示补齐；依赖入口使用生成时的 Cargo 根目录。浏览器拒绝请求或本机未安装 VS Code 时，可使用复制定位入口保留文件、行、列信息，或从本文打开独立源码页查看离线快照。两份 HTML 不重复展示打开方式和快照时效说明，相关使用边界由本文维护；源码操作、定位与校验反馈仍保留。仅打开源码不会启动游戏。

## 对象专属图

对象目录覆盖项目生产 ECS 声明、实体投影和系统／Observer 注册，以及项目实际使用的引擎、第三方、平台与外部输出契约。测试专用声明、普通 helper、闭包和说明卡片不独立生成对象图；说明仍可作为直接关系的上下文出现。实体关系记录通过边及详情表达，真实关系组件仍生成 Component 对象图。

每个组件投影和系统注册保留自己的稳定 ID 与独立 SVG。同类型出现在不同实体上、同函数注册到不同阶段时分别建图，不按名称、类型、函数或 canonical Entity 合并。组件的真实声明、完整泛型实参和锁定包身份用于核对源码来源；原投影归属和每条注册的 Schedule、条件、集合及源码继续保留。复合消息与泛型聚合记录按实际类型拆分，旧聚合 ID 仅维护兼容候选，不作为虚构运行时类型。

每张图只包含一个中心对象、其全部直接关联对象及中心的全部入边和出边。不递归展开间接关系，也不加入邻居之间的边；没有关系的对象生成单卡图。关系统一来自实体包含、系统访问及组件操作、消息与事件、实体引用与 Bevy 关系、注册、集合成员和显式调度约束。对象详情保留自身完整说明、所属插件、读写声明、Query、字段和源码，不用局部关系摘要替代。

仅中心对象的 `kind=Entity` 时，隐藏全部 Component 卡片及所有触及 Component 的边，再由中心与剩余边的端点重算可见节点，不保留过滤后孤立的邻居。一跳完整性按此可见投影核对；过滤后没有边时保留中心单卡。全局对象目录及关系目录仍完整，Component 自身图继续展示关联 Entity。实体右侧的完整组件清单及各投影入口保留，节点 ID 与 URL 不变。

连线分别记录包含、读取字段、可变访问或字段修改、添加、移除、存在过滤和反射访问。`With<T>`、`Without<T>`、`Has<T>`、`Option<&T>` 以及只判断 `get::<T>().is_some()` 的访问必须按实际用途区分；不能把存在检查画成字段读取，也不能从一个 `writes` 记录推断添加或移除。直接赋值、Commands 延迟插入／删除、普通 helper、World 闭包和关系 hook 的实际操作位置、条件及可见时机在连线详情核对，helper 不冒充注册系统。仅有访问声明时明确保留证据级别，未核实的操作列入待核实说明。

通过全局对象搜索、Entity 组件清单及节点详情的“打开对象关系图”进入专属图。URL 的 `object` 使用精确投影或注册 ID，`node` 定位图内节点；原 `feature`／`tab` 保留来源上下文。卡片单击显示详情，中心卡片不重复导航；关联对象可从详情继续进入自己的图。“返回原视图”、所属插件和浏览器前进／后退保持可用，历史返回恢复节点与画布位置。旧链接迁移规则见本文开头的兼容导航说明。

对象视图的 `aspect` 为 `object`，`objectId` 和 `centerNodeId` 标识原始对象；生成时编译 `ecs-object-<key>.svg` 和同名 `.mmd`，并内嵌到离线 HTML 的 `views`。动态清单校验每个对象恰好一图、中心唯一，并按上述可见投影核对一层邻居和入出边完整；不在浏览器按需编译，也不依赖网络运行时。

## Mermaid 布局与连线

App 调度总览与插件“系统与调度”均使用 Mermaid 流程图与 Dagre 原生布局，主图区从左到右排列；按规范化的 Schedule 分组，每个子图内声明 `direction TB`，保持阶段容器横排、真实系统纵排。系统框显示完整名称与短用途，真实依赖直接连到唯一的语义节点；总览同时保留已核实的跨插件调度约束。

Observer 与无固定 Schedule 的生命周期触发流程不串成统一 Observer 区域或排版链，它们在发出系统旁形成局部分支。同一发出位置的直接回调可使用局部无环不可见连线控制扇出宽度，该约束不是 `order` 执行关系。排版可将这些节点作为来源分组的 `visualAttachments` 声明，分组的 `nodes` 仍只记录真实成员；视觉附属不是 Schedule 注册，不能据包围关系推断固定执行阶段。没有唯一阶段来源的无固定 Schedule 组件由 `view.observerBranches` 记录为独立来源分支，透明容器不增加业务身份。系统图将精确事件对象上的“发出位置 → 事件 → Observer”两条原始关系投影为直接触发线，线标签显示事件名，详情提供事件入口、条件、生效时机及源码证据；投影元数据保留两条原关系的身份，原始关系从事件对象图浏览。相同事件名不合并不同对象，多来源连接同一个 Observer；触发线不表示系统执行顺序。插件局部页只展开与内部端点直接相关的触发线，外部端点保留所属入口摘要。事件对象图继续显示原始关系，其他对象图仍只展开原始关系的一跳，不把投影线作为新关系加入目录。

Schedule 之间按当前视图可见阶段的真实先后关系增加箭头，单独记录在 `view.scheduleLinks`，不混入系统执行依赖；跳过本页未展示的阶段不代表两个阶段在引擎中直接相邻。Egui 使用内部 Schedule 驱动连接，原生回调、渲染子应用与说明框不串入主调度链。插件局部页的阶段标题不显示“0…N 次”，不另画循环分支，初始化与条件运行的边界保留在说明及详情中；总览按 [App 调度总览](#app-调度总览) 表达完整驱动骨架及固定循环次数。

启动阶段标题仅显示 `Startup`。状态切换分组保留稳定身份，标题从本页系统的实际运行时注册中提取 `OnEnter`、`OnExit`、`OnTransition` 等 Schedule 类型名，按出现顺序去重后逐行显示，不列参数；测试注册不进入标题。多个状态目标或不同状态 Schedule 共用原分组，不重复系统，也不因标题列表增加执行边；点击系统后在[节点详情](#节点详情)查看每条注册的完整状态参数。

其余可见分组的解释后缀不进入显示标题：`FixedLast`、`FixedPostUpdate`、`EguiPrimaryContextPass`、`RenderApp`、`原生平台回调`、`约束与说明` 各自只显示这里列出的名称；`RunFixedMainLoop · AfterFixedMainLoop` 保留完整标题。显示标题由共享模型推导，原始 `label`、具体 `notes`、稳定组 ID、轨道、系统归属与调度关系不变；`EventTriggered` 仅保留无固定 Schedule 的语义，不生成可视分组及分组定位入口。

容器之间及组内使用独立记录的不可见 `layoutLinks` 约束排版；较长的原生不可见连线可增加布局层级间距，仍须保留原 ID 和真实节点或容器端点。它们不进入语义关系，也不表示执行先后；系统实际执行依赖由模型中 `kind=order` 的关系表达。自动校验分别检查 Schedule 横坐标严格递增且不重叠、组内真实系统纵坐标递增及阶段连线方向，并逐项核对真实成员与视觉附属的覆盖和唯一性，不能把“图已经横排／纵排”当作调度语义成立的证据。

对象图通过原生 Mermaid 方向、不可见 `layoutLinks`、透明排版容器、声明顺序及有界间距组织中心与直接邻居。每个节点只声明一次，各条关系复用原 ID；实体包含关系从 `model.entities[*].components` 取得，不按名称猜测归属。关系详情保留原端点，不将组件投影为另一张实体卡片。Mermaid 子图的方向约束及布局配置见 [官方流程图说明](https://mermaid.js.org/syntax/flowchart.html#direction-in-subgraphs) 与 [布局说明](https://mermaid.js.org/config/layouts.html)。

排版节点没有业务身份，不能成为真实关系端点或增加虚假执行依赖。相反方向的读写边、有向环、并行关系及稠密对象关系均保留；所有候选均通过同一套真实轮廓、路径、箭头和标签检查后采用。

节点尺寸、锚点和走线由锁定版本的 Mermaid 编译器产生。视图中的 `visualType` 表达节点视觉类型，`edgeSemantic` 表达连线视觉语义，`displayLabel` 表达可见文字；稳定身份和模型中的 `kind` 继续维护架构语义。模型语义校验检查节点身份、归属、关系方向与类型、覆盖和产物一致性；渲染检查另行检查编译后的真实轮廓、布局及样式，不能用某一项通过替代另一项。

所有视图的业务边与 Schedule 边统一通过[走线规则](architecture-routing.mjs)检查最终原生 SVG。Dagre 先编译直线布局，实际路径在 `0.5` 个图内像素容差内共线且无遮挡时保留直线；其余边由 Mermaid 以 `basis` 曲线重新编译，至少一段实际轨迹偏离端点弦线超过 `0.25` 个图内像素，共线曲线命令或折线不算曲线。必要时尝试原生 `bumpX`／`bumpY`、不可见排版约束、透明容器、声明顺序及有界间距；各候选保留唯一节点、原关系、稳定 ID、方向与标签，并使用相同严格校验。曲线与全部实际轮廓的相交检查采用 `0.25` 个图内像素误差，包含多轮廓、凹形、外部虚线及 Schedule 标题，不能只检查 Component 或使用轴向包围框代替真实轮廓。不能手改路径、删边、增加虚假业务端点或放宽校验交付。

连线两端均须贴合各自端点的真实轮廓：源端检查路径起点，目标端检查原生箭头尖端；容差沿用实际线宽与 `0.25` 个图内像素的几何误差。Entity、Component 与其他节点均使用自身原生轮廓，不能用透明布局容器或包围框代替；源端断口与目标端悬空均使校验失败。默认原生内边距仍为 `flowchart.padding: 16`；仅在其它几何、列序、标题、曲线、标签及目标端检查全部通过、只剩源端接触失败时，才在同一原生候选尝试 `padding: 4`，并重新通过全部检查。

连线标签以 Mermaid 原生背景轮廓参与同一套避让检查，不得压住无关卡片、Entity 轮廓或 Schedule 标题。标签换行保留完整字符和标签语义；布局、曲线及标签策略回退均须重新通过相同严格检查。标签避让失败时重新编译原生布局，不手工移动 SVG 文字。

最终 HTML 和独立 SVG 都须按 [视觉检查](../testing/README.md#架构图视觉检查) 核对：Schedule 横排、组内真实系统纵排、Observer 靠近发出系统形成局部分支、文字换行与裁切、节点唯一性、连线起止与箭头方向，以及标签、线条、方框的遮挡。阶段容器横向严格递增且不重叠，触发线仍连接真实节点；箭头应清晰连接目标节点，线型和标签须与契约含义一致。密集交叉不能掩盖端点或暗示不存在的顺序，所有视图的业务边均须避开无关节点及容器标题。发现问题时修改 Mermaid 定义、分组、标签或配置并重新编译，保留真实节点和关系，重新检查最终曲线及箭头。

## 项目 Skill 维护

架构图维护使用 [update-ecs-architecture](../../.agents/skills/update-ecs-architecture/SKILL.md)。用户调用 `$update-ecs-architecture` 或提出匹配请求时，按 Skill 核对当前工作区的清单、关系、布局、说明和源码入口。普通代码修改和 Git 提交不要求刷新图。

清单与生成器共同维护语义和 Mermaid 定义；源码声明、注册及访问审计不能推断全部 Rust 行为，自动通过不能代替源码核对。生成器的源码定位在声明缺失或匹配多处时失败；清单的 `required_nodes` 保留功能插件、日志拓扑及关键跨功能契约，校验其注册和可见卡片，避免路径迁移后静默省略。生成覆盖两份 HTML、总览、各非空系统页、全部对象图的 `.mmd` 和 SVG 及内嵌源码快照，并按动态 `views` 校验产物完整性与源码／编译结果对应关系，反映整个当前工作区，不自动暂存或提交。开始前检查已有修改；无法安全合并的产物修改先记录冲突，不能直接覆盖。

图有变更时，按 [架构图视觉检查](../testing/README.md#架构图视觉检查) 查看最终 HTML 的总览、全部插件与基础设施系统页、全部对象图，以及动态清单中的全部 SVG。已有逐图目测基线时，可按 SHA-256 复用未变化 SVG 的记录，重新目测变化产物，并核对最终清单全部有目测记录。检查只打开静态文档，临时文件放根 `tmp/`。失败原因、日志位置和未完成范围写入对应 Issue 或 PR，不能将生成或校验成功当作视觉验收完成。

### 生成与校验命令

以下命令由 Skill 在完成语义更新后使用，也可用于排查当前工作区的生成或校验问题。在仓库根执行；Node.js 最低版本为 `22.13.0`，实际依赖版本与要求以 [package.json](package.json) 和 [package-lock.json](package-lock.json) 为准：

```text
npm ci --prefix docs/diagrams
node docs/diagrams/build-ecs.mjs
node docs/diagrams/check-ecs.mjs
node --test docs/diagrams/*.test.mjs
```

Node 编译器初始化 Mermaid 时显式使用共享的 `maxTextSize: 200000`，frontmatter 保留完整主题、布局和配置；浏览器只读取生成时的编译结果。Mermaid 编译使用 headless Chromium，可通过 `MERMAID_CHROMIUM_PATH` 指定可执行文件，或自动发现已安装的 Chrome／Edge；仅执行架构文档编译，不启动游戏。编译失败须修复并重试，不能以旧 SVG 冒充新产物。

编译器以 `view.id` 作为 `svgId`，独立编译 `.mmd` 时须使用相同 ID，或直接复用项目编译入口。需要原生反向箭头的布局通过 frontmatter 的 `themeCSS` 引用同图真实关系生成的 `pointStart` marker，`nativeReverse` 仅记录逻辑方向。SVG 归一化只添加身份与交互元数据，不移动路径或替换箭头；独立几何检查读取实际 CSS、marker 和路径，分别检查逻辑源端与目标端。

生成器与校验器还依赖 [项目声明定位模块](source-locator.mjs)、[依赖声明定位模块](dependency-sources.mjs)、[源码查看页生成器](source-viewer.mjs)、[编辑器入口共享模块](source-editor.mjs) 及引用的项目与锁定依赖源码。独立校验可能报告未刷新产物的源码入口或快照不符；校验仅允许 CRLF/LF 换行差异，不忽略其他源码内容变化，并核对所有依赖声明入口、Cargo 包根目录和完整文件快照。临时文件遵循 [临时文件管理](../development.md#临时文件管理)。VS Code URI、根目录配置与生成页交互按 [源码定位验证](../testing/README.md#架构图源码定位验证) 检查；编译浏览器或无窗口回归不能代替最终 HTML 的浏览器视觉检查及本机 VS Code 的实际协议打开验证。

图描述代码结构与调度约束，不替代游戏运行或视觉验收。
