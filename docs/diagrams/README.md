# 当前 ECS 架构图

打开 [交互式 HTML](ecs-architecture.html) 查看四个视图。文件内嵌图形与数据，可离线使用；滚轮缩放、左键拖动平移，点击卡片展开字段、读写声明和源码入口。画布内的文字不参与选择，避免拖动误选；右侧详情和源码页中的文字仍可选择复制。详情中的组件与资源还可继续点击。

详情中的“源码位置”保留离线快照入口，点击后在新页面打开 [源码查看页](ecs-source.html)，显示对应完整文件并定位、高亮指定行。并列的 VS Code 入口打开当前本地工作区中的对应文件，定位到节点记录的行，默认列为 `1`。源码页也提供 VS Code 入口，使用当前选择的文件和定位行；切换文件、点击行号后会更新定位。源码文本是生成时的快照，不会自动跟随工作区文件变化，本地文件修改后内容和行号可能与快照不同。两份 HTML 放在同一目录即可离线使用，无需启动服务。

粗实线表示执行先后；蓝虚线表示读取，绿实线表示写入，橙虚线表示事件触发。紫虚线表示普通 `Entity` 引用，紫实线表示 Bevy 关系。框的标签和颜色区分实体、组件、系统、Observer、共享资源、系统私有状态及引擎概览。

数据访问不代表调度顺序；无显式顺序的系统或 Observer 不得画成全序流水线。

实体框按角色汇总组件，可选组件并非始终存在；业务根、视觉根和 GLB 子节点分别表达。引擎集合与渲染等只展示相关流程，不代表全部内部系统或精确全序。源码入口对项目类型指向声明，对框架类型指向项目内使用或注册位置；运行机制由 [当前架构](../architecture.md) 维护。

[ecs-data.json](ecs-data.json) 保存源码核对清单，[build-ecs.mjs](build-ecs.mjs) 生成四视图，[source-viewer.mjs](source-viewer.mjs) 内嵌源码快照，[source-editor.mjs](source-editor.mjs) 提供共享工作区配置与编辑器入口。分享时保留两份 HTML 的相对位置；生成后的页面无需额外加载模块。

## 在 VS Code 中打开源码

从实际检出或 worktree 的 `docs/diagrams/` 目录通过 `file://` 打开 HTML 时，页面根据自己的位置推导工作区根目录；通过“配置工作区”查看并修正“仓库根目录”，点击“保存目录”生效。“恢复默认”清除手动配置并重新使用本地页面推导。由 HTTP 服务提供、HTML 搬到其他位置，或需要指向另一份 worktree 时，先填写目标工作区的绝对根目录。路径可以包含空格、中文、`#` 和 `%`，无需手动编码。

配置按页面所在目录的完整 URL 保存在浏览器本地，主检出和各 worktree 的页面目录相互独立。`workspace` 查询参数优先于保存的配置，保存的配置优先于 `file://` 推导；浏览器禁用存储时，本页仍保留配置，并通过同目录两份 HTML 的链接携带 `workspace` 参数。分享链接前移除该参数中的个人路径。生成文件不包含个人绝对路径或临时快照目录。

VS Code 入口仅在用户点击时调用 `vscode://file/...` 协议；页面加载、选择节点及修改根目录都不会自动打开编辑器。浏览器可能要求确认外部应用，只有安装并注册了该协议的 VS Code 才能处理请求。页面无法确认浏览器是否批准或编辑器是否打开，发出请求不等于打开成功。未配置有效根目录时按提示补齐；浏览器拒绝请求或本机未安装 VS Code 时，可使用复制定位入口保留文件、行、列信息，或继续查看离线快照。仅打开源码不会启动游戏。

## 箭头锚点与走线

箭头只出现在连线末端，使用 SVG 1.1 的 `orient="auto"` 随末段方向旋转。不要使用仅为起点反向提供能力的 SVG 2 `auto-start-reverse`；部分旧静态渲染器无法识别该值，会把所有箭头头部固定画成向右。浏览器和静态预览都需检查实际方向。

连接节点的箭头必须选定上、右、下或左侧的一条边。同侧只有一条连接时，必须从该边的几何中心引出或接入；同侧有多条独立连接时，采用均匀分布的内部等分点：两条使用两个三等分点，三条使用三个四等分点，`n` 条使用 `k / (n + 1)` 的位置（`k = 1..n`），不要求全部挤在中心。计数包含该侧的入线与出线；共用干线在框外分叉或汇合时，节点边上只计一条实际连线。

起始段沿该边的外法线离开源框，末段沿目标边的内法线进入目标框；例如，从右边引出时先水平向右，从下边引出时先竖直向下。绕过其他节点的折线应先离开边界再转弯，不能沿节点边框走线或从角点出线。

末段须长于箭头头部，保留可见线段，不能让头部覆盖转角、分叉或汇合横线。多线的方向、标签与末段应可辨；分叉、汇合点不是节点锚点，不受边等分规则限制。生成器保留节点端点、所选边与等分位置供校验；最终产物仍须完成 [视觉检查](../testing/README.md#架构图视觉检查)。

## 项目 Skill 维护

架构图维护使用 [update-ecs-architecture](../../.agents/skills/update-ecs-architecture/SKILL.md)。用户调用 `$update-ecs-architecture` 或提出匹配请求时，按 Skill 核对当前工作区的清单、关系、布局、说明和源码入口。普通代码修改和 Git 提交不要求刷新图。

清单与生成器共同维护语义和布局；生成器不分析 Rust 架构，校验器也不能识别所有新系统，自动通过不能代替源码核对。生成覆盖两份 HTML、四份 SVG 及内嵌源码快照，反映整个当前工作区，不自动暂存或提交。开始前检查已有修改；无法安全合并的产物修改先记录冲突，不能直接覆盖。

图有变更时，按 [架构图视觉检查](../testing/README.md#架构图视觉检查) 查看最终 HTML 和四份 SVG；重新生成改变图形后须重查。检查只打开静态文档，临时文件放根 `tmp/`。失败原因、日志位置和未完成范围写入对应 Issue 或 PR，不能将生成或校验成功当作视觉验收完成。

### 生成与校验命令

以下命令由 Skill 在完成语义更新后使用，也可用于排查当前工作区的生成或校验问题。在仓库根执行，环境需提供 Node.js：

```text
node docs/diagrams/build-ecs.mjs
node docs/diagrams/check-ecs.mjs
node --test docs/diagrams/check-ecs.test.mjs docs/diagrams/source-editor.test.mjs docs/diagrams/source-viewer.test.mjs
```

生成器与校验器依赖 [源码查看页生成器](source-viewer.mjs)、[编辑器入口共享模块](source-editor.mjs)、[几何校验模块](diagram-geometry.mjs)及清单引用的源码。独立校验可能报告未刷新产物的源码入口或快照不符；校验仅允许 CRLF/LF 换行差异，不忽略其他源码内容变化。临时文件遵循 [临时文件管理](../development.md#临时文件管理)。VS Code URI、根目录配置与生成页交互按 [源码定位验证](../testing/README.md#架构图源码定位验证) 检查；无窗口回归不能代替本机浏览器与 VS Code 的实际协议打开验证。

图描述代码结构与调度约束，不替代游戏运行或视觉验收。
