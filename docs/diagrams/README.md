# 当前 ECS 架构图

通过本地服务打开 [交互式 HTML](generated/pages/ecs-architecture.html)，通过顶部选图控件查看按应用分组的 Schedule、项目及第三方插件对象，或通过全局搜索进入其他对象关系图。主应用中已知启动、每帧和固定更新阶段按执行阶段排列，其他调度按名称排列；列表不表示所有调度之间存在总执行顺序。默认显示主应用的 `Update`，不存在时选择首个非空调度。调度图来自 [bevy_mod_debugdump](https://github.com/jakobhellermann/bevy_mod_debugdump)，包含导出时已注册的项目、Bevy 和第三方系统；对象图来自已核对的 ECS 清单。

Schedule 始终保留右侧说明栏，未选择对象时显示当前调度的英文图例。左键单击系统卡片、集合边框或标题、可见上下文卡片，在右侧显示对象说明、源码和“打开对象关系图”；清除选择后回到图例，右栏与桌面分隔条保持可见。对象图的节点、容器和连线也使用鼠标左键选中，左键拖动继续平移画布。两类图共用选中填充、描边与蓝色外圈；调度图穿过 Graphviz 的 `g`／`a` 包装定位当前对象的真实轮廓，排除子对象、连线和标题层；集合标题指向整个集合，不单独聚焦或高亮文字。标题的遮线背景按集合绑定及原始图元 ID 关联，选中时仅同步所属容器的填充，清除时恢复原始填充及样式优先级；不另加描边或外圈。位置、连线和箭头仍由 Graphviz 或 Mermaid 自动布局。交互只附加到 HTML 中，不修改独立 SVG、DOT 或调度模型；右键、菜单键和 Shift+F10 使用浏览器菜单，不改变选择；聚焦对象后可用 Enter 或 Space 查看说明。左键单击 SVG 内部空白或 SVG 外的主画布背景清除选择；SystemSet 内部浅灰背景仍选中集合，调度依赖线、箭头和标签保持当前选择。全局对象搜索和旧聚合入口的候选项显示在顶栏浮层，同名结果通过所属实体或注册阶段区分。

构建阶段分别将 debugdump 的 DOT 用 Graphviz 渲染、将对象的 Mermaid 编译为 SVG，HTML 只保留界面和启动信息，默认 SVG、共享对象目录及逐视图数据从本地服务按需读取。Schedule 筛选在浏览器的离线 WASM Worker 中重新布局，使用方式见[调度筛选与重新布局](#调度筛选与重新布局)；对象图始终读取静态 SVG，浏览不加载 CDN。桌面使用滚轮缩放、左键拖动平移，窄屏触摸方式见[画布交互与焦点](#画布交互与焦点)。所有对象图未选择节点或清除选择时显示当前视图的[英文图例](#节点与连线视觉规范)。Plugin／PluginGroup 的菜单、搜索、所属插件、对象图及普通链接入口默认不选中卡片；只有有效的显式 `node` 链接、卡片点击或选中历史恢复显示插件说明，其他对象的默认选择不变。画布文字不参与选择，右侧详情和源码页仍可选择复制。

链接使用 `schedule` 记录调度页，`scheduleNode` 保存调度图当前选中对象，重复的 `scheduleIncludePlugin`、`scheduleExcludePlugin` 参数保存已选来源组的稳定 ID；旧系统选择与文本条件继续兼容，规则见[调度筛选](#调度筛选与重新布局)。`object` 保存精确投影或注册 ID，`node` 定位对象图内节点。选择和清除选择替换当前历史，不新增记录；导航继续携带 `workspace`、其他查询参数与片段。返回原视图和浏览器前进／后退恢复调度来源、筛选、选择、对象搜索及画布位置；无效或过期的选择清除，不按同名对象重定向。

对象图及 Schedule 在视口宽于 `900px` 时，可横向拖动画布与右侧面板之间的分隔条。面板初始宽度为 `286px`，最小 `240px`、最大 `720px`，同时为画布保留至少 `360px`；可用空间不足时相应收紧面板上限。宽度只在本次页面会话内保留，刷新后恢复初始值。视口为 `900px` 及以下时采用上下布局，不提供横向分隔条；详情按内容完整展开，随页面一起滚动，不设独立的纵向滚动区。Schedule 选择与清除仅切换右栏内容，不改变画布尺寸；调整右栏宽度保持当前比例和画布中心。

右侧节点及连线详情中的“源码位置”提供 VS Code 入口、定位路径和复制定位；完整文件快照在独立的[源码查看页](generated/pages/ecs-source.html)阅读。根目录配置、依赖定位与反馈规则见[在 VS Code 中打开源码](#在-vs-code-中打开源码)。

| 视图 | 独立 SVG | 阅读目的与实现归属 |
| --- | --- | --- |
| 调度（`schedule`） | `ecs-schedule-<key>.svg` | 看一个应用内一个 Schedule 的系统、集合及顺序依赖；范围见[调度快照](#调度快照)。 |
| 对象关系（`object`） | `ecs-object-<key>.svg` | Plugin／PluginGroup 为中心单卡；Entity 中心隐藏 Component，其余对象展示直接关系。完整规则见[对象专属图](#对象专属图)，从顶部入口、全局搜索或节点详情进入。 |

每张调度图保存同名 `.dot`，每张对象图保存同名 `.mmd`；正式调度清单与 DOT 保存在 `generated/dot/`。文件清单以 `generated/data/manifest.json` 及视图索引为准，构建清理已退出清单的产物，不生成旧功能总览、插件或基础设施系统图。对象 Mermaid 的 YAML frontmatter 使用合法 JSON 对象保存完整主题、布局及配置；锁定渲染依赖后可以从 DOT／Mermaid 重建独立 SVG。

插件入口打开相应 Plugin／PluginGroup 的对象图。顶栏保留项目与基础设施入口，`WorldInspectorPlugin` 紧跟 `EguiPlugin`，两者使用 `Egui / Inspector` 标签；其余插件可通过搜索或旧链接进入，并在“当前对象”中显示，不另列“其他插件”组。菜单入口不改变真实插件装配或调度来源筛选目录。基础设施对象的浏览归属由 [共享目录](src/architecture-infrastructure.mjs) 维护；插值纳入 Avian，第三方世界检查器纳入 Egui，浏览分组不改变实际定义来源与类型身份。对象详情中的“打开所属插件”同样进入所属插件的对象图。`main / App` 是项目应用上下文，原生窗口回调仍归项目窗口策略。

旧 `feature=overview` 进入默认调度页；旧插件或基础设施链接携带有效 `node` 时进入该对象图，无有效节点时进入对应插件对象图。没有可定位对象的旧合并入口回默认调度页。旧 `component=<投影ID>` 精确迁移到该投影，旧 `tab=data/events` 沿用相同的对象定位规则。旧聚合 ID 对应多个实际对象时列出候选项，不任意选中其中一个。兼容导航使用历史替换，保留 `workspace`、其他查询参数与片段，不增加历史记录。

对象节点通过形状和配色表达类型，名称置于首行；连线通过颜色、线型和宽度表达语义，文字仅保留具体契约或约束。图例位于右侧读图指南，独立对象 SVG 和 `.mmd` 只包含业务图形，详见 [节点与连线视觉规范](#节点与连线视觉规范)。这些规则不覆盖 Graphviz 原生调度图。

数据访问不代表调度顺序；无显式顺序的系统或 Observer 不得画成全序流水线。

全局对象与关系目录保留 `main / App` 到插件的真实装配关系、项目安装第三方插件及退出刷新等关系；Plugin／PluginGroup 单卡只改变其专属图的可见投影，其他对象图仍可展示关联插件及原关系。类型定义归属、系统注册归属和实体装配来源分别记录；调度图不使用这些清单关系重新绘制系统边。

业务根、视觉根和 GLB 子节点分别表达，图内存在某个组件不表示该组件始终存在。对象目录中的引擎集合与聚合流程只表达已核实的相关契约；日志后台线程保持 External I/O 身份。节点和连线的源码入口按[源码范围](#源码范围)核对，不把使用位置当作类型定义。运行机制由[当前架构](../architecture.md)维护。

基础清单的依赖定义由 [集中映射](catalog/architecture-source-definitions.mjs) 及 [定位模块](src/dependency-sources.mjs) 维护，包名、相对源码路径和声明符号需要对照真实源码核对。同一类型的多个实体组件复用同一声明；Kira 的项目别名 `KiraAudioPlugin` 指向真实的 `AudioPlugin`，Avian 的二维／三维同名声明按当前三维功能选择。SystemSet 卡片定位真实集合声明与配置，关联函数在完整说明中保留，不把集合当成单个系统函数；`ApplyDeferred` 的不同调度注册共用引擎定义，各自的项目注册位置仍保留。生成与校验通过 `cargo metadata --locked --offline` 获取当前机器的锁定包版本和目录，需要本机已有对应依赖源码；声明缺失、多处匹配、目录或行号不符均使检查失败。

日志拓扑将业务碰撞日志连到 `tracing producer`，再分为 `File worker → 统一会话日志文件` 与 `Console worker` 两路，不绘制业务系统绕过 worker 直接写文件的边。沿相应对象图逐步浏览生产者、后台线程和输出文件；文件节点保留 `physics-file-log` 稳定 ID 与 `External I/O` 类型，源码入口指向 `create_session_file`。退出刷新沿用已有关系，队列与 stderr 不另设终点节点。

[ecs-data.json](catalog/ecs-data.json) 保存基础对象清单，[调度对象增量](src/schedule-objects.mjs) 在保留其身份的基础上补充调度对象、绑定和关系；[调度源码目录](src/schedule-source-catalog.mjs) 按锁定依赖与完整声明身份提供用途、参数及源码证据，不从 DOT 推断读写。[build-ecs.mjs](build-ecs.mjs) 为两类视图的生成入口，校验器重新计算同一增量并检查绑定覆盖、来源哈希和对象数据。

[类型用途目录](src/schedule-type-purposes.mjs) 汇总按完整声明身份维护的中文职责，[Local 用途](catalog/schedule-type-reviewed-local.mjs) 按函数和参数槽区分局部状态。生产构建拒绝缺失用途及重复映射；新增类型需先核对锁定源码，再补入相应目录。原始文档、字段、泛型实参与本图使用场景分别保留，不能用使用统计替代类型职责。未能展开的关联类型保留精确接口身份及具体来源缺口，不借用其他同名声明。

[系统用途目录](src/schedule-system-purposes.mjs) 按真实函数声明维护简短用途与完整说明，具体泛型实例仍各自保留身份。用途须核对函数体及必要的直接 helper，说明主要输入输出、条件与清理行为；函数名翻译、参数清单或通用操作描述不能替代实际职责。正式构建拒绝缺少已核对用途的系统。

[集合用途目录](src/schedule-set-purposes.mjs) 按集合声明及枚举项维护具体职责，结合变体文档和真实配置核对。空阶段保留扩展约定，不声称存在执行成员；匿名集合按本调度的共同运行条件与成员事实单独记录，未定位的配置明确列为缺口。

[函数体操作目录](src/schedule-body-operations.mjs) 保存按完整声明核对的插入、移除、初始化、消息发布及显式数据访问。每条事实校验实际调用位置、类型依据和世界范围；需要 helper 时同时核对调用方与明确 helper 的操作位置。可变借用不等于实际修改，容器的同名方法不等于 ECS 结构操作；动态实体身份、关联类型或回调副作用未能核实时保留具体缺口。

节点的 `description` 保留完整架构说明；过长或技术细节密集时，在同一记录添加可选 `display_summary`，写一句完整的中文用途，系统说明实际做什么，资源和组件说明承载什么。图内优先使用该短句，否则复用简洁的 `description`；不机械截句或增加省略号。组件使用完整名称和实际用途，不由生成器注入所属实体前缀；实体身份由包含关系及右侧详情表达，外部提供插件的来源说明仍保留。短句无需重复读写或运行条件，右侧详情始终使用完整说明。`view.summary` 保留为视图元数据，不在画布顶部显示。

## 目录与加载

根目录保留包配置、维护说明和 build／check／serve 薄入口。实现放在 `src/`，人工维护的清单和证据放在 `catalog/`，回归与辅助模块放在 `tests/`，许可证放在 `licenses/`。正式生成文件分类如下：

```text
generated/
  pages/             架构页与源码页
  data/              索引、共享目录和完整校验模型
    views/           逐视图关系、布局与调度模型
  svg/
    object/          对象关系图
    schedule/        默认调度图
    legend/          图例样例
  dot/               原始调度 DOT 和导出清单
  mermaid/           对象图 Mermaid 原文
```

启动时读取视图索引、对象说明和必要配置；每次只加载目标视图的数据及 SVG，校验哈希与身份后接入原有画布交互。当前视图及最近访问的视图共缓存最多八张。完整构建模型、Mermaid 与 DOT 原文不随浏览器视图重复加载，图例通过独立 SVG 图片展示。资源加载与筛选共用请求编号，迟到结果不覆盖新选择；跨图加载失败保留上次成功视图并提供重试。

## 调度快照

导出模式复用正常应用的插件装配，等待插件就绪并完成 `finish`，在 `cleanup` 之前遍历主应用与可访问子应用中的 `Schedules`。每个应用／Schedule 分别生成 DOT，包含该时点实际注册的系统、集合及调度依赖；同名 Schedule 通过应用身份区分。图不根据对象清单筛选项目系统，也不拼接跨 Schedule 的总序。

快照表示导出时的注册结构，不表示系统已经执行、条件已经满足或实际运行次数，也不包含随后运行时动态新增的注册。Observer 的触发关系、组件读写和业务实体说明仍在对象图浏览，不能从调度图补推。

调度交互目录按应用、Schedule 和原始节点或集合身份绑定对象，并校验 DOT 哈希；`SystemKey` 仅标识本次快照中的注册，不作为跨导出的声明身份。既有对象复用原 ID、说明和关系图，缺失对象依据锁定源码补充。完整函数名仍需区分泛型实参、组合系统及每次注册；集合的 Debug 标题不是完整类型路径，不能仅凭短名绑定。集合成员同时来自容器层级及原始成员边，隐藏 marker 不生成对象。匿名集合保留独立身份，同步端点与 `<missing>` 约束端点按实际类别说明，不冒充普通系统。

导出成功或返回错误时，经正常应用退出路径刷新会话日志；初始化 panic 由会话 panic hook 记录，不发布成功清单。导出不进入游戏循环，不执行 Startup 或状态切换；完整插件装配仍可能初始化 GPU、音频设备并请求资产加载。Agent 可直接运行该专用导出，执行边界见[验证参考](../testing/README.md#agent-验证边界)。

## 调度筛选与重新布局

Schedule 顶栏的“包含”与“排除”分别提供可搜索的多选下拉，选项按系统完整路径的来源分组，不逐个列出系统。项目 `demo::<功能目录>::…` 对应该功能的项目 Plugin；Bevy 和第三方按外层 crate 分组，例如 `bevy_light`、`avian3d`。分组表达系统定义来源，不声称还原实际调用注册接口的具体 Plugin；项目目录保留没有当前系统的 Plugin，依赖目录随导出中的来源生成。

普通函数只看外层路径，不扫描泛型参数中的类型；`<Type as Trait>::method` 按 Trait 的外层来源归组。`Pipe(...)` 递归收集顶层阶段的来源，同一组合系统可属于多组，排除其中任一组即否决该系统。只有参数元组、没有函数来源等无法确定归属的名称保留在“未归类”。

下拉显示来源组名称、说明及当前 Schedule 的系统数。搜索只筛选选项，不成为调度筛选条件；逐项勾选、取消、全选当前搜索结果中有系统的组，以及单栏或全部清空均立即生效，不等待连续操作停顿。页面没有“应用”按钮，Enter 不提交筛选。连续选择和重排完成后，下拉保持打开，并保留搜索词、滚动位置和焦点；旧条件取消后，在当前下拉中仍可重新勾选。顶栏“清空”直接恢复完整图。切换 Schedule 保留选择，没有当前系统的组仍显示并可取消；包含栏只选此类组时为零命中，不回退为全部系统。

新链接以重复的 `scheduleIncludePlugin`、`scheduleExcludePlugin` 参数保存来源组 ID。同栏多选取并集，包含为空时显示全部系统，排除最终否决命中的系统。原系统节点与各次注册身份保持独立，集合名称不参与筛选；原始 DOT、导出哈希和源码指纹不受分组影响。

条件实际变化时立即更新链接并新增一条历史；一次批量操作只新增一次，相同条件不重复记录。筛选视角仅与实际成功显示的条件关联；返回尚未完成或失败的历史条件时重新布局并适合窗口，不套用上一次成功图的视角。

默认 SVG 和动态筛选结果插入页面后使用同一交互目录。筛选成功后，仍可见的选中对象保留详情，被过滤掉的选择清除并显示新图的图例；失败保留上一次成功画面及其图例或详情。迟到结果不得恢复旧选择。

旧链接的 `scheduleIncludeSystem`、`scheduleExcludeSystem` 按系统完整名称精确匹配，区分大小写，名称内逗号不拆分；`scheduleInclude`、`scheduleExclude` 仍按大小写敏感的普通子串匹配，逗号分隔并去掉首尾空白和空项，同栏为 OR。旧选择在下拉中显示为可取消的兼容条件。来源组、旧精确名称和旧文本的包含条件取 OR，全部为空时选中全部系统；各类排除条件共同否决命中的系统。

筛选保留命中系统、必要的祖先集合与集合 marker，以及两端仍存在的原始依赖边。不会加入未命中的系统邻居，也不会跨越已删除系统补边；过滤后的断开关系不表示原调度之间没有间接依赖。不同注册保留原节点身份，不按相同名称合并。零命中时显示空状态；清空两栏后恢复预编译的完整 SVG，不初始化 WASM。

导出中的隐式端点与缺失目标占位在默认图保留；非空筛选仅保留通过原边关联已保留系统或必要 marker 的这类上下文，不计入系统数，不补造完整名称，也不引回未命中的系统。

非空筛选使用随 HTML 内嵌的锁定 `@viz-js/viz` 与 WASM，在 Worker 中执行 Graphviz 布局；不下载第三方脚本、字体或 WASM；SVG 和视图数据由本地服务分发。图与画布使用相同的 `#F6F8FB` 背景；对象图字体及共享 `System`、`SystemSet` 和显式顺序连线样式在布局前应用，集合标题保持可读。字体或字号变更须重新检查系统文字及集合标题边界，所需留白在布局前处理。原始 DOT 与模型文字保持不变，不在输出 SVG 上修改路径或箭头。筛选只改变页面视图，不覆盖正式 DOT、清单或独立 SVG。重新布局失败时显示错误并保留当前图，可清空筛选恢复默认图；浏览器禁止 Worker 或 WASM 时，仍可浏览预编译图。

构建阶段将当前 debugdump DOT 转成浏览器使用的调度模型，保留系统身份、完整名称、有效属性、集合层级与 marker、边端点及 `lhead`／`ltail`；只支持经过校验的导出格式，不把该转换器当作任意 DOT 的无损解析器。原始 DOT 与来源哈希继续作为正式输入保存；模型和渲染样式变化无需重新运行应用，Rust 源码及锁定依赖变化仍按源码指纹要求重新导出。

Schedule 图例在构建时由锁定 Graphviz 和调度主题生成，作为独立 SVG 分发，`guideSamples.schedule` 保存其 URL；默认视图及筛选结果的 `legendKinds` 只列当前成功图中的系统、SystemSet、上下文端点、执行依赖箭头和额外集合成员线。图例与对象图例共用透明背景、无字横向样例和对齐槽位，英文类别名称仅显示在样例右侧。透明底不覆盖说明栏背景；节点按固定横向尺寸布局，原生几何边界四侧保留 `5px` 留白。上下文沿用实际蓝色卡片，集合使用实际浅灰圆角容器；无箭头成员线不作为执行依赖。隐藏布局点不列为对象，零结果保留右栏并显示图例空状态，图例不恢复应用版本、导出时间或哈希等元数据。

## 对象搜索

全局搜索覆盖两类视图中的全部对象。浮层顶部的类型复选区默认显示全部类别，多选类别取并集，“全部类型”恢复默认；类别来自对象目录，修改后立即更新结果。空查询只显示筛选和输入提示，不列出全部目录。结果显示名称、类别及所属实体或注册阶段，长名称换行；不同实体投影和系统注册保留各自入口，不按名称合并。旧聚合入口的候选项不受搜索类别过滤。

搜索仅匹配对象自身名称、已有 Rust 类型名和完整限定路径，稳定 ID 仅精确匹配；说明、访问参数、注册信息、源码内容和关联对象不参与匹配。查询忽略大小写并规范化泛型标点附近的空格；普通多词采用 AND，支持下划线及 CamelCase 分词，泛型查询保留实参区别，例如 `Time<Fixed>` 不匹配其他 `Time<T>`。`Res Time<Fixed>`、`ResMut Time<Fixed>` 和 `Res<Time<Fixed>>` 限定资源类别，与手动类别筛选取交集。

结果按名称或完整类型精确匹配、名称前缀、名称词项、名称子串、限定路径命中的顺序排列，同级按名称和稳定 ID 排序。输入框和结果支持方向键导航、Enter／Space 打开对象及 Escape 关闭浮层。搜索区域外的主键按下关闭浮层，保留搜索词和类别；重新聚焦输入框可展开。搜索词、类别、浮层展开状态及已清除高亮状态随当前历史保存，返回原视图及浏览器前进／后退恢复对应状态，异步加载完成不覆盖较新的输入、类别或关闭操作。

## 画布交互与焦点

首次打开、切换调度或插件对象、进入对象图，以及使用“返回调度图”或“返回原视图”时，自动“适合窗口”，完整显示并居中整张图。对象链接的 `node` 仍选中目标并显示详情，不自动放大。浏览器后退／前进有有效历史视角时恢复此前的缩放、平移及对象选择，否则同样“适合窗口”；主动定位对象节点、详情中的 Schedule 入口及手动缩放保持各自行为。顶栏不提供“定位分组”控件。

画布是具有无障碍名称的 `role="region"`，使用 `tabindex="-1"` 接收程序化焦点，不增加 Tab 停靠点，也不显示浏览器默认焦点框。有效的左键 `pointerdown` 使用 `focus({ preventScroll: true })` 将焦点移到画布，鼠标左键释放时仅在未拖动且位移不超过 `6px` 的情况下，按释放位置命中对象并打开详情，后续合成点击不重复激活；触摸点按不选择。节点可通过 Tab 到达，并使用 Enter 或 Space 激活；集合标题共用集合主体，不增加独立 Tab 停靠点。焦点迁移不改变滚动、平移或缩放。未选中主体显示键盘焦点，已选中主体使用真实轮廓的持续选中效果，不叠加第二层矩形框。

窄屏画布支持单指拖动平移、双指开合缩放，双指中点移动同时平移图形；轻点、拖动及多指手势结束均不选择对象，触点数量变化时不跳动。在画布外的详情、标题及页面空白处上下滑动滚动页面；详情随内容完整展开，不设独立纵向滚动区。窄屏仅高度变化时保留图形缩放和位置，避免地址栏伸缩或软键盘出现后重置阅读位置。

左键单击画布空白和“清除选择”按钮使用同一清理路径，恢复原始轮廓样式；两类图均恢复图例，右栏与桌面分隔条保持可见，插件图不再强制显示插件说明。清除保留搜索词、类别、筛选条件、缩放、画布中心和返回来源，搜索查询不应使历史快照中已清除的高亮重新出现。清除选择时，仅当 `activeElement` 位于图内，或位于即将移除的“清除选择”按钮上，才将焦点移到画布，并阻止焦点操作引起滚动；搜索框、筛选及其他控件的焦点保持不变。交互模块的 `paint` 只更新选中、关联及弱化状态，不负责焦点迁移。源码操作的成功、失败与无障碍反馈保持独立。

## 节点详情

选择对象节点后，右侧从名称和完整 `description` 开始，不显示类型 badge、`phase`、短摘要替代正文或自定义标签。其后按实际数据依次显示功能归属与“打开所属插件”、“打开对象关系图”、注册功能、定义归属、装配来源、所属实体、`Schedule`、`Read`、`Write`、`Query`、事件／消息、字段、约束与说明、完整实体组件、源码位置及清除选择；空栏目省略。Plugin／PluginGroup 不显示“公开契约”，契约数据与关系仍保留；System 对象不显示“约束与说明”，`notes` 与 `sourceGaps` 仍保留在共享数据中。各对象图共用字体、间距、可点击条目、源码控件和面板宽度。同函数其他注册提供独立对象入口，不用其字段与源码覆盖当前注册。

连线详情保留关系语义、方向、端点及具体契约；节点用途、运行条件、约束、图例和错误反馈按各自内容保留。

`Read` 与 `Write` 各自按 canonical Entity 身份归并同一实体的访问，只显示实体名称，不在这两栏列出组件。同名但身份不同的实体仍分别保留；读与写独立去重，不能把写入合并到读取。非实体访问按 `Resource`、`Local<T>`、`NonSend<T>` 分类，保持原记录中的出现顺序；原始访问清单和组件数据继续保留。查询声明及过滤条件在 `Query` 中完整显示。

`Read`、`Write` 是一级标题，下面的 `Entity`、`Resource`、`Local<T>`、`NonSend<T>` 分类相对一级缩进 `16px`，分类条目再缩进 `16px`。字体、字号、字重和配色沿用原样；详情面板收窄至 `240px` 时，分类、长名称及条目仍可换行，不横向溢出。

`Schedule` 中每条注册使用独立块，保留完整参数与注册字段；每个字段单独一行，数组逐项分行，不拼成一长串或截断。实际系统按注册分别建立对象图；仅维护清单中的测试注册不额外增加生产对象或阶段。真实快照中已注册的条件入口仍保留独立实例，例如 `spawn_lighting` 的 Startup 回退与 OnEnter 入口不能因函数相同而合并。SystemSet 与 Engine flow 的多个阶段属于原对象配置，不复制为多个系统函数。

参数 Read／Write 与“函数体操作”分开展示。后者保留目标对象、实际接口、延迟或直接生效、世界范围、条件及操作源码，可继续打开目标对象图；“可变访问”表示借用权限，不声称实际修改字段。正文消息发布与实体事件触发各自保留类别。

## 源码范围

源码区仅渲染按语义类型核对的 `sourceEntries`，按角色分组并在单个“源码位置”栏目提供明确入口。旧 `source` 保留原使用或注册语义，`definition_source` 保留依赖声明信息，二者不能被查看器无条件提升为类型定义。角色、定位与证据由[源码策略](src/architecture-source-policy.mjs)和[证据清单](src/architecture-source-evidence.mjs)维护；相同角色与定位去重，不同 Schedule 注册仍保留各自来源。下表按规范语义类别规定允许显示的入口；不同类别可具有相同的允许角色，但不能据此合并卡片身份或图例。

## 在 VS Code 中打开源码

节点及连线详情不提供离线快照跳转。项目源码按当前工作区定位；Bevy 和第三方的组件、插件优先打开本机锁定依赖中的真实类型声明，定位到记录的行，默认列为 `1`。

本地服务输出带 `workspace` 参数的预览地址，页面据此定位当前检出或 worktree；通过“配置工作区”修正“仓库根目录”，点击“保存目录”生效。“恢复默认”清除手动配置：`file://` 页面重新推导目录，HTTP 页面回到未配置状态。由 HTTP 服务提供、HTML 搬到其他位置，或需要指向另一份 worktree 时，先填写目标工作区的绝对根目录。路径可以包含空格、中文、`#` 和 `%`，无需手动编码。配置入口保留目录输入与校验反馈，页面底部不显示当前目录状态栏。

配置按页面所在目录的完整 URL 保存在浏览器本地；不同服务若复用同一地址和端口会共享该保存值，因此使用服务输出的工作区参数定位当前检出或 worktree。`workspace` 查询参数优先于保存的配置，保存的配置优先于 `file://` 推导；浏览器禁用存储时，本页仍保留配置，并通过同目录两份 HTML 的链接携带 `workspace` 参数。分享链接前移除该参数中的个人路径。项目工作区目录不写入维护清单；外部对象说明目录与源码快照为依赖定位保存生成机器的 Cargo 包绝对根目录，完整项目与依赖源码快照由独立源码页保存。移动到其他机器后仍可阅读快照，依赖的本机编辑器定位需要在目标机器重新生成；修改工作区配置只影响项目文件，不覆盖 Cargo 目录。

在[源码查看页](generated/pages/ecs-source.html)选择项目文件或依赖文件并定位、高亮指定行；VS Code 入口使用当前选择的文件和行，切换文件、点击行号后会更新定位。源码文本是生成时的快照，不会自动跟随本地文件变化，修改后的内容和行号可能与快照不同。离线使用需保留完整生成目录，并通过本地服务打开。

复制定位成功后，当前按钮显示“已复制”并在 `2` 秒后恢复，同时提供无障碍状态反馈；失败时在当前控件附近提示，仍可选择定位文本手动复制。

VS Code 入口仅在用户点击时调用 `vscode://file/...` 协议；页面加载、选择节点及修改根目录都不会自动打开编辑器。浏览器可能要求确认外部应用，只有安装并注册了该协议的 VS Code 才能处理请求。页面无法确认浏览器是否批准或编辑器是否打开，发出请求不等于打开成功。项目入口未配置有效根目录时按提示补齐；依赖入口使用生成时的 Cargo 根目录。浏览器拒绝请求或本机未安装 VS Code 时，可使用复制定位入口保留文件、行、列信息，或从本文打开独立源码页查看离线快照。两份 HTML 保留源码操作、定位与校验反馈，不重复本文的打开方式和快照时效说明。仅打开源码不会启动游戏。

## 节点与连线视觉规范

本节维护对象图的语义样式。Graphviz 调度图复用 `System` 的蓝色圆角卡片、`SystemSet` 的浅灰配色、显式顺序连线的深色及对象图字体，背景与画布同为 `#F6F8FB`；这些呈现属性在 Graphviz 布局前应用。调度图保留原系统和依赖事实，原生卡片通过稳定绑定提供选择高亮及对象说明；下述 Mermaid 轮廓与几何规则仅适用于对象图。

## 对象专属图

对象目录覆盖项目生产 ECS 声明、实体投影和系统／Observer 注册，以及项目实际使用的引擎、第三方、平台与外部输出契约。测试专用声明、普通 helper、闭包和说明卡片不独立生成对象图；说明仍可作为直接关系的上下文出现。实体关系记录通过边及详情表达，真实关系组件仍生成 Component 对象图。

每个组件投影和系统注册保留自己的稳定 ID 与独立 SVG。同类型出现在不同实体上、同函数注册到不同阶段时分别建图，不按名称、类型、函数或 canonical Entity 合并。旧 ID 仅可通过显式 `node_aliases` 指向同一声明和身份。组件的真实声明、完整泛型实参和锁定包身份用于核对源码来源；原投影归属和每条注册的 Schedule、条件、集合及源码继续保留。复合消息与泛型聚合记录按实际类型拆分，旧聚合 ID 仅维护兼容候选，不作为虚构运行时类型。

每张图保留唯一中心对象。中心 `kind` 为 `Plugin` 或 `PluginGroup` 时，只显示该中心卡片，不显示邻居或连线；全局目录、原关系与其他对象图不删减。其余对象包含全部直接关联对象及中心的全部入边和出边，并应用下面的 Entity 可见规则；不递归展开间接关系，也不加入邻居之间的边。没有可见关系时保留中心单卡。关系统一来自实体包含、系统访问及组件操作、消息与事件、实体引用与 Bevy 关系、注册、集合成员和显式调度约束。所有对象详情继续保留完整说明、所属插件、读写声明、Query、字段和源码，不用局部关系摘要替代。

仅中心对象的 `kind=Entity` 时，隐藏全部 Component 卡片及所有触及 Component 的边，再由中心与剩余边的端点重算可见节点，不保留过滤后孤立的邻居。一跳完整性按此可见投影核对；过滤后没有边时保留中心单卡。全局对象目录及关系目录仍完整，Component 自身图继续展示关联 Entity。实体右侧的完整组件清单及各投影入口保留，节点 ID 与 URL 不变。

连线分别记录包含、读取字段、可变访问或字段修改、添加、移除、存在过滤和反射访问。`With<T>`、`Without<T>`、`Has<T>`、`Option<&T>` 以及只判断 `get::<T>().is_some()` 的访问必须按实际用途区分；不能把存在检查画成字段读取，也不能从一个 `writes` 记录推断添加或移除。直接赋值、Commands 延迟插入／删除、普通 helper、World 闭包和关系 hook 的实际操作位置、条件及可见时机在连线详情核对，helper 不冒充注册系统。仅有访问声明时明确保留证据级别，未核实的操作列入待核实说明。

通过插件入口、全局对象搜索、Entity 组件清单及节点详情的“打开对象关系图”进入专属图。URL 的 `object` 使用精确投影或注册 ID，`node` 定位图内节点，`schedule` 保留调度来源上下文。卡片左键单击选中并显示详情，中心卡片不重复导航；关联对象可从详情继续进入自己的图。“返回原视图”、所属插件和浏览器前进／后退保持可用，历史返回恢复节点与画布位置。旧链接迁移规则见本文开头的兼容导航说明。

对象视图的 `aspect` 为 `object`，`objectId` 和 `centerNodeId` 标识原始对象；生成时将 `ecs-object-<key>.svg` 保存在 `generated/svg/object/`、同名 `.mmd` 保存在 `generated/mermaid/`，逐视图元数据保存在 `generated/data/views/`，通过清单按需读取。动态清单校验每个对象恰好一图、中心唯一，并按上述可见投影核对单卡或一层邻居与入出边完整；对象图不在浏览器按需编译，只通过本地服务读取已生成文件。

## Mermaid 布局与连线

对象图使用 Mermaid 流程图，以原生方向、不可见 `layoutLinks`、透明排版容器、声明顺序及有界间距组织中心与直接邻居。排版约束不进入语义关系，不增加业务身份或隐含执行顺序。每个节点只声明一次，各条关系复用原 ID；实体包含关系从 `model.entities[*].components` 取得，不按名称猜测归属。关系详情保留原端点，不将组件投影为另一张实体卡片。Mermaid 子图的方向约束及布局配置见 [官方流程图说明](https://mermaid.js.org/syntax/flowchart.html#direction-in-subgraphs) 与 [布局说明](https://mermaid.js.org/config/layouts.html)。

Graphviz 调度图使用 DOT 的原生布局，不适用本节的 Mermaid 排版与几何检查。

排版节点没有业务身份，不能成为真实关系端点或增加虚假执行依赖。相反方向的读写边、有向环、并行关系及稠密对象关系均保留；所有候选均通过同一套真实轮廓、路径、箭头和标签检查后采用。

节点尺寸、锚点和走线由锁定版本的 Mermaid 编译器产生。视图中的 `visualType` 表达节点视觉类型，`edgeSemantic` 表达连线视觉语义，`displayLabel` 表达可见文字；稳定身份和模型中的 `kind` 继续维护架构语义。模型语义校验检查节点身份、归属、关系方向与类型、覆盖和产物一致性；渲染检查另行检查编译后的真实轮廓、布局及样式，不能用某一项通过替代另一项。

对象图的业务边统一通过[走线规则](src/architecture-routing.mjs)检查最终原生 SVG。Dagre 先编译直线布局，实际路径在 `0.5` 个图内像素容差内共线且无遮挡时保留直线；其余边由 Mermaid 以 `basis` 曲线重新编译，至少一段实际轨迹偏离端点弦线超过 `0.25` 个图内像素，共线曲线命令或折线不算曲线。必要时尝试原生 `bumpX`／`bumpY`、不可见排版约束、透明容器、声明顺序及有界间距；各候选保留唯一节点、原关系、稳定 ID、方向与标签，并使用相同严格校验。曲线与全部实际轮廓的相交检查采用 `0.25` 个图内像素误差，包含多轮廓、凹形、外部虚线及分组标题，不能只检查 Component 或使用轴向包围框代替真实轮廓。不能手改路径、删边、增加虚假业务端点或放宽校验交付。

连线两端均须贴合各自端点的真实轮廓：源端检查路径起点，目标端检查原生箭头尖端；容差沿用实际线宽与 `0.25` 个图内像素的几何误差。Entity、Component 与其他节点均使用自身原生轮廓，不能用透明布局容器或包围框代替；源端断口与目标端悬空均使校验失败。默认原生内边距仍为 `flowchart.padding: 16`；仅在其它几何、列序、标题、曲线、标签及目标端检查全部通过、只剩源端接触失败时，才在同一原生候选尝试 `padding: 4`，并重新通过全部检查。

连线标签以 Mermaid 原生背景轮廓参与同一套避让检查，不得压住无关卡片、Entity 轮廓或 Schedule 标题。标签换行保留完整字符和标签语义；布局、曲线及标签策略回退均须重新通过相同严格检查。缓存同样核对可见节点文字；只有实际文字损坏时才扩大原生自动换行宽度并重新编译，保留输入中的显式换行。标签避让失败时重新编译原生布局，不手工移动 SVG 文字。

最终 HTML 和独立对象 SVG 都须按 [视觉检查](../testing/README.md#架构图视觉检查) 核对完整文字、裁切、节点唯一性、连线起止与箭头方向，以及标签、线条、方框的遮挡。箭头应清晰连接目标节点，线型和标签须与契约含义一致。密集交叉不能掩盖端点或暗示不存在的顺序，业务边须避开无关节点及容器标题。发现问题时修改 Mermaid 定义、分组、标签或配置并重新编译，保留真实节点和关系，重新检查最终曲线及箭头。

## 项目 Skill 维护

架构图维护使用 [update-ecs-architecture](../../.agents/skills/update-ecs-architecture/SKILL.md)。用户调用 `$update-ecs-architecture` 或提出匹配请求时，按 Skill 核对当前工作区的清单、关系、布局、说明和源码入口。普通代码修改和 Git 提交不要求刷新图。

调度清单与 DOT 来自真实应用导出；对象清单与生成器维护对象语义和 Mermaid 定义，源码声明、注册及访问审计不能推断全部 Rust 行为。源码定位在声明缺失或匹配多处时失败；`required_nodes` 保留插件、日志拓扑及关键契约，校验对象覆盖。生成覆盖两份 HTML、外部索引与逐视图 JSON、完整校验模型、独立图例 SVG、调度清单与 DOT／SVG、全部对象的 `.mmd`／SVG 及源码快照，按资源清单校验完整性与来源。开始前检查已有修改，不覆盖无法安全合并的产物；生成不会自动暂存或提交。

架构图变更后，按[视觉检查](../testing/README.md#架构图视觉检查)核对全部 SVG 与最终 HTML；可按该节规则复用未变化 SVG 的逐图目测记录。检查只打开静态文档，不启动游戏；临时材料放根 `tmp/`，结果、失败原因、日志位置和未完成范围记录在对应 Issue 或 PR。生成和校验不代替目测与浏览器验收。

### 生成与校验命令

Rust 源码或锁定依赖变化后，先从仓库根运行专用导出命令，Agent 可直接执行。该入口需要 `debugdump` feature；正式依赖版本以 [Cargo.toml](../../Cargo.toml) 和 [Cargo.lock](../../Cargo.lock) 为准：

```powershell
cargo run --locked --features debugdump -- --dump-schedules tmp/debugdump
```

然后在仓库根安装文档依赖、导入并构建。Node.js 最低版本为 `22.13.0`，实际依赖以 [package.json](package.json) 和 [package-lock.json](package-lock.json) 为准：

```text
npm ci --prefix docs/diagrams
node docs/diagrams/build-ecs.mjs --debugdump tmp/debugdump
node docs/diagrams/check-ecs.mjs
node --test docs/diagrams/tests/*.test.mjs
```

导出目录含 `manifest.json` 和每个 Schedule 的 DOT。清单记录应用、Schedule、稳定文件身份、依赖版本、内容哈希及源码指纹；导入拒绝缺失、冲突或过期输入。成功构建后，正式 `debugdump-manifest.json`、DOT、SVG 与 HTML 一起保留；源码指纹匹配时，省略 `--debugdump` 可直接使用正式 DOT 离线重建。没有有效导出时构建失败，不用旧系统图或测试夹具替代真实结果。

Graphviz 由锁定的 `@viz-js/viz` 生成默认 SVG，浏览器离线 Worker 使用同一版本按需重排筛选后的 Schedule，不依赖系统 Graphviz。对象 Mermaid 使用共享 `maxTextSize: 200000`，frontmatter 保留完整配置，编译使用 headless Chromium；可通过 `MERMAID_CHROMIUM_PATH` 指定路径，否则自动发现 Chrome／Edge，浏览器不运行 Mermaid。两类编译失败均须修复并重试，不能以旧 SVG 冒充新产物。仅调整查看器、筛选模型或呈现样式且源码指纹仍匹配时，直接使用正式 DOT 重建。

编译器以 `view.id` 作为 `svgId`，独立编译 `.mmd` 时须使用相同 ID，或直接复用项目编译入口。需要原生反向箭头的布局通过 frontmatter 的 `themeCSS` 引用同图真实关系生成的 `pointStart` marker，`nativeReverse` 仅记录逻辑方向。SVG 归一化只添加身份与交互元数据，不移动路径或替换箭头；独立几何检查读取实际 CSS、marker 和路径，分别检查逻辑源端与目标端。

生成器与校验器还依赖 [项目声明定位模块](src/source-locator.mjs)、[依赖声明定位模块](src/dependency-sources.mjs)、[源码查看页生成器](src/source-viewer.mjs)、[编辑器入口共享模块](src/source-editor.mjs) 及引用的项目与锁定依赖源码。独立校验可能报告未刷新产物的源码入口或快照不符；校验仅允许 CRLF/LF 换行差异，不忽略其他源码内容变化，并核对所有依赖声明入口、Cargo 包根目录和完整文件快照。临时文件遵循 [临时文件管理](../development.md#临时文件管理)。VS Code URI、根目录配置与生成页交互按 [源码定位验证](../testing/README.md#架构图源码定位验证) 检查；编译浏览器或无窗口回归不能代替最终 HTML 的浏览器视觉检查及本机 VS Code 的实际协议打开验证。

### 本地自动预览

生成与校验完成后，在仓库根运行：

```powershell
node docs/diagrams/serve.mjs
```

服务默认监听 `127.0.0.1:4173`，只读分发当前检出或 worktree 的 `generated/`，并输出带工作区参数的架构页链接。使用 `--port <端口>` 指定其他端口；端口占用时报错，不停止其他进程。源码页位于同一服务的 `pages/ecs-source.html`。旧页面及图文件地址重定向到分类后的路径，保留查询参数；源码定位与工作区配置规则见[在 VS Code 中打开源码](#在-vs-code-中打开源码)。

离线分发需要完整的生成目录和本地服务，断网后仍可切图、搜索、查看源码及重新布局筛选。直接打开主 HTML 时显示启动服务的说明。页面只请求本地 SVG 和 JSON，不访问 CDN，也不下载额外字体或 WASM。

Agent 记录实际 URL 与服务会话或进程标识，日志留在根 `tmp/ecs-architecture/` 的任务目录；验收结束后停止本次新建的服务，前台服务使用 Ctrl+C 停止。浏览器工具若拒绝目标，停止该目标的浏览器验收并记录原因，不通过更换协议、端口、服务或浏览器绕过拒绝；HTTP 检查与静态包检查分别记录。
