# 架构图验证

本指南维护架构图工具的自动验证与按需人工验收。一般测试边界见 [测试指南](../testing/README.md)。Agent 可运行带 `--dump-schedules` 的专用导出；该入口只装配插件并导出，不执行 `Startup`、游戏循环或渲染线程，可能初始化 GPU、音频设备并请求资产，不属于最小无窗口测试。此例外不允许省略导出参数或启动、操作游戏。

静态架构 HTML / SVG 的检查不属于游戏运行；临时输出放在仓库根 `tmp/`。视觉观察及实际浏览器、协议验收仍须遵守下方 [架构图视觉检查](#架构图视觉检查) 的明确启用范围。

## 按变更选择检查

| 变更类型 | 必须执行的检查 |
| --- | --- |
| 生成式 ECS 架构图清单、关系、布局、生成器或生成产物 | 按 [架构图维护](maintenance.md) 生成并校验最终产物，运行相关 Node.js 无窗口回归；SVG 视觉验证仅在用户明确要求时按 [检查范围](#架构图视觉检查) 执行，自动检查与实际观察分别记录。 |
| 架构图或源码页的 VS Code 入口 | 按 [架构图源码定位验证](#架构图源码定位验证) 执行 URI、根目录配置及生成页交互的无窗口回归；实际浏览器与 VS Code 协议验收按 [停用范围](#架构图视觉检查) 不再执行。 |
| 架构图维护执行器 | 运行 `docs/diagrams/tests/` 中相关维护回归，核对统一入口、依赖解析、工作区与复用失效边界；涉及 SVG 栅格化时使用隔离静态 fixture。未修改生成器、模型、布局或正式产物时，不要求专用导出、重建产物或图形验收；栅格化截图仍为待检，不计实际目测通过。 |

## 编译器事实与架构模型检查

架构维护的正式入口见[生成与校验命令](README.md#生成与校验命令)。共享分析工具分为无 rustc 依赖的契约层、编译器层和普通运行层；Node 只消费语义模型及原始 DOT，不重做源码扫描或新旧模型等价比较。

架构维护的执行环境见[维护指南](maintenance.md#本地执行与恢复)。

提取 fixture 覆盖同名类型、别名、重导出、关联类型、类型与常量实参、宏／`include!`、条件编译及源码定位；访问和操作 fixture 区分容器同名方法、存在过滤、可变借用与实际修改，并覆盖 helper、闭包、Commands、主／子世界和明确缺口。装配 fixture 覆盖 Bundle、BSN、required components、子实体及可确认的生命周期。测试依据源码与新契约，不使用旧扫描器产物作为答案。

运行时绑定覆盖重复注册、不同泛型、闭包、组合系统、自定义名称、匿名集合和跨应用同名 Schedule。声明、类型实例、实体模板和每次注册分别检查身份，不以名字或行号合并；编译器事实与快照来自匹配构建，缺少必要绑定不得通过。

架构事实的输入与缓存回归覆盖 `include!`、生成文件、环境、负文件探测、展开期间源码变化，以及报告缺失或损坏时的恢复；单元绑定区分包来源、host／target 和依赖配置，候选消歧不得依赖输入顺序。

身份回归覆盖相同源码跨 worktree、Cargo metadata 与纯移行的稳定性，以及精确包、Name、初始化值、引用常量和 helper 真正变化时的失效；多个 owning unit 行为冲突不能静默择先。绘图复用由[跨工作树原生回归](tests/mermaid-worktree-cache.test.mjs)覆盖共享池和仅有正式产物的冷 checkout；缺失输入指纹、损坏引用或绘图输入变化必须重编，命中继续核对原生文字、几何和路由。缓存恢复不能把旧源码位置覆盖回当前关系证据。

参数关系还须交换单元与访问顺序，核对直接 `Extract` 和间接 helper 的原生作用域、参数槽及来源成对保留；作用域冲突或间接访问不得覆盖成单一入口作用域，Local 仍表示原来的存储域。相同类型 ID 的多个原生显示路径还须覆盖逆序与重复单元，确认名称与关系不因导入顺序变化。

自动功能分组的展示入口须覆盖单插件、多插件和显式配置；交换单元与访问顺序后，选择的现有对象、插件安装关系应保持一致。

隐式析构诊断转存须核对完整多单元和源码记录、输入绑定及对象提示，其他业务缺口保持公开。文本产物须保留 UTF-8 字节并覆盖大型文本，内容相同时复用目标；替换使用暂存文件和原子重命名，重命名失败时保留原目标及完整暂存文件。大型调用图继续走独立的流式完整性校验路径。

语义模型 schema `2` 的回归确认不存在用途注释、用途哈希、待补说明或特殊退出码链路；任意非零模型退出均停止下游。Pages 打包回归须先验证完整审计输入，再检查独立静态清单、相对资源路径、哈希、额外文件、源码与 Schedule 筛选资源以及字节预算；静态包中不得保留主模型或调用图。

## 调度导出验证

导出入口和生成步骤见[生成与校验命令](README.md#生成与校验命令)。Agent 检查默认构建、可选 feature 构建及最小无窗口导出测试：

```powershell
cargo fmt --all -- --check
cargo check --locked
cargo check --locked --features debugdump
cargo test --locked --features debugdump inspector::
```

最小 fixture 检查系统、SystemSet 及依赖边进入 DOT 与结构化快照，原生键和真实类型关联一致；主应用与子应用同名 Schedule 保持独立；状态值、泛型及特殊字符标签不破坏文件身份；导出不执行 Startup 或调度系统；参数、调度初始化及文件写入失败不报告成功。子应用需覆盖真实 `Extract` 参数初始化，核实其访问原主世界，并在成功、构图失败及初始化 panic 后恢复原 `WorldId`、实体和资源；不能用空 `MainWorld` 代替真实上下文。fixture 不安装完整窗口、渲染或音频设施，也不调用真实应用导出命令。

执行专用完整导出时，确认不出现游戏窗口、不进入 Startup，主应用、物理调度及渲染子应用按实际注册进入清单；成功返回零，可返回的错误以非零退出并完成会话日志收尾，初始化 panic 记录异常且不发布清单。插件装配期间可能访问 GPU、音频设备及资产，不以没有窗口推断无设备依赖。导出成功后，再检查清单、编译器事实和运行时快照的构建关联、源码指纹、DOT 哈希、Graphviz 渲染及最终 HTML；缺少真实导出时只报告已通过的代码检查，不能用 fixture 产物交付。

## 调度筛选与页面回归

筛选语义与离线渲染边界由[调度筛选与重新布局](README.md#调度筛选与重新布局)维护。仅修改查看器、过滤模型或呈现样式时，沿用源码指纹匹配的正式 DOT 重建，不需要重新运行应用导出或执行 Rust 检查。运行相关 Node.js 回归及产物校验，正式页面的实际浏览器检查按[停用范围](#架构图视觉检查)处理。

无窗口回归覆盖来源组目录与系统完整路径的对应、项目 Plugin 与依赖 crate 分组、无法确认来源的名称，以及参数中的类型不改变函数来源。检查多组选中取并集、排除优先、选中组在当前 Schedule 无系统时为零命中；旧完整名称条件仍检查大小写、名称内逗号及同名不同注册，旧文本仍检查子串匹配、逗号 OR 和空项处理。三类包含条件取 OR，各类排除共同否决；集合名不匹配系统。核对命中系统、必要祖先集合与 marker、保留边两端及 `lhead`／`ltail`；不得加入系统邻居、复制原边或穿越删除系统补边。原生上下文端点按保留规则检查，不计入系统数，不补造名称或引回未命中系统。检查 DOT 转换前后的节点、边、有效属性和集合层级一致，特殊字符保留，未知输入格式明确失败。零命中返回空状态，空筛选恢复预编译 SVG 且不创建 Worker 或 WASM 实例。

页面回归覆盖包含／排除下拉只列来源组、各自搜索、逐项选择、全选搜索结果中当前有系统的组，以及单栏和全部清空。勾选、取消及清空立即生效，不等待连续操作停顿；搜索不改变实际筛选条件，没有应用按钮或 Enter 提交。核对重排前后下拉展开状态、搜索词、滚动位置和焦点保留，旧条件取消后在当前下拉中仍可重新勾选；异步完成只更新画布和状态，不重建当前选项。切换 Schedule 保留选择，没有本图系统的组、未知组 ID 及旧条件仍可查看和取消。检查每次有效操作只新增一条历史，批量操作一次、相同条件零次；视角只关联实际成功呈现的条件，尚未完成或失败的历史条件返回时重排并适合窗口。

核对 Worker 复用、连续快速操作的迟到结果丢弃、过滤中切页与取消、错误反馈及上次成功图保留。检查重复的 `scheduleIncludePlugin`／`scheduleExcludePlugin` 与兼容的系统、文本参数同 `schedule`、对象来源及工作区参数共同保存，刷新、返回原视图和浏览器前进／后退恢复筛选及有效视角。顶栏选图准确反映当前 Schedule、插件及搜索进入的普通对象；对象搜索使用浮层，选择后显示卡片说明。

对象搜索按[搜索规则](README.md#对象搜索)检查身份字段、类别与排序。覆盖仅在 `runtime`、说明或关联对象中出现关键词的反例，精确名称优先、大小写、普通多词 AND、下划线与 CamelCase、泛型实参及 `Res`／`ResMut` 写法；多类别取并集并与查询类别取交集，同名的不同类型实例、实体模板和重复注册不合并。验证空查询提示、类别即时生效、长名称换行，以及列表与对象图高亮使用同一命中集合。分别在两类图的 SVG 内外空白处点击，确认浮层关闭且搜索词、类别和视角保留，选择、拖动及合成点击仍正常。覆盖 Escape、键盘导航、重新聚焦、类别修改后的焦点，以及搜索期间切图、失败重试、迟到响应和历史恢复；已关闭浮层和已清除高亮不得被异步完成重新展开或恢复。旧历史缺少类别时按全部处理。

以下正式 HTTP 页面与断网目录的实际验收步骤仅在用户明确重新要求时执行，日常维护按[停用范围](#架构图视觉检查)完成相关自动回归。启用后按[本地自动预览](README.md#本地自动预览)预先启动服务，从服务输出的 `http://127.0.0.1:<端口>/pages/ecs-architecture.html` 打开最终页面并显式配置工作区。初次页面加载由本地服务提供；页面载入后按需读取本地 SVG 和 JSON，切换视图与筛选确实重新布局，不请求 CDN、额外 WASM 或字体，清空全部选择与旧条件时直接显示默认 SVG。验证 Worker 或 WASM 不可用时仍能浏览预编译结果，动态 SVG 不接受脚本、事件属性或外部引用。

离线目录验收在断网后通过同一本地服务进行，检查视图切换、搜索、源码及筛选重新布局；直接打开主 HTML 应显示服务启动说明。核对缓存最多八张视图、快速切图与取消、资源缺失或哈希不符、失败重试、深链接及历史恢复。HTTP、静态包与 Node WASM 检查分别记录，浏览器策略拒绝后的停止要求见[本地自动预览](README.md#本地自动预览)。

## 架构图源码定位验证

修改架构图或源码页的编辑器入口时，按[生成与校验命令](README.md#生成与校验命令)，在仓库根完成文档依赖安装、构建、产物校验和相关无窗口回归。

无窗口回归应检查 Windows 盘符、路径分隔符、空格、中文、`#` 与 `%` 的 URI 编码，编译器记录的行列与缺失列时的默认 `1`，非法定位和根目录输入，`file://` 推导与覆盖、HTTP 或搬移后的显式配置，以及主检出与 worktree 配置的隔离。覆盖 `workspace` 参数、目录 URL 对应的浏览器存储与推导值的优先级；存储被禁用时配置仍在本页生效，并通过同目录导航链接传播。测试生成后的页面脚本，确认对象节点／连线详情和源码页当前文件／行使用同一编辑器入口；详情不提供离线快照跳转，VS Code、定位路径和复制定位仍可用。加载、选择节点及更新配置不调用外部协议，只有用户点击才发出请求；未配置对应本机目录时点击源码入口打开配置；生成机 Cargo 根目录不能成为默认编辑器目标。独立源码页继续校验项目与依赖的完整文件快照。检查插件入口进入 Plugin／PluginGroup 单卡对象图，Schedule 在鼠标左键单击或 Enter／Space 激活对象时显示详情，选择不自动打开外部协议；检查源码入口、对象关系图往返及历史恢复。`schedule`、[调度筛选参数](README.md#调度筛选与重新布局)、`scheduleNode`、`object`、`node` 导航保留 `workspace`、`cargoRegistry`、`cargoPackages`、其他查询参数与片段；旧对象身份失效时不按短名重定向。

节点与连线源码按[源码范围](README.md#源码范围)逐类核对。`sourceEntries` 直接来自编译器模型，检查角色、去重、分组及标签；Component 以真实类型定义为入口，具体实体模板上的创建、插入、移除和销毁证据保留在对应装配或操作关系，不能混成类型始终具有的生命周期。System／Observer 保留自身定义及可确认的注册；未确认入口与动态目标保留具体 `sourceGaps`，不以类型定义替代实际调用或操作。

使用真实编译器来源格式覆盖 `\\?\C:\...`、`\\?\UNC\server\share\...` 及非法设备命名空间。生成页面测试运行真实源码编辑器，核对角色标题只出现一次、额外条目标签保留、定位控件与 URI 可用；未配置本机依赖目录时显示原因与包名、版本、包内相对定位，不退回项目根或生成机目录。区分列号缺失与 `0`、负数、非整数、`null` 等非法值，后者不得变成默认列 `1`。

Bevy 和第三方定义依据真实提供包和锁定版本定位，特别核对项目别名、宏生成声明及 Avian 二维／三维重名类型。按编译器契约检查真实声明身份、完整类型实参和每次注册，以及包名、版本、根目录、相对路径、行列、宏来源、完整快照和目录外逃。生成机 Cargo 根目录只保留为审计证据和内部来源身份，不输出到定位控件或直接生成本机 URI。覆盖不同用户名、Windows／Linux 生成路径及不同 registry 目录标识：registry 包仅使用用户配置的本机 registry 源码目录，Git、路径及未知来源仅使用显式包目录映射；包映射优先，项目根独立。验证 `cargoRegistry`／`cargoPackages` 的参数与存储优先级、禁用存储时的跨页传播、非法映射拒绝和恢复默认。不同来源的原始证据不能因隐藏生成机路径而合并；同一逻辑文件键冲突，或同包名及版本来自不同包根（即使文件名不同）时拒绝生成源码页，不能任取一个快照或让包目录映射覆盖其他来源。独立源码页的完整快照与两份页面的本机定位分别验证。

复制定位的回归覆盖节点详情和源码页：成功时仅当前按钮显示“已复制”，通过 `aria-live` 宣告结果，`2` 秒后恢复；重复点击重新计时，不影响其他复制按钮。失败时在当前控件附近提示并保留手动选择复制入口，不宣告成功。两份页面都不显示底部目录状态栏或重复的源码打开方式、快照时效说明；VS Code 入口、定位路径、复制定位、源码页行定位状态和必要错误反馈仍可用。工作区配置保留输入、保存、恢复默认及局部校验反馈，使用边界见 [源码使用说明](README.md#在-vs-code-中打开源码)。

## 架构图视觉检查

架构图变更后，按[维护指南](maintenance.md)完成真实调度输入、对象语义、Graphviz／Mermaid 编译、文字与几何、产物及无窗口交互回归检查。统一工具确认源码、配置、工具链及来源上下文匹配时复用真实 DOT，不为页面变化重复导出。对象分类调整按当前模型契约核对声明、具体类型、注册、实体模板、关系和有效证据覆盖。

HTTP 浏览器与 VS Code 协议验收不再执行，不主动请求启用，也不列为待办、未验证缺项或交付阻断条件。这些项目不进入默认发布检查，相关 URI、资源加载及交互自动回归继续执行。只有用户明确重新要求时才使用本文保留的实际验收步骤；启用 SVG 目测不自动启用这两项。已有执行记录保留，不把不需要验收改记为自动通过。

SVG 视觉验证默认关闭，包括逐图或抽样目测、用于视觉验收的栅格化截图及联系表；只有用户明确重新要求时启用。默认交付记录已跳过，不要求额外确认，不因没有目测证据阻止交付，也不称目测通过。编译、模型、文字与几何、产物及交互自动回归继续执行。临时日志和按需启用的视觉证据放根 `tmp/`，执行结果写入对应 Issue 或 PR；长期文档只保留可复用步骤，不启动或操作游戏。

用户明确启用 SVG 视觉验证时，按当前路径、图身份与完整 SHA-256 查找可追溯的实际目测通过记录，匹配时复用；只重新目测缺少有效当前记录的 SVG。未限定抽样范围时覆盖全部当前清单，限定抽样时如实记录未验范围，不称全量通过。

确定性的执行、计时与恢复使用[维护命令](README.md#生成与校验命令)；用户明确启用的 SVG 冻结、渲染和实际观察使用[视觉诊断命令](maintenance.md#可选视觉诊断)。新工具仅接受 `index-v2.json`，旧目测数据迁移尚未实现，旧记录暂不计入新工具复用；保留旧证据，不自动转换。图像生成不算实际观察，观察与自动结果分别记录。

用户明确重新要求 HTTP 验收时，预先使用[本地 HTTP 服务](README.md#本地自动预览)，并在桌面环境将窗口缩窄，检查顶栏、浮层、筛选控件和画布布局；不要求手机、移动端模拟或真实触屏的单指、双指操作。本地 HTTP 与断网目录分发的覆盖分别记录。

对象聚焦覆盖星形一跳、反向与平行边、自环、显示端点映射、清除及历史恢复；既检查页面选中的集合，也检查原生 SVG 中轮廓、文字、路径、marker 箭头、边标签背景和实体标题的有效透明度，防止邻居其他边仍清晰或嵌套内容重复淡化。短标题覆盖函数、方法、泛型、闭包及 SystemSet 结构文本，核对默认图、离线筛选与单关系图一致，详情和搜索保留原完整名称，原始 DOT 及对象身份不变。

以下清单同时列出自动回归契约与按需实际验收项目。默认只执行自动检查；SVG 实际观察、正式 HTTP 页面及 VS Code 协议验收均仅在用户明确要求对应项目时执行。

1. 按外部资源清单、视图索引和调度清单检查全部应用／Schedule 与对象图。Schedule 对应 DOT／默认 SVG，对象对应完整 Mermaid／SVG，按需加载的完整图与独立产物一致；旧总览、插件及基础设施系统 SVG／Mermaid 不残留。检查主应用默认 `Update` 及缺失时的非空调度回退，顶栏按应用分组且没有左侧导航栏，不因 Schedule 同名而合并。按[筛选回归](#调度筛选与页面回归)分别记录本地 HTTP 与断网目录分发中的内嵌 Worker 重排；完整对象 SVG 从生成目录读取，单关系图通过本地模块按需原生编译，全部视图均不依赖 CDN。
2. 检查普通 Entity 为砖红单层圆角矩形，没有开合按钮、内嵌 Component、第二张实体卡片或无业务身份的空框。编译器模型保留实体创建模板、具体组件类型和装配关系，含条件及跨插件来源；实体右栏不展示组件清单，组件类型对象仍可搜索和链接访问。包含关系来自编译器确认的装配证据，`from`／`to` 和关系 ID 精确连接对应模板与类型实例，不按旧清单投影 ID 验收。
3. 按[对象专属图](README.md#对象专属图)核对每个生产对象的完整导出入口与唯一中心。System 和 Observer 卡片按各自类别与具体 callable 折叠，跨应用、注册作用域的成员记录在 `sourceNodeIds` 中，调度图仍分别显示真实注册。不同具体泛型实例、独立声明、闭包和 Local 实例按原身份分别保留。核对成员映射、原始端点及源码汇总，改变注册输入顺序应得到相同投影。Plugin／PluginGroup 保留中心单卡，Entity 或 System 中心按可见规则过滤 Component，其他对象仅显示一跳关系。覆盖孤立单卡、长名称、外部对象、并行关系、有向环和高密度目录。
4. 从编译器模型独立推导展示关系，确认 `modify` 赋值事实保留在原模型审计并从图中剔除。逐边区分读取、可变访问、存在过滤、实体包含、创建、插入、移除、初始化、销毁和消息／事件语义。关系目录、详情和无障碍名称使用“读访问”“写访问”“读写访问”“查询筛选”，消息参数使用“消息读访问”或“消息写访问”，实际发布事实使用“发布消息”；业务连线不显示文字。检查每种已知语义都有固定非空标签，真实名称和约束按 `·` 追加，重复前缀规范化与未知语义失败均有回归。条件绑定及结构候选使用各自语义。每条可见规范关系须恰好属于一个显示组，正反方向成员完整且原始证据不丢失。参数静态重复按[分组规则](README.md#对象专属图)归组，不同应用、Schedule、World、条件和延迟状态保持独立。核对回调、helper、World 闭包和 Commands 的证据及可见时机，节点与操作源码按[源码范围](README.md#源码范围)检查。
5. 调度图由 Graphviz 自动布局，核对图与画布相同的 `#F6F8FB` 背景、共享对象字体、蓝色圆角系统卡片、浅灰集合及深色依赖线，确认样式在布局前应用。检查完整系统／集合标签、集合标题不被线条遮挡、箭头方向、裁切、初始适合窗口及缩放后的可读性；不手改路径或用对象清单补画调度关系。两类图选中共用填充、增粗与蓝环；使用真实的 `g > g > a > path` 包装及当前全部调度绑定，断言归属正确的轮廓实际改变填充、描边和滤镜，不能仅检查选择类或详情。完整鼠标事件序列覆盖释放位置、`6px` 阈值、拖动返回起点、取消、多指和合成点击，确保只激活一次且触摸点按不选择。集合标题只指向整体、不独立聚焦或高亮，嵌套系统与文字不受集合滤镜影响。核对标题遮线背景按绑定及原始集合 ID 匹配，选中时与所属容器填充一致，清除、切换与重排后恢复原值及样式优先级；背景不增加描边或滤镜。覆盖全部真实集合、重复选择、缩放、历史和筛选异步结果，不影响其他集合或子系统。未选择时 Schedule 显示当前图的 Graphviz 图例，桌面分隔条可调宽，窄屏使用上下布局；鼠标左键单击系统、集合边框与标题、可见上下文卡片后显示精确对象说明，SVG 内部空白和 SVG 外主画布背景清除节点、关系线及搜索产生的高亮，集合浅灰背景仍选中集合，调度依赖线、箭头和标签保持选择。验证重复清除、画布外／空命中及页面控件不误清，保留搜索词和历史查询且返回时不重新高亮；拖动、触摸及右键不触发清除。右键、菜单键与 Shift+F10 使用浏览器菜单。覆盖 Enter／Space、嵌套命中、清除选择、面板调整、源码及对象图往返；图例与详情切换保持画布尺寸、缩放和中心。核对 `scheduleNode` 的刷新、返回、历史恢复和过期清除，筛选成功后保留仍可见的选择、清除消失的选择，失败保留成功画面及详情，迟到请求不恢复旧选择；在筛选等待期间点击空白清除后，无论筛选成功、失败或被后续请求替代，均不得恢复已清除的对象。交互绑定应覆盖全部可见系统、集合及上下文，不能将 marker、重复短名、匿名集合或未注册目标误认普通系统；新增对象完整经过一跳关系和源码检查。导出清单与版本、源码指纹、DOT／默认 SVG／调度模型哈希一致，未知、缺失或过期输入不得通过。

7. 对象业务边按[布局规则](README.md#mermaid-布局与连线)经过[共享走线检查](src/architecture-routing.mjs)。直线须在 `0.5` 图内像素容差内共线且无遮挡；曲线至少一段偏离弦线超过 `0.25` 图内像素，不能用共线曲线命令或折线冒充。覆盖 `basis`、`bumpX`／`bumpY` 与有界原生排版候选，路径避开全部实际轮廓及分组标题。同时检查源端路径起点与目标箭头尖端贴合真实轮廓，以及相连非嵌套框的 `40` 图内单位净距和 `24` 图内单位连续可见箭杆；不得手改路径、增加虚假业务端点或放宽容差。默认 `padding: 16`，只有其他检查全部通过而仅源端接触失败时，才可同候选尝试 `padding: 4`，再跑完整检查。核对长泛型及转义字符的实际可见文字，损坏缓存必须重新编译；扩大自动换行宽度后仍执行全部检查。该组 Mermaid 几何检查不应用到 Graphviz 调度图。 双向显示边须由 Mermaid 原生 `<-->` 编译，分别检查起点与终点的 marker、方向、轮廓接触、边界和遮挡。删除、反转或错位任意一端箭头的负例均须失败，平行边与自环继续检查成员覆盖。
