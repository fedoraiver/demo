# 事故复盘

事故复盘记录值得总结的故障：哪里出了问题、故障机制、现有防护为何漏检，以及如何防止再次发生。

这类记录遵循本 README 的独立约定，不适用 `docs/AGENTS.md`。下方记录格式适用于事故报告，不适用于本 README。

## 何时撰写

缺陷逃过常规开发检查，且满足以下任一条件时撰写复盘：机制隐蔽、原因暴露系统性缺口，或再次定位的代价较高。

普通修复和个别笔误不需要复盘。任务进度和原始排查日志仍保存在 Issue 或 PR 中。

Agent Note 记录主动做出的决策及其替代方案，事故复盘记录实际发生的故障。事故促成长期设计决策时，将两者关联。

## 文件布局与记录格式

文件命名为 `YYYY-MM-DD-topic.md`，日期采用事故发生日期。链接相关 Issue 或 PR。

每份报告包含：

1. `Executive summary`（摘要）：用一个短段落概括故障、根因、漏检的防护环节及长期经验。
2. `Impact and scope`（影响与范围）：受影响的行为、发生条件及已知边界。
3. `Evidence and timeline`（证据与时间线）：用于确认事件经过的观察与事件。
4. `Root cause and missed safeguards`（根因与漏检环节）：技术机制，以及测试、工具或评审未能发现问题的原因。
5. `Prevention`（防复发措施）：修正措施、相关回归覆盖链接及剩余缺口。
6. `Related records`（关联记录）：Issue、PR、Agent Note 及相关的当前文档。

区分已确认的证据、假设与未解决的问题。证据不完整时，不编造完整的因果过程。

有助于解释事故的时间顺序和历史实现细节可记录在此。当前行为链接到对应文档，未完成的修正工作在 Issue 中跟踪。
