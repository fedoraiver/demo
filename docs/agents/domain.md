# Domain docs

本仓库采用多上下文布局，按子项目分别记录领域术语与架构决策。

## 探索前的读取规则

1. 先读取根目录 `CONTEXT-MAP.md`，按任务涉及的上下文找到对应 `CONTEXT.md`。索引应记录每个上下文的职责、源码范围和文档路径。
2. 读取相关子项目的 `CONTEXT.md`，以及根目录 `docs/adr/` 中与本次工作有关的全局架构决策。
3. 读取索引指定的子项目 ADR 目录；默认约定为 `src/<context>/docs/adr/`，具体路径以索引为准。
4. 跨子项目任务读取所有相关上下文，并明确交互边界。

文档不存在时静默继续，依据现有代码和开发指南开展工作，不将缺失视为阻塞，也不预先建议创建占位文档。
当前仓库尚无这些领域文档；本次只配置消费规则。子项目边界、术语和决策明确后，由 `grill-with-docs` 等文档产出流程按需创建并维护索引。

## 目标布局

以下路径展示约定；`<context>` 是实际子项目名称的占位符，不代表现有目录。

- `CONTEXT-MAP.md`：上下文索引。
- `docs/adr/`：全局架构决策。
- `src/<context>/CONTEXT.md`：子项目领域术语与说明。
- `src/<context>/docs/adr/`：子项目架构决策。

## 术语与决策

Issue、重构方案、诊断假设和测试名称采用相关 `CONTEXT.md` 中定义的术语，避免使用文档明确排除的同义词。
需要的概念未记录时，先核对代码和既有用语；确有缺口时留给 `grill-with-docs` 澄清，不自行发明领域定义。
方案与现有 ADR 冲突时，明确指出冲突的 ADR、原因和影响，不静默覆盖既有决策。
所有游戏逻辑仍须遵循根目录 `AGENTS.md` 中的 Bevy ECS 开发指南。
