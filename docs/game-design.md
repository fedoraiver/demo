# 小岛快递 游戏设计初稿

玩家是小岛上唯一的快递员。岛上的物流公司不断接收来自岛外的快递，由玩家将它们送到岛内居民和商户手中。随着玩家熟悉道路、认识收件人并改善运输工具，原本需要反复往返的配送工作，逐渐变成一套由自己安排的岛内配送路线。

本文记录游戏概念、玩法目标和最小可玩版范围，内容按以下状态区分：

- **已确认**：玩家是小岛上唯一的快递员，物流公司持续接收快递，玩家负责岛内分发。
- **设计建议**：下文提出的玩法规则、成长方式和开发阶段范围，尚待确认。
- **待确认**：末尾列出的方向选择，需要进一步明确。

当前可用能力见 [项目说明](../README.md)，具体任务与开发进度按 [任务跟踪约定](agents/issue-tracker.md) 记录。

## 游戏定位

建议采用第三人称小岛配送游戏的形式，以探索、路线规划和轻度经营为主要体验。玩家既要亲自搬运快递，也要决定先送哪里、什么时候回站，以及如何用收入改善工作条件。

整体氛围建议轻松、有生活感。配送应有值得思考的取舍，同时给玩家留下看风景和熟悉小岛的空间。普通订单允许延后，较强的时间压力主要来自玩家主动选择的特殊订单。

核心乐趣是：从不熟悉小岛、一次只能送少量快递的新手，成长为了解每条道路、能够高效安排配送的岛上快递员。

## 世界与玩家职责

物流公司在岛上设有一个快递站，作为收货、存放、取件和结算的中心。岛外运输由公司负责，玩家负责快递从站点到岛内收件地点的最后一段路程。

小岛建议从一块紧凑、相互连通的区域开始，包含快递站、居民住宅和少量商户。建筑外观、门牌和道路地标帮助玩家记住地址；后续可以加入山坡、海边和偏远住户，让路线选择逐渐丰富。

“唯一的快递员”是长期设定。成长优先通过玩家熟练度、运输工具和站点设施体现，岛内配送始终由玩家亲自完成。

## 核心玩法循环

**快递到站 → 查看订单 → 选择装载 → 安排路线 → 送达收件点 → 获得报酬 → 返回补货或结束工作。**

1. **到站收货**：新一批快递送到快递站，玩家查看待配送订单。
2. **查看地址**：每件快递显示收件人、目标地点、体积和配送要求。地图帮助定位，现场门牌用于确认。
3. **选择装载**：玩家根据携带能力选择本次带出的快递。同一区域的订单适合一起配送。
4. **安排路线**：玩家自行决定投递顺序，权衡路程、容量以及特殊订单的时间要求。
5. **完成交付**：到达正确收件点后，通过一次简短交互交付，并获得明确的完成反馈。
6. **再次出发**：根据剩余订单决定继续配送，或返回站点进行结算和升级。

前期重点让玩家理解地址和配送流程；具备批量携带能力后，再通过“这一趟带哪些件、先送哪一家”形成路线规划的乐趣。

## 快递与投递规则

### 快递信息

每件快递都有可区分的订单编号、收件地点和配送状态。玩家拿起快递或查看订单时，应能清楚知道它要送往哪里。世界中的包裹、订单列表和地图标记保持一致。

第一版只使用普通快递。普通件不设置短时间倒计时，让玩家先掌握搬运和投递。后续再加入限时件和大件，分别产生送达顺序与装载容量上的取舍。

| 类型 | 配送要求 | 带来的选择 | 建议阶段 |
| --- | --- | --- | --- |
| 普通件 | 送到指定收件点 | 按区域合并路线 | 最小可玩版 |
| 限时件 | 在约定时间前送达 | 优先处理还是沿原路线配送 | 路线玩法扩展 |
| 大件 | 占用更多载量 | 单独配送还是减少同趟普通件 | 运输工具扩展 |

### 配送状态

基础流程为“站内待取 → 配送中 → 已送达”。拿起包裹开始配送，放到地上不会自动算作送达；放回站点后可以重新安排。只有在对应收件点完成交付，订单才结束。

投错地点时保留包裹，并提示正确地址。每张订单只结算一次，完成后从待配送列表中移除。第一版用固定收件点完成交付，居民的活动时间和复杂对话留待后续设计。

### 持续来件与积压

建议通过跨工作日的固定批次体现“源源不断”：正常收货时每天都有新快递到站，每个工作日的到货总量有限。到货节奏应提前告知玩家，便于安排出门和回站。

未完成的普通件保留到下一天，不凭空消失。站点设置库存上限；接近上限时提示玩家，上限达到后由公司暂停后续批次到站，待库存减少再恢复。控制暂停后的到货总量，避免恢复收货时一次补齐全部积压，立即再次塞满站点。

玩家应有机会清理积压并恢复正常工作。新件数量、站内存量和剩余订单都需要清楚显示。

## 小岛探索与路线选择

地图提供收件点和待送订单标记，但投递顺序由玩家决定。道路长短、目的地之间的距离和携带容量共同影响一次配送的效率。

例如，村口有两个相邻收件点，山坡上还有一个较远收件点。运力有限时，玩家可以先集中送完村口的快递，再专门上山；后续若加入限时件，上山订单也可能成为本趟的优先目标。

探索应能改善实际配送：记住门牌减少辨认时间，发现捷径减少绕路，熟悉地形帮助选择运输工具。地图规模与内容一起增长，避免只有更远的路程、没有新的路线选择。

## 成长与长期目标

配送收入建议用于改善运输和站点条件。升级需要改变玩家的工作方式，让进步能在下一趟配送中被感受到。

- **提高载量**：从手持单件发展到背包或推车，让同一区域的订单能够一次送完。
- **改善运输工具**：后续考虑自行车等工具，扩大单趟配送范围；具体操控与地形限制另行设计。
- **整理站点**：增加货架或分区提示，减少找件和装载的重复操作。

阶段目标可以是完成第一票配送、处理一个完整批次、完成一条多收件点路线，以及稳定清空日常订单。居民和商户的简短反馈可以逐步建立玩家与小岛的联系，较长的角色故事在核心玩法成立后补充。

## 单次工作节奏与反馈

建议采用可以主动结束的工作日。当天最后一批快递到站后，不再追加新件；玩家可以继续处理剩余订单，也可以回站结束工作，将普通件结转到次日。

结算展示完成件数、收入和剩余件数。加入工作日结算后，先保证结算清楚，后续再决定是否加入准时率、路线效率等评价，具体时长、单量、价格和升级成本通过试玩调整。

配送完成时，收件点反馈、提示音、订单状态与收入变化应相互对应。界面优先显示当前包裹的地址、目标位置、载量和剩余订单，帮助玩家决定下一步。

## 最小可玩版范围

最小可玩版建议以现有搬运操作为基础，当前可用能力见 [项目说明](../README.md)。

最小可玩版建议包含：一个快递站、一块紧凑岛内区域、三个固定收件点、普通快递、单件搬运、地址提示、正确投递判定，以及配送计数和简单报酬。完成当前批次后，再接收下一批，先验证玩家是否愿意重复配送。

这一阶段的完整体验是：在站点拿到一件快递，辨认地址，搬到对应收件点，看到订单完成和报酬反馈，再返回领取下一件。放下或投错地点后仍能继续完成订单。

单件搬运阶段主要验证配送闭环。下一阶段加入有限的批量载量和地图订单标记，验证路线选择；随后再考虑工作日结算、库存控制、限时件和工具升级。

## 后续优先确定的方向

- **配送压力**：普通件保持宽松，限时件作为可选挑战；是否进一步强调经营压力待确定。
- **搬运体验**：保留亲手拿放的操作感，同时决定批量携带时如何减少反复操作。
- **经营深度**：优先做运输能力成长，站点扩建和居民故事按核心玩法的反馈决定投入。

首轮试玩重点观察玩家能否独立完成一票配送、是否容易辨认地址，以及连续配送几件后仍有哪些有趣的选择。
