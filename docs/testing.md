# 验证流程

本文维护检查方法、用户手动验收步骤和预期结果。开发规则见 [开发规范](development.md)，当前实现与暂缓边界见 [架构说明](architecture.md)，操作、设置与日志位置见 [README](../README.md)。

验收清单描述预期结果，不代表已经执行。用户反馈只确认其实际报告的场景，不能据此推断其他帧率、边界条件或完整清单均已通过；每次变更实际完成的检查、失败结果和未验证事项记录在关联 Issue 或 PR 中。持箱转向问题的用户确认与经验见[架构说明](architecture.md#持箱转向错位的经验)。

## Agent 验证边界

- 游戏只能由用户自行启动、游玩并完成窗口交互与视觉验收。Agent 禁止启动、打开或操作游戏。
- Agent 不得使用 `cargo run`、直接执行游戏程序、脚本或其他间接方式启动游戏，也不得通过 Computer Use、浏览器自动化、屏幕截图、录屏或模拟键鼠操作游戏。
- Agent 可以阅读代码、进行格式和编译检查，并运行无窗口自动化测试。测试只使用最小 `App` / `World` 和必要的临时文件，不得创建游戏窗口、启动完整游戏或依赖桌面交互。
- 用户提供会话日志后，Agent 可以读取并分析；不得以验证、调试或检查日志为由自行启动游戏。
- 需要实际游玩确认的行为，交付时必须列出用户步骤、预期结果和日志位置，明确标记未完成的运行或视觉验证。
- 架构图是静态文档，Agent 可以仅打开其 HTML / SVG 或查看渲染截图进行视觉检查；该检查不启动或操作游戏，临时输出统一放在根 `tmp/`。

## 按变更类型选择检查

| 变更类型 | 必须执行的检查 |
| --- | --- |
| 仅修改普通文档 | 检查内容是否准确、职责是否重复、相对链接与引用是否有效。不需要执行游戏或 Rust 检查。 |
| 修改架构图清单、关系、布局、生成器或生成产物 | 生成并校验最终产物；架构图有变更时必须完成下面的 [架构图视觉检查](#架构图视觉检查)，自动校验不能代替目测。检查由架构图维护 Agent / Hook 流程承担。 |
| 修改架构图自动维护工具 | 执行 [架构图自动维护](diagrams/README.md#agent-hook-自动维护) 的产物校验与 Node.js 无窗口回归；在根 `tmp/` 的独立仓库验证真实提交、amend、`-a`、普通及自定义索引的部分路径提交、索引快照和六份产物纳入同次提交，检查提交后无反向暂存差异且其他已暂存文件保留、未暂存输入与手工产物保护、生成或校验失败阻止提交且原索引和正式产物不变，以及既有 Hook 保留；不修改主仓库历史。普通代码修改不要求手动维护或刷新架构图。 |
| 修改 Rust 代码 | 阅读相关实现，运行 `cargo fmt --all -- --check` 和 `cargo check --locked`。 |
| 修改行为 | 在 Rust 检查之外，增加或运行有针对性的无窗口测试，验证相关组件变化、查询过滤、消息或调度结果；运行或视觉效果交给用户手动验收。 |
| 修改运行美术或海岛装配 | 验证 GLB 结构与清单，并执行下面的 [海岛资源与无窗口验证](#海岛资源与无窗口验证)；模型显示、动作效果和实际海岛通行由用户手动验收。 |

Rust 检查命令：

```powershell
cargo fmt --all -- --check
cargo check --locked
```

行为测试可按测试名称或模块选择；需要运行仓库全部无窗口测试时使用：

```powershell
cargo test --locked
```

测试应检验实际业务行为和边界条件。只使用最小测试环境；即使命令属于测试，也不能借此创建窗口或启动完整游戏。

Hook 回归还须确认 `post-commit` 只对齐本次已提交的六份产物，不生成或重新提交；本次 Git 进程记录缺失、记录中的候选树与 HEAD 不一致，或 `--no-verify` 跳过生成时，不修改索引。模拟提交后索引同步失败时，确认提交已存在且错误报告保留待处理记录；使用完整 Git 调用标识的 `synchronize-index` 重试能对齐产物，错误标识不修改索引。

启动日志的无窗口回归位于 [startup_log.rs](../src/startup_log.rs)：只提供 `PrototypeConfig`、`Time<Fixed>` 与 `StartupLogPlugin`，捕获四条启动日志，检查各输出一次、使用实际资源值、保留原 target，后续更新不重复输出。测试不注册窗口、渲染或完整场景，也不由日志插件初始化玩法资源。

会话日志的无窗口回归位于 [session_log.rs](../src/session_log.rs)，可用 `cargo test --locked session_log::tests` 选择。`blocked_sink_does_not_block_tracing_producer` 用门闩阻塞实际写入，确认解除阻塞前日志调用已返回；`blocked_console_does_not_block_file_or_producer` 同时确认文件输出能独立写完并刷新。不能只用不稳定的绝对耗时判断是否阻塞；解除门闩后核对记录数量、顺序与完整内容，没有丢失或截断。

`shutdown_drains_all_queued_records` 不提前刷新，直接释放守护对象后检查全部记录与顺序。`shutdown_rejects_new_records_and_drains_accepted_records` 在设备仍阻塞时关闭队列，确认已接受记录排空、后续提交返回错误。`sync_barrier_waits_for_complete_prior_records` 使用短写输出端，确认同步时此前记录已完整写入；panic 生命周期测试还须在 hook 返回后、退出刷新前就读到异常上下文。`output_failures_are_reported_and_workers_join` 覆盖写入、刷新、同步和线程 panic 失败，要求后续写入及关闭能反馈错误，线程仍被回收。正常退出先记录退出结果，再排空文件与控制台；关闭时不能仅依赖队列发送端析构。

保留时间、级别、target、结构化字段、统一过滤、文件无 ANSI 色码与历史会话不覆盖的检查。`log_plugin_preserves_explicit_rust_log_filter` 在独立子进程设置 `RUST_LOG`，确认文件与控制台同时沿用覆盖后的过滤规则。需要安装全局 `LogPlugin` 的测试在独立测试子进程运行，其余可使用局部 subscriber；均不安装窗口、渲染器或启动游戏，临时输出位于根 `tmp/`。

`failed_console_does_not_fallback_to_synchronous_stderr_or_block_panic_file_sync` 注入控制台写入故障，再通过实际日志与 panic hook 记录事件，确认健康文件在 hook 返回时已有完整上下文，stderr 没有 tracing 格式层的同步错误回退；退出与关闭仍须反馈设备错误。

设置的无窗口检查需覆盖默认上限 `60`（包括省略 `max_fps` 或文件缺失）、`59` 解析失败、`60` 与自定义 `120` 解析成功。加载内容为 `{"max_fps": 59}` 的临时 JSON 文件时，应回退到默认上限 `60`，且原文件内容不变。

## 海岛资源与无窗口验证

运行 GLB 与场景装配的检查位于 [scene.rs](../src/scene.rs) 的 `scene::tests`，使用真实的运行资源和无窗口测试环境。可在仓库根目录执行：

```powershell
cargo test --locked scene::tests
```

若制作资源中存在可访问的离线验证工具，可在先确认工具与当前资产版本匹配后，额外检查模型文件结构和几何。临时报告统一放在根 `tmp/`；制作工具的检查不能代替运行资源加载、业务实体去重、碰撞与生命周期测试。

资源与场景测试使用最小 `App` / `World`，只注册所需资源、BSN 实例、变换、动画或物理设施，不注册窗口后端、渲染器，不启动完整游戏。资源加载检查可以读取真实 GLB；装配和失败边界可以构造最小资源或层级，并实际应用延迟命令。碰撞与恢复回归需要执行 Avian 的物理调度，不能只断言已请求生成碰撞。

| 场景 | 应验证的结果 |
| --- | --- |
| 五份运行 GLB 加载 | 海岛、主角、普通纸箱、易碎纸箱和木箱句柄最终就绪；主角存在 `Idle`、`Walk`、`Carry_Idle` 命名动作；缺失资源记录路径和错误，并且不提前生成玩家。 |
| 地图实例就绪与重复通知 | 从 `WorldInstanceReady` 的实际层级读取 `source_asset`；展示主角、手持易碎纸箱与三只木箱及其子实体被移除，保留四名 NPC；多次更新或重复通知不重复生成业务实体和碰撞。 |
| 资源与碰撞准备顺序 | 玩家、控制者、相机与五件可搬物品只在资源和实际碰撞准备完成后生成；等待期间不出现自由下落的玩家或箱体，准备完成后只生成一批。 |
| 场景碰撞与模型变换 | 地形、建筑、码头、固定道具与棕榈树干的结构网格按节点变换合并为静态三角碰撞；开放商铺入口保留，海水、草和叶片无支撑碰撞。旧地面盒与测试墙不生成。 |
| 台阶与平台连接 | 原步阶只有显示网格；五组入口斜坡分别与对应实际地板边界配对，顶面接到室内地板高度，并向地板内延伸 `0.05 m`。最小物理场景中胶囊能沿斜坡通过台阶与地板衔接处到达入口平台，箱体在平台落地，不被完整建筑包围盒堵住入口。 |
| 入口驻足、行走与 CCD 性能对照 | `station_character_ccd_avoids_expensive_stationary_and_walking_sweeps` 在真实物流站室内地板分别驻足和通过实际控制力往返行走，执行实际固定物理步。采样期间不移除碰撞，人物未休眠且高度仍在平台范围；行走的实际位移跨度须超过 `1 m`。对比角色当前 `NON_LINEAR` 速度门槛配置与旧默认零门槛配置的 `SolverDiagnostics::swept_ccd` 和 `app.update()` 耗时，两种活动下当前配置的扫掠耗时均应低于旧配置的四分之一。停止移动并停稳后再检查接地与稳定高度，不要求行走每步都接地。箱体 CCD 配置不变，入口通行仍由实际海岛物理测试覆盖。 |
| 动态模型与物理根 | 一名主角与普通纸箱、易碎纸箱、三只木箱分别拥有业务根；模型通过 `ChildOf` 挂接，视觉节点没有重复刚体。木箱碰撞尺寸及轴心偏移对齐模型，固定货架纸箱没有 `Pickable`。 |
| 握持偏移与帧同步 | 纸箱和木箱各自的 `CarryGrip` 同时用于模拟目标和逐帧 `HeldTarget`；零固定步、正常固定步及多固定步下均保持同一偏移来源，释放后不再追逐目标。 |
| 主角动画选择与生命周期 | 按命名动作绑定，只处理主角视觉子树；使用真实水平速度而非输入意图选择 `Idle` / `Walk`，持物优先 `Carry_Idle`，切换有过渡，相同状态保持播放进度；等待 GLB、缺失动作和角色销毁不会留下失效绑定。 |
| 玩家与物品落水 | `Position.y < -1.5` 时玩家在模拟前解除持物并回出生点；仅释放尚未落水的持有物，物品自身落水后各自回初始姿态。清除线速度、角速度与玩家单次请求，保留持续移动轴并恢复自由碰撞。设置相机水平角不同于出生朝向并持续按 W，验证同一 `FixedUpdate` 依次执行落水恢复、当前相机朝向同步、移动模拟，恢复当步沿当前视角前进。当前帧与连续零固定步帧不跨岛插值；下一次 `FixedFirst` 在 `Reset` 与 `UpdateStart` 之间清理临时暂停，保留此前已有暂停。阈值边界和连续更新不重复恢复；持箱落水后无残留跟随关系。 |

这些检查覆盖组件、资源、层级和物理结果。模型颜色、低多边形外观、手与箱子的贴合、动画过渡及实际通行手感仍按 [海岛美术与落水验收](#海岛美术与落水验收) 由用户确认。

入口性能对照使用相同构建配置与固定 60 Hz 模拟，待资源装配完成、物体稳定后预热，再重复采样；不将加载或限帧等待计入固定步开销。只改变角色 `NON_LINEAR` 的速度门槛，当前配置为线速度 `8 m/s`、角速度 `0.1 rad/s`，旧默认配置为零门槛；避免将某台机器的绝对耗时写成通用门槛。再次诊断位置相关开销时，可扩展到沙地、入口平台和门槛，并结合 `CollisionDiagnostics::narrow_phase` 区分普通接触计算。

高速薄墙回归 `character_ccd_blocks_high_speed_velocity_and_impulses_at_different_yaws` 将推测接触距离限制为 `0.001 m`，以不同水平 yaw 验证角色受到初速度或外部冲量后仍被扫掠阻挡。先完成一次高速物理步建立引擎预测邻域，再创建薄墙并检查后续实际固定步；移除 CCD 的对照应穿过同一薄墙，避免推测接触造成假通过。不能仅在零 yaw 下验证，也不能将 `LINEAR` 当作与当前非线性算法等效的替代。无窗口结果只验证 CPU 物理开销和行为，不能证明真实渲染 FPS；具体耗时和执行结果记录在关联 Issue 或 PR 中。

## 架构图视觉检查

每次架构图有变更后，架构图维护 Agent / Hook 流程必须在报告完成前实际查看最终生成的 [交互式 HTML](diagrams/ecs-architecture.html) 与四份独立 SVG。生成、结构校验和无窗口回归只能确认各自覆盖的条件，不能代替视觉检查。只检查原图、生成器源码或路径坐标也不能视为目测通过。普通游戏代码变更且架构图未变化时，不增加人工图形检查要求。

1. 在浏览器中仅打开架构文档，依次检查 App 总览、调度与读写、实体关系、事件与 Observer 四个视图的整体布局；确认边缘节点、箭头与线条没有被画布裁切。随后查看对应独立 SVG，确认交付文件的渲染与 HTML 一致。
2. 放大每个修改区域及其相邻连接，逐条追踪箭头从源节点到目标节点：起止位置应贴合正确节点边界，箭头方向与关系含义一致，箭头头部可见；末段线条必须比箭头头部更长，并在头部之外保留清晰可见的线段，避免头部盖住转角、分叉或汇合横线。分叉与汇合连续清晰，不在中途出现多余箭头，也不能暗示源码中不存在的执行顺序。
3. 重点检查直线、折线和转角是否连续，箭头头部是否与最后一段线条相连；检查线条与节点边框、节点文字、关系标签及其他线条的重叠，避免穿过节点、遮挡文字、断线或无法辨认的交叉。整体缩放与局部放大都应保持连接可读。
4. 发现问题后修复并重新生成、校验，再检查最终 HTML 与 SVG；检查后若图形再次变化，须重新检查变化后的版本。截图、渲染副本及其他临时输出统一保存在仓库根 `tmp/` 下，不提交版本控制。
5. 在对应 Issue 或 PR 记录实际检查的产物版本、视图与修改区域、结果，以及按需保留的截图位置；长期文档只保留可复用步骤。交付说明应区分自动校验和视觉检查。工具不可用或其他阻碍导致未完成时，明确记录原因和未完成范围，不能报告架构图验收通过。

上述检查属于架构文档验证，不启动或操作游戏。游戏画面、游玩和窗口交互验收仍只能由用户完成。

## 持物与视角同步的无窗口验证

使用最小 `App` / `World`、手动时间和必要的变换传播插件，检查固定模拟与逐帧显示姿态的边界；不加载窗口、渲染器或完整游戏场景，不调用 `App::run`。

Avian 的物理步位于 `FixedPostUpdate`。涉及速度、重力、接地或碰撞的回归必须执行实际物理调度，不能只运行 `FixedUpdate` 后把施力当成已经完成运动；使用最小物理插件和几何碰撞体即可，无需窗口或渲染插件。

| 场景 | 应验证的结果 |
| --- | --- |
| 手动时间步为 `Duration::ZERO`，本帧没有固定步 | 输入更新观察角度或切换视角后，`RunFixedMainLoop` 在插值之后仍依次同步角色水平朝向、`HeldTarget`、镜头和人物 `Visibility`；物理位置和速度不被额外推进，跳跃与交互请求不被额外消费。 |
| 渲染更新按 120 Hz 推进，固定模拟为 60 Hz | 两种视角下，包括没有固定步的交替帧在内，`HeldTarget` 都与本帧角色呈现位置和朝向一致；运行 `PostUpdate` 变换传播后，木箱视觉子实体的 `GlobalTransform` 与实际箱体根的插值 `Transform` 一致；视角切换当帧的镜头与人物可见性一致。箱体可以因惯性或碰撞偏离持握目标。 |
| 固定步正常执行 | 角色朝向仍在移动施力、跳跃、交互之前同步；物理步骤按固定时间积分，逐帧同步不重复施力或执行拿放。 |
| 释放物体后继续改变视角 | `HeldBy` 与 `HeldTarget` 已移除，释放瞬间位置、线速度与角速度不被重写；后续视角变化不会施加持握力，物体仍按惯性、重力和碰撞运动，视觉子实体与实际根姿态一致。 |
| 默认模式、连续按下与长按 I | 默认第三人称；绑定 I 的动作每次按下只切换一次，松开后可再次切换。 |
| 模式角度与第一人称眼位 | 首次第一人称俯仰为 `0°`，两种模式共享水平角并分别恢复俯仰；第三人称限制 `5°..80°`，第一人称限制 `-85°..85°`；第一人称位置为角色脚底上方 `1.65`。 |
| 同帧观察与切换 | 鼠标位移先更新原模式角度，切换在 `EnhancedInputSystems::Apply` 后消费请求，目标模式恢复自己的俯仰角；首次第一人称保持平视，不受动作遍历顺序影响。 |
| 鼠标释放、失焦及无效关联 | Esc 释放鼠标后 I 仍切换且不恢复捕获；失焦、控制目标不存在或相机目标与角色关联不符时不切换，不影响其他相机。 |
| 人物与木箱可见性 | 第一人称只隐藏对应的 `CharacterVisual`，切回恢复；相机或控制者丢失、关联失效后人物恢复显示；木箱视觉和其他角色不被隐藏。 |

这些检查验证组件状态与调度结果，不能代替真实窗口中的鼠标手感、持箱虚影和视觉稳定性验收。执行结果按本次变更记录在关联 Issue 或 PR 中。

物理行为回归还应覆盖：输入后逐步加速、松键减速、斜向目标速度一致、外部冲量实际推动角色及后续主动制动、角色碰墙受阻与推动自由箱体、脚底接地及侧墙不接地、持握箱按碰撞层过滤而不充当支撑面、空中请求不重复跳跃、自由箱体落地、持箱受墙阻挡、释放保留速度、隔墙拾取过滤、同批次拾取不重复占用，以及持有者销毁或关系异常解除后清理目标、恢复碰撞并自然下落。场景装配测试检查物理组件位于业务根实体，视觉子实体不重复添加刚体或碰撞体，实际海岛碰撞顶面与出生高度一致。

### 避免测试掩盖帧间错位

持箱转向问题的旧测试采用“鼠标输入 → `app.update()` → 主动补跑固定步 → 断言”的顺序，补跑阶段修复了帧末原本错误的姿态，导致测试通过。初始化拾取关系可以先执行固定步，但输入后的本帧检查必须在 `app.update()` 返回时立即完成，不能先补跑模拟或手动调用同步系统。

新增或修改相机、转向和附件跟随时，检查以下测试条件：

- 用 `TimeUpdateStrategy::ManualDuration(Duration::ZERO)` 覆盖连续没有固定步的帧，并比较 `Time<Fixed>::elapsed()`，确认测试确实没有推进固定时间。
- 用 120 Hz 渲染更新与 60 Hz 固定模拟覆盖交替帧；每帧断言人物、持握目标和相机使用本帧角度，并统计确实存在没有固定步的帧。另保留单帧多个固定步的检查，确认鼠标位移不会重复应用，运动只按模拟时间推进。
- 安装无窗口的 `TransformPlugin`，同时检查业务根实体的 `Transform` 与本帧 `PostUpdate` 后的根和模型子实体 `GlobalTransform`，覆盖用于渲染的最终姿态。窗口组件可仅作为输入所需的 ECS 数据，不能安装窗口后端或渲染插件。
- 释放后先确认 `HeldBy`、`HeldTarget` 移除，再连续转动视角。零固定步时物理位置和速度应保持；有固定步时允许物体自然移动，需确认它不再追逐持握目标，不能只检查持有状态。
- 比较世界矩阵分解得到的旋转时，注意四元数 `q` 与 `-q` 表示同一旋转。应比较实际前向、上向向量或等价旋转，避免把符号变化误判为同步错误。

对应回归位于 [camera.rs](../src/camera.rs)：`held_target_and_visuals_use_current_frame_without_teleporting_box` 检查无固定步与 120 Hz 帧末的持握目标、箱体根与视觉姿态；`turning_updates_grip_target_and_released_box_stops_following` 检查转向后释放保留实际物理姿态及解除关系后不再跟随目标；`turning_preserves_translation_interpolation_and_camera_reads_presented_position` 以 240 Hz 连续转向检查角色平移插值、镜头同帧呈现位置与角色视觉世界变换。修改这些测试时必须保留上述立即断言的边界。

## 用户手动验收

以下命令和步骤仅供用户自行执行。请在仓库根目录启动游戏：

```powershell
cargo run --locked
```

按下面九项检查当前原型。设置文件的字段、默认值和有效范围见 [README](../README.md)。

1. 资源准备后能看到完整海岛、蓝色制服主角、前方普通纸箱和易碎纸箱，物流总站内的柜台与货架之间有三只木箱；箱体应保留相对三角布局，不穿入墙体或柜台。初始镜头跟随出生点附近的主角。站立时移动鼠标，镜头直接环绕、俯仰，人物水平朝向同步变化且位置不变；持续向上下移动鼠标，应在 `5°..80°` 的边界停止，无侧倾或距离变化。
2. 按 I 后即时进入第一人称，首次镜头水平向前，自己的模型不遮挡镜头；人物位置和水平朝向不因切换改变。移动鼠标可左右观察并向上、向下俯仰，在 `-85°..85°` 边界停止。松开再按 I 切回第三人称，恢复之前的第三人称俯仰；再次进入第一人称应恢复上次第一人称俯仰，水平朝向始终延续当前方向。长按 I 应只切换一次。
3. 在两种视角下转动镜头后按 W / S，人物沿视角的水平前后方向逐渐加速，松键后较快减速；按 A / D 时横移，后退和横移都不改变朝向。斜向输入不会提高目标速度，镜头持续跟随；上下观察不改变水平移动方向。向建筑侧墙移动应受阻，沿墙横移仍能移动；用人物推自由纸箱和木箱，箱子应因碰撞移动，人物不应穿过墙体或箱体。
4. 在两种视角下按空格时人物起跳并自然落地；持续按住或在空中再次按下不会额外起跳。贴墙时不能凭墙面重复空中起跳，跳跃中切换视角应保持人物的跳跃过程。
5. 分别靠近普通纸箱、易碎纸箱和木箱按 E，箱子应从当前位置被拉向人物身前。分别慢速、快速转向并移动、跳跃：慢速时稳定跟随，快速变化时允许箱子因惯性滞后，停下后应稳定回到手前；上下观察不改变水平持握目标。持箱向建筑侧墙前进或把箱子转向墙体，箱体应受阻并影响角色，不能穿墙。持箱按 I 切换视角，第一人称仍显示实际箱体，切回第三人称恢复人物模型；持续按住 E 不会重复拿放。
6. 松开后再次按 E，木箱从当前物理位置释放，保留速度并自然下落，不能瞬间落到面前地面。分别在站立、移动、快速转向与跳跃时释放，检查自由箱体的惯性、落地碰撞和滚动；继续转动、切换视角和移动，箱子不再追逐手前目标。走远后按 E 不会拾取，走近后可以再次拿起；把箱体留在墙另一侧，隔墙时即使处于拾取范围也不应拿起，绕到无遮挡的一侧应可拾取。
7. 按 Esc 后光标显示，移动鼠标不再转动镜头；光标位于检查器外且未编辑字段时，按 I 仍能切换视角，光标保持显示。左键点击检查器之外的游戏区域恢复鼠标控制。切换到其他窗口后应释放鼠标，失焦时按 I 不切换；回到游戏窗口后仍需左键点击恢复。恢复时镜头不应因释放期间的位移突然跳转。
8. 默认设置下用外部帧率监测工具观察帧率：性能足够时应接近 60 FPS，性能不足时可低于上限。把 `settings.json` 中的 `max_fps` 改为 `120` 后重新启动，观察上限提高，相同输入下人物加速、减速、跳跃与箱体掉落过程应保持一致，相同鼠标位移对应的旋转幅度也应相同。在 60 FPS 与 120 FPS 设置下都重复第 2～6 项，确认人物和箱体运动平滑、无固定步交替造成的抖动或虚影；物理持握的正常惯性与墙体阻挡应在两种帧率下都存在，第一人称无人物遮挡。两次会话日志中的 `simulation_hz` 应均约为 `60`，`max_fps_after` 分别为 `60` 和 `120`。另将 `max_fps` 改为 `59` 后重新启动，本次日志应记录设置无效的警告及回退上限 `60`，原设置文件仍保留 `59`；改为 `60` 后重新启动，应成功加载且不再出现该警告。完成后恢复默认设置 `60`。
9. 正常关闭窗口后查看 `logs/` 中本次 `unix-<时间戳>_<会话UUID>.log`，应包含会话开始、版本和配置、实体生成、移动输入变化、起跳着陆、拿起放下、视角切换和正常退出。四项集中启动日志 `Prototype gameplay initialized`、`Fixed simulation timestep initialized`、`Camera pose synchronization configured`、`World inspector enabled` 应各出现一次，日志 target 分别为 `demo::gameplay`、`demo::settings`、`demo::camera`、`demo::inspector`，不要求四条之间的先后顺序。`demo::camera` 的英文日志还记录相机生成、视角切换与鼠标捕获变化，便于核对释放、恢复和失焦原因；相机目标或控制者丢失时记录警告。再次启动应生成新文件，旧文件保留。

多人公平裁决、角色退出前的主动交接和多角色持有碰撞过滤仍属于 [架构说明](architecture.md) 中记录的暂缓边界。同批次拾取预留、持有者销毁或关系异常解除后的目标清理、恢复碰撞与自然下落由无窗口回归验证；完整多人流程不纳入当前原型验收范围。

### 海岛美术与落水验收

以下步骤由用户在真实游戏窗口中执行；用于确认视觉和运行表现，不代表已完成验收。

1. 环顾并走访海岛，确认地形、海水、棕榈、荒草、物流总站、Pizza 店、Music 店与两栋居民木屋正确显示。人物、建筑和箱体应保持正常比例与内置材质颜色；岛上只有一名玩家主角，NPC 为调度员、两名店员和居民，没有地图展示主角或重复木箱残留。
2. 依次走上三个商铺及两栋住宅的入口台阶，再到码头；应能沿入口上到平台并站稳，五处台阶与对应地板的衔接处不因门槛或间隙卡住人物、使人物下陷或把人物弹开，商铺前厅没有被整栋碰撞封住。尝试走向建筑侧墙、固定道具和棕榈树干，应受到对应结构阻挡；草和叶片不应阻挡行走，海水不能充当陆地地面。
3. 站立、行走、松键减速，再分别拿起和放下三种箱体。主角应在 `Idle`、`Walk`、`Carry_Idle` 间平滑切换，站立或同一动作持续播放时不能反复回到第一帧；持物移动仍采用已有的搬运站立动作。纸箱静止持握时位于双手之间，较大的木箱稍向前留出空间；碰撞或快速转向造成的正常偏离仍允许存在。四名 NPC 与柜台、货架上的固定纸箱、商店摆件本次只展示，不需要能交互或搬走。
4. 先空手从岸边走入海中，再持箱重复。人物下沉后应回到出生点，清除落水前速度和待执行的跳跃、拿放请求；松开移动键后应停稳，继续按住移动键时仍可以继续行走。持箱落水后箱子解除跟随，尚未落水的箱子从真实位置自然下落。把普通纸箱、易碎纸箱和木箱分别推落或放落海中，箱体自身落水后应回到各自初始位置，恢复自由碰撞并稳定落地，没有旧位置拖影或重复实例。
5. 在 `max_fps = 60` 与 `120` 下重复平台通行、动画切换、拿放与落水恢复，确认两种视角下行为一致。检查本次 `logs/unix-<时间戳>_<会话UUID>.log` 中的资源加载、地图与碰撞准备、动态实体生成、动画及恢复记录；失败时提供对应资源路径、错误上下文和实际操作步骤。
6. 对照入口掉帧反馈截图中的物流站平台位置与相机视角，保持相同构建模式、窗口尺寸和检查器展开状态，在修改前后分别设置 `max_fps = 60`、`120`。等待加载与初始物体运动稳定后，先驻足转动视角，再在平台上行走、转向，反复上下入口台阶并跨过门槛进入室内。用同一外部帧率工具分别记录驻足与移动的 FPS、帧时间，确认行走时不再因日志输出出现明显停顿，人物仍站稳、转向及通行正常；性能足够时接近对应上限，不要求硬件一定达到 120 FPS。正常退出后保留各次 `logs/unix-<时间戳>_<会话UUID>.log`，核对 `simulation_hz`、`max_fps_after`、会话标识与退出记录；行走中产生的移动、接地、碰撞和动画状态变化应完整保留，并将前后结果写入关联 Issue 或 PR。该项实机 FPS 验收须由用户完成，无窗口测试通过不代表已经验收。

发布包检查还应确认携带完整的 `assets/`，由用户在发布包预期的工作目录自行启动。缺失资源时不应出现悬空玩家或无碰撞的可玩地图；本次会话日志应提供路径和加载错误供排查。

### 世界检查器验收

1. 启动后应显示 `World Inspector`，展开 `Entities`、`Resources`、`Assets`，确认能找到人物、木箱和相机，以及 `PrototypeConfig`、网格和材质。展开人物组件应能查看移动意图和运动状态。
2. 按 Esc 后将光标移到面板并点击、拖动或滚动，应保持光标自由，镜头不转动。也检查从面板外快速移入并立即点击，不应重新捕获鼠标。把面板拖到窗口中央，再点击面板外恢复控制；持续移动并点击左键，人物不应因隐藏光标重叠面板而停下，面板字段也不应改变。再次按 Esc 后应立即能正常点击和编辑。
3. 在检查器字段中输入 W、E、I 或空格，人物不应移动、跳跃、拿放或切换视角；原先持续移动的输入在上下文停用后应清零。点击面板外恢复控制时镜头不跳转，单次动作需松开后重新按下才触发。
4. 检查本次 `logs/unix-<时间戳>_<会话UUID>.log`，启动时应包含 `World inspector enabled`，上下文停用与恢复应记录输入状态变化。正常退出后历史会话文件保留。
5. 展开人物和木箱根实体的物理运动组件与 `Transform`，点击面板外恢复控制，移动、持握或释放箱体时检查速度和位置变化；箱体静止后运动变化应停止。组件标题的金色边框依据 Bevy 变化标记，插值系统和持续可变访问也可能保持高亮，不能据此单独判断箱体仍在运动。

无窗口回归只检查 Egui 命中、输入上下文与组件状态，不安装窗口后端或渲染插件；面板排版、鼠标交互手感和资产预览需用户按以上步骤验收。

## 日志检查与问题反馈

会话文件命名和位置见 [README](../README.md)，日志规则与调试过滤配置见 [开发规范](development.md)。验收时先确认本次文件的会话开始时间和配置，再将日志中的实体、前后值和原因与操作步骤对应。

- 鼠标捕获及实际移动输入的离散变化，默认以 `info` 级别落盘，应能对应释放、恢复、失焦和移动输入变化。
- 启动时应有 `Camera pose synchronization configured`，字段为 `simulation_schedule="FixedUpdate"`、`grip_force_schedule="FixedUpdate"`、`physics_schedule="FixedPostUpdate"`、`presentation_schedule="RunFixedMainLoop"`、`presentation_order="interpolation_character_facing_hold_target_camera_visibility"`。这条日志说明采用的同步配置，人物与箱体运动、持握转动及视角切换是否稳定仍需按上述步骤目测确认。
- 美术与场景日志应记录所需资源的加载、失败路径、地图实例与碰撞准备状态，以及动态实体生成；结构碰撞日志用于核对实际地图范围和组成。玩法日志记录起跳、接地变化，以及 `Carryable item picked up`、`Carryable item released`；物理碰撞日志用于核对阻挡发生的实体。释放日志应能对应释放前的真实位置和速度；异常关联清理应记录原因。所有日志均写入本次 `logs/unix-<时间戳>_<会话UUID>.log`，提供问题反馈时保留该文件。
- `demo::character_animation` 应记录 `Courier animation initialized` 与 `Courier animation changed`，动作字段使用 `Idle`、`Walk`、`Carry_Idle`，切换日志包含 `animation_before`、`animation_after` 和原因；持续播放同一动作不应逐帧重复输出切换记录。绑定失败应保留缺失动作或失效关联信息。
- `demo::island_recovery` 的 `Entity recovered after entering water` 应包含恢复实体、`position_before`、`position_after` 和 `reason="water_recovery"`；持箱落水还应出现 `Held item released during water recovery`，确认解除持握。连续更新不应重复记录同一次恢复。恢复后箱体碰撞与人物输入是否正确仍需结合无窗口回归和上述用户步骤确认。
- 相机初始化应记录 `perspective="third_person"`。每次有效按 I 应出现一条 `Camera perspective changed`，包含 `perspective_before`、`perspective_after`、共享 `yaw`、两种模式的 `pitch_before`、`pitch_after` 和 `reason="toggle_perspective_action"`；长按不应连续产生切换日志，失焦时不应产生切换日志。
- 视角角度和世界移动速度属于连续数据，以 `debug` 级别每 0.5 秒最多采样一次；默认日志中没有这些采样不代表功能没有执行。需要排查时，由用户按开发规范中的过滤配置自行启动。
- 状态变化日志应包含时间、级别、模块或系统、相关实体或业务 ID、变化前后值和触发原因；错误应保留操作、相关文件路径和原始错误信息。
- 后台输出期间文件和控制台显示可能稍有延迟，不据此判断事件未发生；正常退出应记录退出、等待已入队记录写完并刷新日志，再读取本次会话文件核对完整性。异常退出时检查最后保留下来的上下文；不要为补充日志而覆盖或删除旧会话文件。

反馈问题时提供复现步骤、实际结果与预期结果、相关设置，以及对应会话日志文件。运行日志和游戏存档分别管理，日志不能作为存档使用。
