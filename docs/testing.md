# 验证流程

本文维护检查方法、用户手动验收步骤和预期结果。开发规则见 [开发规范](development.md)，当前实现与暂缓边界见 [架构说明](architecture.md)，操作、设置与日志位置见 [README](../README.md)。

验收清单描述预期结果，不代表已经执行。用户反馈只确认其实际报告的场景，不能据此推断其他帧率、边界条件或完整清单均已通过；每次变更实际完成的检查、失败结果和未验证事项记录在关联 Issue 或 PR 中。持箱转向问题的用户确认与经验见[架构说明](architecture.md#持箱转向错位的经验)。

## Agent 验证边界

- 游戏只能由用户自行启动、游玩并完成窗口交互与视觉验收。Agent 禁止启动、打开或操作游戏。
- Agent 不得使用 `cargo run`、直接执行游戏程序、脚本或其他间接方式启动游戏，也不得通过 Computer Use、浏览器自动化、屏幕截图、录屏或模拟键鼠操作游戏。
- Agent 可以阅读代码、进行格式和编译检查，并运行无窗口自动化测试。测试只使用最小 `App` / `World` 和必要的临时文件，不得创建游戏窗口、启动完整游戏或依赖桌面交互。
- 用户提供会话日志后，Agent 可以读取并分析；不得以验证、调试或检查日志为由自行启动游戏。
- 需要实际游玩确认的行为，交付时必须列出用户步骤、预期结果和日志位置，明确标记未完成的运行或视觉验证。
- 架构图是静态文档，Agent 可以仅打开其 HTML / SVG 或查看渲染截图进行视觉检查；该检查不启动或操作游戏，临时输出统一放在根 `tmp/`。

## 按变更类型选择检查

| 变更类型 | 必须执行的检查 |
| --- | --- |
| 仅修改普通文档 | 检查内容是否准确、职责是否重复、相对链接与引用是否有效。不需要执行游戏或 Rust 检查。 |
| 修改架构图清单、关系、布局、生成器或生成产物 | 生成并校验最终产物；架构图有变更时必须完成下面的 [架构图视觉检查](#架构图视觉检查)，自动校验不能代替目测。检查由架构图维护 Agent / Hook 流程承担。 |
| 修改架构图或源码页的 VS Code 入口 | 按 [架构图源码定位验证](#架构图源码定位验证) 执行 URI、根目录配置、生成页交互及 Hook 依赖的无窗口回归；在安装 VS Code 的本机浏览器实际点击核对文件与行列，记录外部协议确认及未完成事项。 |
| 修改架构图自动维护工具 | 执行 [架构图自动维护](diagrams/README.md#agent-hook-自动维护) 的产物校验与 Node.js 无窗口回归；在根 `tmp/` 的独立仓库验证真实提交、amend、`-a`、普通及自定义索引的部分路径提交、索引快照和六份产物纳入同次提交，检查提交后无反向暂存差异且其他已暂存文件保留、未暂存输入与手工产物保护、生成或校验失败阻止提交且原索引和正式产物不变，以及既有 Hook 保留；不修改主仓库历史。普通代码修改不要求手动维护或刷新架构图。 |
| 修改 Rust 代码 | 阅读相关实现，运行 `cargo fmt --all -- --check` 和 `cargo check --locked`。 |
| 修改行为 | 在 Rust 检查之外，增加或运行有针对性的无窗口测试，验证相关组件变化、查询过滤、消息或调度结果；运行或视觉效果交给用户手动验收。 |
| 修改运行美术或海岛装配 | 验证 GLB 结构与清单，并执行下面的 [海岛资源与无窗口验证](#海岛资源与无窗口验证)；模型显示、动作效果和实际海岛通行由用户手动验收。 |

Rust 检查命令：

```powershell
cargo fmt --all -- --check
cargo check --locked
```

行为测试可按测试名称或模块选择；需要运行仓库全部无窗口测试时使用：

```powershell
cargo test --locked
```

测试应检验实际业务行为和边界条件。只使用最小测试环境；即使命令属于测试，也不能借此创建窗口或启动完整游戏。

Hook 回归还须确认 `post-commit` 只对齐本次已提交的六份产物，不生成或重新提交；本次 Git 进程记录缺失、记录中的候选树与 HEAD 不一致，或 `--no-verify` 跳过生成时，不修改索引。模拟提交后索引同步失败时，确认提交已存在且错误报告保留待处理记录；使用完整 Git 调用标识的 `synchronize-index` 重试能对齐产物，错误标识不修改索引。

初始化日志的无窗口回归位于仅在测试构建注册的 [initialization_log_tests.rs](../src/initialization_log_tests.rs)，可用 `cargo test --locked initialization_log_tests` 选择。测试在最小依赖环境中安装实际 `GameplayPlugin`、`SettingsPlugin`、`CameraControlPlugin` 和 `ProjectInspectorPlugin`，执行真实 `Startup` 注册；不能只手工添加四个日志系统来代替插件注册验证。分别检查插件安装时对应记录出现、缺少该插件时对应记录不出现，以及四项组合时每条仅输出一次、后续更新不重复输出。提供自定义且最终生效的 `PrototypeConfig` 和 `Time<Fixed>`，核对实际资源值、原有 target、`info` 级别、英文消息和结构化字段；检查器还须保留 `plugin="WorldInspectorPlugin"` 与 `reason="initialization"`。测试只执行所需调度，不安装窗口后端、渲染器或完整场景，临时日志放在根 `tmp/`；日志系统不初始化或覆盖玩法配置与固定时间步。

会话日志的无窗口回归位于 [session_log.rs](../src/session_log.rs)，可用 `cargo test --locked session_log::tests` 选择。`blocked_sink_does_not_block_tracing_producer` 用门闩阻塞实际写入，确认解除阻塞前日志调用已返回；`blocked_console_does_not_block_file_or_producer` 同时确认文件输出能独立写完并刷新。不能只用不稳定的绝对耗时判断是否阻塞；解除门闩后核对记录数量、顺序与完整内容，没有丢失或截断。

`shutdown_drains_all_queued_records` 不提前刷新，直接释放守护对象后检查全部记录与顺序。`shutdown_rejects_new_records_and_drains_accepted_records` 在设备仍阻塞时关闭队列，确认已接受记录排空、后续提交返回错误。`sync_barrier_waits_for_complete_prior_records` 使用短写输出端，确认同步时此前记录已完整写入；panic 生命周期测试还须在 hook 返回后、退出刷新前就读到异常上下文。`output_failures_are_reported_and_workers_join` 覆盖写入、刷新、同步和线程 panic 失败，要求后续写入及关闭能反馈错误，线程仍被回收。正常退出先记录退出结果，再排空文件与控制台；关闭时不能仅依赖队列发送端析构。

保留时间、级别、target、结构化字段、统一过滤、文件无 ANSI 色码与历史会话不覆盖的检查。`log_plugin_preserves_explicit_rust_log_filter` 在独立子进程设置 `RUST_LOG`，确认文件与控制台同时沿用覆盖后的过滤规则。需要安装全局 `LogPlugin` 的测试在独立测试子进程运行，其余可使用局部 subscriber；均不安装窗口、渲染器或启动游戏，临时输出位于根 `tmp/`。

`failed_console_does_not_fallback_to_synchronous_stderr_or_block_panic_file_sync` 注入控制台写入故障，再通过实际日志与 panic hook 记录事件，确认健康文件在 hook 返回时已有完整上下文，stderr 没有 tracing 格式层的同步错误回退；退出与关闭仍须反馈设备错误。

设置的无窗口检查需覆盖默认上限 `60`（包括省略 `max_fps` 或文件缺失）、`59` 解析失败、`60` 与自定义 `120` 解析成功。加载内容为 `{"max_fps": 59}` 的临时 JSON 文件时，应回退到默认上限 `60`，且原文件内容不变。

## 海岛资源与无窗口验证

新道具资产的离线重建、GLB 清单与挂点矩阵检查、Blender 预览检查见 [道具美术资产](../art/items/README.md#重建与离线验证)。全库检查工具同时读取海岛与道具清单。新道具尚未注册到 `ArtAssets`，以下海岛场景测试不能证明新装备、机械或魔法效果已经接入。

运行 GLB 与场景装配的检查由 [scene.rs](../src/scene.rs) 注册为 `scene::tests`，具体测试集中在 [scene_tests.rs](../src/scene_tests.rs)，使用真实的运行资源和无窗口测试环境。可在仓库根目录执行：

```powershell
cargo test --locked scene::tests
```

若制作资源中存在可访问的离线验证工具，可在先确认工具与当前资产版本匹配后，额外检查模型文件结构和几何。临时报告统一放在根 `tmp/`；制作工具的检查不能代替运行资源加载、业务实体去重、碰撞与生命周期测试。

资源与场景测试使用最小 `App` / `World`，只注册所需资源、BSN 实例、变换、动画或物理设施，不注册窗口后端、渲染器，不启动完整游戏。资源加载检查可以读取真实 GLB；装配和失败边界可以构造最小资源或层级，并实际应用延迟命令。碰撞与恢复回归需要执行 Avian 的物理调度，不能只断言已请求生成碰撞。

| 场景 | 应验证的结果 |
| --- | --- |
| 五份运行 GLB 加载 | 海岛、主角、普通纸箱、易碎纸箱和木箱句柄最终就绪；主角存在全部 16 个命名动作、非空曲线与 `0.8 s` 时长；缺失资源记录路径和错误，并且不提前生成玩家。 |
| 地图实例就绪与重复通知 | 从 `WorldInstanceReady` 的实际层级读取 `source_asset`；展示主角、手持易碎纸箱与三只木箱及其子实体被移除，保留四名 NPC，每名只拥有一份静态身体碰撞；多次更新或重复通知不重复生成业务实体和碰撞。 |
| 资源与碰撞准备顺序 | 玩家、控制者、相机与五件可搬物品只在资源和实际碰撞准备完成后生成；等待期间不出现自由下落的玩家或箱体，准备完成后只生成一批。 |
| 菜单会话与加载阶段生命周期 | `island_sessions_wait_for_assets_survive_pause_and_clean_up_on_menu_return` 检查游戏进入后等待资产、加载中返回主菜单、连续开始及退出清理。主菜单只生成展示舞台，进入 `InGame` 建立加载相机与灯光，运行时推进装配；加载阶段暂停不生成动态实体。退出会话清理地图、碰撞、NPC、动态业务根、控制者与相机，保留全局资产强句柄。重复开始只生成一套海岛与五件物品；退出后迟到的实例通知不使新会话误用旧地图。 |
| 场景碰撞与模型变换 | 地形、建筑、码头、固定道具与棕榈树干的结构网格按节点变换合并为静态三角碰撞；开放商铺入口保留，海水、草和叶片无支撑碰撞。旧地面盒与测试墙不生成。 |
| NPC 身体碰撞与能力边界 | 从真实地图装配得到四名 `DisplayNpc`，各自的 `IslandCollider` 子实体具有静态刚体、脚底对齐的胶囊与 `World` 碰撞层；复用人物高度／半径并保留模型实例变换。执行 Avian 物理步，确认玩家、自由箱体与使用持握碰撞层的箱体不能穿过 NPC，NPC 保持原地。NPC 没有玩家输入、移动、拾取或建筑查询组件；重复通知不增加碰撞，退出会话后没有碰撞子实体残留。 |
| 台阶与平台连接 | 原步阶只有显示网格；五组入口斜坡分别与对应实际地板边界配对，顶面接到室内地板高度，并向地板内延伸 `0.05 m`。最小物理场景中胶囊能沿斜坡通过台阶与地板衔接处到达入口平台，箱体在平台落地，不被完整建筑包围盒堵住入口。 |
| 入口驻足、行走与 CCD 性能对照 | `station_character_ccd_avoids_expensive_stationary_and_walking_sweeps` 在真实物流站室内地板分别驻足和通过实际控制力往返行走，执行实际固定物理步。采样期间不移除碰撞，人物未休眠且高度仍在平台范围；行走的实际位移跨度须超过 `1 m`。对比角色当前 `NON_LINEAR` 速度门槛配置与旧默认零门槛配置的 `SolverDiagnostics::swept_ccd` 和 `app.update()` 耗时，两种活动下当前配置的扫掠耗时均应低于旧配置的四分之一。停止移动并停稳后再检查接地与稳定高度，不要求行走每步都接地。箱体 CCD 配置不变，入口通行仍由实际海岛物理测试覆盖。 |
| 动态模型与物理根 | 一名主角与普通纸箱、易碎纸箱、三只木箱分别拥有业务根；模型通过 `ChildOf` 挂接，视觉节点没有重复刚体。木箱碰撞尺寸及轴心偏移对齐模型，固定货架纸箱没有 `Pickable`。 |
| 整体持箱、握持偏移与帧同步 | 通过实际交互建立持握，安全对齐后同形碰撞代理的 `ColliderOf.body` 为人物，箱体没有独立 `RigidBody`，业务根不进入人物的销毁关系。三种箱体使用正常 `CarryGrip` 持续走向真实 NPC，代理有求解接触、NPC 不动、人物停在箱体后方且握点不被压缩。零／多固定步及 120／240 Hz 的实际帧末同时检查箱体根和视觉子体跟随人物同一呈现姿态，释放后不再追逐目标。 |
| 主角动画选择与生命周期 | 按命名动作绑定，只处理主角视觉子树；使用角色局部真实速度而非输入意图连续混合方向与持箱动作，步频随实际速度变化，斜向保持正确步幅；方向／拿放变化保留统一步相位，接地噪声不过度切换空中姿态；实际动画求值后鞋底不穿脚底平面且物理根不被改动；等待 GLB、缺失动作和角色销毁不会留下失效绑定。 |
| 玩家与物品落水 | `Position.y < -1.5` 时玩家在模拟前解除持物并回出生点；仅释放尚未落水的持有物，物品自身落水后各自回初始姿态。清除线速度、角速度与玩家单次请求，保留持续移动轴并恢复自由碰撞。设置相机水平角不同于出生朝向并持续按 W，验证同一 `FixedUpdate` 依次执行落水恢复、当前相机朝向同步、移动模拟，恢复当步沿当前视角前进。当前帧与连续零固定步帧不跨岛插值；下一次 `FixedFirst` 在 `Reset` 与 `UpdateStart` 之间清理临时暂停，保留此前已有暂停。阈值边界和连续更新不重复恢复；持箱落水后无残留跟随关系。 |

这些检查覆盖组件、资源、层级和物理结果。模型颜色、低多边形外观、手与箱子的贴合、动画过渡及实际通行手感仍按 [海岛美术与落水验收](#海岛美术与落水验收) 由用户确认；NPC 身体碰撞的视觉贴合与实际阻挡按 [NPC 碰撞验收](#npc-碰撞验收) 检查。

入口性能对照使用相同构建配置与固定 60 Hz 模拟，待资源装配完成、物体稳定后预热，再重复采样；不将加载或限帧等待计入固定步开销。只改变角色 `NON_LINEAR` 的速度门槛，当前配置为线速度 `8 m/s`、角速度 `0.1 rad/s`，旧默认配置为零门槛；避免将某台机器的绝对耗时写成通用门槛。再次诊断位置相关开销时，可扩展到沙地、入口平台和门槛，并结合 `CollisionDiagnostics::narrow_phase` 区分普通接触计算。

高速薄墙回归 `character_ccd_blocks_high_speed_velocity_and_impulses_at_different_yaws` 将推测接触距离限制为 `0.001 m`，以不同水平 yaw 验证角色受到初速度或外部冲量后仍被扫掠阻挡。先完成一次高速物理步建立引擎预测邻域，再创建薄墙并检查后续实际固定步；移除 CCD 的对照应穿过同一薄墙，避免推测接触造成假通过。不能仅在零 yaw 下验证，也不能将 `LINEAR` 当作与当前非线性算法等效的替代。无窗口结果只验证 CPU 物理开销和行为，不能证明真实渲染 FPS；具体耗时和执行结果记录在关联 Issue 或 PR 中。

## 菜单、设置与资产的无窗口验证

菜单回归只使用最小 `App / World`、必要的状态／输入插件和 BSN 实体树，不安装窗口后端或渲染器。应覆盖：

- 页面只暴露可用的 `MenuButton` 动作，导航序号连续；`Continue`、`Multiplayer` 和所有 `Coming Soon` 设置不进入焦点或业务动作列表。
- 菜单动作使用真实 Enhanced Input 绑定，长按确认／返回不重复执行；鼠标和键盘请求进入同一消费入口，页面切换后旧请求不穿透。
- 菜单音效只检查 `SoundRequest`，不打开音频设备：真实导航／移入已有按钮发出焦点音，接受操作和设置结果发出对应确认或返回音。同帧鼠标与键盘请求只反馈一次；无效动作、当前分类重选、设置边界、静止光标、按钮内移动、页面重建悬停及单按钮导航不发声。设置应用失败发出 `MenuCancel`，不冒充订单交付失败。
- 文字测量、按钮移入／移出、输入来源切换与重建后的焦点按 [文字布局与高亮回归](#文字布局与高亮回归) 检查。
- 主菜单、暂停与帮助在支持的 16:9 视口内完整显示，不装配滚动区域，滚轮与焦点导航不改变页面偏移。设置仅右侧纸色面板内的 `SETTINGS` 标题、分类项目、说明和保存提示进入滚动层级；左侧分类、底部 `Restore Defaults / Apply / Back` 与页脚固定，在这些区域触发滚轮不会改变面板或整页偏移。面板内容溢出时显示其右侧滚动条，滑块大小和位置对应可见比例及偏移；面板滚轮、区域内焦点滚入、滑块拖动和轨道点击共同更新有效偏移，无溢出时偏移归零并隐藏滚动条。滚动前后固定区域的实际位置保持且处于视口内；窗口变化或分类切换后按新布局更新，旧树销毁后不残留拖动状态，轨道与滑块不进入按钮导航列表。
- `InGame` 的进入／退出管理完整海岛及业务实体，`Running / Paused` 切换保留角色、箱体、控制者、相机与持有关系；暂停当帧清意图并停止物理步、主角动画状态更新与落水恢复，加载阶段也不推进地图装配。恢复不补发跳跃／拿放请求。从暂停设置同时通过键盘和旧按钮返回后，连续两帧仍保持暂停。
- 主菜单与暂停释放光标并停用玩法上下文；恢复运行跳过自由光标位移，F3 调试释放与检查器输入隔离仍可用。
- 设置草稿的应用、取消与恢复默认值；有效自定义值打开页面后保留，帧率预设和灵敏度步进不越界；非法值、序列化或写入失败不修改当前生效设置或原文件。
- 音量草稿的实时预览、分类切换保留、成功应用及 `Back / Esc` 回滚；`Restore Defaults` 预览全部默认值但不自动保存。保存失败保留草稿预览，已应用设置与原文件不变，随后返回恢复已应用音量。
- `audio` 节及各缺省字段补齐为 `100`；边界 `0 / 100` 可解析和保存回读；负数、超出 `100`、小数及其他非法类型拒绝，加载时整体回退默认且原文件不变。按钮和键盘／手柄调整 `5%` 不越界，鼠标滑条映射精确到 `1%`。
- Audio 页包含三项可用音量行和 `Test SFX`，仅 `Music Volume` 为占位；每行文字、箭头、滑条、百分比／`Muted` 都有有效测量，箭头与滑条进入连续导航序号。滑条拖动不中途重建实体树，不连续发送确认音，仅释放且数值改变后反馈一次。`Test SFX` 只发出拾取素材的播放请求，不触发玩法消息或持握关系。
- 在设置面板滚动至可调字段后，通过真实调整请求改变值，数值文字应原位更新；`Restore Defaults`、`Apply` 及成功／失败提示更新均不得替换 `MenuRoot`、`MenuScroll`、滚动条轨道／滑块或按钮实体。已有焦点控件身份保持，合法 `ScrollPosition` 不复位；内容变短时允许夹取至新范围，滑块位置按实际偏移同步。离开后重新进入或切换分类才生成新页面并初始化滚动与焦点。
- 设置文件保存创建与替换的完整 JSON 回读；Windows 下独占文件句柄导致替换失败时保留原文件。设置测试与保存暂存文件分别位于根 `tmp/settings-tests/`、`tmp/settings-save/`。
- 离开主菜单清理展示根及菜单相机，保留无关相机；相机构图数学检查不能替代实际渲染验收。

### 文字布局与高亮回归

本节用于防止文字零宽与悬停残留再次出现，原因和开发规则见 [UI 布局与高亮规范](development.md#ui-布局与高亮规范)。新增共享文字样式或按钮样式时，必须检查其所有使用场景，不能只验证一个示例按钮或一帧的颜色。

文字回归使用真实字体测量与 UI 布局系统，在最小无窗口 `App` 中提供字体及虚拟相机尺寸，不安装渲染器、窗口后端或完整游戏。完成资产事件与布局更新后，检查非空短标签的 `ComputedNode` 宽高大于零且 `TextLayoutInfo` 字形非空；只断言 `Text` 字符串、字体句柄或 BSN 组件存在会漏掉“有字形但节点零宽”的故障。

覆盖横排页脚键帽及说明、帧率箭头／数值／FPS、音量名称／箭头／百分比／`Muted`、`Test SFX`、设置底部三个操作、帮助编号与键位；同时在有限宽度容器中检查长正文宽度受约束并实际形成多行，防止修复短文字时破坏换行。现有入口为 [widgets.rs](../src/ui/widgets.rs) 的 `bsn_row_text_keeps_intrinsic_width_and_column_text_wraps`。该测试使用内嵌字体与虚拟视口，不覆盖项目字体加载、全部分辨率或实际渲染输出。

[screens.rs](../src/ui/screens.rs) 的固定菜单回归使用实际项目字体与页面 BSN 树，在 `960×540`、`1280×720`、`1920×1080` 虚拟视口完成真实测量和 UI 布局，结合 `ComputedNode` 与 `UiGlobalTransform` 检查 Main/Pause/Help 的按钮、页脚和全部文字实际位于视口内，非空文字尺寸与字形有效；帮助须覆盖三张卡片的完整正文、标题、编号和键位。另通过指针滚轮事件与焦点系统验证三个固定页面不滚动、Settings 仅右侧纸色面板保留滚动，并检查仅高度变化也重建页面。设置回归按实际实体祖先关系核对滚动范围，在面板滚动前后比较左侧分类、底部操作与页脚的实际位置，并验证面板内越界字段能随焦点滚入、固定按钮导航不触发滚入。测试不创建原生窗口或安装渲染器，不能代替下方用户目测。

指针回归必须触发实际 `Pointer<Scroll>` 与滚动条指针 Observer，不能仅断言 `MenuScroll`、事件类型或样式字段存在。无窗口 fixture 仍须注册 `Window` 组件类型，并安装 Bevy 原生 `ScrollbarPlugin`，使指针遍历能够按真实层级传播；从纸色面板内容与滑块触发的正向滚动结果用于证明事件确实到达处理者，从左侧分类、底部操作或外层空白触发的滚轮则须保持偏移不变。滚动条检查覆盖面板溢出与无溢出、滑块比例与两端位置、行／像素滚轮、拖动与轨道点击分页，以及分类切换、视口变化和旧实体销毁后的清理；零滚动范围或零轨道行程不能产生非有限偏移。轨道与滑块不得覆盖面板正文或底部固定操作，显隐前后面板预留宽度应保持，避免改变内容折行形成反复显隐。

设置刷新回归先记录非零滚动偏移、焦点序号以及页面根、滚动区域、轨道、滑块和字段按钮的实体身份，再发送字段调整、恢复默认和应用请求，完成真实布局后核对文字内容、身份与偏移。范围仍能容纳旧偏移时要求完全保持；内容变短时要求偏移等于旧值在新有效范围内的夹取结果。不能只断言草稿值变化而漏查页面替换或滚动复位；分类切换与离页再进入则须验证旧树销毁、新树及初始滚动状态。

高亮回归使用实际 BSN 页面与样式系统，至少覆盖以下过程，并在每次 `app.update()` 后断言背景和边框：

| 过程 | 应验证的结果 |
| --- | --- |
| 对每个可交互按钮执行 `None → Hovered → None`，并检查按下后释放／移出的状态 | 移入高亮、离开恢复；此前被点击或保存为 `MenuFocus` 的按钮也不残留高亮。 |
| 主菜单、暂停、帮助及四个设置分类逐一切换 | 所有可交互按钮遵循相同规则，特别检查当前分类和 `Apply`；帮助编号与占位项无按钮动作且不进入焦点列表。 |
| 鼠标静止在另一按钮上，通过真实 Enhanced Input 动作导航，再切换页面重建或原位更新草稿 | 只保留导航焦点，旧悬停与重建产生的新 `Hovered` 都不抢焦点；草稿更新不替换焦点按钮实体。 |
| 导航后真实移动鼠标到同一按钮内部、空白区域、窗口外，或点击按钮 | 即使 `Interaction` 没有变化也切回鼠标来源；空白与窗口外无遗留导航高亮，点击按钮只产生一次语义请求。 |

现有入口为 [navigation.rs](../src/ui/navigation.rs) 的页面悬停循环、输入来源接管与页面重建测试，以及 [screens.rs](../src/ui/screens.rs) 的导航样式测试。新增控件应纳入对应页面覆盖；模拟 `Interaction` 的测试确认状态与样式逻辑，真实命中区域、字体显示与裁切仍由用户按 [英文菜单与暂停验收](#英文菜单与暂停验收) 检查。此处列出检查要求，不表示本次已运行测试或完成游戏视觉验收。

## 架构图源码定位验证

修改架构图或源码页的编辑器入口时，在仓库根运行生成、产物校验和相关无窗口回归：

```text
node docs/diagrams/build-ecs.mjs
node docs/diagrams/check-ecs.mjs
node --test docs/diagrams/source-editor.test.mjs docs/diagrams/source-viewer.test.mjs docs/diagrams/check-ecs.test.mjs .codex/hooks/architecture-hook.test.mjs
```

无窗口回归应检查 Windows 盘符、路径分隔符、空格、中文、`#` 与 `%` 的 URI 编码，行号与默认列 `1`，非法定位和根目录输入，`file://` 推导与覆盖、HTTP 或搬移后的显式配置，以及主检出与 worktree 配置的隔离。覆盖 `workspace` 参数、目录 URL 对应的浏览器存储与推导值的优先级；存储被禁用时配置仍在本页生效，并通过同目录导航链接传播。测试生成后的页面脚本，确认架构节点和源码页当前文件／行使用同一共享入口，加载、选择节点及更新配置不调用外部协议，只有用户点击才发出请求；未配置根目录时显示提示，离线链接始终可用。检查产物不含生成机器的绝对路径或 Hook 临时快照路径，Hook 快照页面不自动推导为可编辑工作区；Hook 隔离仓库还须验证候选索引缺少 `source-editor.mjs` 时阻止提交，工作区副本不能补齐，原索引及正式产物保持不变。

安装了 VS Code 的本机还须实际点击验证。仅打开架构文档和对应源码，不启动或操作游戏；临时副本和截图统一放在仓库根 `tmp/` 下。按 [使用说明](diagrams/README.md#在-vs-code-中打开源码) 配置根目录后检查：

| 场景 | 应验证的结果 |
| --- | --- |
| 从实际检出或 worktree 的 `docs/diagrams/ecs-architecture.html` 打开一个带源码的节点 | 离线入口显示生成时的完整文件并高亮记录行；接受浏览器外部应用提示后，VS Code 打开该检出或 worktree 的实际文件，光标位于对应行、列 `1`。 |
| 在源码页切换文件并点击不同的有效行号 | 当前定位更新，VS Code 入口打开所选文件和当前行；没有有效定位时的提示或默认行规则与入口说明一致。 |
| 在根 `tmp/` 中创建路径带空格、中文、`#`、`%` 的检出副本 | 填写副本的绝对根目录后，实际打开副本中的对应文件，特殊字符不被拆成片段、查询或重复编码，行列准确。 |
| 将两份 HTML 搬到根 `tmp/` 的其他目录，或从 HTTP 服务访问 | 根目录未配置时提示配置；显式指向正确检出后能打开对应文件，修正目录后立即使用新值，不误用生成位置或 Hook 快照。 |
| 拒绝浏览器协议请求，或在未注册 VS Code 协议的环境点击 | 页面不宣称打开成功，仍可复制定位或查看离线快照；浏览器侧反馈与 VS Code 的实际打开结果分别记录。 |

浏览器脚本不能可靠判断外部协议是否获批、应用是否安装或是否成功定位。无窗口测试只验证 URI 与请求行为，实际协议处理必须查看 VS Code。执行版本、各场景结果和未完成范围记录在对应 Issue 或 PR；长期文档不保存本次验收记录。

## 架构图视觉检查

每次架构图有变更后，架构图维护 Agent / Hook 流程必须在报告完成前实际查看最终生成的 [交互式 HTML](diagrams/ecs-architecture.html) 与四份独立 SVG。生成、结构校验和无窗口回归只能确认各自覆盖的条件，不能代替视觉检查。只检查原图、生成器源码或路径坐标也不能视为目测通过。普通游戏代码变更且架构图未变化时，不增加人工图形检查要求。

1. 在浏览器中仅打开架构文档，依次检查 App 总览、调度与读写、实体关系、事件与 Observer 四个视图的整体布局；确认边缘节点、箭头与线条没有被画布裁切。随后查看对应独立 SVG，确认交付文件的渲染与 HTML 一致。
2. 放大每个修改区域及其相邻连接，逐条追踪箭头从源节点到目标节点：按 [箭头锚点与走线](diagrams/README.md#箭头锚点与走线) 核对同侧连接数量、单线中心或多线等分点，以及首、末段方向，不能从角点或沿边框引出；箭头方向与关系含义一致，箭头头部可见。末段线条必须比箭头头部更长，并在头部之外保留清晰可见的线段，避免头部盖住转角、分叉或汇合横线。分叉与汇合连续清晰，不在中途出现多余箭头，也不能暗示源码中不存在的执行顺序。修改共用走线时，还要检查同一侧的其他关系。
3. 重点检查直线、折线和转角是否连续，箭头头部是否与最后一段线条相连；检查线条与节点边框、节点文字、关系标签及其他线条的重叠，避免穿过节点、遮挡文字、断线或无法辨认的交叉。整体缩放与局部放大都应保持连接可读。
4. 发现问题后修复并重新生成、校验，再检查最终 HTML 与 SVG；检查后若图形再次变化，须重新检查变化后的版本。截图、渲染副本及其他临时输出统一保存在仓库根 `tmp/` 下，不提交版本控制。
5. 在对应 Issue 或 PR 记录实际检查的产物版本、视图与修改区域、结果，以及按需保留的截图位置；长期文档只保留可复用步骤。交付说明应区分自动校验和视觉检查。工具不可用或其他阻碍导致未完成时，明确记录原因和未完成范围，不能报告架构图验收通过。

上述检查属于架构文档验证，不启动或操作游戏。游戏画面、游玩和窗口交互验收仍只能由用户完成。

## 持物与视角同步的无窗口验证

使用最小 `App` / `World`、手动时间和必要的变换传播插件，检查固定模拟与逐帧显示姿态的边界；不加载窗口、渲染器或完整游戏场景，不调用 `App::run`。

Avian 的物理步位于 `FixedPostUpdate`。涉及速度、重力、接地或碰撞的回归必须执行实际物理调度，不能只运行 `FixedUpdate` 后把施力当成已经完成运动；使用最小物理插件和几何碰撞体即可，无需窗口或渲染插件。

| 场景 | 应验证的结果 |
| --- | --- |
| 手动时间步为 `Duration::ZERO`，本帧没有固定步 | 输入更新观察角度或切换视角后，`RunFixedMainLoop` 在插值之后仍依次同步角色水平朝向、`HeldTarget`、环绕镜头、建筑遮挡需求、建筑淡化和人物 `Visibility`；物理位置和速度不被额外推进，跳跃与交互请求不被额外消费，零时间步不推进淡化计时。 |
| 渲染更新按 120／240 Hz 推进，固定模拟为 60 Hz | 两种视角下，拾取对齐完成后，包括没有固定步的交替帧在内，实际箱体 `Transform` 和 `HeldTarget` 都与本帧人物呈现位置和朝向一致；运行 `PostUpdate` 后，视觉子实体 `GlobalTransform` 与实际箱体根一致。持握箱不再独立追赶人物；视角切换当帧的镜头与人物可见性一致。 |
| 固定步正常执行 | 角色朝向仍在移动施力、跳跃、交互之前同步；物理步骤按固定时间积分，逐帧同步不重复施力或执行拿放。 |
| 释放物体后继续改变视角 | `HeldBy`、`HeldTarget` 与挂接状态已移除，箱体恢复独立动态刚体与自由碰撞，人物质量还原；释放保留安全世界姿态与实际线速度、角速度。后续视角变化不再移动箱体，物体仍按惯性、重力和碰撞运动，视觉子实体与实际根姿态一致。 |
| 默认模式、连续按下与长按 I | 默认第三人称；绑定 I 的动作每次按下只切换一次，松开后可再次切换。 |
| 模式角度与第一人称眼位 | 首次第一人称俯仰为 `0°`，两种模式共享水平角并分别恢复俯仰；第三人称限制 `5°..80°`，第一人称限制 `-85°..85°`；第一人称位置为角色脚底上方 `1.65`。 |
| 同帧观察与切换 | 鼠标位移先更新原模式角度，切换在 `EnhancedInputSystems::Apply` 后消费请求，目标模式恢复自己的俯仰角；首次第一人称保持平视，不受动作遍历顺序影响。 |
| 鼠标释放、失焦及无效关联 | F3 调试释放光标后，未操作检查器时 I 仍切换且不恢复捕获；失焦、暂停、控制目标不存在或相机目标与角色关联不符时不切换，不影响其他相机。 |
| 人物与木箱可见性 | 第一人称只隐藏对应的 `CharacterVisual`，切回恢复；相机或控制者丢失、关联失效后人物恢复显示；木箱视觉和其他角色不被隐藏。 |

这些检查验证组件状态与调度结果，不能代替真实窗口中的鼠标手感、持箱虚影和视觉稳定性验收。执行结果按本次变更记录在关联 Issue 或 PR 中。

物理行为回归还应覆盖：输入后逐步加速、松键减速、斜向目标速度一致、外部冲量实际推动角色及后续主动制动、角色碰墙受阻与推动自由箱体、脚底接地及侧墙不接地、持握箱按碰撞层过滤而不充当支撑面、空中请求不重复跳跃、自由箱体落地、持箱受墙阻挡、释放保留速度、隔墙拾取过滤、同批次拾取不重复占用，以及持有者销毁或关系异常解除后清理目标、恢复碰撞并自然下落。场景装配测试检查物理组件位于业务根实体，视觉子实体不重复添加刚体或碰撞体，实际海岛碰撞顶面与出生高度一致。

### 避免测试掩盖帧间错位

持箱转向问题的旧测试采用“鼠标输入 → `app.update()` → 主动补跑固定步 → 断言”的顺序，补跑阶段修复了帧末原本错误的姿态，导致测试通过。初始化拾取关系可以先执行固定步，但输入后的本帧检查必须在 `app.update()` 返回时立即完成，不能先补跑模拟或手动调用同步系统。

新增或修改相机、转向和附件跟随时，检查以下测试条件：

- 用 `TimeUpdateStrategy::ManualDuration(Duration::ZERO)` 覆盖连续没有固定步的帧，并比较 `Time<Fixed>::elapsed()`，确认测试确实没有推进固定时间。
- 用 120 Hz 渲染更新与 60 Hz 固定模拟覆盖交替帧；每帧断言人物、持握目标和相机使用本帧角度，并统计确实存在没有固定步的帧。另保留单帧多个固定步的检查，确认鼠标位移不会重复应用，运动只按模拟时间推进。
- 安装无窗口的 `TransformPlugin`，同时检查业务根实体的 `Transform` 与本帧 `PostUpdate` 后的根和模型子实体 `GlobalTransform`，覆盖用于渲染的最终姿态。窗口组件可仅作为输入所需的 ECS 数据，不能安装窗口后端或渲染插件。
- 释放后先确认 `HeldBy`、`HeldTarget` 移除，再连续转动视角。零固定步时物理位置和速度应保持；有固定步时允许物体自然移动，需确认它不再追逐持握目标，不能只检查持有状态。
- 比较世界矩阵分解得到的旋转时，注意四元数 `q` 与 `-q` 表示同一旋转。应比较实际前向、上向向量或等价旋转，避免把符号变化误判为同步错误。

对应回归位于 [camera.rs](../src/camera.rs)：`held_box_aligns_safely_then_shares_current_frame_pose_and_visuals` 检查无固定步与 120 Hz 帧末的持握目标、箱体根与视觉姿态；`turning_updates_grip_target_and_released_box_stops_following` 检查转向后释放保留实际物理姿态及解除关系后不再跟随目标；`turning_preserves_translation_interpolation_and_camera_reads_presented_position` 以 240 Hz 连续转向检查角色平移插值、镜头同帧呈现位置与角色视觉世界变换。修改这些测试时必须保留上述立即断言的边界。

整体持箱的补充回归位于 [carry_frame_tests.rs](../src/carry_frame_tests.rs) 和 [carry_rotation.rs](../src/carry_rotation.rs)。真实 E 绑定完成拾取与短暂对齐后，再发出待验证鼠标输入；每次 `app.update()` 返回立即检查本帧箱体与视觉姿态，不补跑固定步。转向测试必须覆盖起点、终点都空但中途扫过薄墙的完整弧线、正反半圈与整圈、角度 wrap、偏心复合箱体、贴墙转入与转离，以及地面已有接触的水平转动。新引入的转向阻挡应在同帧自动释放于转动前安全位置，镜头完成请求角度；直走受阻仍保持持握。拿放与异常清理还须检查质量还原、独立实体身份、代理清理、人物／箱体销毁和落水后的恢复；双方同时落水须覆盖两种实体遍历顺序，箱子始终使用自己的出生点。

空旷转向还须使用三角网格地面，不能只测方盒地面。`open_mesh_ground_turn_keeps_actual_held_parcel_in_zero_step_frame` 检查离地箱体经真实鼠标动作转动后，在零固定步帧末仍被持有；几何回归同时覆盖凸箱和偏心复合木箱。`scene::tests::real_island_open_area_turning_keeps_standard_and_fragile_parcels_held` 保留真实地图碰撞和模型，先确认整圈包络没有其他障碍，再覆盖不同始角、微小转动、正反半圈及零／单固定步，逐帧检查实际箱体、GLB 模型和镜头。地形查询误报不能通过忽略地面、关闭自动放下或缩小箱体来规避；完整路径与薄墙阻挡回归必须仍通过。

建筑旁还须检查有限三角面的边缘与转离墙面。`scene::tests::real_island_logged_building_side_microturns_keep_paper_parcels_held` 使用会话日志中的箱体中心和多种始角；`scene::tests::real_island_clear_turns_beside_building_walls_keep_all_parcels_held` 使用物流站和 Music 店的实际墙边及三种箱体。每段输入前，用真实箱体局部包围盒八角的圆弧极值构造整段包络，再确认包络与世界没有交集；不能只查起点、终点或将无限延长平面当成有限墙面。输入后立即检查持握关系、实际模型和镜头，失败时沿碰撞实体父级核对导入资产。实际墙体、薄墙和新引入接触的阻挡回归应同时通过。

### 遮挡检测与淡化的无窗口验证

建筑遮挡检测和材质淡化分别在 [camera_obstruction.rs](../src/camera_obstruction.rs) 与 [camera_fade.rs](../src/camera_fade.rs) 检查。使用最小 `App` / `World`、必要的 Avian 空间查询、`Assets<StandardMaterial>`、手动时间和简单几何；材质数据检查不需要安装渲染器。需要确认真实地图的部件分类与几何时复用 [海岛资源与无窗口验证](#海岛资源与无窗口验证)，不启动完整游戏。

| 场景 | 应验证的结果 |
| --- | --- |
| 环绕镜头、角色身体与实际持物 | 检测复用本帧固定跟随计算，身体多个采样点的需求取并集；包裹因惯性或碰撞偏离 `HeldTarget` 时，读取插值后的实际根 `Transform`。小球扫掠覆盖木板细缝，中心射线从细缝穿过时仍能正确请求建筑淡化；镜头附近的外壳重叠也请求淡化，但不调整位置。 |
| 固定距离、方向与自身可见性 | 建筑外壳挡住视线或镜头落入墙面时，遮挡系统不写相机 `Transform`，距离与方向保持原环绕计算；地形、树干等非建筑遮挡不缩距、不改向且不产生透明需求。第三人称人物保持显示，不因镜头位置自动隐藏；只有第一人称隐藏自身视觉。不改变人物物理位置、视角模式或拿放请求。 |
| 建筑分类与玩法隔离 | 五种建筑每栋只有一份 `CameraShell` 外壳查询几何，不增加室内或非建筑查询体；已知外壳、室内装饰和未知部件分类明确，未知部件保持不透明。完整 `World` 碰撞保留，额外外壳查询体使用空碰撞掩码，并从接地、拾取视线等玩法查询显式排除；原有建筑阻挡、斜坡支撑、隔墙不能拾取仍成立。 |
| 同材质的不同建筑实例 | 仅所需建筑的外壳副本降至原 alpha 的 `20%`；另一建筑及 GLB 原始材质不变，原本半透明的材质不被变得更不透明。室内柜台、货架、NPC 和包裹保持正常材质，恢复后不残留透明或错误句柄。 |
| 过渡与抖动抑制 | 手动推进时间，检查约 `0.15 s` 淡化、连续 `0.25 s` 无遮挡才开始恢复、约 `0.35 s` 恢复。保持遮挡时不反复重启计时；恢复过程中再次遮挡可重新淡化，门框处短暂解除需求不会立即闪回不透明。 |
| 多相机、失效目标与视角切换 | 有效角色目标的第三人称相机需求取并集，一台离开不能清除另一台需求；控制者解绑而镜头仍有效时继续保护。第一人称、相机或目标失效后清除对应需求，没有有效第三人称相机时立即恢复原始外观，不修改无关相机和建筑。 |
| 暂停及退出会话 | 暂停冻结镜头姿态、淡化程度和计时；失效关联与实体销毁清理仍运行。返回主菜单或重新进入游戏后旧建筑、材质副本与缓存不残留，新会话从正常外观开始。 |
| 显示同步与日志 | 在零固定步、120 Hz 渲染／60 Hz 模拟及单帧多个固定步的实际 `app.update()` 后立即断言本帧数据；离散遮挡、淡化阶段变化有统一日志，同一持续状态不逐帧重复写入。 |

上述检查只能确认几何查询、材质数据、生命周期与调度行为；透明叠层、阴影、室内可读性与固定环绕镜头的观感必须由用户按 [镜头遮挡验收](#第三人称遮挡与建筑淡化验收) 完成。实际执行记录留在关联 Issue 或 PR。

## 完成代码变更前的自查

以下检查用于确认变更遵守 [开发规范](development.md)，具体规则在该文档中维护：

- 实体身份、实体数据、共享数据和行为分别放在合适的位置；输入处理优先使用 `bevy_enhanced_input`。
- 必要的中文注释已补齐，Rust 注释格式正确，注释与代码一致，删除了失效说明。
- 系统仅声明必要的读写访问；执行依赖和延迟命令的可见时机正确。
- 跨固定步与渲染帧的功能已核对[显示一致性约束](development.md#固定模拟与逐帧显示的一致性)，相关测试不会通过补跑固定步掩盖帧末错误。
- 功能插件注册了所需的系统、资源和消息；实体销毁后不会留下错误引用或失效缓存。
- 架构图维护由 Agent Hook 负责，不作为普通代码任务的手动自查项；维护或排查自动维护工具时，按 [Hook 检查与失败处理](diagrams/README.md#agent-hook-自动维护) 验证实际结果。架构图有变更时由维护 Agent / Hook 流程完成 [视觉检查](#架构图视觉检查)，未完成的自动维护或视觉检查不能报告成功。
- 新增或修改的关键流程、状态变化和错误有对应文件日志；每次游玩创建独立会话日志并保留历史记录。
- 已执行本次变更对应的格式、编译和无窗口测试检查，并记录结果；未完成的运行或视觉验证已明确列出。

如需偏离一般工程约定，在代码注释或交付说明中解释具体理由和影响，并保持偏离范围最小。任何一般约定的例外都不能豁免禁止 Agent 启动或操作游戏的约束。

## 用户手动验收

以下命令和步骤仅供用户自行执行。请在仓库根目录启动游戏：

```powershell
cargo run --locked
```

先按 [README](../README.md#美术与字体准备) 准备 GLB 与字体，再检查菜单与原型。以下步骤均为用户手动执行，排版、动画、真实输入手感与运行效果不能由 Agent 的编译或无窗口测试代替。

Windows MSVC 用户先确认上述启动命令不再以 `0xc0000139`（`STATUS_ENTRYPOINT_NOT_FOUND`）退出，能够显示主菜单并创建本次 `logs/unix-<时间戳>_<会话UUID>.log`。随后按下方菜单验收的第 5、6 步检查 16:9 拖拽、最大化与 DPI，并核对窗口策略安装日志；正常退出后保留会话日志。若仍在应用初始化前失败而没有新日志，应保留终端的退出码与构建目标信息，不能据此判断游戏内窗口策略已运行。

### 英文菜单与暂停验收

1. 启动后应显示英文主菜单，左侧按钮、纸张面板与底部操作提示清晰，鼠标悬停或实际导航时显示黄色高亮；右侧为真实快递员、包裹、快递站和海岛展示舞台。页脚键帽 `Arrows / Enter / Esc` 及其说明必须完整可见，不能只有边框或空白。主菜单不显示世界检查器，不创建可操控角色。快递员应循环播放展示动作，包裹附件位置应合理。若背景缺项，检查本次 `logs/unix-<时间戳>_<会话UUID>.log` 的 `Menu asset failed to load` 路径；动画异常检查 `Menu courier animation could not start`。
2. 用鼠标、方向键和 Enter 分别操作；长按 Enter 不应反复开始或确认。对每个可交互按钮检查鼠标进入高亮、移到空白恢复；再用键盘或手柄导航，应显示当前焦点，静止光标不抢焦点，真实移动到空白应清除导航高亮。键盘焦点应跳过灰色 `Continue`、`Multiplayer`；点击它们应保持当前页面，显示 `Coming Soon`，不加载存档或加入房间。进入 `How to Play`，检查 `01 / 02 / 03`、卡片标题、`WASD / Space / E / E again / Mouse / I` 键位文字完整可见；黄色编号块仅作装饰，不响应鼠标或键盘。`Back` 与 Esc 返回主菜单。
3. 进入 `Settings`，四个分类都能打开。左侧分类与右侧底部 `Restore Defaults / Apply / Back` 应始终可见，只有右侧纸色面板中的 `SETTINGS` 标题、分类项目、说明与保存提示可滚动。对照 [README](../README.md#菜单与占位功能) 检查所有未实现项显示 `Coming Soon`，点击不改变值，方向键焦点跳过。`Graphics` 的 `Frame Rate Limit` 应完整显示 `< 数值 FPS >`，左右箭头和数值均可见；`Controls` 的 `Mouse Sensitivity / Invert Camera Y` 可以调整，当前字段的右侧说明与焦点对应。`Audio` 的三项音量应完整显示名称、左右箭头、滑条和百分比，`0%` 显示 `Muted`，`Test SFX` 可操作而 `Music Volume` 不可操作；听感与分类隔离按 [音频检查与用户验收](#音频检查与用户验收) 完成。检查三个底部操作的文字完整显示，逐一悬停再离开均恢复普通颜色；当前分类和 `Apply` 不常驻黄色。
4. 先将右侧面板滚动到 `Frame Rate Limit`，连续点击左右箭头，再用键盘调整，应只更新数值，面板与滑块保持当前位置，控件不消失或跳回顶部；对其他可调字段重复。选择 `Restore Defaults` 和 `Apply` 后，数值与提示更新也应保持滚动位置，只有内容变短、原偏移超出新范围时允许适度夹取。调整草稿后选择 `Back` 或按 Esc，再进入设置，应恢复上次生效值及音量，并按新页面初始化滚动位置；切换分类同样不沿用旧页面偏移。选择 `Restore Defaults` 后先返回，不应写入默认值；再次恢复默认并 `Apply`，应显示 `Settings applied.`，`settings.json` 保存完整有效内容（包括三项 `audio` 字段）。音量编辑与恢复默认立即预览，分类切换保留草稿与预览；调整后 `Apply` 不必重启即可保存音量并影响帧率或鼠标设置；若保存失败，原文件与运行设置应保持，页面保留草稿、音量预览与合法滚动位置并原位给出英文重试提示，返回后恢复已应用音量。
5. 在 Windows 或 macOS 拖动四边与四角放大、缩小，窗口内容区应始终保持 16:9；检查最小 `960×540`、初始 `1280×720` 及可容纳的大尺寸。主菜单、暂停与帮助的全部内容不应重叠或裁切，帮助的三张卡片、完整正文、键位与 `Back` 应同时可见；在三个页面的按钮、卡片与空白处滚动鼠标滚轮／触控板，并用方向键轮换焦点，页面位置应保持。进入设置，右侧纸色面板内容超过高度时，其右侧应出现滚动条：在面板内滚动滚轮、拖动滑块和点击轨道均只移动面板内容，滑块位置同步变化，拖到两端不越界，左侧分类、底部三个操作与页脚保持原位。再分别在左侧分类、底部操作和外层空白处滚动，面板与整页均不应移动；用方向键移到面板内的越界字段时应自动滚入，导航到固定分类或底部操作时不应移动面板。切换分类或放大到面板内容无需滚动时，滚动条应隐藏；缩小后再次出现时比例正确。拖动中返回或切换分类，新页面不应跟随旧滑块继续移动；返回主菜单、暂停或帮助后仍无滚动。`UI Scale` 占位不提供窗口尺寸或手动比例控制。
6. 点击最大化、双击标题栏，并在 Windows 检查系统贴靠及 `Win+方向键`：应保持工作区内可见的 16:9 内容区；macOS 不进入系统全屏与全屏平铺；桌面平铺后仍应恢复为符合比例的窗口。可用时拖到不同 DPI 的屏幕再缩放，比例与按钮命中应正常；最小化、恢复和关闭窗口仍正常。本次 `logs/unix-<时间戳>_<会话UUID>.log` 应包含 `Window policy initialized` 与 `Native window aspect ratio policy installed`，Windows 跨 DPI 时另有 `Native window policy DPI changed`。实际缩放与视觉验收由用户完成。
7. 选择 `Start Game` 后菜单展示舞台消失，先准备海岛资源与碰撞，就绪后进入完整海岛、一名玩家、普通纸箱和易碎纸箱各一件、三只木箱与一台玩法相机的场景；运行时显示世界检查器。游戏中按 Esc，应出现暂停菜单并显示光标；移动鼠标、按 WASD／Space／E／I 或点击菜单空白处，均不应控制角色、转动镜头或恢复捕获。腾空、持箱或箱体下落时暂停，观察人物、箱体与主角动画应保持；加载阶段暂停也不应提前生成玩家。
8. 暂停中进入设置或帮助，再返回，游戏仍保持暂停且角色／箱体状态不重置。选择 `Resume` 或在暂停根页面按 Esc，恢复当前场景并捕获鼠标；镜头不应因暂停时移动光标而跳转，不应补发暂停前未消费的跳跃或拿放操作。
9. 暂停菜单选择 `Back to Main Menu`，应回到完整展示舞台。再次 `Start Game` 应重新准备一套海岛场景，只有一名玩家、五件初始可搬物品与一台玩法相机。反复切换时不得出现旧地图、碰撞、NPC、持有关系或相机残留，不得叠加两套场景或检查器。也在加载阶段返回主菜单后重新开始，确认迟到的地图就绪通知不会影响新会话。主菜单选择 `Quit` 应正常退出并保留本次日志。

菜单与设置日志预期包含 `Application state changed`、`Menu page changed`、`Menu backdrop spawned`，成功保存有 `Game settings saved` 与 `Game settings saved and applied`；错误带操作、路径与英文原因。排查设置滚动条时，用户在自行启动前设置 `RUST_LOG=info,demo::ui=debug`（PowerShell：`$env:RUST_LOG = "info,demo::ui=debug"`），在本次 `logs/unix-<时间戳>_<会话UUID>.log` 中检查 `Settings scrollbar visibility changed` 的英文显隐与尺寸字段；正常级别不要求包含该调试记录，排查结束后按 [日志排查](development.md#日志排查) 移除环境覆盖。未进入 `Start Game` 就退出时，不要求出现玩法实体生成或跳跃／拿放日志。

### 物理原型验收

选择 `Start Game` 后按下面九项检查当前原型。设置文件的字段、默认值和有效范围见 [README](../README.md#设置)。

1. 资源准备后能看到完整海岛、蓝色制服主角、前方普通纸箱和易碎纸箱，物流总站内的柜台与货架之间有三只木箱；箱体应保留相对三角布局，不穿入墙体或柜台。初始镜头跟随出生点附近的主角。站立并移动鼠标，镜头直接环绕、俯仰，人物水平朝向同步变化且位置不变；持续向上下移动鼠标，应在 `5°..80°` 的边界停止，无侧倾或距离变化。建筑淡化另按 [镜头遮挡验收](#第三人称遮挡与建筑淡化验收) 检查。
2. 按 I 后即时进入第一人称，首次镜头水平向前，自己的模型不遮挡镜头；人物位置和水平朝向不因切换改变。移动鼠标可左右观察并向上、向下俯仰，在 `-85°..85°` 边界停止。松开再按 I 切回第三人称，恢复之前的第三人称俯仰；再次进入第一人称应恢复上次第一人称俯仰，水平朝向始终延续当前方向。长按 I 应只切换一次。
3. 在两种视角下转动镜头后按 W / S，人物沿视角的水平前后方向逐渐加速，松键后较快减速；按 A / D 时横移，后退和横移都不改变朝向。斜向输入不会提高目标速度，镜头持续跟随；上下观察不改变水平移动方向。向建筑侧墙移动应受阻，沿墙横移仍能移动；用人物推自由纸箱和木箱，箱子应因碰撞移动，人物不应穿过墙体或箱体。
4. 在两种视角下按空格时人物起跳并自然落地；持续按住或在空中再次按下不会额外起跳。贴墙时不能凭墙面重复空中起跳，跳跃中切换视角应保持人物的跳跃过程。
5. 分别靠近普通纸箱、易碎纸箱和木箱按 E，箱子从当前位置短暂安全对齐到手前。空地中慢速、快速转向并移动、跳跃，完成对齐后的箱体应与人物稳定保持同一相对姿态，不出现追赶双手的滞后；上下观察不改变水平持握位置。持箱直走顶住建筑或 NPC 时，人物与箱子应一起停住并保持持握，人物不能追进箱子。转身时箱体路径碰到墙、NPC 或其他箱体，应在转动前的安全位置自动放下，人物和镜头继续正常转向；起终点都空但途中经过障碍也要触发。贴地切向和从墙面转离不能误放。按 I 切换视角本身不放下；第一人称显示实际箱体，第三人称恢复人物模型，长按 E 不重复拿放。
6. 松开后再次按 E，纸箱或木箱从当前物理位置释放，保留速度并自然下落，不能瞬间落到面前地面。分别在站立、移动、快速转向与跳跃时释放，检查自由箱体的惯性、落地碰撞和滚动；继续转动、切换视角和移动，箱子不再追逐手前目标。走远后按 E 不会拾取，走近后可以再次拿起；把箱体留在墙另一侧，隔墙时即使处于拾取范围也不应拿起，绕到无遮挡的一侧应可拾取。
7. 按 F3 后光标显示，游戏仍运行，移动鼠标不再转动镜头；光标位于检查器外且未编辑字段时，按 I 仍能切换视角，光标保持显示。左键点击检查器之外的游戏区域恢复鼠标控制。切换到其他窗口后应释放鼠标，失焦时按 I 不切换；回到游戏窗口后仍需左键点击恢复。恢复时镜头不应因释放期间的位移突然跳转。Esc 的暂停与恢复另按上面的菜单验收步骤检查。
8. 默认设置下用外部帧率监测工具观察帧率：性能足够时应接近 60 FPS，性能不足时可低于上限。把 `settings.json` 中的 `max_fps` 改为 `120` 后重新启动，观察上限提高，相同输入下人物加速、减速、跳跃与箱体掉落过程应保持一致，相同鼠标位移对应的旋转幅度也应相同。在 60 FPS 与 120 FPS 设置下都重复第 2～6 项，确认人物和箱体运动平滑、无固定步交替造成的抖动或虚影；持箱时的固定握姿与整体阻挡、释放后的惯性应在两种帧率下都保持一致，第一人称无人物遮挡。两次会话日志中的 `simulation_hz` 应均约为 `60`，`max_fps_after` 分别为 `60` 和 `120`。另将 `max_fps` 改为 `59` 后重新启动，本次日志应记录设置无效的警告及回退上限 `60`，原设置文件仍保留 `59`；改为 `60` 后重新启动，应成功加载且不再出现该警告。完成后恢复默认设置 `60`。
9. 正常关闭窗口后查看 `logs/` 中本次 `unix-<时间戳>_<会话UUID>.log`，应包含会话开始、版本和配置、实体生成、移动输入变化、起跳着陆、拿起放下、视角切换和正常退出。四项集中启动日志 `Prototype gameplay initialized`、`Fixed simulation timestep initialized`、`Camera pose synchronization configured`、`World inspector enabled` 应各出现一次，日志 target 分别为 `demo::gameplay`、`demo::settings`、`demo::camera`、`demo::inspector`，不要求四条之间的先后顺序。`demo::camera` 的英文日志还记录相机生成、视角切换与鼠标捕获变化，便于核对释放、恢复和失焦原因；相机目标或控制者丢失时记录警告。再次启动应生成新文件，旧文件保留。

多人公平裁决、角色退出前的主动交接和完整多人玩法与联机同步仍属于 [架构说明](architecture.md) 中记录的暂缓边界。同批次拾取预留、持有者销毁或关系异常解除后的目标清理、恢复碰撞与自然下落由无窗口回归验证；完整多人流程不纳入当前原型验收范围。

### NPC 碰撞验收

以下步骤仅由用户自行启动游戏并在实际窗口执行，用于检查身体碰撞贴合、阻挡和通行手感，仍需手动验收；无窗口测试通过不代表这些运行或视觉检查已完成。在 worktree 验收时，从该 worktree 的仓库根目录启动，本次日志位于该目录的 `logs/unix-<时间戳>_<会话UUID>.log`，不要混用其他工作目录的日志。

1. 选择 `Start Game`，依次找到物流总站调度员、Pizza 店员、Music 店员和居民。空手从可接近的正面与侧面持续走向其身体：人物应在身体附近受阻，沿身体边缘能绕开，不应穿过躯干；NPC 始终保留原位置与姿态。目测阻挡位置不能明显离开人物身体，也不能延伸成挡住入口或周围通道的大墙。
2. 分别用玩家推动自由纸箱与木箱接近 NPC，再持普通纸箱、易碎纸箱和木箱向 NPC 前进或转向。自由、手持箱体都应在碰到 NPC 身体时受阻，不穿过躯干；完成对齐后握姿固定，直走受阻时人物与箱子一起停住并保持持握，转向路径受阻时在原安全位置自动放下且镜头继续转动。NPC 不被推动，释放后箱体仍自然下落并保持碰撞。
3. 在第一、第三人称分别重复空手与持箱阻挡。NPC 不随建筑外壳淡化，按 E 不会拿起 NPC，也不出现对话或商店操作；主角移动、拿放与视角切换仍正常。
4. 暂停后恢复，NPC 与碰撞保持当前场景；返回主菜单，再次 `Start Game` 后应只出现四名 NPC，各自身体附近的阻挡位置一致，不残留上一会话的不可见障碍。
5. 正常退出后检查本次日志：每次进入新的游戏会话，应有四条 `demo::scene` 的 `Display NPC collider initialized`，包含 `npc`、`collider`、`height`、`radius` 和 `reason="npc_collision_ready"`；暂停恢复不应重复输出。`Island colliders ready` 的 `npc_count` 与 `npc_collider_count` 均应为 `4`，`collider_count` 包含 NPC 身体碰撞。使用发生碰撞时的双方实体记录辅助定位。若身体贴合、穿透或通道出现异常，提供 NPC 所在位置、接近方向、箱体类型、视角、实际结果及对应会话日志。日志只能辅助排查，不能代替上述目测与操作检查。

### 第三人称遮挡与建筑淡化验收

以下步骤仅由用户在实际游戏窗口执行，描述预期结果，不代表已经完成运行或视觉验证。Agent 验证范围仅限代码阅读、格式／编译检查及相关无窗口测试；无窗口通过不能代替透明叠层、室内可读性和镜头观感验收。用户自行启动方法见 [README](../README.md#用户启动)。

1. 默认第三人称空手走近物流总站，缓慢进入、退出前厅，再在门口短距离反复往返并转动镜头。只有遮住身体或实际持物位置的建筑外壳应淡到原不透明度的 `20%`，短暂无遮挡不会立即闪回；离开遮挡约 `0.25 s` 后开始恢复，约 `0.35 s` 恢复完毕。镜头保持原环绕距离，方向仍由鼠标决定，不自动绕到另一侧或切视角。
2. 对物流总站、Pizza 店、Music 店及两栋居民木屋分别重复入口、室内与建筑背面的转向检查。墙面、屋顶等已识别外壳可淡化；柜台、货架、NPC、包裹及未知部件保持原样，未遮挡的另一栋同材质建筑不会一起变透明。目测确认原有颜色、室内结构与可搬物仍可辨认，记录透明叠层、阴影或屋顶仍遮挡的具体部件。
3. 分别持普通纸箱、易碎纸箱和木箱进入房屋，慢速与快速转向、靠近门框或侧墙并释放。遮挡判断应覆盖实际箱体，拿起对齐期间和碰撞自动放下后也应能看清；建筑淡化不让角色或包裹穿墙，隔墙时仍不能拾取。手持箱、货架箱与 NPC 本身不会跟外壳一起淡化。
4. 保持第三人称，绕着建筑侧墙和墙角转动视角，让镜头经过透明墙面，再经过树干、码头固定结构与岸坡。房屋遮挡、镜头落入透明墙面以及非建筑遮挡都不应使系统缩短距离、推开镜头或自动改向，人物模型在第三人称始终保持显示。地形、树干、码头保持正常外观，即使遮住角色也不变透明；非建筑遮挡仍存在属于当前方案边界。
5. 外壳已淡化时按 I 进入第一人称，建筑应恢复正常外观，自己的模型仍隐藏，实际包裹保持显示。再切回第三人称，按当前视角重新处理遮挡；共享水平角与各自记住的俯仰角仍正确，人物位置、速度和持握关系不因切换改变。
6. 外壳正在淡化或恢复时按 Esc 暂停，等待后观察淡化程度与镜头位置应保持。打开暂停设置／帮助再返回，仍保持暂停；恢复后继续当前过渡，镜头不因暂停期间鼠标位移跳转。
7. 在建筑淡化状态下通过暂停菜单返回主菜单，再次 `Start Game`。应只出现一套新场景，新建筑从正常外观开始，没有旧淡化或材质残留；在加载期间退出后再次开始也检查一次。正常退出游戏并重新启动，确认本次效果不保存进下一会话。
8. 在 `max_fps = 60` 与 `120` 下重复门口往返、持箱转向、固定环绕距离、视角切换与暂停步骤。预期过渡时间相同，零固定步交替帧不使角色、持物和外壳状态抖动。正常退出后保留各次 `logs/unix-<时间戳>_<会话UUID>.log`，对照 `Camera building occlusion changed`、`Building camera fade changed` 的实体、前后状态和原因，以及视角／暂停／退出记录；持续同一遮挡状态不应逐帧重复写入。将实际步骤、结果与未完成项记录在对应 Issue 或 PR。

### 海岛美术与落水验收

以下步骤由用户在真实游戏窗口中执行；用于确认视觉和运行表现，不代表已完成验收。

1. 环顾并走访海岛，确认地形、海水、棕榈、荒草、物流总站、Pizza 店、Music 店与两栋居民木屋正确显示。人物、建筑和箱体应保持正常比例与内置材质颜色；岛上只有一名玩家主角，NPC 为调度员、两名店员和居民，没有地图展示主角或重复木箱残留。
2. 依次走上三个商铺及两栋住宅的入口台阶，再到码头；应能沿入口上到平台并站稳，五处台阶与对应地板的衔接处不因门槛或间隙卡住人物、使人物下陷或把人物弹开，商铺前厅没有被整栋碰撞封住。尝试走向建筑侧墙、固定道具和棕榈树干，应受到对应结构阻挡；草和叶片不应阻挡行走，海水不能充当陆地地面。
3. 站立、行走、松键减速，再分别拿起和放下三种箱体。主角应在站立、四方向移动与持箱移动间连续混合，站立或同一动作持续播放时不能反复回到第一帧；持箱时腿部继续迈步，双手保持搬运姿态。详细动作与镜头边界按下文检查。纸箱对齐后位于双手之间，较大的木箱稍向前留出空间；快速转向应保持握持姿态，转向遇到阻挡则在转动前的位置放下。四名 NPC 的身体阻挡按 [NPC 碰撞验收](#npc-碰撞验收) 检查；NPC 与柜台、货架上的固定纸箱、商店摆件不能交互或搬走。
4. 先空手从岸边走入海中，再持箱重复。人物下沉后应回到出生点，清除落水前速度和待执行的跳跃、拿放请求；松开移动键后应停稳，继续按住移动键时仍可以继续行走。持箱落水后箱子解除跟随，尚未落水的箱子从真实位置自然下落。把普通纸箱、易碎纸箱和木箱分别推落或放落海中，箱体自身落水后应回到各自初始位置，恢复自由碰撞并稳定落地，没有旧位置拖影或重复实例。
5. 在 `max_fps = 60` 与 `120` 下重复平台通行、动画切换、拿放与落水恢复，确认两种视角下行为一致。检查本次 `logs/unix-<时间戳>_<会话UUID>.log` 中的资源加载、地图与碰撞准备、动态实体生成、动画及恢复记录；失败时提供对应资源路径、错误上下文和实际操作步骤。
6. 对照入口掉帧反馈截图中的物流站平台位置与相机视角，保持相同构建模式、窗口尺寸和检查器展开状态，在修改前后分别设置 `max_fps = 60`、`120`。等待加载与初始物体运动稳定后，先驻足转动视角，再在平台上行走、转向，反复上下入口台阶并跨过门槛进入室内。用同一外部帧率工具分别记录驻足与移动的 FPS、帧时间，确认行走时不再因日志输出出现明显停顿，人物仍站稳、转向及通行正常；性能足够时接近对应上限，不要求硬件一定达到 120 FPS。正常退出后保留各次 `logs/unix-<时间戳>_<会话UUID>.log`，核对 `simulation_hz`、`max_fps_after`、会话标识与退出记录；行走中产生的移动、接地、碰撞和动画状态变化应完整保留，并将前后结果写入关联 Issue 或 PR。该项实机 FPS 验收须由用户完成，无窗口测试通过不代表已经验收。

发布包检查还应确认携带完整的 `assets/`，由用户在发布包预期的工作目录自行启动。缺失资源时不应出现悬空玩家或无碰撞的可玩地图；本次会话日志应提供路径和加载错误供排查。

### 人物动作与镜头验收

以下仅为用户手动步骤与预期结果，不代表已完成游戏运行或视觉验收。先在 `max_fps = 60`，再在 `120` 下重复：

1. 空手依次按 W、S、A、D，再按 WA、WD、SA、SD；应分别前走、倒走、左右横移和斜向混合，人物继续面朝视角方向，脚步不因换方向跳回第一帧。松键后随真实减速自然回到站立；靠墙持续按移动键时，不因输入存在而原地快速走动。
2. 按住移动键，缓慢及快速转动鼠标，并反复反向或绕满一圈；腿部方向应随本帧朝向和真实速度衔接，鞋底不因混合伸腿穿地，人物和持物目标不相隔一帧追赶。观察起停时是否存在明显漂浮或抖动，实际坡面脚步贴合仍需用户确认。
3. 对普通纸箱、易碎纸箱和木箱分别重复上述移动、转向与 E 拿放。腿部保持迈步，持箱上身不过度摆臂，对齐后的箱体与人物共同保持持握姿态；直走受阻不挤进身体，转向路径受阻自动放下且镜头不锁住。空手／持箱按空格时应看到一次伸展、收腿、下落准备和落地屈膝缓冲，再衔接当前移动／站立；最高点不反复切换，空中不持续踩步。连续按住空格不能再次起跳。空中拿放或暂停恢复不重播起跳，短暂地面探测丢失不误触发落地。
4. 在建筑侧墙、转角、低屋顶和门口转动第三人称镜头：保持固定环绕距离，遮挡身体或实际持物的建筑外壳渐变至原不透明度的 20%。按 I 切换后第一人称仍在既定眼位并隐藏人物，建筑恢复正常外观。完整范围按 [镜头遮挡验收](#第三人称遮挡与建筑淡化验收) 检查。
5. 持箱移动时暂停并恢复，再返回主菜单重新进入游戏；暂停保持动作，恢复不突然回到第一步，主菜单仍是 `Carry_Idle` 展示，重新开始没有旧动画关联。

查看本次 `logs/unix-<时间戳>_<会话UUID>.log` 的 `Courier animation initialized / changed / detached`、`Camera building occlusion changed / Building camera fade changed` 以及资产错误。动画初始化应包含 `clip_count=16`；详细角度与速度采样按 [日志排查](development.md#日志排查) 启用。提交问题时保留对应会话日志、帧率设置和操作顺序。

离线检查可运行 `python3 -B art/scripts/validate_assets.py --report tmp/character-animation/assets.json` 与 `python3 -B -m unittest discover -s art/scripts -p test_character_assets.py`，覆盖 GLB 命名、时长、全骨覆盖、循环首尾与一次性动作终点、根与髋部水平静止、夹帧行走／落地鞋底高度，以及八组持箱／空手下肢一致性。该检查不替代运行时混合求值的无窗口回归或上述实机步骤。

### 世界检查器验收

1. 选择 `Start Game` 并运行时应显示 `World Inspector`；主菜单、暂停及从暂停打开的设置／帮助均隐藏检查器。展开 `Entities`、`Resources`、`Assets`，确认能找到人物、木箱和相机，以及 `PrototypeConfig`、网格和材质。展开人物组件应能查看移动意图和运动状态。
2. 按 F3 后将光标移到面板并点击、拖动或滚动，应保持光标自由，镜头不转动。也检查从面板外快速移入并立即点击，不应重新捕获鼠标。把面板拖到窗口中央，再点击面板外恢复控制；持续移动并点击左键，人物不应因隐藏光标重叠面板而停下，面板字段也不应改变。再次按 F3 后应能正常点击和编辑；不要用 Esc 代替 F3，Esc 会暂停并隐藏检查器。
3. 在检查器字段中输入 W、E、I 或空格，人物不应移动、跳跃、拿放或切换视角；原先持续移动的输入在上下文停用后应清零。点击面板外恢复控制时镜头不跳转，单次动作需松开后重新按下才触发。
4. 检查本次 `logs/unix-<时间戳>_<会话UUID>.log`，启动时应包含来自 `demo::inspector` 的 `World inspector enabled`，字段为 `plugin="WorldInspectorPlugin"` 与 `reason="initialization"`。这表示检查器插件注册，即使启动主菜单未显示面板也应输出；开始、暂停、恢复及重新进入游戏不重复输出该初始化记录。上下文停用与恢复应记录输入状态变化，正常退出后历史会话文件保留。
5. 展开人物和木箱根实体的物理运动组件与 `Transform`，点击面板外恢复控制，移动、持握或释放箱体时检查速度和位置变化；箱体静止后运动变化应停止。组件标题的金色边框依据 Bevy 变化标记，插值系统和持续可变访问也可能保持高亮，不能据此单独判断箱体仍在运动。

无窗口回归只检查 Egui 命中、输入上下文与组件状态，不安装窗口后端或渲染插件；面板排版、鼠标交互手感和资产预览需用户按以上步骤验收。

## 音频检查与用户验收

代码检查仍执行 `cargo fmt --all -- --check` 和 `cargo check --locked`。`cargo test --locked audio` 检查清单契约与全部素材的 Kira 解码、排队限制和持握警告；其中播放端测试覆盖暂停期间真实时间冷却、为 UI 预留并发、已排队实例计数及未加载请求不延后播放。音量回归还需检查默认增益等于原有 `0.25` 基准、总音量与各分类相乘并保留素材间响度、零音量使用真正静音、预览及回滚选择正确混音源，以及静音新请求不占用并发／冷却且恢复不重放。菜单消息、滑条释放反馈、设置预览与输入去重用 `cargo test --locked ui::`，设置兼容与保存回读用 `cargo test --locked settings::tests`。实际落地及拾取消息测试位于 `physics_tests`，可用 `cargo test --locked physics_tests` 覆盖，也可执行全部无窗口测试。解码测试仅调用 `StaticSoundData::from_file`；排队与混音测试仅使用类型通道的数据资源，不安装 Kira 输出插件、窗口或完整游戏。正在播放声音的实际输出变化仍由用户验收。

音频文件技术检查与试听快照命令见 [音频管线](audio.md#重现与检查)。`quality_report.json` 的通过只确认格式、静音、削波、DC、循环采样边界及哈希，不能替代人耳听感和真实设备输出。浏览器试听测试只操作独立的音频工具页面，不操作游戏。

用户按以下步骤验收：

1. 打开 [逐项试听页面](../assets/audio/audition.html)，将监听音量先调低，逐条播放菜单、拾取、交接、碰撞、弹开、警告与交付结果。预期各声可区别、起止没有明显点击、没有过长静音或过响；切换素材自动停止上一声。循环合成底声至少听三个周期，检查接缝与重复感。真实海浪、风和推车候选显示未下载；合成底声不得标为真实录音。
2. 自行启动游戏，在主菜单用鼠标移入可操作按钮，再用方向键或手柄改变焦点，每次实际变化应有短焦点音；快速变化允许受 75 ms 冷却限制。光标停住、在同一按钮内部移动、离开按钮和页面重建不应重复发声。进入帮助后仅有一个返回按钮，继续按导航键不应反复播放焦点音；`Coming Soon` 项也不发声。
3. 在主菜单进入 `Settings → Audio`，先确认三项默认 `100%` 保持原有响度。按钮、左右方向键或手柄每次调整 `5%`；拖动滑条可得到如 `37%` 的整数百分比，改变过程中音量立即变化但不连续响确认音，放开且数值改变后仅反馈一次。把音量调到边界后继续调整不发声；三行文字、数值与滑条在窄窗口中仍完整可见。切换设置分类并返回，草稿和预览保留。
4. 分别把 `SFX Volume` 和 `UI Volume` 调为 `0%`：前者应显示 `Muted` 且 `Test SFX` 无声，菜单导航仍有声音；后者应让菜单静音，但 `Test SFX` 仍可播放。总音量为 `0%` 时两者都无声。恢复音量后仅新的操作发声，不补播静音期间的导航或试听请求。在试听声播放期间调整相应音量，当前声音也应同步变化；`Test SFX` 不生成物品、不移动角色、不建立持有关系。
5. 调整音量后用 `Back / Esc` 返回，重新进入设置应恢复最近一次成功应用的值和听感。`Restore Defaults` 应立即预览三个 `100%`，返回不保存；再次编辑并 `Apply`，应保存完整 `audio` 字段且重新启动仍采用已保存值。打开其他设置／帮助、改变分类、实际调整帧率或鼠标设置、恢复默认及成功应用仍使用确认音，返回用返回音；反馈服从当时有效的总音量与 UI 音量。若保存失败，保留草稿及其临时听感并显示英文重试提示，原文件和已应用值不变，返回后恢复已应用音量；故障条件及操作记录放入对应 Issue 或 PR。
6. 选择 `Start Game`，游戏中按 Esc 打开暂停应有确认音。暂停期间菜单反馈与 `Test SFX` 仍可用，并重复第 3～5 项音量预览、分类隔离、应用和返回检查；返回暂停页后角色／箱体仍暂停。`Resume / Esc` 恢复及 `Back to Main Menu` 应有返回音。暂停时不应新增落地或持握警告，试听只播放已有素材。`Quit` 正常退出并停止声音，不要求退出确认音完整播放。
7. 游戏运行时分别靠近普通纸箱、易碎纸箱和木箱按 E，成功拿起只提示一次；走远后按 E 不播放成功提示。持握时再次按 E 提示释放，真正撞击地面时另有落地声；当前共用第一版落地素材，静置后没有连续撞击声，侧面碰墙不会冒充落地。应用较低 `SFX Volume` 后重复，应降低玩法音效而不改变菜单音量；应用 `0%` 后这些声音静音，但玩法动作仍正常。
8. 持箱直走顶墙或 NPC，人物与箱子应一起停住，保持受阻不持续鸣叫。附近转向遇到阻挡应自动放下并提示一次释放，镜头继续自由转动；正常拾取对齐和空旷处快速转向不应频繁报警。两种视角、60/120 FPS 下分别检查，音效不改变物理规则。
9. 当前没有主动交接、推车、明确弹开或订单交付玩法，不能用游戏验收声称它们已接入；对应素材仅在试听页评审。合成环境底声不会在场景中自动播放。
10. 检查本次 `logs/unix-<时间戳>_<会话UUID>.log`：包含 `Audio pipeline initialized`、各 `Audio asset requested` 和获准反馈的 `Audio cue queued`；菜单操作有 `Menu audio cue emitted`，与排队日志的 `event="menu_hover" / "menu_confirm" / "menu_cancel"` 对照，落地与警告有 `Audio cue emitted`。预览进入／退出和正式配置变化有 `Audio mix changed`，箭头调整和拖动放手汇总有 `Audio volume preview changed`；试听有 `Audio sample requested` 与 `reason="settings_preview"`，成功保存有 `Game settings saved` 与 `Game settings saved and applied`，加载／保存／应用应包含三项音量，失败记录操作与路径。无声时先看音量和 `Muted` 状态，再看 `Audio asset failed to load` 的路径与错误及 Kira 的 `Failed to setup audio`。必要时用户以 `RUST_LOG=info,demo::audio=debug` 自行启动，检查 `Audio cue skipped` 是否因 `reason="muted"`、加载、冷却或并发上限；正常退出应有 `Audio channels stopped`，保留历史会话。

以上步骤描述预期结果，实际听感、设备输出和游戏验证由用户完成；具体一次运行记录放在关联 Issue 或 PR。

## 日志检查与问题反馈

会话文件命名和位置见 [README](../README.md)，日志规则与调试过滤配置见 [开发规范](development.md)。验收时先确认本次文件的会话开始时间和配置，再将日志中的实体、前后值和原因与操作步骤对应。

- 用户自行启动后，正常退出并检查本次会话文件：`demo::gameplay` 的 `Prototype gameplay initialized`、`demo::settings` 的 `Fixed simulation timestep initialized`、`demo::camera` 的 `Camera pose synchronization configured` 与 `demo::inspector` 的 `World inspector enabled` 均应以 `info` 级别各出现一次。玩法记录应对应实际 `PrototypeConfig`，固定模拟频率应对应实际 `Time<Fixed>`；暂停、恢复和重新开始游戏不能重复这些启动记录。确认正常退出记录存在、已入队日志排空并刷新完成，文件末尾没有缺失或截断；再次自行启动并正常退出后，应生成新的会话文件，第一份文件仍保留且未被覆盖。用户覆盖 `RUST_LOG` 时按实际过滤规则核对，低于过滤级别的记录缺失不能直接判定插件未注册。
- 鼠标捕获及实际移动输入的离散变化，默认以 `info` 级别落盘，应能对应释放、恢复、失焦和移动输入变化。
- 启动时应有 `Camera pose synchronization configured`，字段为 `simulation_schedule="FixedUpdate"`、`carry_schedule="FixedUpdate"`、`grip_mode="shared_body"`、`physics_schedule="FixedPostUpdate"`、`presentation_schedule="RunFixedMainLoop"`、`presentation_order="interpolation_character_facing_carry_pose_camera_occlusion_fade_visibility"`。这条日志说明采用的同步配置，人物与箱体运动、持握转动、视角切换及遮挡过渡是否稳定仍需按上述步骤目测确认。
- 美术与场景日志应记录所需资源的加载、失败路径、地图实例与碰撞准备状态，以及动态实体生成；结构碰撞日志用于核对实际地图范围和组成。玩法日志记录起跳、接地变化，以及 `Carryable item picked up`、`Carryable item released`；物理碰撞日志用于核对阻挡发生的实体。释放日志应能对应释放前的真实位置和速度；异常关联清理应记录原因。所有日志均写入本次 `logs/unix-<时间戳>_<会话UUID>.log`，提供问题反馈时保留该文件。
- `demo::character_animation` 应记录 `Courier animation initialized` 与 `Courier animation changed`，动作字段使用 `Idle`、`Walk`、`Carry_Idle`，切换日志包含 `animation_before`、`animation_after` 和原因；持续播放同一动作不应逐帧重复输出切换记录。绑定失败应保留缺失动作或失效关联信息。
- `demo::island_recovery` 的 `Entity recovered after entering water` 应包含恢复实体、`position_before`、`position_after` 和 `reason="water_recovery"`；持箱落水还应出现 `Held item released during water recovery`，确认解除持握。连续更新不应重复记录同一次恢复。恢复后箱体碰撞与人物输入是否正确仍需结合无窗口回归和上述用户步骤确认。
- 相机初始化应记录 `perspective="third_person"`。每次有效按 I 应出现一条 `Camera perspective changed`，包含 `perspective_before`、`perspective_after`、共享 `yaw`、两种模式的 `pitch_before`、`pitch_after` 和 `reason="toggle_perspective_action"`；长按不应连续产生切换日志，失焦时不应产生切换日志。
- 每台第三人称相机的建筑遮挡需求变化应记录 `Camera building occlusion changed`，包含 `camera`、`target_entity`、`building`、`occluded_before`、`occluded_after` 和 `reason`。建筑需求、恢复完成与失效目标清理统一记录 `Building camera fade changed`，分别通过 `reason="camera_obstruction_changed"`、`clearance_grace_completed`、`no_active_third_person_camera` 或 `third_person_target_unavailable` 区分。这些记录位于 `demo::camera`；暂停不继续写入计时驱动的变化，持续相同状态不逐帧重复输出。日志只能辅助定位，不能单独证明透明叠层、固定环绕距离与镜头画面正确。
- 视角角度和世界移动速度属于连续数据，以 `debug` 级别每 0.5 秒最多采样一次；默认日志中没有这些采样不代表功能没有执行。需要排查时，由用户按开发规范中的过滤配置自行启动。
- 状态变化日志应包含时间、级别、模块或系统、相关实体或业务 ID、变化前后值和触发原因；错误应保留操作、相关文件路径和原始错误信息。
- 后台输出期间文件和控制台显示可能稍有延迟，不据此判断事件未发生；正常退出应记录退出、等待已入队记录写完并刷新日志，再读取本次会话文件核对完整性。异常退出时检查最后保留下来的上下文；不要为补充日志而覆盖或删除旧会话文件。

反馈问题时提供复现步骤、实际结果与预期结果、相关设置，以及对应会话日志文件。运行日志和游戏存档分别管理，日志不能作为存档使用。
