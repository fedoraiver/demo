# Agent Note: 分离 Bevy App 通用说明与项目流程架构

Status: implemented — 已分离通用 Bevy App 说明与项目流程架构。

## Problem

架构首页混合了 Bevy App 概念、项目装配过程和 game_flow 的状态、时钟及共享调度，使通用机制与具体实现难以区分。装配文字和图片重复了入口代码中的插件注册。

仅说明渲染位于独立子应用，不能解释 `App` 如何包含主应用与其他子应用，也没有交代世界隔离、入口调度和数据传输机制。

## Decision

将 [架构首页](../../../architecture/README.md) 限定为 Bevy 0.20 的通用 App 机制、默认生命周期及 12 个项目模块的阅读入口。[应用流程](../../../architecture/game_flow.md) 维护项目状态、时钟和跨模块调度；[会话日志](../../../architecture/session_log.md#退出与异常) 维护退出时先释放 App 再记录结果和刷新日志的顺序。

App 与 SubApp 的说明先介绍包含结构和世界边界，再解释普通更新与显式提取；渲染仅作为应用实例，说明流水线线程安排由插件提供，不展开完整渲染管线。

## Changes

- 首页删除项目装配说明与图，补充通用概念和一张默认生命周期图；说明固定循环依赖时间设施，后续更新由 runner 驱动，状态转换由状态插件提供。
- 首页移除外部参考链接，保留项目模块的内部阅读入口。
- 补充 App 与 SubApp 的结构图、普通更新顺序图及说明，覆盖主应用也是 SubApp、独立 World、默认配置目标、入口调度与提取回调；以渲染解释用途和线程边界，保留主调度生命周期图与模块表。
- game_flow 承接菜单、会话、场景生命周期和两张原有项目图，保留暂停清零、无状态测试例外、三个公开调度链与零／多个固定步的边界，并说明固定 60 Hz 模拟与渲染限帧的分离。
- 更新 [Agent 阅读入口](../../../../AGENTS.md)、[文档归属规范](../../../AGENTS.md)、[开发规范](../../../development.md) 及相关模块和架构图说明的引用；旧 Notes 保留原有历史结论。

## Alternatives considered

- 保留首页中的项目装配和共享调度：入口集中，但仍混合通用概念与项目实现，且 game_flow 没有独立归属。
- 将引擎和第三方插件也列入项目模块清单：会扩大清单职责，因此只列现有 12 个项目模块，通用介绍中解释 Plugin 机制。
- 只保留渲染子应用的一句说明：无法交代通用结构和数据流；完整介绍渲染管线则超出首页的通用机制范围，因此采用通用说明与简短渲染实例。

## Consequences

通用介绍与项目运行规范有独立归属，首页不再承担项目共享契约。开发者从模块表进入详细说明，跨功能调度直接读取 game_flow。场景模块沿用源码入口，不为索引完整而新增空文档；本次不改变代码、接口、配置或运行行为。

## Verification

核对首页通用内容边界、12 个项目模块、所有迁移章节入链及必要退出和初始化约束。依据锁定 Bevy 源码复核 App/SubApp 结构、世界隔离、入口调度、提取时机和流水线渲染边界。新增结构与更新图使用锁定 Mermaid 依赖检查语法，原主调度生命周期图保持一致，迁移到 game_flow 的两张项目图应与原文一致；独立复核需逐项比较迁移前后正文，避免将通用默认调度与项目自定义调度混淆。图形语法校验不代表 SVG 已完成视觉验收，具体执行结果由交付说明或对应 Issue／PR 记录。
