# Agent Note: 记录 Agent 开发设计、改动与抉择

Status: implemented — 开发规范和 Notes 约定已加入过程记录要求。

## Problem

开发者需要在仓库中查看 Agent 如何设计、实际完成了哪些工作，以及为何作出相关抉择。仅在存在长期决策时编写笔记，会遗漏普通开发任务的改动说明。

## Decision

开发过程统一使用 `docs/notes/`，沿用既有生命周期和类别。形成方案或开始实施时新增或更新主题记录，随进展维护，交付前补齐实际完成范围与未完成事项；内容详略与改动规模相称。

## Changes

- 在根 [Agent 开发指南](../../../AGENTS.md#conventions) 加入开发过程中维护 Notes、供开发者查阅的要求。
- 在 [Notes 约定](../README.md) 中扩大记录范围，补充写入时机和实际改动章节，保留独立文档规则、日期命名和生命周期；简单改动可以简记，无真实替代方案时如实说明。
- 同步 [文档归属](../../AGENTS.md#the-tier-taxonomy-one-home-per-fact) 与 [开发规范](../../development.md#文档维护)，明确设计、已完成工作与决策理由的归属。

## Alternatives considered

继续只为长期决策编写 Notes：维护记录较少，但无法让开发者查看一般开发任务的设计和实际改动，不满足本次记录要求。

## Consequences

每项开发任务都需维护相关笔记。主题记录复用已有位置，避免重复；记录保留工作与抉择摘要，具体命令输出和逐次验证结果仍由关联 Issue 或 PR 承载。当前运行行为仍由对应架构、指南与源码维护。

## Verification

检查 Agent 入口、文档归属和 Notes 约定是否一致，并核对记录是否区分计划与实际改动、说明真实抉择和未完成范围。相对链接与锚点应可解析；本规则不改变产品行为或游戏验收范围。
