# 游戏手动验收

本指南供用户在真实游戏窗口中检查已有功能。先完成验收准备，再选择受本次变更影响的部分；修改共享控件、输入、物理或调度时，要覆盖其所有使用场景。开发者的命令与无窗口覆盖范围见 [验证参考](README.md)。

这些步骤只描述操作和预期，不代表已执行或通过。Agent 不启动或操作游戏；用户反馈仅确认实际报告的场景。实际结果与未执行的帧率、平台及边界记录在对应 Issue 或 PR 中。

## 验收准备

以下命令和步骤仅供用户自行执行。先按 [使用说明](../usage.md#资源准备) 确认运行资源完整。排版、真实输入与声音输出必须在实际窗口与设备上确认。

在仓库根目录启动游戏；在 worktree 验收时，从该 worktree 根目录启动，并使用该目录生成的 [会话日志](../usage.md#会话日志)，不要混用其他检出的会话：

```powershell
cargo run --locked
```

Windows MSVC 用户先确认能够显示主菜单并创建本次会话日志，再按菜单验收第 5、6 步检查 16:9 拖拽、最大化与 DPI，并核对窗口策略安装日志。若以 `0xc0000139`（`STATUS_ENTRYPOINT_NOT_FOUND`）或其他错误在应用初始化前退出、没有新日志，保留终端退出码和构建目标；这不能证明游戏内窗口策略已运行。

## 英文菜单与暂停验收

1. 启动后应显示 `Grey-boxing` 英文主菜单，按钮、纸张面板与底部操作提示清晰，背景为纯色。鼠标悬停或实际导航时显示黄色高亮，页脚键帽 `Arrows / Enter / Esc` 及其说明完整可见。主菜单隐藏世界检查器，玩法角色在开始后创建。
2. 用鼠标、方向键和 Enter 分别操作；长按 Enter 不应反复开始或确认。对每个可交互按钮检查鼠标进入高亮、移到空白恢复；再用键盘或手柄导航，应显示当前焦点，静止光标不抢焦点，真实移动到空白应清除导航高亮。灰色 `Continue`、`Multiplayer` 均显示 `Coming Soon`，键盘焦点应跳过它们；鼠标点击不切换页面、不加载存档或加入房间。进入 `How to Play`，检查 `01 / 02 / 03`、卡片标题、`WASD / Space / E / E again / Mouse / Esc` 键位文字完整可见；黄色编号块仅作装饰，不响应鼠标或键盘。`Back` 与 Esc 返回主菜单。
3. 进入 `Settings`，四个分类都能打开。左侧分类与右侧底部 `Restore Defaults / Apply / Back` 应始终可见，只有右侧纸色面板中的 `SETTINGS` 标题、分类项目、说明与保存提示可滚动。对照 [使用说明](../usage.md#菜单与占位功能) 检查所有未实现项显示 `Coming Soon`，点击不改变值，方向键焦点跳过。`Graphics` 的 `Frame Rate Limit` 应完整显示 `< 数值 FPS >`，左右箭头和数值均可见；`Controls` 的 `Mouse Sensitivity / Invert Camera Y` 可以调整，当前字段的右侧说明与焦点对应。Audio 页两行音量的箭头、滑条与百分比完整显示，`0%` 显示 `Muted`，Music 为不可操作占位，声音按 [音频验收](#音频验收) 检查。检查三个底部操作的文字完整显示，逐一悬停再离开均恢复普通颜色；当前分类和 `Apply` 不常驻黄色。
4. 先将右侧面板滚动到 `Frame Rate Limit`，连续点击左右箭头，再用键盘调整，应只更新数值，面板与滑块保持当前位置，控件不消失或跳回顶部；对其他可调字段重复。选择 `Restore Defaults` 和 `Apply` 后，数值与提示更新也应保持滚动位置，只有内容变短、原偏移超出新范围时允许适度夹取。调整草稿后选择 `Back` 或按 Esc，再进入设置，应恢复上次生效值，并按新页面初始化滚动位置；切换分类同样不沿用旧页面偏移。选择 `Restore Defaults` 后先返回，不应写入默认值；再次恢复默认并 `Apply`，应显示 `Settings applied.`，`settings.json` 保存帧率、相机、总音量及 UI 音量。调整后 `Apply` 不必重启即可生效，若保存失败，原文件与运行设置保持，页面保留草稿与合法滚动位置并原位给出英文重试提示。
5. 在 Windows 或 macOS 拖动四边与四角放大、缩小，窗口内容区应始终保持 16:9；检查最小 `960×540`、初始 `1280×720` 及可容纳的大尺寸。主菜单、暂停与帮助的全部内容不应重叠或裁切，帮助的三张卡片、完整正文、键位与 `Back` 应同时可见；在三个页面的按钮、卡片与空白处滚动鼠标滚轮／触控板，并用方向键轮换焦点，页面位置应保持。进入设置，右侧纸色面板内容超过高度时，其右侧应出现滚动条：在面板内滚动滚轮、拖动滑块和点击轨道均只移动面板内容，滑块位置同步变化，拖到两端不越界，左侧分类、底部三个操作与页脚保持原位。再分别在左侧分类、底部操作和外层空白处滚动，面板与整页均不应移动；用方向键移到面板内的越界字段时应自动滚入，导航到固定分类或底部操作时不应移动面板。切换分类或放大到面板内容无需滚动时，滚动条应隐藏；缩小后再次出现时比例正确。拖动中返回或切换分类，新页面不应跟随旧滑块继续移动；返回主菜单、暂停或帮助后仍无滚动。`UI Scale` 占位不提供窗口尺寸或手动比例控制。
6. 点击最大化、双击标题栏，并在 Windows 检查系统贴靠及 `Win+方向键`：应保持工作区内可见的 16:9 内容区；macOS 不进入系统全屏与全屏平铺；桌面平铺后仍应恢复为符合比例的窗口。可用时拖到不同 DPI 的屏幕再缩放，比例与按钮命中应正常；最小化、恢复和关闭窗口仍正常。本次会话日志应包含 `Window policy initialized` 与 `Native window aspect ratio policy installed`，Windows 跨 DPI 时另有 `Native window policy DPI changed`。实际缩放与视觉验收由用户完成。
7. 选择 `Start Game` 后纯色菜单背景相机被替换，直接进入一块平地、一名物理玩家、三个可搬方块与一台玩法相机的场景，运行时显示世界检查器。游戏中按 Esc 出现暂停菜单并显示光标，移动鼠标、按 WASD／Space／E 或点击菜单空白处均不应控制角色、转动镜头或恢复捕获。腾空、持箱或方块下落时暂停，人物和方块保持当前状态。
8. 暂停中进入设置或帮助，再返回，游戏仍保持暂停且角色／箱体状态不重置。选择 `Resume` 或在暂停根页面按 Esc，恢复当前场景并捕获鼠标；镜头不应因暂停时移动光标而跳转，不应补发暂停前未消费的跳跃或拿放操作。
9. 暂停菜单选择 `Back to Main Menu` 后回到纯色背景主菜单，再次 `Start Game` 应只有一名玩家、三个初始方块与一台玩法相机。反复切换时没有旧地面、碰撞、方块、持有关系或相机残留，不叠加场景或检查器。主菜单选择 `Quit` 应正常退出并保留本次日志。

菜单与设置日志预期包含 `Application state changed`、`Menu page changed`、`Menu backdrop spawned`，成功保存有 `Game settings saved` 与 `Game settings saved and applied`；错误带操作、路径与英文原因。排查设置滚动条时，用户在自行启动前设置 `RUST_LOG=info,demo::ui=debug`（PowerShell：`$env:RUST_LOG = "info,demo::ui=debug"`），在本次会话日志中检查 `Settings scrollbar visibility changed` 的英文显隐与尺寸字段；正常级别不要求包含该调试记录，排查结束后按 [日志排查](../development.md#日志排查) 移除环境覆盖。未进入 `Start Game` 就退出时，不要求出现玩法实体生成或跳跃／拿放日志。

## 物理交互验收

选择 `Start Game` 后按下面九项检查当前 demo。设置文件的字段、默认值和有效范围见 [使用说明](../usage.md#设置)。

1. 开始后以第一人称看到灰色平地与三个纯色方块。初始镜头位于角色脚底上方 `1.65 m`，水平向前，人物碰撞身体不遮挡镜头。
2. 站立并移动鼠标，镜头可左右观察和上下俯仰，人物水平朝向同步变化且位置不变；持续向上下移动鼠标，应在 `-85°..85°` 的边界停止，无侧倾。按下或长按 I 不改变视角、人物位置或拿放状态。
3. 转动镜头后按 W / S，人物沿视角的水平前后方向逐渐加速，松键后较快减速；按 A / D 时横移，后退和横移都不改变朝向。斜向输入不会提高目标速度，镜头持续跟随；上下观察不改变水平移动方向。用人物推自由方块，方块应因碰撞移动，人物不应直接穿过方块。
4. 按空格时人物起跳并自然落地，第一人称眼位随人物升降；持续按住或在空中再次按下不会额外起跳。
5. 分别靠近三个方块按 E，箱子从当前位置短暂安全对齐到手前。空地中慢速、快速转向并移动、跳跃，完成对齐后的箱体应与人物稳定保持同一相对姿态，不出现滞后；上下观察不改变水平持握位置。持箱直走与其他方块碰撞时，人物与箱子应作为整体响应并保持持握，人物不能追进箱子。转身时箱体路径碰到其他方块，应在转动前的安全位置自动放下，人物和镜头继续正常转向；起终点都空但途中经过障碍也要触发。贴地切向和远离已有接触不能误放。实际箱体始终可见，长按 E 不重复拿放。
6. 松开后再次按 E，方块从当前物理位置释放，保留速度并自然下落，不能瞬间落到面前地面。分别在站立、移动、快速转向与跳跃时释放，检查自由箱体的惯性、落地碰撞和滚动；继续转动和移动，箱子不再追逐手前目标。走远后按 E 不会拾取，走近后可以再次拿起。
7. 按 [世界检查器](../usage.md#世界检查器) 的切换前约束结束交互，再按 F3，光标应显示，游戏模拟仍运行，WASD／空格／E 和鼠标位移均不控制角色；点击检查器内外均保持该模式。再次按 F3 恢复游戏控制，检查器仍显示。切换到其他窗口后应释放鼠标，回到游戏窗口后仍需按 F3 恢复。恢复时镜头不应因释放期间的位移突然跳转。Esc 的暂停与恢复另按上面的菜单验收步骤检查。
8. 默认设置下用外部帧率监测工具观察帧率：性能足够时应接近 60 FPS，性能不足时可低于上限。把 `settings.json` 中的 `max_fps` 改为 `120` 后重新启动，观察上限提高，相同输入下人物加速、减速、跳跃与箱体掉落过程应保持一致，相同鼠标位移对应的旋转幅度也应相同。在 60 FPS 与 120 FPS 设置下都重复第 2～6 项，确认人物和箱体运动平滑、无固定步交替造成的抖动或虚影；持箱时的固定握姿与整体阻挡、释放后的惯性应在两种帧率下都保持一致，第一人称无人物遮挡。两次会话日志中的 `simulation_hz` 应均约为 `60`，`max_fps_after` 分别为 `60` 和 `120`。另将 `max_fps` 改为 `59` 后重新启动，本次日志应记录设置无效的警告及回退上限 `60`，原设置文件仍保留 `59`；改为 `60` 后重新启动，应成功加载且不再出现该警告。完成后恢复默认设置 `60`。
9. 正常关闭窗口后，按 [日志检查与问题反馈](#日志检查与问题反馈) 核对本次会话的启动配置、移动、起跳着陆、拿放、相机捕获及退出记录，再次启动确认会话文件隔离。

同批次拾取预留、持有者销毁或关系异常解除后的目标清理、恢复碰撞与自然下落由无窗口回归验证。

## 人物移动与镜头验收

先在 `max_fps = 60`，再在 `120` 下检查第一人称移动与持物的连续性：

1. 空手依次按 W、S、A、D，再按 WA、WD、SA、SD；应分别前走、倒走、左右横移和斜向移动，人物继续面朝视角方向。松键后随真实减速自然停稳，推动自由方块时碰撞正常。
2. 按住移动键，缓慢及快速转动鼠标，并反复反向或绕满一圈；镜头和持物应响应本帧朝向，持物不相隔一帧追赶。观察起停时是否存在明显漂浮或抖动。
3. 对三个方块分别重复上述移动、转向与 E 拿放。对齐后的箱体与人物共同保持持握姿态；直走受阻不挤进身体，转向路径受阻自动放下且镜头不锁住。空手／持箱按空格时眼位自然升降并稳定落地，连续按住空格不能再次起跳。
4. 持箱移动时暂停并恢复，再返回主菜单重新进入游戏。暂停保持当前姿态，恢复时镜头不跳转，重新开始镜头平视，只有初始的三个方块和一台玩法相机。
5. 从平地边缘离开后角色继续下落，按 Esc 返回主菜单再重新开始，角色与方块恢复初始布局。

提交问题时保留对应会话日志、帧率设置和操作顺序，详细角度与速度采样按 [日志排查](../development.md#日志排查) 启用。

## 世界检查器验收

1. 选择 `Start Game` 并运行时应显示 `World Inspector`；主菜单、暂停及从暂停打开的设置／帮助均隐藏检查器。展开 `Entities`、`Resources`、`Assets`，确认能找到人物、方块和相机，以及 `PrototypeConfig`、网格和材质。展开人物组件应能查看移动意图和运动状态。
2. 按 F3 后将光标移到面板并点击、拖动或滚动，应保持光标自由，镜头不转动。把面板拖到窗口中央，松开鼠标后点击面板外，仍应保持检查器模式。结束交互并按 F3 恢复游戏控制后，持续移动并点击左键，人物不应因隐藏光标重叠面板而停下，面板字段也不应改变。再次按 F3 后应能正常点击和编辑；每次切换前按 [世界检查器](../usage.md#世界检查器) 结束输入手势，不用 Esc 代替 F3。
3. 检查器模式下，分别在字段内和面板外按 W、E 或空格，人物均不应移动、跳跃或拿放。完成编辑并点击空白处移除字段焦点、关闭菜单，松开其他键鼠后按 F3，游戏控制应恢复且镜头不跳转；随后重新按 W、E 或空格应正常响应。
4. 检查本次会话日志，启动时应包含来自 `demo::inspector` 的 `World inspector enabled`，字段为 `plugin="WorldInspectorPlugin"` 与 `reason="initialization"`。这表示检查器插件注册，即使启动主菜单未显示面板也应输出；开始、暂停、恢复及重新进入游戏不重复输出该初始化记录。上下文停用与恢复应记录输入状态变化，正常退出后历史会话文件保留。
5. 展开人物和方块根实体的物理运动组件与 `Transform`，结束交互后按 F3 恢复游戏控制，移动、持握或释放箱体时检查速度和位置变化；箱体静止后运动变化应停止。组件标题的金色边框依据 Bevy 变化标记，插值系统和持续可变访问也可能保持高亮，不能据此单独判断箱体仍在运动。

无窗口回归只检查模式切换、Egui 输入转发、输入上下文与组件状态，不安装窗口后端或渲染插件；面板排版、鼠标交互手感和资产预览需用户按以上步骤验收。

## 音频验收

以下步骤覆盖当前接入的菜单声音与音量设置。

1. 在主菜单用鼠标移入按钮，再用方向键或手柄改变焦点，真实焦点变化应有短反馈。静止光标、按钮内移动、无效操作、当前分类重选和单按钮页面的无效导航不反复发声。
2. 打开 `Settings → Audio`，确认 `Master Volume / UI Volume` 两行默认 `100%`。按钮与左右导航每次调整 `5%`，拖动滑条能得到整数百分比，改变期间立即预览，释放且数值改变后只确认一次。任一音量为 `0%` 时菜单静音，恢复后只对新操作发声。
3. 切换分类保留草稿与预览，`Back / Esc` 恢复已应用音量。`Restore Defaults` 预览默认值，返回时丢弃，`Apply` 成功后重新启动应保留两项音量。保存失败保留草稿预览、原文件与已应用值，返回后恢复已应用音量。
4. 暂停中重复菜单导航与音量编辑，声音继续反馈，角色与方块保持暂停。恢复与返回主菜单使用返回音，正常退出停止声音。
5. 可用 [逐项试听页面](../../assets/audio/audition.html) 评审当前音频素材的区别、起止与响度。检查会话日志中的 `Audio pipeline initialized`、资源请求、菜单请求与混音变化。素材来源和技术检查见 [音频管线](../audio.md)，问题反馈附会话日志及音量设置。

## 日志检查与问题反馈

会话文件命名和位置见 [使用说明](../usage.md#会话日志)，日志规则与调试过滤配置见 [开发规范](../development.md)。验收时先确认本次文件的会话开始时间、版本和配置，再将日志中的实体、前后值和原因与操作步骤对应。

- `demo::gameplay` 的 `Prototype gameplay initialized`、`demo::settings` 的 `Fixed simulation timestep initialized` 与 `demo::inspector` 的 `World inspector enabled` 均应以 `info` 级别各出现一次，三条之间无先后要求。玩法记录应对应实际 `PrototypeConfig`，固定模拟频率应对应实际 `Time<Fixed>`；暂停、恢复和重新开始游戏不能重复这些启动记录。用户覆盖 `RUST_LOG` 时按实际过滤规则核对，低于过滤级别的记录缺失不能直接判定插件未注册。
- 鼠标捕获及实际移动输入的离散变化，默认以 `info` 级别落盘，应能对应释放、恢复、失焦和移动输入变化。
- 场景日志记录平地、玩家、控制者、相机与方块生成。玩法日志记录起跳、接地变化，以及 `Carryable item picked up`、`Carryable item released`，物理碰撞日志用于核对阻挡发生的实体。释放日志应对应释放前的真实位置和速度，异常关联清理应记录原因。所有日志写入本次会话日志，反馈问题时保留该文件。
- 相机随会话生成时记录 `Greybox session spawned`，包含 `camera`、`character`、`controller`、`position` 和 `reason`；相机目标或控制者丢失时记录警告。初始眼位与镜头跟随按上述步骤确认。
- 视角角度和世界移动速度属于连续数据，以 `debug` 级别每 0.5 秒最多采样一次；默认日志中没有这些采样不代表功能没有执行。需要排查时，由用户按开发规范中的过滤配置自行启动。
- 状态变化日志应包含时间、级别、模块或系统、相关实体或业务 ID、变化前后值和触发原因；错误应保留操作、相关文件路径和原始错误信息。
- 后台输出期间文件和控制台显示可能稍有延迟，不据此判断事件未发生。正常退出后确认退出记录存在、已入队记录排空并刷新、文件末尾无缺失或截断；再次启动并正常退出后应生成新文件，旧文件保留。异常退出时检查最后保留下来的上下文；不要为补充日志而覆盖或删除旧会话文件。

反馈问题时提供复现步骤、实际结果与预期结果、相关设置，以及对应会话日志文件。日志用于问题排查，不能恢复游戏进度。
