# 游戏手动验收

本指南供用户在真实游戏窗口中检查已有功能。先完成验收准备，再选择受本次变更影响的部分；修改共享控件、输入、物理或调度时，要覆盖其所有使用场景。开发者的命令与无窗口覆盖范围见 [验证参考](README.md)。

这些步骤只描述操作和预期，不代表已执行或通过。Agent 不启动或操作游戏；用户反馈仅确认实际报告的场景，未执行的帧率、平台与边界应单独标明。

## 验收准备

以下命令和步骤仅供用户自行执行。请在仓库根目录启动游戏：

```powershell
cargo run --locked
```

先按 [使用说明](../usage.md#美术与字体准备) 准备 GLB 与字体。在 worktree 验收时，从该 worktree 根目录启动，并使用该目录的 `logs/unix-<时间戳>_<会话UUID>.log`，不要混用其他检出的会话。排版、动画、真实输入和听感必须在实际窗口与设备上确认。

Windows MSVC 用户先确认能够显示主菜单并创建本次 `logs/unix-<时间戳>_<会话UUID>.log`，再按菜单验收第 5、6 步检查 16:9 拖拽、最大化与 DPI，并核对窗口策略安装日志。若以 `0xc0000139`（`STATUS_ENTRYPOINT_NOT_FOUND`）或其他错误在应用初始化前退出、没有新日志，保留终端退出码和构建目标；这不能证明游戏内窗口策略已运行。

## 英文菜单与暂停验收

1. 启动后应显示英文主菜单，左侧按钮、纸张面板与底部操作提示清晰，鼠标悬停或实际导航时显示黄色高亮；右侧为真实快递员、包裹、快递站和海岛展示舞台。页脚键帽 `Arrows / Enter / Esc` 及其说明必须完整可见，不能只有边框或空白。主菜单不显示世界检查器，不创建可操控角色。快递员应循环播放展示动作，包裹附件位置应合理。若背景缺项，检查本次 `logs/unix-<时间戳>_<会话UUID>.log` 的 `Menu asset failed to load` 路径；动画异常检查 `Menu courier animation could not start`。
2. 用鼠标、方向键和 Enter 分别操作；长按 Enter 不应反复开始或确认。对每个可交互按钮检查鼠标进入高亮、移到空白恢复；再用键盘或手柄导航，应显示当前焦点，静止光标不抢焦点，真实移动到空白应清除导航高亮。键盘焦点应跳过灰色 `Continue`、`Multiplayer`；点击它们应保持当前页面，显示 `Coming Soon`，不加载存档或加入房间。进入 `How to Play`，检查 `01 / 02 / 03`、卡片标题、`WASD / Space / E / E again / Mouse / Esc` 键位文字完整可见；黄色编号块仅作装饰，不响应鼠标或键盘。`Back` 与 Esc 返回主菜单。
3. 进入 `Settings`，四个分类都能打开。左侧分类与右侧底部 `Restore Defaults / Apply / Back` 应始终可见，只有右侧纸色面板中的 `SETTINGS` 标题、分类项目、说明与保存提示可滚动。对照 [使用说明](../usage.md#菜单与占位功能) 检查所有未实现项显示 `Coming Soon`，点击不改变值，方向键焦点跳过。`Graphics` 的 `Frame Rate Limit` 应完整显示 `< 数值 FPS >`，左右箭头和数值均可见；`Controls` 的 `Mouse Sensitivity / Invert Camera Y` 可以调整，当前字段的右侧说明与焦点对应。`Audio` 的三项音量应完整显示名称、左右箭头、滑条和百分比，`0%` 显示 `Muted`，`Test SFX` 可操作而 `Music Volume` 不可操作；听感与分类隔离按 [音频验收](#音频验收) 完成。检查三个底部操作的文字完整显示，逐一悬停再离开均恢复普通颜色；当前分类和 `Apply` 不常驻黄色。
4. 先将右侧面板滚动到 `Frame Rate Limit`，连续点击左右箭头，再用键盘调整，应只更新数值，面板与滑块保持当前位置，控件不消失或跳回顶部；对其他可调字段重复。选择 `Restore Defaults` 和 `Apply` 后，数值与提示更新也应保持滚动位置，只有内容变短、原偏移超出新范围时允许适度夹取。调整草稿后选择 `Back` 或按 Esc，再进入设置，应恢复上次生效值及音量，并按新页面初始化滚动位置；切换分类同样不沿用旧页面偏移。选择 `Restore Defaults` 后先返回，不应写入默认值；再次恢复默认并 `Apply`，应显示 `Settings applied.`，`settings.json` 保存完整有效内容（包括三项 `audio` 字段）。音量编辑与恢复默认立即预览，分类切换保留草稿与预览；调整后 `Apply` 不必重启即可保存音量并影响帧率或鼠标设置；若保存失败，原文件与运行设置应保持，页面保留草稿、音量预览与合法滚动位置并原位给出英文重试提示，返回后恢复已应用音量。
5. 在 Windows 或 macOS 拖动四边与四角放大、缩小，窗口内容区应始终保持 16:9；检查最小 `960×540`、初始 `1280×720` 及可容纳的大尺寸。主菜单、暂停与帮助的全部内容不应重叠或裁切，帮助的三张卡片、完整正文、键位与 `Back` 应同时可见；在三个页面的按钮、卡片与空白处滚动鼠标滚轮／触控板，并用方向键轮换焦点，页面位置应保持。进入设置，右侧纸色面板内容超过高度时，其右侧应出现滚动条：在面板内滚动滚轮、拖动滑块和点击轨道均只移动面板内容，滑块位置同步变化，拖到两端不越界，左侧分类、底部三个操作与页脚保持原位。再分别在左侧分类、底部操作和外层空白处滚动，面板与整页均不应移动；用方向键移到面板内的越界字段时应自动滚入，导航到固定分类或底部操作时不应移动面板。切换分类或放大到面板内容无需滚动时，滚动条应隐藏；缩小后再次出现时比例正确。拖动中返回或切换分类，新页面不应跟随旧滑块继续移动；返回主菜单、暂停或帮助后仍无滚动。`UI Scale` 占位不提供窗口尺寸或手动比例控制。
6. 点击最大化、双击标题栏，并在 Windows 检查系统贴靠及 `Win+方向键`：应保持工作区内可见的 16:9 内容区；macOS 不进入系统全屏与全屏平铺；桌面平铺后仍应恢复为符合比例的窗口。可用时拖到不同 DPI 的屏幕再缩放，比例与按钮命中应正常；最小化、恢复和关闭窗口仍正常。本次 `logs/unix-<时间戳>_<会话UUID>.log` 应包含 `Window policy initialized` 与 `Native window aspect ratio policy installed`，Windows 跨 DPI 时另有 `Native window policy DPI changed`。实际缩放与视觉验收由用户完成。
7. 选择 `Start Game` 后菜单展示舞台消失，先准备海岛资源与碰撞，就绪后进入完整海岛、一名玩家、普通纸箱和易碎纸箱各一件、三只木箱与一台玩法相机的场景；运行时显示世界检查器。游戏中按 Esc，应出现暂停菜单并显示光标；移动鼠标、按 WASD／Space／E 或点击菜单空白处，均不应控制角色、转动镜头或恢复捕获。腾空、持箱或箱体下落时暂停，观察人物、箱体与主角动画应保持；加载阶段暂停也不应提前生成玩家。
8. 暂停中进入设置或帮助，再返回，游戏仍保持暂停且角色／箱体状态不重置。选择 `Resume` 或在暂停根页面按 Esc，恢复当前场景并捕获鼠标；镜头不应因暂停时移动光标而跳转，不应补发暂停前未消费的跳跃或拿放操作。
9. 暂停菜单选择 `Back to Main Menu`，应回到完整展示舞台。再次 `Start Game` 应重新准备一套海岛场景，只有一名玩家、五件初始可搬物品与一台玩法相机。反复切换时不得出现旧地图、碰撞、NPC、持有关系或相机残留，不得叠加两套场景或检查器。也在加载阶段返回主菜单后重新开始，确认迟到的地图就绪通知不会影响新会话。主菜单选择 `Quit` 应正常退出并保留本次日志。

菜单与设置日志预期包含 `Application state changed`、`Menu page changed`、`Menu backdrop spawned`，成功保存有 `Game settings saved` 与 `Game settings saved and applied`；错误带操作、路径与英文原因。排查设置滚动条时，用户在自行启动前设置 `RUST_LOG=info,demo::ui=debug`（PowerShell：`$env:RUST_LOG = "info,demo::ui=debug"`），在本次 `logs/unix-<时间戳>_<会话UUID>.log` 中检查 `Settings scrollbar visibility changed` 的英文显隐与尺寸字段；正常级别不要求包含该调试记录，排查结束后按 [日志排查](../development.md#日志排查) 移除环境覆盖。未进入 `Start Game` 就退出时，不要求出现玩法实体生成或跳跃／拿放日志。

## 物理交互验收

选择 `Start Game` 后按下面九项检查当前 demo。设置文件的字段、默认值和有效范围见 [使用说明](../usage.md#设置)。

1. 资源准备后以第一人称看到完整海岛、前方普通纸箱和易碎纸箱，物流总站内的柜台与货架之间有三只木箱；箱体应保留相对三角布局，不穿入墙体或柜台。初始镜头位于角色脚底上方 `1.65 m`，水平向前，自己的角色模型不遮挡镜头；建筑保持原有外观。
2. 站立并移动鼠标，镜头可左右观察和上下俯仰，人物水平朝向同步变化且位置不变；持续向上下移动鼠标，应在 `-85°..85°` 的边界停止，无侧倾。按下或长按 I 不改变视角、人物位置或拿放状态。
3. 转动镜头后按 W / S，人物沿视角的水平前后方向逐渐加速，松键后较快减速；按 A / D 时横移，后退和横移都不改变朝向。斜向输入不会提高目标速度，镜头持续跟随；上下观察不改变水平移动方向。向建筑侧墙移动应受阻，沿墙横移仍能移动；用人物推自由纸箱和木箱，箱子应因碰撞移动，人物不应穿过墙体或箱体。
4. 按空格时人物起跳并自然落地，第一人称眼位随人物升降；持续按住或在空中再次按下不会额外起跳。贴墙时不能凭墙面重复空中起跳。
5. 分别靠近普通纸箱、易碎纸箱和木箱按 E，箱子从当前位置短暂安全对齐到手前。空地中慢速、快速转向并移动、跳跃，完成对齐后的箱体应与人物稳定保持同一相对姿态，不出现滞后；上下观察不改变水平持握位置。持箱直走顶住建筑或 NPC 时，人物与箱子应一起停住并保持持握，人物不能追进箱子。转身时箱体路径碰到墙、NPC 或其他箱体，应在转动前的安全位置自动放下，人物和镜头继续正常转向；起终点都空但途中经过障碍也要触发。贴地切向和从墙面转离不能误放。实际箱体始终可见，长按 E 不重复拿放。
6. 松开后再次按 E，纸箱或木箱从当前物理位置释放，保留速度并自然下落，不能瞬间落到面前地面。分别在站立、移动、快速转向与跳跃时释放，检查自由箱体的惯性、落地碰撞和滚动；继续转动和移动，箱子不再追逐手前目标。走远后按 E 不会拾取，走近后可以再次拿起；把箱体留在墙另一侧，隔墙时即使处于拾取范围也不应拿起，绕到无遮挡的一侧应可拾取。
7. 按 F3 后光标显示，游戏仍运行，移动鼠标不再转动镜头。左键点击检查器之外的游戏区域恢复鼠标控制。切换到其他窗口后应释放鼠标，回到游戏窗口后仍需左键点击恢复。恢复时镜头不应因释放期间的位移突然跳转。Esc 的暂停与恢复另按上面的菜单验收步骤检查。
8. 默认设置下用外部帧率监测工具观察帧率：性能足够时应接近 60 FPS，性能不足时可低于上限。把 `settings.json` 中的 `max_fps` 改为 `120` 后重新启动，观察上限提高，相同输入下人物加速、减速、跳跃与箱体掉落过程应保持一致，相同鼠标位移对应的旋转幅度也应相同。在 60 FPS 与 120 FPS 设置下都重复第 2～6 项，确认人物和箱体运动平滑、无固定步交替造成的抖动或虚影；持箱时的固定握姿与整体阻挡、释放后的惯性应在两种帧率下都保持一致，第一人称无人物遮挡。两次会话日志中的 `simulation_hz` 应均约为 `60`，`max_fps_after` 分别为 `60` 和 `120`。另将 `max_fps` 改为 `59` 后重新启动，本次日志应记录设置无效的警告及回退上限 `60`，原设置文件仍保留 `59`；改为 `60` 后重新启动，应成功加载且不再出现该警告。完成后恢复默认设置 `60`。
9. 正常关闭窗口后查看 `logs/` 中本次 `unix-<时间戳>_<会话UUID>.log`，应包含会话开始、版本和配置、实体生成、移动输入变化、起跳着陆、拿起放下和正常退出。四项集中启动日志 `Prototype gameplay initialized`、`Fixed simulation timestep initialized`、`Camera pose synchronization configured`、`World inspector enabled` 应各出现一次，日志 target 分别为 `demo::gameplay`、`demo::settings`、`demo::camera`、`demo::inspector`，不要求四条之间的先后顺序。`demo::camera` 的英文日志还记录相机生成与鼠标捕获变化，便于核对释放、恢复和失焦原因；相机目标或控制者丢失时记录警告。再次启动应生成新文件，旧文件保留。

同批次拾取预留、持有者销毁或关系异常解除后的目标清理、恢复碰撞与自然下落由无窗口回归验证。

## NPC 碰撞验收

本节检查四名 NPC 的身体碰撞贴合、阻挡和通行手感。

1. 选择 `Start Game`，依次找到物流总站调度员、Pizza 店员、Music 店员和居民。空手从可接近的正面与侧面持续走向其身体：人物应在身体附近受阻，沿身体边缘能绕开，不应穿过躯干；NPC 始终保留原位置与姿态。目测阻挡位置不能明显离开人物身体，也不能延伸成挡住入口或周围通道的大墙。
2. 分别用玩家推动自由纸箱与木箱接近 NPC，再持普通纸箱、易碎纸箱和木箱向 NPC 前进或转向。自由、手持箱体都应在碰到 NPC 身体时受阻，不穿过躯干；完成对齐后握姿固定，直走受阻时人物与箱子一起停住并保持持握，转向路径受阻时在原安全位置自动放下且镜头继续转动。NPC 不被推动，释放后箱体仍自然下落并保持碰撞。
3. 在第一人称下重复空手与持箱阻挡。NPC 保持原有外观，按 E 不会拿起 NPC，也不出现对话或商店操作；主角移动、拿放与观察仍正常。
4. 暂停后恢复，NPC 与碰撞保持当前场景；返回主菜单，再次 `Start Game` 后应只出现四名 NPC，各自身体附近的阻挡位置一致，不残留上一会话的不可见障碍。
5. 正常退出后检查本次日志：每次进入新的游戏会话，应有四条 `demo::scene` 的 `Display NPC collider initialized`，包含 `npc`、`collider`、`height`、`radius` 和 `reason="npc_collision_ready"`；暂停恢复不应重复输出。`Island colliders ready` 的 `npc_count` 与 `npc_collider_count` 均应为 `4`，`collider_count` 包含 NPC 身体碰撞。使用发生碰撞时的双方实体记录辅助定位。若身体贴合、穿透或通道出现异常，提供 NPC 所在位置、接近方向、箱体类型、视角、实际结果及对应会话日志。日志只能辅助排查，不能代替上述目测与操作检查。

## 海岛美术与落水验收

1. 环顾并走访海岛，确认地形、海水、棕榈、荒草、物流总站、Pizza 店、Music 店与两栋居民木屋正确显示。NPC、建筑和箱体应保持正常比例与内置材质颜色；NPC 为调度员、两名店员和居民，没有地图展示主角或重复木箱残留，自己的角色模型保持隐藏。
2. 依次走上三个商铺及两栋住宅的入口台阶，再到码头；应能沿入口上到平台并站稳，五处台阶与对应地板的衔接处不因门槛或间隙卡住人物、使人物下陷或把人物弹开，商铺前厅没有被整栋碰撞封住。尝试走向建筑侧墙、固定道具和棕榈树干，应受到对应结构阻挡；草和叶片不应阻挡行走，海水不能充当陆地地面。
3. 站立、行走、松键减速，再分别拿起和放下三种箱体。第一人称镜头应平稳跟随，箱体完成对齐后相对人物的位置稳定，较大的木箱稍向前留出空间；快速转向应保持握持姿态，转向遇到阻挡则在转动前的位置放下。详细移动与镜头边界按下文检查。四名 NPC 的身体阻挡按 [NPC 碰撞验收](#npc-碰撞验收) 检查；NPC 与柜台、货架上的固定纸箱、商店摆件不能交互或搬走。
4. 先空手从岸边走入海中，再持箱重复。人物下沉后应回到出生点，清除落水前速度和待执行的跳跃、拿放请求；松开移动键后应停稳，继续按住移动键时仍可以继续行走。持箱落水后箱子解除跟随，尚未落水的箱子从真实位置自然下落。把普通纸箱、易碎纸箱和木箱分别推落或放落海中，箱体自身落水后应回到各自初始位置，恢复自由碰撞并稳定落地，没有旧位置拖影或重复实例。
5. 在 `max_fps = 60` 与 `120` 下重复平台通行、拿放与落水恢复，确认第一人称下行为一致。检查本次 `logs/unix-<时间戳>_<会话UUID>.log` 中的资源加载、地图与碰撞准备、动态实体生成、动画及恢复记录；失败时提供对应资源路径、错误上下文和实际操作步骤。
6. 在物流站入口平台与室内，保持相同构建模式、窗口尺寸和检查器展开状态，分别设置 `max_fps = 60`、`120`。等待加载与初始物体运动稳定后，先驻足转动视角，再在平台上行走、转向，反复上下入口台阶并跨过门槛进入室内。用同一外部帧率工具分别记录驻足与移动的 FPS、帧时间，确认行走流畅，人物站稳、转向及通行正常；性能足够时接近对应上限，不要求硬件一定达到 120 FPS。正常退出后保留各次 `logs/unix-<时间戳>_<会话UUID>.log`，核对 `simulation_hz`、`max_fps_after`、会话标识与退出记录；行走中的移动、接地、碰撞和动画状态变化应完整保留。结果写入关联 Issue 或 PR。该项实机 FPS 验收须由用户完成，无窗口测试通过不代表已经验收。

发布包检查还应确认携带完整的 `assets/`，由用户在发布包预期的工作目录自行启动。缺失资源时不应出现悬空玩家或无碰撞的可玩地图；本次会话日志应提供路径和加载错误供排查。

## 人物移动与镜头验收

先在 `max_fps = 60`，再在 `120` 下检查第一人称移动与持物的连续性：

1. 空手依次按 W、S、A、D，再按 WA、WD、SA、SD；应分别前走、倒走、左右横移和斜向移动，人物继续面朝视角方向。松键后随真实减速自然停稳，靠墙持续按移动键时不能穿墙。
2. 按住移动键，缓慢及快速转动鼠标，并反复反向或绕满一圈；镜头和持物应响应本帧朝向，持物不相隔一帧追赶。观察起停、坡面通行时是否存在明显漂浮或抖动，自己的角色模型始终隐藏。
3. 对普通纸箱、易碎纸箱和木箱分别重复上述移动、转向与 E 拿放。对齐后的箱体与人物共同保持持握姿态；直走受阻不挤进身体，转向路径受阻自动放下且镜头不锁住。空手／持箱按空格时眼位自然升降并稳定落地，连续按住空格不能再次起跳。
4. 在建筑侧墙、转角、低屋顶和门口观察，镜头保持角色眼位，建筑外观保持正常，身体与实际持物仍受结构碰撞阻挡。
5. 持箱移动时暂停并恢复，再返回主菜单重新进入游戏；暂停保持当前姿态，恢复时镜头不跳转。主菜单仍是 `Carry_Idle` 展示；重新开始镜头平视，没有上一会话的相机或动画关联。

角色动画仍在后台更新，自身模型隐藏后，动画绑定与混合通过无窗口回归检查；主菜单展示动画可直接目测。查看本次 `logs/unix-<时间戳>_<会话UUID>.log` 的 `Courier animation initialized / changed / detached` 以及资产错误。动画初始化应包含 `clip_count=16`；详细角度与速度采样按 [日志排查](../development.md#日志排查) 启用。提交问题时保留对应会话日志、帧率设置和操作顺序。

动作文件与运行时混合检查见 [海岛资源与无窗口验证](README.md#海岛资源与无窗口验证)；文件检查不能替代本节的第一人称移动与持物验收。

## 世界检查器验收

1. 选择 `Start Game` 并运行时应显示 `World Inspector`；主菜单、暂停及从暂停打开的设置／帮助均隐藏检查器。展开 `Entities`、`Resources`、`Assets`，确认能找到人物、木箱和相机，以及 `PrototypeConfig`、网格和材质。展开人物组件应能查看移动意图和运动状态。
2. 按 F3 后将光标移到面板并点击、拖动或滚动，应保持光标自由，镜头不转动。也检查从面板外快速移入并立即点击，不应重新捕获鼠标。把面板拖到窗口中央，再点击面板外恢复控制；持续移动并点击左键，人物不应因隐藏光标重叠面板而停下，面板字段也不应改变。再次按 F3 后应能正常点击和编辑；不要用 Esc 代替 F3，Esc 会暂停并隐藏检查器。
3. 在检查器字段中输入 W、E 或空格，人物不应移动、跳跃或拿放；原先持续移动的输入在上下文停用后应清零。点击面板外恢复控制时镜头不跳转，单次动作需松开后重新按下才触发。
4. 检查本次 `logs/unix-<时间戳>_<会话UUID>.log`，启动时应包含来自 `demo::inspector` 的 `World inspector enabled`，字段为 `plugin="WorldInspectorPlugin"` 与 `reason="initialization"`。这表示检查器插件注册，即使启动主菜单未显示面板也应输出；开始、暂停、恢复及重新进入游戏不重复输出该初始化记录。上下文停用与恢复应记录输入状态变化，正常退出后历史会话文件保留。
5. 展开人物和木箱根实体的物理运动组件与 `Transform`，点击面板外恢复控制，移动、持握或释放箱体时检查速度和位置变化；箱体静止后运动变化应停止。组件标题的金色边框依据 Bevy 变化标记，插值系统和持续可变访问也可能保持高亮，不能据此单独判断箱体仍在运动。

无窗口回归只检查 Egui 命中、输入上下文与组件状态，不安装窗口后端或渲染插件；面板排版、鼠标交互手感和资产预览需用户按以上步骤验收。

## 音频验收

音频文件的技术检查与试听工具见 [音频管线](../audio.md#重现与检查)。质量报告不能替代人耳听感和真实设备输出；试听页只操作独立音频工具，不操作游戏。

1. 打开 [逐项试听页面](../../assets/audio/audition.html)，将监听音量先调低，逐条播放菜单、拾取、交接、碰撞、弹开、警告与交付结果。预期各声可区别、起止没有明显点击、没有过长静音或过响；切换素材自动停止上一声。循环合成底声至少听三个周期，检查接缝与重复感。真实海浪、风和推车候选显示未下载；合成底声不得标为真实录音。
2. 自行启动游戏，在主菜单用鼠标移入可操作按钮，再用方向键或手柄改变焦点，每次实际变化应有短焦点音；快速变化允许受 75 ms 冷却限制。光标停住、在同一按钮内部移动、离开按钮和页面重建不应重复发声。进入帮助后仅有一个返回按钮，继续按导航键不应反复播放焦点音；`Coming Soon` 项也不发声。
3. 在主菜单进入 `Settings → Audio`，先确认三项默认 `100%` 保持原有响度。按钮、左右方向键或手柄每次调整 `5%`；拖动滑条可得到如 `37%` 的整数百分比，改变过程中音量立即变化但不连续响确认音，放开且数值改变后仅反馈一次。把音量调到边界后继续调整不发声；三行文字、数值与滑条在窄窗口中仍完整可见。切换设置分类并返回，草稿和预览保留。
4. 分别把 `SFX Volume` 和 `UI Volume` 调为 `0%`：前者应显示 `Muted` 且 `Test SFX` 无声，菜单导航仍有声音；后者应让菜单静音，但 `Test SFX` 仍可播放。总音量为 `0%` 时两者都无声。恢复音量后仅新的操作发声，不补播静音期间的导航或试听请求。在试听声播放期间调整相应音量，当前声音也应同步变化；`Test SFX` 不生成物品、不移动角色、不建立持有关系。
5. 调整音量后用 `Back / Esc` 返回，重新进入设置应恢复最近一次成功应用的值和听感。`Restore Defaults` 应立即预览三个 `100%`，返回不保存；再次编辑并 `Apply`，应保存完整 `audio` 字段且重新启动仍采用已保存值。打开其他设置／帮助、改变分类、实际调整帧率或鼠标设置、恢复默认及成功应用仍使用确认音，返回用返回音；反馈服从当时有效的总音量与 UI 音量。若保存失败，保留草稿及其临时听感并显示英文重试提示，原文件和已应用值不变，返回后恢复已应用音量；故障条件及操作记录放入对应 Issue 或 PR。
6. 选择 `Start Game`，游戏中按 Esc 打开暂停应有确认音。暂停期间菜单反馈与 `Test SFX` 仍可用，并重复第 3～5 项音量预览、分类隔离、应用和返回检查；返回暂停页后角色／箱体仍暂停。`Resume / Esc` 恢复及 `Back to Main Menu` 应有返回音。暂停时不应新增落地或持握警告，试听只播放已有素材。`Quit` 正常退出并停止声音，不要求退出确认音完整播放。
7. 游戏运行时分别靠近普通纸箱、易碎纸箱和木箱按 E，成功拿起只提示一次；走远后按 E 不播放成功提示。持握时再次按 E 提示释放，真正撞击地面时另有落地声；当前共用第一版落地素材，静置后没有连续撞击声，侧面碰墙不会冒充落地。应用较低 `SFX Volume` 后重复，应降低玩法音效而不改变菜单音量；应用 `0%` 后这些声音静音，但玩法动作仍正常。
8. 持箱直走顶墙或 NPC，人物与箱子应一起停住，保持受阻不持续鸣叫。附近转向遇到阻挡应自动放下并提示一次释放，镜头继续自由转动；正常拾取对齐和空旷处快速转向不应频繁报警。在第一人称、60/120 FPS 下分别检查，音效不改变物理规则。
9. 交接、推车、弹开与交付结果等素材仅在试听页评审，素材名称不代表已确定玩法。合成环境底声不会在场景中自动播放。
10. 检查本次 `logs/unix-<时间戳>_<会话UUID>.log`：包含 `Audio pipeline initialized`、各 `Audio asset requested` 和获准反馈的 `Audio cue queued`；菜单操作有 `Menu audio cue emitted`，与排队日志的 `event="menu_hover" / "menu_confirm" / "menu_cancel"` 对照，落地与警告有 `Audio cue emitted`。预览进入／退出和正式配置变化有 `Audio mix changed`，箭头调整和拖动放手汇总有 `Audio volume preview changed`；试听有 `Audio sample requested` 与 `reason="settings_preview"`，成功保存有 `Game settings saved` 与 `Game settings saved and applied`，加载／保存／应用应包含三项音量，失败记录操作与路径。无声时先看音量和 `Muted` 状态，再看 `Audio asset failed to load` 的路径与错误及 Kira 的 `Failed to setup audio`。必要时用户以 `RUST_LOG=info,demo::audio=debug` 自行启动，检查 `Audio cue skipped` 是否因 `reason="muted"`、加载、冷却或并发上限；正常退出应有 `Audio channels stopped`，保留历史会话。

以上步骤描述预期结果，实际听感、设备输出和游戏验证由用户完成；具体一次运行记录放在关联 Issue 或 PR。

## 日志检查与问题反馈

会话文件命名和位置见 [使用说明](../usage.md#会话日志)，日志规则与调试过滤配置见 [开发规范](../development.md)。验收时先确认本次文件的会话开始时间和配置，再将日志中的实体、前后值和原因与操作步骤对应。

- 用户自行启动后，正常退出并检查本次会话文件：`demo::gameplay` 的 `Prototype gameplay initialized`、`demo::settings` 的 `Fixed simulation timestep initialized`、`demo::camera` 的 `Camera pose synchronization configured` 与 `demo::inspector` 的 `World inspector enabled` 均应以 `info` 级别各出现一次。玩法记录应对应实际 `PrototypeConfig`，固定模拟频率应对应实际 `Time<Fixed>`；暂停、恢复和重新开始游戏不能重复这些启动记录。确认正常退出记录存在、已入队日志排空并刷新完成，文件末尾没有缺失或截断；再次自行启动并正常退出后，应生成新的会话文件，第一份文件仍保留且未被覆盖。用户覆盖 `RUST_LOG` 时按实际过滤规则核对，低于过滤级别的记录缺失不能直接判定插件未注册。
- 鼠标捕获及实际移动输入的离散变化，默认以 `info` 级别落盘，应能对应释放、恢复、失焦和移动输入变化。
- 启动时应有 `Camera pose synchronization configured`，字段为 `simulation_schedule="FixedUpdate"`、`carry_schedule="FixedUpdate"`、`grip_mode="shared_body"`、`physics_schedule="FixedPostUpdate"`、`presentation_schedule="RunFixedMainLoop"`、`presentation_order="interpolation_character_facing_carry_pose_camera_visibility"`。这条日志说明采用的同步配置，人物与箱体运动、持握转动与镜头跟随是否稳定仍需按上述步骤目测确认。
- 美术与场景日志应记录所需资源的加载、失败路径、地图实例与碰撞准备状态，以及动态实体生成；结构碰撞日志用于核对实际地图范围和组成。玩法日志记录起跳、接地变化，以及 `Carryable item picked up`、`Carryable item released`；物理碰撞日志用于核对阻挡发生的实体。释放日志应能对应释放前的真实位置和速度；异常关联清理应记录原因。所有日志均写入本次 `logs/unix-<时间戳>_<会话UUID>.log`，提供问题反馈时保留该文件。
- `demo::character_animation` 应记录 `Courier animation initialized` 与 `Courier animation changed`，动作字段匹配实际命名动作，如 `Idle`、`Walk`、`Carry_Idle`；切换日志包含 `animation_before`、`animation_after` 和原因，持续播放同一动作不逐帧重复输出切换记录。绑定失败应保留缺失动作或失效关联信息。
- `demo::island_recovery` 的 `Entity recovered after entering water` 应包含恢复实体、`position_before`、`position_after` 和 `reason="water_recovery"`；持箱落水还应出现 `Held item released during water recovery`，确认解除持握。连续更新不应重复记录同一次恢复。恢复后箱体碰撞与人物输入是否正确仍需结合无窗口回归和上述用户步骤确认。
- 相机生成应记录 `First-person camera spawned`，包含 `camera`、`character`、`controller`、`position` 和 `reason`；初始眼位、镜头跟随与自身模型隐藏按上述步骤确认。
- 视角角度和世界移动速度属于连续数据，以 `debug` 级别每 0.5 秒最多采样一次；默认日志中没有这些采样不代表功能没有执行。需要排查时，由用户按开发规范中的过滤配置自行启动。
- 状态变化日志应包含时间、级别、模块或系统、相关实体或业务 ID、变化前后值和触发原因；错误应保留操作、相关文件路径和原始错误信息。
- 后台输出期间文件和控制台显示可能稍有延迟，不据此判断事件未发生；正常退出应记录退出、等待已入队记录写完并刷新日志，再读取本次会话文件核对完整性。异常退出时检查最后保留下来的上下文；不要为补充日志而覆盖或删除旧会话文件。

反馈问题时提供复现步骤、实际结果与预期结果、相关设置，以及对应会话日志文件。运行日志和游戏存档分别管理，日志不能作为存档使用。
