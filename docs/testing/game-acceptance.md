# 人工补充验收

非音频客观行为、画面、原生窗口、性能和日志的验收条件见[应用自动化验收](app-acceptance.md)，检查器见[专项验证](inspector.md#世界检查器验收)。本指南保留主观判断与本套应用自动化排除的音频验收入口，不要求人工重复客观清单。自动化未实现或环境缺失时，对应条目保持待实现／未验证，不能因目前没有脚本就视为只能手工。

普通游戏仍由用户启动和操作，Agent 使用[验收构建](README.md#agent-验证边界)。当前驱动范围见[自动化覆盖](app-acceptance.md#当前驱动范围)，结果按实际范围写入对应 Issue 或 PR；用户反馈只确认其报告的条件。

## 验收准备

先看自动化报告和缺口，只选择受变更影响的人工项。需要在普通游戏中确认时，用户从对应 worktree 工作目录启动并保留[会话日志](../player-guide.md#会话日志)，不混用其他检出的设置与日志：

```powershell
cargo run --locked
```

## 主观视觉与操作体验

1. 首次引入或有意改变视觉基线时，由用户批准风格、构图与表现是否符合预期。后续文字缺失、裁切、比例、穿透、材质异常、抖动和虚影等按[自动化画面与连续呈现检查](app-acceptance.md#判定与证据)执行，不作为每次都需用户目测的理由。
2. 客观输入延迟、速度、姿态和连续性检查之后，用户评价鼠标、移动、跳跃、持物和实体设备的主观舒适度，例如是否容易晕动或疲劳。若能明确成响应时间、误差等可重复指标，应补入自动化契约，后续不再重复手测该指标。

## 音频验收

音频不纳入本套应用自动化驱动，当前的触发、音量预览、混音、静音、正常退出与设备听感条件由用户按[音频模块验收](audio.md#音频验收)执行。原有素材工具与无窗口音频测试保留。应用验收报告不包含听感判定。

只评价当前接入的菜单反馈，素材与事件范围见[音频事件合同](../assets/audio/events.md)。录音与数字测量不能单独证明目标扬声器或耳机的主观辨识度、音色和舒适度；未执行设备与条件分别报告。

## 确实无法自动驱动的专项

只有具体平台路径无法通过受控接口可靠触发或观测，并记录原因和已覆盖的替代路径时，才追加人工专项，列出环境、操作、预期与范围。多显示器、系统贴靠、macOS 全屏／平铺等不预设为人工项；缺平台、缺硬件或驱动未开发属于自动化缺口。人工执行一条不能把其他平台或缺口标为通过。

## 日志检查与问题反馈

非音频日志字段、计数、过滤、刷新和会话隔离由[自动化日志验收](app-acceptance.md#会话日志)负责。人工反馈附对应日志、设置、设备与环境、复现步骤、预期及实际感受；引用已有自动化产物，不手工重抄断言。保留原会话文件，日志不能恢复游戏进度。
