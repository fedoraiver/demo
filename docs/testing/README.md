# 验证参考

本文供开发者按变更范围选择检查，维护无窗口测试、链接产物和静态架构文档的验证契约。开发规则见 [开发规范](../development.md)，当前机制见 [架构说明](../architecture.md)。游戏窗口、真实输入、画面和听感按 [游戏手动验收](game-acceptance.md) 由用户检查；操作与配置见 [使用说明](../usage.md)。

测试文件命名、插件归属和模块注册遵循 [测试代码组织](../development.md#测试代码组织)。

验收清单描述预期结果，不代表已经执行。用户反馈只确认其实际报告的场景，不能据此推断其他帧率、边界条件或完整清单均已通过；每次变更实际完成的检查、失败结果和未验证事项记录在关联 Issue 或 PR 中。

## Agent 验证边界

游戏只能由用户启动和操作。Agent 不通过 `cargo run`、可执行程序、脚本、Computer Use 或其他间接方式启动游戏，也不截取游戏画面、录屏或模拟键鼠。用户提供的日志可直接分析，无需启动游戏。

Agent 可阅读代码、检查格式和编译，并执行最小 `App` / `World` 的无窗口测试；不创建游戏窗口、加载完整游戏或依赖桌面交互。架构图维护允许 Agent 运行 `--dump-schedules` 专用 debugdump 导出：该入口只完成插件装配并导出，不执行 `Startup`、游戏循环或渲染线程。它可能初始化 GPU、音频设备并请求资产，不属于最小无窗口测试；此例外不允许省略导出参数或启动、操作游戏。静态架构 HTML / SVG 的视觉检查不属于游戏运行，允许查看，临时输出放在根 `tmp/`。

交付时分别报告自动检查、用户实际验收及未完成项；需要实机确认时，给出对应验收步骤、预期和日志位置。

## 按变更类型选择检查

| 变更类型                                     | 必须执行的检查                                                                                                                                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仅修改普通文档                               | 检查内容是否准确、职责是否重复、相对链接与引用是否有效。不需要执行游戏或 Rust 检查。                                                                                                                                                                          |
| 修改架构图清单、关系、布局、生成器或生成产物 | 按 [项目 Skill 维护](../diagrams/README.md#项目-skill-维护) 生成并校验最终产物，运行相关 Node.js 无窗口回归；SVG 视觉验证仅在用户明确要求时按[检查范围](#架构图视觉检查)执行，自动检查与实际观察分别记录。 |
| 修改架构图或源码页的 VS Code 入口            | 按 [架构图源码定位验证](#架构图源码定位验证) 执行 URI、根目录配置及生成页交互的无窗口回归；实际浏览器与 VS Code 协议验收按[停用范围](#架构图视觉检查)不再执行。 |
| 仅修改架构图维护 Skill 的 Markdown 说明      | 检查 [Skill](../../.agents/skills/update-ecs-architecture/SKILL.md) 的入口、触发范围、步骤与相对链接，确认使用当前工作区、保留已有修改、不自动暂存或提交。未修改架构图及其工具时，不要求重新生成产物或执行图形验收。普通代码修改和 Git 提交不触发架构图更新。 |
| 修改架构图维护 Skill 的执行脚本              | 运行 `docs/diagrams/tests/` 中相关维护回归，核对统一入口、依赖解析、工作区与复用失效边界；涉及 SVG 栅格化时使用隔离静态夹具。未修改生成器、模型、布局或正式产物时，不要求专用导出、重建产物或图形验收；栅格化截图仍为待检，不计实际目测通过。 |
| 修改 Rust 代码                               | 阅读相关实现，运行 `cargo fmt --all -- --check` 和 `cargo check --locked`。                                                                                                                                                                                   |
| 修改行为                                     | 在 Rust 检查之外，增加或运行有针对性的无窗口测试，验证相关组件变化、查询过滤、消息或调度结果；运行或视觉效果交给用户手动验收。                                                                                                                                |

Rust 检查命令：

```powershell
cargo fmt --all -- --check
cargo check --locked
```

行为测试可按测试名称或模块选择；需要运行仓库全部无窗口测试时使用：

```powershell
cargo test --locked
```

测试应检验实际业务行为和边界条件。只使用最小测试环境；即使命令属于测试，也不能借此创建窗口或启动完整游戏。

## 单字段结构体约束

修改项目 Rust 源码后、提交 PR 前，运行[具名字段检查入口](../../scripts/check-named-fields.ps1)。它使用[共享编译器工具](../../tools/rustc-analysis/Cargo.toml)，执行工具格式、共享工具与规则回归，再检查项目全部 Cargo 目标和共享工具自身。规则回归入口保留在[兼容测试包](../../tools/check-named-fields/Cargo.toml)，其 CLI、报告和 driver 委托统一实现。

```powershell
pwsh -NoProfile -File ./scripts/check-named-fields.ps1
pwsh -NoProfile -File ./scripts/check-named-fields.ps1 -Features debugdump
```

`-Target`、`-Features`、`-AllFeatures` 只选择根项目的编译配置；嵌套工具使用独立请求，不继承这些选项。未显式指定平台时遵循各自 Cargo 配置，features 默认启用各自默认集合；嵌套工具的依赖先行顺序见[维护缓存](../diagrams/README.md#生成与校验命令)。脚本通过自身路径选择检出，退出时恢复工作目录与临时环境。工具产物位于根 `tmp/rustc-analysis/`，Cargo 分析缓存和逐次报告位于短目录 `tmp/ra/`，回归夹具也只写入根 `tmp/`。工具链与组件见[开发规范](../development.md#技术栈与版本)。

规则通过 Cargo wrapper 接入 `cargo check --all-targets`，在 `after_expansion` 检查完成条件编译与宏展开的 AST。启用的生产、测试、示例、基准和构建脚本目标均参与；第三方宏在被检查 crate 生成的类型也参与，依赖 crate 的内部类型不参与。未启用分支和未加载文件不计入范围；模块、宏或 `include!` 引入的类型按真实展开结果检查。

恰好一个字段的元组结构体报错；具名字段、无字段标记、多字段元组结构体和枚举变体允许。诊断包含声明、真实行列、目标和可取得的宏调用／定义链，同一声明跨目标合并，不同宏调用位置分别保留。Cargo 编译单元与本次分析报告共同核验完整性；编译、宏展开、ABI 或报告错误不能作为无违规结果。

命令退出码为 `0`（通过）、`1`（字段违规）或 `2`（工具错误）。编译游戏测试目标只用于检查，不执行游戏测试程序或启动游戏。

## 实体命名检查

实体命名约束见[开发规范](../development.md#entity实体只表示身份)。[检查入口](../../scripts/check-entity-names.ps1)使用共享 rustc 宿主的真实类型、宏来源和 MIR，检查项目生产 lib／bin 创建时的组件与 BSN 组合；创建后补名不满足规则。测试夹具、第三方内部实体和导入资产内部节点不计入规则范围。

```powershell
pwsh -NoProfile -File ./scripts/check-entity-names.ps1
pwsh -NoProfile -File ./scripts/check-entity-names.ps1 -Features debugdump
```

入口执行共享工具与[实体规则回归包](../../tools/check-entity-names/Cargo.toml)的检查，再以选定配置检查生产源码。`-Target`、`-Features` 和 `-AllFeatures` 的选择与具名字段入口一致，跨目标检查需要对应 Rust 标准库。Cargo 准备构建脚本和过程宏，不执行被检查程序。

实体规则和架构装配分析复用[编译器值流](../../tools/rustc-analysis/compiler/src/entity/analysis.rs)、trait 实例、常量求值及活跃性分析。调用摘要跟踪泛型、引用修改、闭包捕获、有限分支和装箱前场景；递归与状态扩张在预算内处理。Bundle、required 构造和 BSN 分别提供证据，父实体与子实体独立验证。`-Zalways-encode-mir` 和 `-Zmir-opt-level=0` 只作用于专用分析编译。

确定缺少 `Name` 或可确定空名时输出 `error[entity-name]`；无法确认名称存在性时输出 `error[unresolved-name]`，两者均使检查失败。确认 `Name` 存在且没有确定空名时通过，不因其余动态组件报错；动态名称通过不表示非空性已获证明，父实体有名称也不能掩盖子实体缺名。

诊断包含源码、行列、调用或宏来源、实体层级和具体原因。编译、宏展开、必要 MIR 或报告异常属于工具错误。命令退出码为 `0`（通过）、`1`（违规或名称存在性无法判定）或 `2`（工具错误）；缓存与报告边界见[编译器事实检查](#编译器事实与架构模型检查)。

## 会话日志无窗口验证

在仓库根按范围运行：

```powershell
cargo test --locked game_flow::tests::initialization_tests
cargo test --locked session_log::
```

[初始化日志测试](../../src/game_flow/tests.rs) 安装真实功能插件并执行 `Startup`；手工注册日志系统不能证明插件实际完成注册。[日志测试](../../src/session_log/tests.rs) 检查下列会话生命周期与后台输出边界，不能只凭短时间内没有阻塞或文件存在判定通过。

| 场景                 | 必须保留的契约                                                                                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 功能插件初始化       | 玩法、设置和检查器三个插件各记录一次，缺少插件不报告该功能初始化，后续更新不重复；字段取启动时最终 `PrototypeConfig` 和 `Time<Fixed>`，日志系统不覆盖配置。保留 target、`info` 级别、英文消息，检查器字段含 `plugin="WorldInspectorPlugin"`、`reason="initialization"`。 |
| 文件或控制台阻塞     | 生产者仍能返回，控制台阻塞不妨碍文件独立写入和刷新；解除阻塞后核对完整数量与顺序，不靠绝对耗时判定。                                                                                                                                                   |
| 刷新、panic 与关闭   | 同步屏障之前的短写记录全部完成；panic hook 返回时文件已有异常上下文。正常退出排空已接受记录，关闭拒绝新记录，并刷新和回收线程，不能仅依赖发送端析构。                                                                                                  |
| 设备与线程故障       | 写入、刷新、同步和线程 panic 均反馈失败；控制台故障不回退到同步 stderr，也不阻塞健康文件的 panic 同步，退出和关闭仍报告错误。                                                                                                                          |
| 格式、过滤与会话隔离 | 时间、级别、target 和结构化字段齐全，文件无 ANSI 色码；显式 `RUST_LOG` 同时作用于文件和控制台，每次会话新建文件，不覆盖历史。                                                                                                                          |

全局 `LogPlugin` 与环境变量隔离放在独立测试子进程，其余检查可使用局部 subscriber。临时文件使用根 `tmp/`；本节不安装窗口或渲染器。用户对真实会话文件的检查见 [日志检查与问题反馈](game-acceptance.md#日志检查与问题反馈)。

## 场景与无窗口验证

灰盒场景与物理检查见 [场景测试](../../src/scene_assembly/tests.rs)，在仓库根目录执行。

```powershell
cargo test --locked scene_assembly::tests
cargo test --locked character::tests
cargo test --locked physics::tests
```

场景测试使用最小 `App / World`，只注册所需资源、BSN、变换和物理设施。检查开始时装配一套平地、玩家、控制者、相机、灯光与三个方块，网格与碰撞位于业务根。执行真实物理步验证接地和方块落地，通过真实 E 动作验证拿放。暂停与恢复保留实体，返回主菜单完整清理，连续开始只出现一套初始场景。

这些检查覆盖组件、资源、层级和物理结果。场景显示、输入手感及帧间稳定性仍按 [物理交互验收](game-acceptance.md#物理交互验收) 由用户确认。

休眠身体的首步行为由角色和物理回归共同检查：静置足够时间后仍进入 `Sleeping`，继续静置不被自身回写唤醒；随后主动移动、跳跃或外部冲量必须在首个真实固定步改变位移与速度。首步加速度位移按实际固定步长与 `SubstepCount` 的半隐式 Euler 序列计算，不能用改变速度但未完成物理积分的状态作为通过依据。

高速薄墙回归 `character_ccd_blocks_high_speed_velocity_and_impulses_at_different_yaws` 用 `SpeculativeCcd::new(0.001)` 限制推测接触距离，以不同水平 yaw 验证角色受到初速度或外部冲量后仍被扫掠阻挡。先完成一次高速物理步建立引擎预测邻域，再创建薄墙并检查后续实际固定步；用 `CcdFilter::NONE` 显式关闭扫掠的对照应穿过同一薄墙，避免 Avian 的自动 CCD 或推测接触造成假通过。不能仅在零 yaw 下验证，也不能将线性算法当作与当前非线性算法等效的替代。无窗口结果只验证 CPU 物理开销和行为，不能证明真实渲染 FPS；具体耗时和执行结果记录在关联 Issue 或 PR 中。

`character_ccd_keeps_dynamic_body_protection_after_plugin_upgrade` 验证高速角色被动态薄墙逐帧阻挡，以 Avian 默认过滤的穿墙对照证明动态过滤位必要。`approaching_fast_dynamic_bodies_keep_their_order_with_predictive_neighbors` 覆盖角色与箱体、两个箱体高速相向运动：使用真实身体工厂，先推进一个尚未交会的高速步建立预测邻域，再逐帧保持顺序与最小间距；只移除双方 `SpeculativeCcd` 的对照应在随后的首个交会步交叉，证明速度扩张邻域参与候选生成，不能仅靠扫掠组件存在判断安全。

## 菜单、设置与资产的无窗口验证

菜单回归只使用最小 `App / World`、必要的状态／输入插件和 BSN 实体树，不安装窗口后端或渲染器。UI 夹具显式安装第三方 `EnhancedInputPlugin`，通过与 `GameUiPlugin` 共用的普通注册函数安装菜单生命周期、真实输入与页面，不依赖 `FirstPersonPlugin`。跨功能夹具显式安装所需项目 Plugin；需要状态时安装 `GameFlowPlugin` 并进入运行状态，没有应用状态时复用 `game_flow::configure_feature_order`，不补跑系统代替实际调度。应覆盖：

- 页面只暴露可用的 `MenuButton` 动作，导航序号连续；`Continue`、`Multiplayer` 和所有 `Coming Soon` 设置不进入焦点或业务动作列表。
- 菜单动作使用真实 Enhanced Input 绑定，长按确认／返回不重复执行；鼠标和键盘请求进入同一消费入口，页面切换后旧请求不穿透。
- 原生 Picking 与 Button 的实际链路覆盖主键同帧按下／释放、文字子节点命中、右键／中键、取消后再次按键及重建旧目标；只接受主键菜单动作，音量滑条同帧完整点击仍采样并结束，其他指针键不改变主键高亮或执行请求。按钮取得原生焦点后，Space 只产生未消费的原生 `Activate`，Enter 仍只经 Enhanced Input 执行一次。
- 文字测量、按钮移入／移出、输入来源切换与重建后的焦点按 [文字布局与高亮回归](#文字布局与高亮回归) 检查。
- 主菜单、暂停与帮助在支持的 16:9 视口内完整显示且不滚动；设置仅右侧纸色面板内容可滚动。具体布局、滚动条和刷新边界见 [文字布局与高亮回归](#文字布局与高亮回归)。
- `AppState` 的 `MainMenu / Running / Paused` 切换管理会话与暂停；离开主菜单创建会话，返回主菜单清理平地及业务实体，`Running / Paused` 切换保留角色、箱体、控制者、相机与持有关系；暂停当帧清意图并停止物理步。恢复不补发跳跃／拿放请求。从暂停设置同时通过键盘和旧按钮返回后，连续两帧仍保持暂停。
- 主菜单与暂停释放光标并停用玩法上下文；恢复运行跳过自由光标位移。F3 可在游戏与检查器模式间双向切换；检查器模式停用全部玩法输入，面板内外点击均不恢复捕获。
- 设置草稿的应用、取消与恢复默认值；有效自定义值打开页面后保留，帧率预设和灵敏度步进不越界；非法值、序列化或写入失败不修改当前生效设置或原文件。
- `audio` 的总音量与 UI 音量缺省为 `100`，覆盖 `0 / 100` 及非法值。旧 `audio.sfx_volume` 读取时忽略，当前音量、帧率和相机值正常保留，保存时省略退休字段。其他未知字段、重复当前字段及非法值继续拒绝，读取失败不修改原文件。
- 音量草稿即时预览，切换分类保留编辑，`Apply` 成功后保存，`Back / Esc` 回滚，恢复默认只预览。保存失败保留原文件、已应用值及草稿预览。
- 当前 Audio 页提供总音量与 UI 音量两行调整，每行箭头、滑条、百分比／`Muted` 测量有效并进入连续导航，Music 为占位。拖动不重建页面或连续发送确认音，释放且值改变时反馈一次。
- 设置字段、恢复默认与应用结果原位刷新，保持控件身份、焦点和有效滚动偏移；离开重进或切换分类才重建页面。
- 设置默认帧率上限为 `60`，省略 `max_fps` 或文件缺失时采用默认值；`59` 拒绝，`60` 与 `120` 可解析。无效文件回退到 `60` 且原文件不变。设置文件保存创建与替换的完整 JSON 回读；Windows 下独占文件句柄导致替换失败时保留原文件。设置测试与保存暂存文件分别位于根 `tmp/settings-tests/`、`tmp/settings-save/`。
- 离开主菜单清理背景根及菜单相机，保留无关相机。

检查入口为 [状态与暂停测试](../../src/game_flow/tests.rs)、[菜单测试](../../src/ui/tests.rs) 和 [设置持久化测试](../../src/settings/tests.rs)。可按模块选择运行，例如：

```powershell
cargo test --locked settings::tests
cargo test --locked ui::
```

窗口策略回归用 `cargo test --locked window_policy::`：覆盖初始 16:9、最小尺寸、无窗口应用不安装原生后端、Windows 拖边／拖角锚点及角内拖缩小、DPI 物理最小尺寸、工作区最大化和重复请求幂等。平台无关几何与 Windows 桥接共用源码，macOS 也运行这些数学检查，并检查工作区内容尺寸拟合；原生消息、跨屏和实际最大化效果由用户验收。

## 编译器事实与架构模型检查

架构维护的正式入口见[生成与校验命令](../diagrams/README.md#生成与校验命令)。共享分析工具分为无 rustc 依赖的契约层、编译器层和普通运行层；Node 只消费语义模型及原始 DOT，不重做源码扫描或新旧模型等价比较。

检查具名字段、实体规则和工具回归后，按需独立提取与装配：

```powershell
pwsh -NoProfile -File ./scripts/rustc-analysis.ps1 extract --workspace . --out tmp/ecs-architecture/compiler
pwsh -NoProfile -File ./scripts/rustc-analysis.ps1 model --facts tmp/ecs-architecture/compiler/facts.json --runtime tmp/ecs-architecture/compiler/runtime.json --annotations docs/diagrams/catalog/annotations.json --out tmp/ecs-architecture/compiler/model.json
```

提取夹具覆盖同名类型、别名、重导出、关联类型、类型与常量实参、宏／`include!`、条件编译及源码定位；访问和操作夹具区分容器同名方法、存在过滤、可变借用与实际修改，并覆盖 helper、闭包、Commands、主／子世界和明确缺口。装配夹具覆盖 Bundle、BSN、required components、子实体及可确认的生命周期。测试依据源码与新契约，不使用旧扫描器产物作为答案。

运行时绑定覆盖重复注册、不同泛型、闭包、组合系统、自定义名称、匿名集合和跨应用同名 Schedule。声明、类型实例、实体模板和每次注册分别检查身份，不以名字或行号合并；编译器事实与快照来自匹配构建，缺少必要绑定不得通过。

三个入口均核对冷／热运行：无修改时复用根包和依赖报告，run 或请求路径变化不重编，缓存违规结果仍返回失败；只改项目源码时确认本地报告记录实际启用增量，未改依赖仍为 Cargo `fresh`。缓存位置、v2 契约、输入证明与单次局部恢复规则见[维护缓存](../diagrams/README.md#生成与校验命令)。

共享工具的 `driver_inputs`、`incremental_entries` 与 `incremental_disk` 回归分别检查编译器读时输入、真实 Cargo 三入口及磁盘增量多会话。输入变化覆盖 `include!`／二进制 include、生成文件、环境、负文件探测与展开期间源码变化；缓存恢复覆盖缺失和损坏报告。单元绑定还须覆盖 normal/test、lib/bin、精确包来源、host/target 和 unit graph 顺序及非等价闭包，包含自身配置相同而子依赖 features／profile 不同的真实 Cargo 冷／热运行。恢复回归核对无关本轮报告的保留、重编报告的替换，以及原始报告 SHA 或输入快照改变时拒绝保留。磁盘回归使用 `Compilation::Continue` 完成代码生成，以原生会话计数证明加载前次增量图，并运行 `-Zincremental-verify-ich`，同时核对原生 TypeId 与便携编码隔离。

嵌套工具回归覆盖普通／dev／build 依赖、默认启用的可选依赖、`build.target`、根不可达单元和包级环，检查依赖先行、剩余原序与冷／热复用。候选消歧回归覆盖完整／不完整 `extern` 名表、未加载但仍登记的 `--extern`、混合 Rust／artifact 库及二进制、示例库、构建脚本、artifact-only 例外，候选换序后仍须通过完整证明。

身份与用途回归覆盖相同源码跨 worktree、Cargo metadata 与纯移行的稳定性，以及精确包、Name、初始化值、引用常量和 helper 真正变化时的失效；多个 owning unit 行为冲突不能静默择先。绘图复用由[跨工作树原生回归](../diagrams/tests/mermaid-worktree-cache.test.mjs)覆盖共享池和仅有正式产物的冷 checkout；缺失输入指纹、损坏引用或绘图输入变化必须重编，命中继续核对原生文字、几何和路由。缓存恢复不能把旧源码位置覆盖回当前关系证据。

参数关系还须交换单元与访问顺序，核对直接 `Extract` 和间接 helper 的原生作用域、参数槽及来源成对保留；作用域冲突或间接访问不得覆盖成单一入口作用域，Local 仍表示原来的存储域。相同类型 ID 的多个原生显示路径还须覆盖逆序与重复单元，确认名称与用途不因导入顺序变化。

自动功能分组的展示入口须覆盖单插件、多插件和显式配置；交换单元与访问顺序后，选择的现有对象、插件安装关系及用途应保持一致。

用途局部证明还须检查 trait impl 新增、删除、约束、关联类型、成员覆盖和默认体／helper 变化，包含 generic／blanket impl。完整清单按实际元数据视图认证，空集合也参与比较；证书缺失、不同视图清单冲突或未建模行为必须回退。改变无关普通函数体时，已证明独立的用途及绘图输入应保持稳定；单次运行的命中数量和耗时写入验证记录，不将某台机器的收益作为固定门槛。

重复常量 DAG 回归须验证有限展开后的明确用途回退、叶节点变化后的失效和逐声明预算原因；真实 driver 同时核对通用 `inputs.complete` 仍为真，避免把语义预算回退变成每次清理重编。未支持成员采用浅层证据时，普通函数体与关联类型变化仍须分别改变对应成员证据。

隐式析构诊断转存须核对完整多单元和源码记录、输入绑定、对象提示及用途失效判断，其他业务缺口保持公开。文本分发继续按 UTF-8 字节执行 100 MiB 上限；达到或超过边界时，真实写入器须保留既有目标与暂存文件，大型调用图仍走独立的流式完整性校验路径。

模型缺少必要中文用途时写入 `pending-descriptions.json` 并返回 `3`。维护 Skill 的大模型读取确切源码与 helper，在 `annotations.json` 补写用途和证据哈希，再恢复模型及受影响下游。回归须确认用途补写不改结构事实、事实未变不重提取、说明失效会重新进入待补状态，且未补齐前不发布正式产物。

## 调度导出验证

导出入口和生成步骤见[生成与校验命令](../diagrams/README.md#生成与校验命令)。Agent 检查默认构建、可选 feature 构建及最小无窗口导出测试：

```powershell
cargo fmt --all -- --check
cargo check --locked
cargo check --locked --features debugdump
cargo test --locked --features debugdump inspector::
```

最小夹具检查系统、SystemSet 及依赖边进入 DOT 与结构化快照，原生键和真实类型关联一致；主应用与子应用同名 Schedule 保持独立；状态值、泛型及特殊字符标签不破坏文件身份；导出不执行 Startup 或调度系统；参数、调度初始化及文件写入失败不报告成功。子应用需覆盖真实 `Extract` 参数初始化，核实其访问原主世界，并在成功、构图失败及初始化 panic 后恢复原 `WorldId`、实体和资源；不能用空 `MainWorld` 代替真实上下文。夹具不安装完整窗口、渲染或音频设施，也不调用真实应用导出命令。

执行专用完整导出时，确认不出现游戏窗口、不进入 Startup，主应用、物理调度及渲染子应用按实际注册进入清单；成功返回零，可返回的错误以非零退出并完成会话日志收尾，初始化 panic 记录异常且不发布清单。插件装配期间可能访问 GPU、音频设备及资产，不以没有窗口推断无设备依赖。导出成功后，再检查清单、编译器事实和运行时快照的构建关联、源码指纹、DOT 哈希、Graphviz 渲染及最终 HTML；缺少真实导出时只报告已通过的代码检查，不能用夹具产物交付。

## 调度筛选与页面回归

筛选语义与离线渲染边界由[调度筛选与重新布局](../diagrams/README.md#调度筛选与重新布局)维护。仅修改查看器、过滤模型或呈现样式时，沿用源码指纹匹配的正式 DOT 重建，不需要重新运行应用导出或执行 Rust 检查。运行相关 Node.js 回归及产物校验，正式页面的实际浏览器检查按[停用范围](#架构图视觉检查)处理。

无窗口回归覆盖来源组目录与系统完整路径的对应、项目 Plugin 与依赖 crate 分组、无法确认来源的名称，以及参数中的类型不改变函数来源。检查多组选中取并集、排除优先、选中组在当前 Schedule 无系统时为零命中；旧完整名称条件仍检查大小写、名称内逗号及同名不同注册，旧文本仍检查子串匹配、逗号 OR 和空项处理。三类包含条件取 OR，各类排除共同否决；集合名不匹配系统。核对命中系统、必要祖先集合与 marker、保留边两端及 `lhead`／`ltail`；不得加入系统邻居、复制原边或穿越删除系统补边。原生上下文端点按保留规则检查，不计入系统数，不补造名称或引回未命中系统。检查 DOT 转换前后的节点、边、有效属性和集合层级一致，特殊字符保留，未知输入格式明确失败。零命中返回空状态，空筛选恢复预编译 SVG 且不创建 Worker 或 WASM 实例。

页面回归覆盖包含／排除下拉只列来源组、各自搜索、逐项选择、全选搜索结果中当前有系统的组，以及单栏和全部清空。勾选、取消及清空立即生效，不等待连续操作停顿；搜索不改变实际筛选条件，没有应用按钮或 Enter 提交。核对重排前后下拉展开状态、搜索词、滚动位置和焦点保留，旧条件取消后在当前下拉中仍可重新勾选；异步完成只更新画布和状态，不重建当前选项。切换 Schedule 保留选择，没有本图系统的组、未知组 ID 及旧条件仍可查看和取消。检查每次有效操作只新增一条历史，批量操作一次、相同条件零次；视角只关联实际成功呈现的条件，尚未完成或失败的历史条件返回时重排并适合窗口。

核对 Worker 复用、连续快速操作的迟到结果丢弃、过滤中切页与取消、错误反馈及上次成功图保留。检查重复的 `scheduleIncludePlugin`／`scheduleExcludePlugin` 与兼容的系统、文本参数同 `schedule`、对象来源及工作区参数共同保存，刷新、返回原视图和浏览器前进／后退恢复筛选及有效视角。顶栏选图准确反映当前 Schedule、插件及搜索进入的普通对象；对象搜索使用浮层，选择后显示卡片说明。

对象搜索按[搜索规则](../diagrams/README.md#对象搜索)检查身份字段、类别与排序。覆盖仅在 `runtime`、说明或关联对象中出现关键词的反例，精确名称优先、大小写、普通多词 AND、下划线与 CamelCase、泛型实参及 `Res`／`ResMut` 写法；多类别取并集并与查询类别取交集，同名的不同类型实例、实体模板和重复注册不合并。验证空查询提示、类别即时生效、长名称换行，以及列表与对象图高亮使用同一命中集合。分别在两类图的 SVG 内外空白处点击，确认浮层关闭且搜索词、类别和视角保留，选择、拖动及合成点击仍正常。覆盖 Escape、键盘导航、重新聚焦、类别修改后的焦点，以及搜索期间切图、失败重试、迟到响应和历史恢复；已关闭浮层和已清除高亮不得被异步完成重新展开或恢复。旧历史缺少类别时按全部处理。

以下正式 HTTP 页面与断网目录的实际验收步骤仅在用户明确重新要求时执行，日常维护按[停用范围](#架构图视觉检查)完成相关自动回归。启用后按[本地自动预览](../diagrams/README.md#本地自动预览)预先启动服务，从服务输出的 `http://127.0.0.1:<端口>/pages/ecs-architecture.html` 打开最终页面并显式配置工作区。初次页面加载由本地服务提供；页面载入后按需读取本地 SVG 和 JSON，切换视图与筛选确实重新布局，不请求 CDN、额外 WASM 或字体，清空全部选择与旧条件时直接显示默认 SVG。验证 Worker 或 WASM 不可用时仍能浏览预编译结果，动态 SVG 不接受脚本、事件属性或外部引用。

离线目录验收在断网后通过同一本地服务进行，检查视图切换、搜索、源码及筛选重新布局；直接打开主 HTML 应显示服务启动说明。核对缓存最多八张视图、快速切图与取消、资源缺失或哈希不符、失败重试、深链接及历史恢复。HTTP、静态包与 Node WASM 检查分别记录，浏览器策略拒绝后的停止要求见[本地自动预览](../diagrams/README.md#本地自动预览)。

## 架构图源码定位验证

修改架构图或源码页的编辑器入口时，按[生成与校验命令](../diagrams/README.md#生成与校验命令)，在仓库根完成文档依赖安装、构建、产物校验和相关无窗口回归。

无窗口回归应检查 Windows 盘符、路径分隔符、空格、中文、`#` 与 `%` 的 URI 编码，编译器记录的行列与缺失列时的默认 `1`，非法定位和根目录输入，`file://` 推导与覆盖、HTTP 或搬移后的显式配置，以及主检出与 worktree 配置的隔离。覆盖 `workspace` 参数、目录 URL 对应的浏览器存储与推导值的优先级；存储被禁用时配置仍在本页生效，并通过同目录导航链接传播。测试生成后的页面脚本，确认对象节点／连线详情和源码页当前文件／行使用同一编辑器入口；详情不提供离线快照跳转，VS Code、定位路径和复制定位仍可用。加载、选择节点及更新配置不调用外部协议，只有用户点击才发出请求；未配置项目根目录时显示局部提示，已有 Cargo 根目录的依赖声明仍可定位。独立源码页继续校验项目与依赖的完整文件快照。检查插件入口进入 Plugin／PluginGroup 单卡对象图，Schedule 在鼠标左键单击或 Enter／Space 激活对象时显示详情，选择不自动打开外部协议；检查源码入口、对象关系图往返及历史恢复。`schedule`、[调度筛选参数](../diagrams/README.md#调度筛选与重新布局)、`scheduleNode`、`object`、`node` 导航保留 `workspace`、其他查询参数与片段；旧对象身份失效时不按短名重定向。

节点与连线源码按[源码范围](../diagrams/README.md#源码范围)逐类核对。`sourceEntries` 直接来自编译器模型，检查角色、去重、分组及标签；Component 以真实类型定义为入口，具体实体模板上的创建、插入、移除和销毁证据保留在对应装配或操作关系，不能混成类型始终具有的生命周期。System／Observer 保留自身定义及可确认的注册；未确认入口与动态目标保留具体 `sourceGaps`，不以类型定义替代实际调用或操作。

使用真实编译器来源格式覆盖 `\\?\C:\...`、`\\?\UNC\server\share\...` 及非法设备命名空间。生成页面测试运行真实源码编辑器，核对角色标题只出现一次、额外条目标签保留、定位控件与 URI 可用；依赖根缺失或非法时显示原因与相对定位，不退回项目根。区分列号缺失与 `0`、负数、非整数、`null` 等非法值，后者不得变成默认列 `1`。

Bevy 和第三方定义依据真实提供包和锁定版本定位，特别核对项目别名、宏生成声明及 Avian 二维／三维重名类型。按编译器契约检查真实声明身份、完整类型实参和每次注册，以及包名、版本、根目录、相对路径、行列、宏来源、完整快照和目录外逃。Cargo 路径与锁定包来自分析运行，不维护声明正则或本机目录映射；工作区配置只改变项目定位，不能覆盖依赖根。独立源码页的完整快照与两份页面的本机定位分别验证。

复制定位的回归覆盖节点详情和源码页：成功时仅当前按钮显示“已复制”，通过 `aria-live` 宣告结果，`2` 秒后恢复；重复点击重新计时，不影响其他复制按钮。失败时在当前控件附近提示并保留手动选择复制入口，不宣告成功。两份页面都不显示底部目录状态栏或重复的源码打开方式、快照时效说明；VS Code 入口、定位路径、复制定位、源码页行定位状态和必要错误反馈仍可用。工作区配置保留输入、保存、恢复默认及局部校验反馈，使用边界见 [源码使用说明](../diagrams/README.md#在-vs-code-中打开源码)。

## 架构图视觉检查

架构图变更后，按[维护 Skill](../../.agents/skills/update-ecs-architecture/SKILL.md)完成真实调度输入、对象语义、Graphviz／Mermaid 编译、文字与几何、产物及无窗口交互回归检查。统一工具确认源码、配置、工具链及来源上下文匹配时复用真实 DOT，不为页面变化重复导出。对象分类调整按当前模型契约核对声明、具体类型、注册、实体模板、关系和有效证据覆盖。

HTTP 浏览器与 VS Code 协议验收不再执行，不主动请求启用，也不列为待办、未验证缺项或交付阻断条件。维护状态记录为 `not-required`，相关 URI、资源加载及交互自动回归继续执行。只有用户明确重新要求时才使用本文保留的实际验收步骤；启用 SVG 目测不自动启用这两项。已有执行记录保留，不把不需要验收改记为自动通过。

SVG 视觉验证默认关闭，包括逐图或抽样目测、用于视觉验收的栅格化截图及联系表；只有用户明确重新要求时启用。默认交付记录已跳过，不要求额外确认，不因没有目测证据阻止交付，也不称目测通过。编译、模型、文字与几何、产物及交互自动回归继续执行。临时日志和按需启用的视觉证据放根 `tmp/`，执行结果写入对应 Issue 或 PR；长期文档只保留可复用步骤，不启动或操作游戏。

用户明确启用 SVG 视觉验证时，按当前路径、图身份与完整 SHA-256 查找可追溯的实际目测通过记录，匹配时复用；只重新目测缺少有效当前记录的 SVG。未限定抽样范围时覆盖全部当前清单，限定抽样时如实记录未验范围，不称全量通过。

确定性的执行、计时与恢复使用[维护命令](../diagrams/README.md#生成与校验命令)；用户明确启用的 SVG 冻结、渲染和子代理观察使用[SVG 证据命令](../diagrams/README.md#svg-证据命令)。新工具仅接受 `index-v2.json`，旧目测数据迁移尚未实现，旧记录暂不计入新工具复用；保留旧证据，不自动转换。图像生成不算实际观察，观察与自动结果分别记录。

用户明确重新要求 HTTP 验收时，预先使用[本地 HTTP 服务](../diagrams/README.md#本地自动预览)，并在桌面环境将窗口缩窄，检查顶栏、浮层、筛选控件和画布布局；不要求手机、移动端模拟或真实触屏的单指、双指操作。本地 HTTP 与断网目录分发的覆盖分别记录。

对象聚焦覆盖星形一跳、反向与平行边、自环、显示端点映射、清除及历史恢复；既检查页面选中的集合，也检查原生 SVG 中轮廓、文字、路径、marker 箭头、边标签背景和实体标题的有效透明度，防止邻居其他边仍清晰或嵌套内容重复淡化。短标题覆盖函数、方法、泛型、闭包及 SystemSet 结构文本，核对默认图、离线筛选与单关系图一致，详情和搜索保留原完整名称，原始 DOT 及对象身份不变。

以下清单同时列出自动回归契约与按需实际验收项目。默认只执行自动检查；SVG 实际观察、正式 HTTP 页面及 VS Code 协议验收均仅在用户明确要求对应项目时执行。

1. 按外部资源清单、视图索引和调度清单检查全部应用／Schedule 与对象图。Schedule 对应 DOT／默认 SVG，对象对应完整 Mermaid／SVG，按需加载的完整图与独立产物一致；旧总览、插件及基础设施系统 SVG／Mermaid 不残留。检查主应用默认 `Update` 及缺失时的非空调度回退，顶栏按应用分组且没有左侧导航栏，不因 Schedule 同名而合并。按[筛选回归](#调度筛选与页面回归)分别记录本地 HTTP 与断网目录分发中的内嵌 Worker 重排；完整对象 SVG 从生成目录读取，单关系图通过本地模块按需原生编译，全部视图均不依赖 CDN。
2. 检查普通 Entity 为砖红单层圆角矩形，没有开合按钮、内嵌 Component、第二张实体卡片或无业务身份的空框。编译器模型保留实体创建模板、具体组件类型和装配关系，含条件及跨插件来源；实体右栏不展示组件清单，组件类型对象仍可搜索和链接访问。包含关系来自编译器确认的装配证据，`from`／`to` 和关系 ID 精确连接对应模板与类型实例，不按旧清单投影 ID 验收。
3. 按[对象专属图](../diagrams/README.md#对象专属图)核对每个生产对象恰好一张完整导出图，组件类型实例、实体创建模板和系统注册分别保留；同一类型可连接多个模板，同函数的多次注册及不同泛型实例不合并。完整图仅含一个中心，不递归扩展，也不增加邻居之间的边。Plugin 与 PluginGroup 均为中心单卡、零可见边，说明遵循节点详情范围；全局关系及其他对象图中的插件邻居不删除。仅中心 `kind=Entity` 时过滤全部 Component 及所有触及 Component 的边，可见节点恰为中心与剩余边端点；其余完整图保留全部直接邻居及中心的全部入出边，Component 自身图仍展示关联 Entity。全局对象与关系目录不因过滤丢失记录。高密度默认阅读路径按下面的目录及单关系图检查。SystemSet／Engine flow 的阶段配置不冒充多个系统函数；仅维护清单中的测试注册不额外增加生产阶段，真实快照已注册的 Startup 条件回退仍保留独立实例。覆盖孤立单卡、长名称、外部对象、并行关系、相反读写方向、有向环及稠密关系。
4. 按编译器模型逐边核对包含、字段读取、可变访问、实际修改、添加、移除、存在过滤及反射访问的可见语义。`With`／`Without`／`Has` 和存在判断不能冒充字段读取，`writes` 不自动证明插入或移除。回调、普通 helper、World 闭包与 Commands 延迟操作要保留真实条件、时机及证据；未核实关系标缺口，不画猜测的业务边。节点与操作源码按[源码范围](../diagrams/README.md#源码范围)检查。

## 持物与视角同步的无窗口验证

使用最小 `App` / `World`、手动时间和必要的变换传播插件，检查固定模拟与逐帧显示姿态的边界；不加载窗口、渲染器或完整游戏场景，不调用 `App::run`。

Avian 的物理步位于 `FixedPostUpdate`。涉及速度、重力、接地或碰撞的回归必须执行实际物理调度，不能只运行 `FixedUpdate` 后把施力当成已经完成运动；使用最小物理插件和几何碰撞体即可，无需窗口或渲染插件。

### 避免测试掩盖帧间错位

初始化拾取关系可以先执行固定步，但输入后的本帧检查必须在 `app.update()` 返回时立即完成，不能先补跑模拟或手动调用同步系统。

新增或修改相机、转向和附件跟随时，检查以下测试条件：

- 用 `TimeUpdateStrategy::ManualDuration(Duration::ZERO)` 覆盖连续没有固定步的帧，并比较 `Time<Fixed>::elapsed()`，确认测试确实没有推进固定时间。
- 用 120 Hz 渲染更新与 60 Hz 固定模拟覆盖交替帧；每帧断言人物、持握目标和相机使用本帧角度，并统计确实存在没有固定步的帧。另保留单帧多个固定步的检查，确认鼠标位移不会重复应用，运动只按模拟时间推进。
- 安装无窗口的 `TransformPlugin`，同时检查业务根实体的 `Transform` 与本帧 `PostUpdate` 后的根和模型子实体 `GlobalTransform`，覆盖用于渲染的最终姿态。窗口组件可仅作为输入所需的 ECS 数据，不能安装窗口后端或渲染插件。
- 释放后先确认 `HeldBy`、`HeldTarget` 移除，再连续转动视角。零固定步时物理位置和速度应保持；有固定步时允许物体自然移动，需确认它不再追逐持握目标，不能只检查持有状态。
- 比较世界矩阵分解得到的旋转时，注意四元数 `q` 与 `-q` 表示同一旋转。应比较实际前向、上向向量或等价旋转，避免把符号变化误判为同步错误。

检查入口为 [第一人称与动作路由测试](../../src/first_person/tests.rs)、[物品跨帧与旋转测试](../../src/item_interaction/tests.rs) 和 [灰盒场景测试](../../src/scene_assembly/tests.rs)。通过真实 E 绑定完成拾取和短暂对齐后再发鼠标输入，所有场景保留帧末立即断言：

| 转向与清理场景 | 必须保留的边界                                                                                                                                                                                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 完整旋转路径   | 起终点均空、途中扫过薄墙仍受阻；覆盖正反半圈、整圈、角度 wrap、凸箱、偏心复合箱、贴墙转入／转离及已有地面接触。新阻挡在同帧于转动前安全位置放下，镜头完成角度；直走受阻仍持握。                                                                        |
| 空旷地形 | 用三角网格或方盒地面确认整圈包络无其他障碍，覆盖不同始角、微转、正反半圈及零／单固定步。离地箱在零固定步帧仍被持有，不能忽略地面、关闭自动放下或缩小箱体规避误报。 |
| 有限墙面 | 用最小有限三角面、方盒墙和偏心复合箱覆盖多种始角，证明整段路径与障碍分离。不能只查端点或把有限墙面当无限平面，帧末检查持握、视觉与镜头。真实薄墙和新接触仍须阻挡。 |
| 生命周期清理 | 拿放、人物／箱体销毁、关系异常解除后恢复质量、碰撞与独立实体身份并清除代理。 |

## 音频无窗口验证

```powershell
cargo test --locked audio
cargo test --locked ui::
cargo test --locked settings::tests
```

音频测试只解码文件或使用通道数据，不安装设备输出。当前用例覆盖已接入声音的清单、解码、冷却与并发，以及 UI 通道的默认基准增益、总音量与分类音量相乘、零音量静音及恢复不补播。菜单检查真实导航、悬停、确认、返回、输入去重，以及滑条释放反馈。管线回归使用隔离素材覆盖额外分类、事件映射、导入、清单、质量检查与试听快照，并检查试听分类、路径及循环属性。声音技术检查见 [音频管线](../audio.md)，实际听感和输出由用户按 [音频验收](game-acceptance.md#音频验收) 确认。

## 完成代码变更前的自查

以下检查用于确认变更遵守 [开发规范](../development.md)，具体规则在该文档中维护：

- 必要的中文注释已补齐，Rust 注释格式正确，注释与代码一致，删除了失效说明。
- 系统仅声明必要的读写访问；执行依赖和延迟命令的可见时机正确。
- 跨固定步与渲染帧的功能已核对[显示一致性约束](../development.md#固定模拟与逐帧显示的一致性)，相关测试不会通过补跑固定步掩盖帧末错误。
- 功能插件注册了所需的系统、资源和消息；实体销毁后不会留下错误引用或失效缓存。
- 架构图更新按 [项目 Skill 维护](../diagrams/README.md#项目-skill-维护) 执行，不作为普通代码任务或每次提交的自查项；完成产物及自动回归检查，SVG 视觉验证遵守[默认关闭与明确启用规则](#架构图视觉检查)，跳过的项目不计为实际观察通过。
- 新增或修改的关键流程、状态变化和错误有对应文件日志；每次游玩创建独立会话日志并保留历史记录。
- 已执行本次变更对应的格式、编译和无窗口测试检查，并记录结果；未完成的运行或视觉验证已明确列出。

如需偏离一般工程约定，在代码注释或交付说明中解释具体理由和影响，并保持偏离范围最小。任何一般约定的例外都不能豁免禁止 Agent 启动或操作游戏的约束。
