# 验证参考

本文供开发者按变更范围选择检查，维护无窗口测试、链接产物和静态架构文档的验证契约。开发规则见 [开发规范](../development.md)，当前机制见 [架构说明](../architecture.md)。游戏窗口、真实输入、画面和听感按 [游戏手动验收](game-acceptance.md) 由用户检查；操作与配置见 [使用说明](../usage.md)。

验收清单描述预期结果，不代表已经执行。用户反馈只确认其实际报告的场景，不能据此推断其他帧率、边界条件或完整清单均已通过；每次变更实际完成的检查、失败结果和未验证事项记录在关联 Issue 或 PR 中。

## Agent 验证边界

游戏只能由用户启动和操作。Agent 不通过 `cargo run`、可执行程序、脚本、Computer Use 或其他间接方式启动游戏，也不截取游戏画面、录屏或模拟键鼠。用户提供的日志可直接分析，无需启动游戏。

Agent 可阅读代码、检查格式和编译，并执行最小 `App` / `World` 的无窗口测试；不创建游戏窗口、加载完整游戏或依赖桌面交互。静态架构 HTML / SVG 的视觉检查不属于游戏运行，允许查看，临时输出放在根 `tmp/`。

交付时分别报告自动检查、用户实际验收及未完成项；需要实机确认时，给出对应验收步骤、预期和日志位置。

## 按变更类型选择检查

| 变更类型 | 必须执行的检查 |
| --- | --- |
| 仅修改普通文档 | 检查内容是否准确、职责是否重复、相对链接与引用是否有效。不需要执行游戏或 Rust 检查。 |
| 修改架构图清单、关系、布局、生成器或生成产物 | 按 [项目 Skill 维护](../diagrams/README.md#项目-skill-维护) 生成并校验最终产物，运行相关 Node.js 无窗口回归；架构图有变更时必须完成下面的 [架构图视觉检查](#架构图视觉检查)，自动校验不能代替目测。检查由执行维护 Skill 的 Agent 承担。 |
| 修改架构图或源码页的 VS Code 入口 | 按 [架构图源码定位验证](#架构图源码定位验证) 执行 URI、根目录配置及生成页交互的无窗口回归；在安装 VS Code 的本机浏览器实际点击核对文件与行列，记录外部协议确认及未完成事项。 |
| 仅修改架构图维护 Skill 或其说明 | 检查 [Skill](../../.agents/skills/update-ecs-architecture/SKILL.md) 的入口、触发范围、步骤与相对链接，确认使用当前工作区、保留已有修改、不自动暂存或提交。未修改架构图及其工具时，不要求重新生成产物或执行图形验收。普通代码修改和 Git 提交不触发架构图更新。 |
| 修改 Rust 代码 | 阅读相关实现，运行 `cargo fmt --all -- --check` 和 `cargo check --locked`。 |
| 修改行为 | 在 Rust 检查之外，增加或运行有针对性的无窗口测试，验证相关组件变化、查询过滤、消息或调度结果；运行或视觉效果交给用户手动验收。 |
| 修改运行美术或海岛装配 | 验证 GLB 结构与清单，并执行下面的 [海岛资源与无窗口验证](#海岛资源与无窗口验证)；模型显示、动作效果和实际海岛通行由用户手动验收。 |

Rust 检查命令：

```powershell
cargo fmt --all -- --check
cargo check --locked
```

行为测试可按测试名称或模块选择；需要运行仓库全部无窗口测试时使用：

```powershell
cargo test --locked
```

测试应检验实际业务行为和边界条件。只使用最小测试环境；即使命令属于测试，也不能借此创建窗口或启动完整游戏。

## 会话日志无窗口验证

在仓库根按范围运行：

```powershell
cargo test --locked game_flow::initialization_tests
cargo test --locked session_log::
```

[初始化日志测试](../../src/game_flow/initialization_tests.rs) 安装真实功能插件并执行 `Startup`；手工注册日志系统不能证明插件实际完成注册。[会话生命周期测试](../../src/session_log/tests.rs) 和 [后台输出测试](../../src/session_log/output_tests.rs) 覆盖下列边界，不能只凭短时间内没有阻塞或文件存在判定通过。

| 场景 | 必须保留的契约 |
| --- | --- |
| 功能插件初始化 | 四个插件各记录一次，缺少插件不报告该功能初始化，后续更新不重复；字段取启动时最终 `PrototypeConfig` 和 `Time<Fixed>`，日志系统不覆盖配置。保留 target、`info` 级别、英文消息，检查器字段含 `plugin="WorldInspectorPlugin"`、`reason="initialization"`。 |
| 文件或控制台阻塞 | 生产者仍能返回，控制台阻塞不妨碍文件独立写入和刷新；解除阻塞后核对完整数量与顺序，不靠绝对耗时判定。 |
| 刷新、panic 与关闭 | 同步屏障之前的短写记录全部完成；panic hook 返回时文件已有异常上下文。正常退出排空已接受记录，关闭拒绝新记录，并刷新和回收线程，不能仅依赖发送端析构。 |
| 设备与线程故障 | 写入、刷新、同步和线程 panic 均反馈失败；控制台故障不回退到同步 stderr，也不阻塞健康文件的 panic 同步，退出和关闭仍报告错误。 |
| 格式、过滤与会话隔离 | 时间、级别、target 和结构化字段齐全，文件无 ANSI 色码；显式 `RUST_LOG` 同时作用于文件和控制台，每次会话新建文件，不覆盖历史。 |

全局 `LogPlugin` 与环境变量隔离放在独立测试子进程，其余检查可使用局部 subscriber。临时文件使用根 `tmp/`；本节不安装窗口或渲染器。用户对真实会话文件的检查见 [日志检查与问题反馈](game-acceptance.md#日志检查与问题反馈)。

## 海岛资源与无窗口验证

新道具资产的离线重建、GLB 清单与挂点矩阵检查、Blender 预览检查见 [道具美术资产](../../art/items/README.md#重建与离线验证)。全库检查工具同时读取海岛与道具清单。新道具尚未注册到 `ArtAssets`，以下海岛场景测试不能证明新装备、机械或魔法效果已经接入。

运行 GLB 与场景装配使用真实资源和无窗口环境；[tests.rs](../../src/scene_assembly/tests.rs) 提供共享夹具，碰撞、生命周期和转向检查分别位于同目录的 `collision_tests.rs`、`lifecycle_tests.rs` 与 `turn_tests.rs`，均通过 `scene_assembly::tests` 注册。可在仓库根目录执行：

```powershell
cargo test --locked scene_assembly::tests
```

主角 GLB 的离线文件检查使用普通 Python，不启动 Blender 或游戏：

```powershell
python3 -B art/scripts/validate_assets.py --report tmp/character-animation/assets.json
python3 -B -m unittest discover -s art/scripts -p test_character_assets.py
```

检查命名、时长、全骨覆盖、循环首尾与一次性动作终点、根与髋部水平静止、夹帧行走／落地鞋底高度，以及八组持箱／空手下肢一致性。临时报告放在根 `tmp/`；文件验证不能代替运行时动画求值、资源加载、碰撞和生命周期检查。

资源与场景测试使用最小 `App` / `World`，只注册所需资源、BSN 实例、变换、动画或物理设施，不注册窗口后端、渲染器，不启动完整游戏。资源加载检查可以读取真实 GLB；装配和失败边界可以构造最小资源或层级，并实际应用延迟命令。碰撞与恢复回归需要执行 Avian 的物理调度，不能只断言已请求生成碰撞。

| 场景 | 应验证的结果 |
| --- | --- |
| 五份运行 GLB 加载 | 海岛、主角、普通纸箱、易碎纸箱和木箱句柄最终就绪；主角存在全部 16 个命名动作、非空曲线与 `0.8 s` 时长；缺失资源记录路径和错误，并且不提前生成玩家。 |
| 地图实例就绪与重复通知 | 从 `WorldInstanceReady` 的实际层级读取 `source_asset`；展示主角、手持易碎纸箱与三只木箱及其子实体被移除，保留四名 NPC，每名只拥有一份静态身体碰撞；多次更新或重复通知不重复生成业务实体和碰撞。 |
| 资源与碰撞准备顺序 | 玩家、控制者、相机与五件可搬物品只在资源和实际碰撞准备完成后生成；等待期间不出现自由下落的玩家或箱体，准备完成后只生成一批。 |
| 菜单会话与加载阶段生命周期 | `island_sessions_wait_for_assets_survive_pause_and_clean_up_on_menu_return` 检查游戏进入后等待资产、加载中返回主菜单、连续开始及退出清理。主菜单只生成展示舞台，进入 `InGame` 建立加载相机与灯光，运行时推进装配；加载阶段暂停不生成动态实体。退出会话清理地图、碰撞、NPC、动态业务根、控制者与相机，保留全局资产强句柄。重复开始只生成一套海岛与五件物品；退出后迟到的实例通知不使新会话误用旧地图。 |
| 场景碰撞与模型变换 | 地形、建筑、码头、固定道具与棕榈树干的结构网格按节点变换合并为静态三角碰撞；开放商铺入口保留，海水、草和叶片无支撑碰撞。 |
| NPC 身体碰撞与能力边界 | 从真实地图装配得到四名 `DisplayNpc`，各自的 `IslandCollider` 子实体具有静态刚体、脚底对齐的胶囊与 `World` 碰撞层；复用人物高度／半径并保留模型实例变换。执行 Avian 物理步，确认玩家、自由箱体与使用持握碰撞层的箱体不能穿过 NPC，NPC 保持原地。NPC 没有玩家输入、移动或拾取组件；重复通知不增加碰撞，退出会话后没有碰撞子实体残留。 |
| 台阶与平台连接 | 原步阶只有显示网格；五组入口斜坡分别与对应实际地板边界配对，顶面接到室内地板高度，并向地板内延伸 `0.05 m`。最小物理场景中胶囊能沿斜坡通过台阶与地板衔接处到达入口平台，箱体在平台落地，不被完整建筑包围盒堵住入口。 |
| 入口驻足、行走与 CCD 性能对照 | `station_character_ccd_avoids_expensive_stationary_and_walking_sweeps` 在真实物流站室内地板分别驻足和通过实际控制力往返行走，执行实际固定物理步。采样期间不移除碰撞，人物未休眠且高度仍在平台范围；行走的实际位移跨度须超过 `1 m`。对比角色当前 `NON_LINEAR` 速度门槛配置与零门槛对照配置的 `SolverDiagnostics::swept_ccd` 和 `app.update()` 耗时，两种活动下当前配置的扫掠耗时均应低于对照配置的四分之一。停止移动并停稳后再检查接地与稳定高度，不要求行走每步都接地。箱体 CCD 配置不变，入口通行仍由实际海岛物理测试覆盖。 |
| 动态模型与物理根 | 一名主角与普通纸箱、易碎纸箱、三只木箱分别拥有业务根；模型通过 `ChildOf` 挂接，视觉节点没有重复刚体。木箱碰撞尺寸及轴心偏移对齐模型，固定货架纸箱没有 `Pickable`。 |
| 整体持箱、握持偏移与帧同步 | 通过实际交互建立持握，安全对齐后同形碰撞代理的 `ColliderOf.body` 为人物，箱体没有独立 `RigidBody`，业务根不进入人物的销毁关系。三种箱体使用正常 `CarryGrip` 持续走向真实 NPC，代理有求解接触、NPC 不动、人物停在箱体后方且握点不被压缩。零／多固定步及 120／240 Hz 的实际帧末同时检查箱体根和视觉子体跟随人物同一呈现姿态，释放后不再追逐目标。 |
| 主角动画选择与生命周期 | 按命名动作绑定，只处理主角视觉子树；使用角色局部真实速度而非输入意图连续混合方向与持箱动作，步频随实际速度变化，斜向保持正确步幅；方向／拿放变化保留统一步相位，接地噪声不过度切换空中姿态；实际动画求值后鞋底不穿脚底平面且物理根不被改动；等待 GLB、缺失动作和角色销毁不会留下失效绑定。 |
| 玩家与物品落水 | `Position.y < -1.5` 时玩家在模拟前解除持物并回出生点；仅释放尚未落水的持有物，物品自身落水后各自回初始姿态。清除线速度、角速度与玩家单次请求，保留持续移动轴并恢复自由碰撞。设置相机水平角不同于出生朝向并持续按 W，验证同一 `FixedUpdate` 依次执行落水恢复、当前相机朝向同步、移动模拟，恢复当步沿当前视角前进。当前帧与连续零固定步帧不跨岛插值；下一次 `FixedFirst` 在 `Reset` 与 `UpdateStart` 之间清理临时暂停，保留此前已有暂停。阈值边界和连续更新不重复恢复；持箱落水后无残留跟随关系。 |

这些检查覆盖组件、资源、层级和物理结果。模型颜色、低多边形外观、手与箱子的贴合、动画过渡及实际通行手感仍按 [海岛美术与落水验收](game-acceptance.md#海岛美术与落水验收) 由用户确认；NPC 身体碰撞的视觉贴合与实际阻挡按 [NPC 碰撞验收](game-acceptance.md#npc-碰撞验收) 检查。

入口性能对照使用相同构建配置与固定 60 Hz 模拟，待资源装配完成、物体稳定后预热，再重复采样；不将加载或限帧等待计入固定步开销。只改变角色 `NON_LINEAR` 的速度门槛，当前配置为线速度 `8 m/s`、角速度 `0.1 rad/s`，对照配置为零门槛；避免将某台机器的绝对耗时写成通用门槛。再次诊断位置相关开销时，可扩展到沙地、入口平台和门槛，并结合 `CollisionDiagnostics::narrow_phase` 区分普通接触计算。

高速薄墙回归 `character_ccd_blocks_high_speed_velocity_and_impulses_at_different_yaws` 将推测接触距离限制为 `0.001 m`，以不同水平 yaw 验证角色受到初速度或外部冲量后仍被扫掠阻挡。先完成一次高速物理步建立引擎预测邻域，再创建薄墙并检查后续实际固定步；移除 CCD 的对照应穿过同一薄墙，避免推测接触造成假通过。不能仅在零 yaw 下验证，也不能将 `LINEAR` 当作与当前非线性算法等效的替代。无窗口结果只验证 CPU 物理开销和行为，不能证明真实渲染 FPS；具体耗时和执行结果记录在关联 Issue 或 PR 中。

## 菜单、设置与资产的无窗口验证

菜单回归只使用最小 `App / World`、必要的状态／输入插件和 BSN 实体树，不安装窗口后端或渲染器。UI 夹具显式安装第三方 `EnhancedInputPlugin`，通过与 `GameUiPlugin` 共用的普通注册函数安装菜单生命周期、真实输入与页面，不依赖 `FirstPersonPlugin`。跨功能夹具显式安装所需项目 Plugin；需要状态时安装 `GameFlowPlugin` 并进入运行状态，没有应用状态时复用 `game_flow::configure_feature_order`，不补跑系统代替实际调度。应覆盖：

- 页面只暴露可用的 `MenuButton` 动作，导航序号连续；`Continue`、`Multiplayer` 和所有 `Coming Soon` 设置不进入焦点或业务动作列表。
- 菜单动作使用真实 Enhanced Input 绑定，长按确认／返回不重复执行；鼠标和键盘请求进入同一消费入口，页面切换后旧请求不穿透。
- 菜单音效只检查 `SoundRequest`，不打开音频设备：真实导航／移入已有按钮发出焦点音，接受操作和设置结果发出对应确认或返回音。同帧鼠标与键盘请求只反馈一次；无效动作、当前分类重选、设置边界、静止光标、按钮内移动、页面重建悬停及单按钮导航不发声。设置应用失败发出 `MenuCancel`，不使用其他素材事件。
- 文字测量、按钮移入／移出、输入来源切换与重建后的焦点按 [文字布局与高亮回归](#文字布局与高亮回归) 检查。
- 主菜单、暂停与帮助在支持的 16:9 视口内完整显示且不滚动；设置仅右侧纸色面板内容可滚动。具体布局、滚动条和刷新边界见 [文字布局与高亮回归](#文字布局与高亮回归)。
- `InGame` 的进入／退出管理完整海岛及业务实体，`Running / Paused` 切换保留角色、箱体、控制者、相机与持有关系；暂停当帧清意图并停止物理步、主角动画状态更新与落水恢复，加载阶段也不推进地图装配。恢复不补发跳跃／拿放请求。从暂停设置同时通过键盘和旧按钮返回后，连续两帧仍保持暂停。
- 主菜单与暂停释放光标并停用玩法上下文；恢复运行跳过自由光标位移，F3 调试释放与检查器输入隔离仍可用。
- 设置草稿的应用、取消与恢复默认值；有效自定义值打开页面后保留，帧率预设和灵敏度步进不越界；非法值、序列化或写入失败不修改当前生效设置或原文件。
- 音量草稿的实时预览、分类切换保留、成功应用及 `Back / Esc` 回滚；`Restore Defaults` 预览全部默认值但不自动保存。保存失败保留草稿预览，已应用设置与原文件不变，随后返回恢复已应用音量。
- `audio` 节及各缺省字段补齐为 `100`；边界 `0 / 100` 可解析和保存回读；负数、超出 `100`、小数及其他非法类型拒绝，加载时整体回退默认且原文件不变。按钮和键盘／手柄调整 `5%` 不越界，鼠标滑条映射精确到 `1%`。
- Audio 页包含三项可用音量行和 `Test SFX`，仅 `Music Volume` 为占位；每行文字、箭头、滑条、百分比／`Muted` 都有有效测量，箭头与滑条进入连续导航序号。滑条拖动不中途重建实体树，不连续发送确认音，仅释放且数值改变后反馈一次。`Test SFX` 只发出拾取素材的播放请求，不触发玩法消息或持握关系。
- 设置字段、恢复默认与应用结果原位刷新，保持控件身份、焦点和有效滚动偏移；离开重进或切换分类才重建页面。
- 设置默认帧率上限为 `60`，省略 `max_fps` 或文件缺失时采用默认值；`59` 拒绝，`60` 与 `120` 可解析。无效文件回退到 `60` 且原文件不变。设置文件保存创建与替换的完整 JSON 回读；Windows 下独占文件句柄导致替换失败时保留原文件。设置测试与保存暂存文件分别位于根 `tmp/settings-tests/`、`tmp/settings-save/`。

## 架构图源码定位验证

修改架构图或源码页的编辑器入口时，在仓库根运行生成、产物校验和相关无窗口回归：

```text
npm ci --prefix docs/diagrams

```

无窗口回归应检查 Windows 盘符、路径分隔符、空格、中文、`#` 与 `%` 的 URI 编码，行号与默认列 `1`，非法定位和根目录输入，`file://` 推导与覆盖、HTTP 或搬移后的显式配置，以及主检出与 worktree 配置的隔离。覆盖 `workspace` 参数、目录 URL 对应的浏览器存储与推导值的优先级；存储被禁用时配置仍在本页生效，并通过同目录导航链接传播。测试生成后的页面脚本，确认右侧节点及连线详情和源码页当前文件／行使用同一共享编辑器入口；详情不提供离线快照跳转，VS Code、定位路径和复制定位仍可用，项目插件页顶部只显示名称与标识。加载、选择节点及更新配置不调用外部协议，只有用户点击才发出请求；未配置项目根目录时显示局部配置提示，已有 Cargo 根目录的依赖声明仍可定位。独立源码页继续生成并校验项目与依赖的完整文件快照。检查总览卡片只更新右侧详情，侧栏或“打开所属插件”按钮才进入插件；三个页签、外部契约跳转、返回及浏览器历史正常，`feature`、`tab`、`node` 导航保留 `workspace` 参数。侧栏四个第三方入口位于 Bevy 引擎之前。

Bevy 和第三方 `Component`、`Plugin`，以及已审阅的系统集合、引擎系统／Observer、同步节点，必须优先定位锁定依赖中的真实定义；项目插件、资源、实体和聚合输出继续使用原有入口。检查组件的定义归属、插件实际提供包、项目别名、宏生成声明以及二维／三维重名声明；例如 `Friction` 指向 Avian 的 `physics_material.rs`，`KiraAudioPlugin` 指向依赖的 `AudioPlugin`。按动态目标清单逐个核对全部集中映射，并覆盖 `PlayTypedChannels` 与不同调度注册的 `ApplyDeferred` 在所有可见视图中的入口，确认定义路径一致、各自的原项目注册 `source` 保留。覆盖缺失定义、唯一匹配、篡改的包名／版本／根目录／文件／行号、目录外逃，以及依赖快照缺失、残缺或标识不符；原项目源码和快照继续校验。Cargo 包路径由本机 `cargo metadata --locked --offline` 提供，只保存到生成的两份 HTML，不硬写清单或映射；两份 HTML 包含本机 Cargo 绝对目录及依赖完整快照，跨机器打开时应重新生成本机定位。工作区配置只改变项目定位，不能覆盖依赖根目录；维护文件和 SVG 不应带入个人目录或临时快照路径。

复制定位的回归覆盖节点详情和源码页：成功时仅当前按钮显示“已复制”，通过 `aria-live` 宣告结果，`2` 秒后恢复；重复点击重新计时，不影响其他复制按钮。失败时在当前控件附近提示并保留手动选择复制入口，不宣告成功。两份页面都不显示底部目录状态栏或重复的源码打开方式、快照时效说明；VS Code 入口、定位路径、复制定位、源码页行定位状态和必要错误反馈仍可用。工作区配置保留输入、保存、恢复默认及局部校验反馈，使用边界见 [源码使用说明](../diagrams/README.md#在-vs-code-中打开源码)。

## 架构图视觉检查

按 [Entity 开合规则](../diagrams/README.md#entity-展开与缩略)覆盖默认全部缩略、`A 展开 → B 展开 → A 收起`、三个以上 Entity 同时展开，以及独立收起其中一个；其他 Entity 的状态保持，画布没有“展开全部”或“全部缩略”按钮。检查 Entity 卡片、外部虚线和图例统一为砖红色单层矩形，缩略后所有 Component 均隐藏、外框实际缩小，相关连线改连 Entity，展开后恢复具体 Component。分别断言 canonical 端点与显示端点，不只检查节点可见性。动态 `view.entityViews` 的每个 SVG／Mermaid 与主视图一同校验和目测；按需生成的多实体组合另在实际浏览器中检查，覆盖无组件实体、同名组件、单列、多列、长标题及两个端点均被折叠的关系。

放大检查右上角原生按钮：缩略显示 `+`、展开显示 `−`，尺寸 `24×24` 个 SVG 单位，距上、右边界各 `8` 个 SVG 单位并随缩放同步；名称、用途及外部虚线不被覆盖，没有组件的 Entity 没有按钮。控件与节点选择及拖动独立，按钮无障碍名称包含 Entity 和组件数量，`aria-expanded`、Tab、Enter、Space 及重排后焦点恢复正确，详情入口同步。分别检查缩放、画布锚点、实际滤镜数量和清除恢复，确认没有第二个蓝框。

分别检查手动集合、临时搜索集合和历史恢复：命中隐藏组件只补开其所属 Entity，清空搜索恢复手动集合；搜索中点击开合按钮后退出搜索，只将当前 Entity 的目标状态应用到原手动集合，其他搜索临时补开项不写入历史。组件深链接及边详情端点补开目标而不关闭其他 Entity；收起当前选中组件所在 Entity 时选择转到 Entity，其他选择不变。首次进入为空集合，旧 `all`、`collapsed`、单 Entity ID 状态兼容，新状态保存数组；切页、历史返回和保存工作区不丢失状态、命中数、关系或源码入口。

Entity 容器本身保留原身份的点击、Tab、Enter／Space、搜索、连线端点、源码及跨插件导航；组件单击只选择最近的 Component，不冒泡选择 Entity。选中 Entity 保持完整组件清晰，选中 Component 保持所属 Entity 清晰，只有实际选中的对象增加外圈与滤镜。对同组搜索多选、Entity 与 Component 同时选中及真实连线端点分别断言命中数、选中集合和滤镜数量；弱化 Entity 只影响其自身轮廓和标题，不能通过父级透明度使所选组件变淡。覆盖重复选择、极小缩放、清除、切页和历史返回，准确恢复各自的填充、线宽、滤镜与优先级，容器及组件均不出现双蓝框。

按[读图规则](../diagrams/README.md)检查 `main / App` 到插件的纯装配注册边均不显示，插件页签不残留因过滤而孤立的外部 `main / App`；原始模型与稳定 ID 不变，项目插件安装第三方插件及日志退出刷新等真实协作关系仍有可见入口。

分别检查总览与侧栏的 Bevy、Avian、Enhanced Input、Kira、Egui 五个入口及三个页签，四个第三方入口位于同一侧栏分节，插值归 Avian、第三方 Inspector 归 Egui；总览复用已有规范插件节点，没有第三方汇总卡片。导出分别使用 `ecs-infrastructure-*` 及 `ecs-third-party-<library>-*`，其中 `library` 为 `avian`、`enhanced-input`、`kira`、`egui`，动态清单、内嵌图与独立产物一一对应，没有旧混合第三方产物。抽查输入、物理、音频、界面和项目载荷事件的归属，跨入口节点的来源摘要、详情及跳转一致，Bevy 容器的 `defined_in` 不随第三方载荷的浏览归属改变；现有业务节点 ID 与关系不丢失。旧 `third_party` 链接带真实节点时定位当前归属页签，无节点、节点失效或指向 `third-party-plugins` 时回总览，保留工作区、其他参数与片段并替换历史；旧 `infrastructure` 节点链接仍能定位，无节点时进入 Bevy。`main / App` 仅作应用上下文，原生回调位于窗口策略。

沿日志箭头核对碰撞日志只进入 `tracing producer`，文件写入必须经过 `File worker`，控制台输出经 `Console worker`；物理插件仅展示 producer 外部契约，完整内部链位于会话日志页。确认文件节点仍为 `physics-file-log`、类型为 `External I/O`，源码定位到 `create_session_file`，不存在业务系统直写文件的边，也未增加队列、stderr 终点或退出刷新关系。

检查 `Read`、`Write` 一级标题之下的 `Entity`、`Resource`、`Local<T>`、`NonSend<T>` 分类缩进 `16px`，条目再缩进 `16px`，不叠加浏览器默认列表缩进；字体、字号、字重与配色保持原样。以面板最小宽度 `240px` 检查长实体名、长泛型、连续标识符和多条列表可换行、无横向溢出；分类与条目的点击和源码定位不受影响。

按[画布交互与焦点](../diagrams/README.md#画布交互与焦点)覆盖自动回归及实际浏览器检查：画布具有 `tabindex="-1"`、`role="region"` 和有效无障碍名称，可程序化聚焦但不进入 Tab 顺序，也不显示默认焦点框。有效 `pointerdown` 聚焦画布且使用 `preventScroll`，`pointerup` 激活命中节点或连线后焦点仍不落到卡片，不因焦点更新改变页面滚动或画布位置。键盘 Tab 仍能到达节点，未选中节点有 `:focus-visible:not(.selected)` 反馈，Enter、Space 可激活；激活后只有真实轮廓选中效果，没有第二层矩形蓝框。保留极小缩放、外部虚线、多轮廓及取消恢复的原有选中检查。

分别检查 `Read` 与 `Write` 的 canonical Entity 归并：同实体多个组件只显示一个实体名，不出现组件列表；同名不同实体仍各自保留，两栏分别去重。非实体访问按 `Resource`、`Local<T>`、`NonSend<T>` 分类并保持原记录顺序，读写方向与原始数据不变；`Query` 的声明、参数与过滤条件完整，实体组件仍可在对应详情查看。

检查每条注册是独立块，所有原字段与 Schedule 参数完整保留，字段逐行、数组逐项分行；覆盖多处注册、空数组、含泛型及嵌套标点的条件，不将多条注册或数组合成长串。状态组标题对同类型多个目标仅显示一次类型名；点击系统后仍能逐条核对各目标的完整 OnEnter、OnExit 或 OnTransition 参数，以及被标题排除的测试注册，清单数据未被展示精简删改。

Mermaid 的 headless Chromium 只用于编译 `.mmd`，可由 `MERMAID_CHROMIUM_PATH` 指定或自动查找已安装的 Chrome／Edge；构建环境与依赖恢复见 [生成与校验命令](../diagrams/README.md#生成与校验命令)。编译成功、静态 SVG 检查和最终 HTML 的真实浏览器验证分别记录，不能用编译浏览器的内部页面代替 HTML 验收，也不能绕过浏览器对本地文档的访问限制。上述检查不启动或操作游戏；游戏画面、游玩和窗口交互验收仍只能由用户完成。

## 持物与视角同步的无窗口验证

使用最小 `App` / `World`、手动时间和必要的变换传播插件，检查固定模拟与逐帧显示姿态的边界；不加载窗口、渲染器或完整游戏场景，不调用 `App::run`。

Avian 的物理步位于 `FixedPostUpdate`。涉及速度、重力、接地或碰撞的回归必须执行实际物理调度，不能只运行 `FixedUpdate` 后把施力当成已经完成运动；使用最小物理插件和几何碰撞体即可，无需窗口或渲染插件。

| 场景 | 应验证的结果 |
| --- | --- |
| 手动时间步为 `Duration::ZERO`，本帧没有固定步 | 输入更新观察角度后，`RunFixedMainLoop` 在插值之后仍依次同步角色水平朝向、`HeldTarget`、第一人称镜头和人物 `Visibility`；物理位置和速度不被额外推进，跳跃与交互请求不被额外消费。 |
| 渲染更新按 120／240 Hz 推进，固定模拟为 60 Hz | 拾取对齐完成后，包括没有固定步的交替帧在内，实际箱体 `Transform` 和 `HeldTarget` 都与本帧人物呈现位置和朝向一致；运行 `PostUpdate` 后，视觉子实体 `GlobalTransform` 与实际箱体根一致。持握箱不再独立追赶人物，第一人称镜头与人物可见性保持一致。 |
| 固定步正常执行 | 角色朝向仍在移动施力、跳跃、交互之前同步；物理步骤按固定时间积分，逐帧同步不重复施力或执行拿放。 |
| 释放物体后继续改变视角 | `HeldBy`、`HeldTarget` 与挂接状态已移除，箱体恢复独立动态刚体与自由碰撞，人物质量还原；释放保留安全世界姿态与实际线速度、角速度。后续视角变化不再移动箱体，物体仍按惯性、重力和碰撞运动，视觉子实体与实际根姿态一致。 |
| 默认眼位与观察角度 | 相机初始俯仰为 `0°`，俯仰限制 `-85°..85°`；位置为角色脚底上方 `1.65`。鼠标位移更新同一组水平角与俯仰角，角色移动与持握只读取水平角。 |
| I 键未绑定 | 经真实设备输入按下、持续按住并重新按下 I，第一人称相机角度、目标和眼位不改变，人物与持物状态不受影响。 |
| 鼠标释放、失焦及无效关联 | F3 调试释放光标、窗口失焦或暂停时不应用鼠标观察位移；控制目标不存在或相机目标与角色关联不符时不改变角色朝向，不影响其他相机。恢复捕获时不应用自由光标期间积累的位移。 |
| 人物与木箱可见性 | 第一人称只隐藏对应的 `CharacterVisual`；相机或控制者丢失、关联失效后人物恢复显示；木箱视觉和其他角色不被隐藏。 |

这些检查验证组件状态与调度结果，不能代替真实窗口中的鼠标手感、持箱虚影和视觉稳定性验收。执行结果按本次变更记录在关联 Issue 或 PR 中。

物理行为回归还应覆盖：输入后逐步加速、松键减速、斜向目标速度一致、外部冲量实际推动角色及后续主动制动、角色碰墙受阻与推动自由箱体、脚底接地及侧墙不接地、持握箱按碰撞层过滤而不充当支撑面、空中请求不重复跳跃、自由箱体落地、持箱受墙阻挡、释放保留速度、隔墙拾取过滤、同批次拾取不重复占用，以及持有者销毁或关系异常解除后清理目标、恢复碰撞并自然下落。场景装配测试检查物理组件位于业务根实体，视觉子实体不重复添加刚体或碰撞体，实际海岛碰撞顶面与出生高度一致。

### 避免测试掩盖帧间错位

初始化拾取关系可以先执行固定步，但输入后的本帧检查必须在 `app.update()` 返回时立即完成，不能先补跑模拟或手动调用同步系统。

新增或修改相机、转向和附件跟随时，检查以下测试条件：

- 用 `TimeUpdateStrategy::ManualDuration(Duration::ZERO)` 覆盖连续没有固定步的帧，并比较 `Time<Fixed>::elapsed()`，确认测试确实没有推进固定时间。
- 用 120 Hz 渲染更新与 60 Hz 固定模拟覆盖交替帧；每帧断言人物、持握目标和相机使用本帧角度，并统计确实存在没有固定步的帧。另保留单帧多个固定步的检查，确认鼠标位移不会重复应用，运动只按模拟时间推进。
- 安装无窗口的 `TransformPlugin`，同时检查业务根实体的 `Transform` 与本帧 `PostUpdate` 后的根和模型子实体 `GlobalTransform`，覆盖用于渲染的最终姿态。窗口组件可仅作为输入所需的 ECS 数据，不能安装窗口后端或渲染插件。
- 释放后先确认 `HeldBy`、`HeldTarget` 移除，再连续转动视角。零固定步时物理位置和速度应保持；有固定步时允许物体自然移动，需确认它不再追逐持握目标，不能只检查持有状态。
- 比较世界矩阵分解得到的旋转时，注意四元数 `q` 与 `-q` 表示同一旋转。应比较实际前向、上向向量或等价旋转，避免把符号变化误判为同步错误。

第一人称共享夹具见 [pose_tests.rs](../../src/first_person/pose_tests.rs)，捕获、视角与持物姿态检查位于同目录的 `capture_tests.rs`、`view_tests.rs`、`held_pose_tests.rs`，动作路由见 `action_tests.rs`。物品跨帧与旋转检查见 [frame_tests.rs](../../src/item_interaction/frame_tests.rs) 和 [rotation_tests.rs](../../src/item_interaction/rotation_tests.rs)，真实资产转向检查见 [turn_tests.rs](../../src/scene_assembly/turn_tests.rs)。真实 E 绑定完成拾取和短暂对齐后再发鼠标输入，所有场景保留帧末立即断言：

| 转向与恢复场景 | 必须保留的边界 |
| --- | --- |
| 完整旋转路径 | 起终点均空、途中扫过薄墙仍受阻；覆盖正反半圈、整圈、角度 wrap、凸箱、偏心复合箱、贴墙转入／转离及已有地面接触。新阻挡在同帧于转动前安全位置放下，镜头完成角度；直走受阻仍持握。 |
| 空旷地形 | 同时用三角网格与真实海岛碰撞／GLB 模型，确认整圈包络无其他障碍，再覆盖不同始角、微转、正反半圈及零／单固定步。离地箱在零固定步帧仍被持有；不能忽略地面、关闭自动放下或缩小箱体规避误报。 |
| 有限墙面 | 使用日志箱体中心、多种始角，以及物流站／Music 店实际墙边和三种箱体。用实际局部包围盒八角的圆弧极值证明整段包络与世界分离；不能只查端点或把有限墙面当无限平面。帧末检查持握、模型与镜头，失败时沿碰撞实体父级定位资产；实际墙体、薄墙和新接触仍须阻挡。 |
| 清理与落水 | 拿放、人物／箱体销毁、关系异常解除后恢复质量、碰撞与独立实体身份并清除代理；双方同时落水覆盖两种遍历顺序，箱子始终回自己的出生点。 |

- 系统仅声明必要的读写访问；执行依赖和延迟命令的可见时机正确。
- 跨固定步与渲染帧的功能已核对[显示一致性约束](../development.md#固定模拟与逐帧显示的一致性)，相关测试不会通过补跑固定步掩盖帧末错误。
- 功能插件注册了所需的系统、资源和消息；实体销毁后不会留下错误引用或失效缓存。
- 架构图更新按 [项目 Skill 维护](../diagrams/README.md#项目-skill-维护) 执行，不作为普通代码任务或每次提交的自查项；架构图有变更时由执行 Skill 的 Agent 完成产物校验和 [视觉检查](#架构图视觉检查)，未完成的维护或视觉检查不能报告成功。
- 新增或修改的关键流程、状态变化和错误有对应文件日志；每次游玩创建独立会话日志并保留历史记录。
- 已执行本次变更对应的格式、编译和无窗口测试检查，并记录结果；未完成的运行或视觉验证已明确列出。

如需偏离一般工程约定，在代码注释或交付说明中解释具体理由和影响，并保持偏离范围最小。任何一般约定的例外都不能豁免禁止 Agent 启动或操作游戏的约束。
