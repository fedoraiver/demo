## 判定与证据

脚本读取类别标题及固定格式的表格，标题、已实现编号与脚本须保持同步。每行子项使用固定编号。表中「脚本」项由所属脚本执行，「待实现」项保留验收义务及所缺证据。报告记录子项编号、预期、实际和证据。可用状态为 `passed`、`failed`、`blocked`、`not_run` 和 `not_implemented`。`not_implemented` 表示覆盖缺口，不影响总脚本通过；环境阻塞需要说明缺失的能力或条件，失败后尚未到达的子项记为未执行。运行过程及证据记入报告，对应 Issue 或 PR 引用报告和会话日志。

键鼠从原生 Bevy 消息进入实际业务链路。场景前置修改须记录，验收动作由输入驱动。应用状态和磁盘用结构化断言，日志以本次正式会话的路径和行号为证据。信息级日志依赖本次子进程的 `RUST_LOG=info`。退出前后的捕获和持物等观测只有落实到相应子项才计入覆盖。

截图记录对应主窗口的捕获结果、尺寸和文件位置。外观判定需要可用图像和批准的基线，连续呈现需要采集帧和时刻与输入、固定步及场景状态对齐。首次和有意改变的视觉基线由用户批准。真实性能须用原生呈现采样，在相同构建、视口、DPI 和设备下分开记录配置上限、实际帧率和帧时间分布。真窗口手势由对应平台的辅助工具驱动，并预先核对目标进程和前台身份。跨 DPI 需要实际显示事件。

## 菜单与暂停

| 子项 | 执行方式 | 操作与通过条件 |
| --- | --- | --- |
| **MENU-01.main_menu_ready** | 脚本 | 启动后，主菜单资源和可操作按钮就绪，布局可用于输入，玩法角色尚未创建。 |
| **MENU-01.appearance** | 待实现 | 用图像基线验证 `Grey-boxing`、纯色背景、按钮与纸张面板、页脚键帽和说明可见。 |
| **MENU-02.keyboard_navigation** | 脚本 | 用方向键导航，观察焦点和导航输入来源变化，再用 Enter 进入帮助并用 Esc 返回。 |
| **MENU-02.mouse_help_and_back** | 脚本 | 点击 `How to Play` 后进入帮助，捕获 `help.png`，并通过鼠标点击 Back 返回主菜单。 |
| **MENU-02.focus_and_placeholders** | 待实现 | 检查 Enter 长按与手柄导航、全部按钮悬停和静止光标下的焦点保持、`Continue` 与 `Multiplayer` 占位项不触发操作，以及帮助卡片、键位和两种返回操作。 |
| **MENU-05.layout_and_scroll** | 待实现 | 用布局和图像验证主菜单、帮助和暂停无重叠裁切且保持位置。设置页在溢出时支持滚轮、滑块、轨道和键盘聚焦滚动，分类栏、底部按钮及页脚位置保持。切页、返回或调整尺寸后核对滚动状态。 |
| **MENU-05.native_resize** | 待实现 | 在 Windows 和 macOS 拖动四边和四角，核对内容区保持 16:9 和可用工作区；通常最小为 `960×540`，工作区更小时以完整容纳窗口为先，允许小于该最小尺寸。 |
| **MENU-06.native_window_management** | 待实现 | 通过 Windows 最大化和贴靠、macOS Zoom 和非全屏平铺、跨 DPI 移动、最小化和恢复检查客户区、命中与窗口策略日志，覆盖对应平台的原生路径；macOS Zoom 保留系统行为，绕过比例约束的 Zoom／平铺请求仅在越界时校准，并验证系统全屏及全屏平铺被禁用。 |
| **MENU-07.start_game_scene** | 脚本 | 点击 `Start Game` 后进入运行状态，观察一名角色、三个方块及玩法相机，确认鼠标捕获且主菜单相机已清理。 |
| **MENU-07.pause_input_isolation** | 脚本 | 在起跳后腾空时通过 Esc 进入暂停，确认光标显示并捕获 `pause.png`。暂停时注入键鼠，核对角色、方块和镜头状态保持。 |
| **MENU-07.pause_mid_action** | 待实现 | 分别在持箱和方块下落时暂停并验证姿态冻结。 |
| **MENU-08.resume_session** | 脚本 | 从暂停打开帮助并返回暂停，核对场景保持。通过菜单恢复运行和鼠标捕获，核对沿用当前场景并继续落地。 |
| **MENU-08.pause_subpages_and_input_reset** | 待实现 | 从暂停访问设置并返回，核对场景冻结。用 Esc 恢复时镜头保持，暂停前的跳跃和拿放请求不会补发。 |
| **MENU-09.restart_session** | 脚本 | 暂停回主菜单后观察旧玩法实体清理。再次开始，核对仅生成本轮的一名角色、三个方块和一台玩法相机。 |
| **MENU-09.quit_button** | 待实现 | 点击主菜单 `Quit` 后核对退出码和日志。窗口关闭路径见 `LOG-10.normal_exit_record`。 |

## 设置

| 子项 | 执行方式 | 操作与通过条件 |
| --- | --- | --- |
| **MENU-03.tabs** | 脚本 | 进入设置并依次点击四个分类，观察实际选中的分类，并确认各页保留 Apply 和 Back。 |
| **MENU-03.controls_and_layout** | 待实现 | 验证占位项不可修改，分类和底部操作可见，当前字段说明与焦点对应。验证图形页帧率控件、控制页纵轴与[灵敏度](ui.md#鼠标灵敏度验收)、音量控件及滑块外观。 |
| **MENU-04.frame_rate_discard** | 脚本 | 通过菜单选择不同帧率档位后返回，核对生效值和磁盘保持原值，重新进入设置后草稿取生效值。 |
| **MENU-04.frame_rate_apply** | 脚本 | 选择不同帧率档位并点击 Apply，核对提示、生效值和真实 `settings.toml` 中的 `[game].max_fps`。 |
| **MENU-04.settings_restored** | 脚本 | 游戏退出后核对磁盘仍是本次写出的版本，再验证文件字节与启动前一致，或恢复启动前缺失的状态。外部修改或归属不明时保留备份，记录恢复失败。 |
| **MENU-04.settings_scroll_and_defaults** | 待实现 | 连续点击、键盘调整各字段，确认滚动位置及滑块保持。核对切换分类或重进设置的滚动初始化，以及 `Restore Defaults` 后取消和 Apply 的不同结果。 |
| **PHYS-08.settings_fallback** | 待实现 | 分别用帧率 `59` 和 `60` 重启，核对字段警告、实际上限、文件原值和退出恢复。 |

应用读取[真实设置文件](../player-guide.md#设置)。设置脚本在启动前记录原始字节或缺失状态，独占保存 `tmp/acceptance-settings-recovery.json`。遇到中断或测试失败也在进程结束后尝试恢复。

## 物理交互

| 子项 | 执行方式 | 操作与通过条件 |
| --- | --- | --- |
| **PHYS-01.initial_scene** | 脚本 | 从主菜单开始，观察地面、三个方块和接地角色，核对相机初始偏航与俯仰接近零、相对角色的高度及眼位设置均为 `1.65 m`，捕获 `game.png`。 |
| **PHYS-01.scene_appearance** | 待实现 | 核对渲染中的灰色地面、纯色方块与镜头无遮挡。 |
| **PHYS-03.movement_dynamics** | 待实现 | 核对加速、松键减速、斜向目标速度与俯仰下水平移动方向，实测推动方块和阻挡。WASD 的基本方向见 `VIEW-01.wasd`。 |
| **PHYS-04.single_jump** | 脚本 | 从接地状态按住空格，观察起跳、升起、落地，核对长按仅触发一次起跳。 |
| **PHYS-04.airborne_input** | 待实现 | 空中再次按空格，核对跳跃未叠加，跟随镜头眼位随高度变化。 |
| **PHYS-05.pickup** | 脚本 | 在初始场景按 E，核对最近方块进入持有状态。 |
| **PHYS-05.carry_collision** | 待实现 | 三个方块分别验证对齐、持箱移动及跳跃、碰撞时的共同阻挡、途中扫掠受阻的自动放下和边缘接触。核对箱体可见和长按 E 的重复触发边界。 |
| **PHYS-06.release** | 脚本 | 释放 E 后重新按下，核对同一方块解除持有并自然下落。 |
| **PHYS-06.release_dynamics** | 待实现 | 移动、转身及跳跃中释放，核对姿态、惯性和落地反应。远处无法拾取，返回可再拾取。 |
| **PHYS-08.presentation_rates** | 待实现 | 在 60／120 FPS 上限下采样真实呈现，比较相同输入下的旋转、移动、跳跃及持箱和释放。核对模拟频率、帧率日志和连续画面。 |

F3 相关的 `PHYS-07` 见[检查器验收](inspector.md#世界检查器验收)。`PHYS-09` 的日志证据归[会话日志](#会话日志)。

## 会话日志

| 子项 | 执行方式 | 操作与通过条件 |
| --- | --- | --- |
| **PHYS-09.gameplay_session_log** | 待实现 | 完成玩法交互后，核对本次会话中的配置、移动、跳落、拿放及捕获日志。日志隔离与尾记录见 `LOG-06` 和 `LOG-10`。 |
| **LOG-01.session_start** | 脚本 | 通过本次进程的会话信息读取日志，核对唯一的 INFO 启动记录中的会话 ID 和日志文件名与本次会话一致、游戏及 Bevy 版本字段均非空，验证文件无 ANSI 色码。 |
| **LOG-02.initialization_once** | 脚本 | 核对玩法、固定时步与限帧的初始化各出现一次，且验收构建没有检查器初始化记录。检查器初始化见 `INSPECT-04`。 |
| **LOG-03.fixed_configuration** | 脚本 | 核对 `Fixed simulation timestep initialized` 中的 `simulation_hz` 约为 60 Hz 和初始化限帧值，确认限帧日志与生效配置上限一致；此项不测量实际帧率。 |
| **LOG-03.settings_history** | 待实现 | 用部分缺失字段或越界配置启动并应用新设置，核对加载、回退和应用过程的日志与生效值。 |
| **LOG-04.two_scene_assemblies** | 脚本 | 在同一进程中开始两次，每次对应一次场景装配与三个方块日志。 |
| **LOG-05.input_and_physics_events** | 待实现 | 按移动、起跳、接地与拿放顺序核对实际事件、释放时的位置和速度、异常关系的清理原因。 |
| **LOG-06.restart_file_isolation** | 脚本 | 重启游戏，核对新会话使用独立路径，旧日志字节保持不变。场景清理由 `MENU-09.restart_session` 检查。 |
| **LOG-07.camera_binding** | 待实现 | 核对日志中的人物、控制者、相机关联和初始眼位，触发丢失目标的警告并核对原因。 |
| **LOG-08.capture_and_sampling** | 待实现 | 核对捕获、释放和失焦日志与输入一致。按实际日志级别检查角度和速度采样限频。F3 日志归检查器专项。 |
| **LOG-09.failure_diagnostics** | 待实现 | 受控触发配置写入、资源加载或启动故障，保留操作、路径、原因、进程输出及退出码。Windows MSVC 的 `0xc0000139` 启动失败单独注明。 |
| **LOG-10.normal_exit_record** | 脚本 | 请求关闭真实窗口并等待进程正常退出，核对本次会话尾部的完整退出记录。后台输出故障见[日志无窗口验证](session_log.md#会话日志无窗口验证)。 |
