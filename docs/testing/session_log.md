# session_log 测试

[测试指南](README.md)说明分层和执行边界；实机步骤由用户执行。

## 会话日志无窗口验证

在仓库根按范围运行：

```powershell
cargo test --locked game_flow::tests::initialization_tests
cargo test --locked session_log::
```

[初始化日志测试](../../src/game_flow/tests.rs) 安装真实功能插件并执行 `Startup`；手工注册日志系统不能证明插件实际完成注册。[日志测试](../../src/session_log/tests.rs) 检查下列会话生命周期与后台输出边界，不能只凭短时间内没有阻塞或文件存在判定通过。

| 场景                 | 必须保留的契约                                                                                                                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 功能插件初始化       | 玩法、设置和检查器三个插件各记录一次，缺少插件不报告该功能初始化，后续更新不重复；字段取启动时最终 `PrototypeConfig` 和 `Time<Fixed>`，日志系统不覆盖配置。保留 target、`info` 级别、英文消息，检查器字段含 `plugin="WorldInspectorPlugin"`、`reason="initialization"`。 |
| 文件或控制台阻塞     | 生产者仍能返回，控制台阻塞不妨碍文件独立写入和刷新；解除阻塞后核对完整数量与顺序，不靠绝对耗时判定。                                                                                                                                                                     |
| 刷新、panic 与关闭   | 同步屏障之前的短写记录全部完成；panic hook 返回时文件已有异常上下文。正常退出排空已接受记录，关闭拒绝新记录，并刷新和回收线程，不能仅依赖发送端析构。                                                                                                                    |
| 设备与线程故障       | 写入、刷新、同步和线程 panic 均反馈失败；控制台故障不回退到同步 stderr，也不阻塞健康文件的 panic 同步，退出和关闭仍报告错误。                                                                                                                                            |
| 格式、过滤与会话隔离 | 时间、级别、target 和结构化字段齐全，文件无 ANSI 色码；显式 `RUST_LOG` 同时作用于文件和控制台，每次会话新建文件，不覆盖历史。                                                                                                                                            |

全局 `LogPlugin` 与环境变量隔离放在独立测试子进程，其余检查可使用局部 subscriber。临时文件使用根 `tmp/`；本节不安装窗口或渲染器。用户对真实会话文件的检查见 [日志检查与问题反馈](session_log.md#日志检查与问题反馈)。

## 日志检查与问题反馈

会话文件命名和位置见 [玩家指南](../player-guide.md#会话日志)，日志规则与调试过滤配置见 [开发规范](../development.md)。验收时先确认本次文件的会话开始时间、版本和配置，再将日志中的实体、前后值和原因与操作步骤对应。

- `demo::gameplay` 的 `Prototype gameplay initialized`、`demo::settings` 的 `Fixed simulation timestep initialized` 与 `demo::inspector` 的 `World inspector enabled` 均应以 `info` 级别各出现一次，三条之间无先后要求。玩法记录应对应实际 `PrototypeConfig`，固定模拟频率应对应实际 `Time<Fixed>`；暂停、恢复和重新开始游戏不能重复这些启动记录。用户覆盖 `RUST_LOG` 时按实际过滤规则核对，低于过滤级别的记录缺失不能直接判定插件未注册。
- 鼠标捕获及实际移动输入的离散变化，默认以 `info` 级别落盘，应能对应释放、恢复、失焦和移动输入变化。
- 场景日志记录平地、玩家、控制者、相机与方块生成。玩法日志记录起跳、接地变化，以及 `Carryable item picked up`、`Carryable item released`，物理碰撞日志用于核对阻挡发生的实体。释放日志应对应释放前的真实位置和速度，异常关联清理应记录原因。所有日志写入本次会话日志，反馈问题时保留该文件。
- 相机随会话生成时记录 `Greybox session spawned`，包含 `camera`、`character`、`controller`、`position` 和 `reason`；相机目标或控制者丢失时记录警告。初始眼位与镜头跟随按 [人物移动与镜头验收](first_person.md#人物移动与镜头验收) 确认。
- 视角角度和世界移动速度属于连续数据，以 `debug` 级别每 0.5 秒最多采样一次；默认日志中没有这些采样不代表功能没有执行。需要排查时，由用户按开发规范中的过滤配置自行启动。
- 状态变化日志应包含时间、级别、模块或系统、相关实体或业务 ID、变化前后值和触发原因；错误应保留操作、相关文件路径和原始错误信息。
- 后台输出期间文件和控制台显示可能稍有延迟，不据此判断事件未发生。正常退出后确认退出记录存在、已入队记录排空并刷新、文件末尾无缺失或截断；再次启动并正常退出后应生成新文件，旧文件保留。异常退出时检查最后保留下来的上下文；不要为补充日志而覆盖或删除旧会话文件。

反馈问题时提供复现步骤、实际结果与预期结果、相关设置，以及对应会话日志文件。日志用于问题排查，不能恢复游戏进度。
