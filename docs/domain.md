# 领域文档读取约定

当前仓库是一个用于探索和提升游戏制作水平的 demo，当前玩法尚未确定。使用 [当前架构](architecture.md) 作为实现概览，当前可用能力、操作与配置见 [使用说明](usage.md)。领域术语和架构决策在实际需要时补充；本文件负责告诉技能应读取哪些已有资料。

## 当前读取顺序

1. 读取根 [Agent 开发指南](../AGENTS.md) 指定的必读工程规范。
2. 读取 [当前架构](architecture.md)，定位任务涉及的模块和数据流，再核对相关源码。
3. 涉及玩法目标时读取 [游戏设计](game-design.md) 和相关 Issue，区分已确认设定、建议与待定事项，不从现有场景或资源推断玩法方向。
4. 涉及设计决策时，按 [Agent Notes 约定](../.agents/notes/README.md) 读取与任务相关的决策；讨论尚未实施的方案时，同时读取相关提案。
5. 如果已有 `CONTEXT.md`、`CONTEXT-MAP.md` 或 ADR，按下方规则继续读取。

`CONTEXT.md`、`CONTEXT-MAP.md` 或 ADR 缺失时静默继续，依据已有架构、代码和开发指南开展工作，不将缺失视为阻塞，也不为目录完整而创建占位文件。

## 领域文档扩展后的读取规则

- Agent Notes 按其约定以 `{lifecycle}/{class}/YYYY-MM-DD-title.md` 组织。当前决策读取相关 `implemented/` 记录；`proposed/` 表示尚未完成的提案，`rejected/` 和 `archived/` 仅供背景查阅，不作为现行实现权威。实际行为仍以源码和当前架构为准。
- 单上下文项目存在根 `CONTEXT.md` 时，读取它及其引用的相关决策。
- 出现真实的多个上下文后，使用根 `CONTEXT-MAP.md` 索引各上下文的职责、源码范围、`CONTEXT.md` 和决策记录；先读取索引，再读取任务涉及的上下文与相关全局决策。
- 如果已有实际使用的 ADR，读取相关原记录，并通过 Agent Notes 或上下文索引链接它。同一决策只保留一个完整维护位置，不复制记录，也不为套用目录惯例另建平行 ADR 目录。
- 跨上下文任务读取所有相关资料，并明确交互边界。采用多上下文布局时，同步更新本文件和根 AGENTS 的读取入口。

只有真实术语、边界和决策需要记录时，才建立相应领域文档。已采用的具体布局和消费规则由实际资料维护。

## 术语与决策

Issue、重构方案、诊断假设和测试名称采用相关 `CONTEXT.md` 中定义的术语，避免使用文档明确排除的同义词。

需要的概念未记录时，先核对代码和既有用语；确有缺口时留给 `grill-with-docs` 等领域澄清流程，不自行发明领域定义。

方案与现行 Agent Note 或实际使用的 ADR 冲突时，明确指出对应记录、原因和影响，不静默覆盖既有决策。所有游戏逻辑仍须遵循根 [Agent 开发指南](../AGENTS.md) 与 [开发规范](development.md)。
